Ни один кандидат не имеет PDF, preview, разрешения печати или статуса ready.

| [Торунь](https://metravel.by/quests/torun/torun-copernicus), `torun-copernicus`, ID20 | PL; 100мин; medium; 8 шагов: 5 required, 1 final, 2 optional | Компактный городской набор и разнообразные типы заданий; проверяет риск утечки ответа через историю | Аудитория, исправления текста книги, точные печатные ответы вместо диапазонов, права/медиа |

Это целевой отбор двух проб, не рейтинг всех квестов. Первый page каталога
использован для подтверждения именно ID12/20, не для заявления о полном каталоге.
У обоих нет детских/возрастных меток: `audience=null`, никакого автоматического
присвоения adult/family/child. Длительность — метаданные онлайн-источника, не
замер прохождения бумажной книги. `start` в агрегате каталога не добавляет
девятую точку: физический порядок берётся из массива `steps` bundle.

fail0/backtracks0/over-budget0. Forward/reverse OSM и ручное уточнение локальными

## Снимок источника и воспроизведение хеша

`source.contentSha256` — локальный SHA-256 UTF-8 JSON следующей проекции,
не серверный номер ревизии. Источник получается по точному `bundleUrl` без
авторизации. Счётчики, рейтинги, первый прошедший и другие персональные поля
исключены. Ключи сортируются рекурсивно; строки Unicode сохраняются без
ASCII-экранирования, разделители — запятая и двоеточие без пробелов; LF в конце нет.

Эквивалентная проекция в Python (вход `q` — разобранный JSON bundle):

```python
content = {k: q.get(k) for k in [
    'id', 'quest_id', 'title', 'content_locale', 'intro', 'steps', 'finale', 'cover_url'
]}
content['steps'] = json.loads(q['steps']) if isinstance(q['steps'], str) else q['steps']
content['city'] = {k: q['city'].get(k) for k in ['id', 'country_code']}
payload = json.dumps(content, sort_keys=True, ensure_ascii=False, separators=(',', ':')).encode('utf-8')
digest = hashlib.sha256(payload).hexdigest()
```

Все поля каждого шага сохраняются в содержательном хеше, в том числе hint,
answer_pattern, роль и координаты. Хеш не является проверкой истинности текста
и не заменяет редакционную ревизию. Отдельно сверяются метаданные каталога
duration/difficulty/tags и URL города; изменение этих полей тоже требует
повторного решения об аудитории/пригодности. Изменение source hash, состава,
порядка или cover SHA запрещает молча переиспользовать прежнее согласование.
Хеш cover получен из фактически скачанных байтов; width/height прочитаны из файла,
не из увеличенного preview. Полные raw-снимки и результаты геопроб — ignored
`.codex-temp/books-f1/`; этот каталог не считается постоянным вложением борда.
После изменения живого источника старый хеш служит обнаружению drift, а не
способом восстановления утраченных байтов: перед сборкой нужен сохранённый
разрешённый архив источника и отдельная редакционная ревизия.

## План изданий и проверок

Player и host получают разные строгие входные схемы, одинаковые source hash,
editorial revision и упорядоченные step IDs. Player содержит только проверенные
title/location/story/task; hint, answer_pattern, answerKey и host-медиа туда не
переходят. Для открытого вопроса host явно описывает критерии, не выдумывает
единственный ответ. Проверяется весь пакет, включая PDF metadata/слои и preview.

В постановке F1 — 4 страницы на шаг; для 8 шагов это 32 страницы блоков,
а не готовый общий объём. Предложение: место/история, задание/ответ игрока,
свободное фото, чистый дневник. Образец, служебные страницы и optional-блоки
ещё согласуются. Четыре стороны обложки считаются отдельно. Геометрия v1
и минимум30 мест у страновых книг сохраняются; старый manifest не ослабляется.

После v1: подтвердить аудиторию/географию/ответы/права → согласовать текст и
один образец → реализовать адаптер и отдельную композиционную схему поверх
общего PDF-движка → два player/host-комплекта в двух профилях → actual-PDF
QR/text/fonts/boxes, preview из тех же PDF → code review/gate → production
mobile390→desktop1440. Физическая проверка и приём провайдером — отдельные
проверки; цифровой файл сам по себе не объявляется готовым к печати.
