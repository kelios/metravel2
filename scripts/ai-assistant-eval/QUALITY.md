# Небольшой набор качества модели

Приоритеты владельца: **следование запросу → полезность и точность → язык и
естественность**. Все три оцениваются отдельно, среднего балла, скрывающего
нарушение условий вопроса, нет.

Отчёт разделяет автопроверки и независимую смысловую оценку, а также считает
их разногласия. Это позволяет улучшать сам оценщик: ложный автопровал нельзя
выдавать за доказанный недостаток модели. Строгий итог требует обоих pass.

`cases.quality.jsonl` — 10 пар «вопрос → пример хорошего ответа» и проверяемые
условия. Формулировка ответа свободная. `fixtures.quality.json` — фиксированные
карточки сайта: сведения каталога `/api/quests/?compact=true` и названия двух
статей `/api/travels/?query=Краков`, прочитанные 25.10.2026. Фрагменты статей
сокращены до смысла их названий; числа квестов взяты из `points/duration_min`.
Это небольшой набор для разработки, не независимый скрытый экзамен и не оценка
всего каталога. Не добавлять его в обучение при сравнении версий на этом наборе.

| Пример | Запрос проверяет | Главное ожидание |
| --- | --- | --- |
| q01 | Один семейный квест, Краков, ≤90 минут | Прокоцим, 90 минут, одна ссылка |
| q02 | Точные данные одного квеста | Дракон: 9 точек, 120 минут |
| q03 | Город и два числовых ограничения | Прокоцим: 8 точек, 90 минут |
| q04 | Сравнение двух длительностей | 90 и 45 минут; минский короче |
| q05 | Отсутствующая цена | Признать, что цены нет в материалах |
| q06 | Город, отсутствующий в карточках | Не выдавать другие города за Гданьск |
| q07 | Уточнение «второй» в фиксированной истории | Прокоцим, 90 минут |
| q08 | Условия q01 и польский язык | Один подходящий вариант, ответ по-польски |
| q09 | Минск, до часа, один вариант | Цмок, 45 минут |
| q10 | Зимняя статья вместо квестов | Статья о зимних поездках из Кракова |

Запуск на локальном `llama-server` (Node ≥22.6 с type stripping; на этом Mac
Node 22 лежит отдельно от системного Node 20):

```bash
PATH="/opt/homebrew/opt/node@22/bin:$PATH" npm run ai:assistant:quality
# Один пример:
PATH="/opt/homebrew/opt/node@22/bin:$PATH" npm run ai:assistant:quality -- --only q01
# Повторная оценка сохранённых ответов после добавления judge.jsonl:
PATH="/opt/homebrew/opt/node@22/bin:$PATH" npm run ai:assistant:quality -- --report .codex-temp/ai-assistant-eval/<прогон>
```

Runner использует `buildAssistantMessages`, `LlamaCppGenerator` и страж ссылок
приложения. Дополнительно сохраняет сырой ответ до стража и проверяет его:
исправленная стражем выдуманная ссылка всё равно считается провалом модели.
`q07` проверяет фиксированную историю, а не полноценный диалог из двух генераций.
Поиск, UI, лимиты и фильтр тем проверяет отдельный `ai:assistant:eval`.

Артефакты — в ignored `.codex-temp/ai-assistant-eval/quality-<время>/`:
`meta.json` (модель, коммит, хеш входов), `results.jsonl` (карточки, промпт,
сырой и показанный ответ), `report.md`, `judge-task.md`. По `judge-task.md`
судья пишет `judge.jsonl` по рубрике `JUDGE.md`, дополнительно выставляя
`instruction`, `usefulness`, `language`: 0 — плохо, 1 — частично, 2 — выполнено.
Для смыслового pass нужны 2/2 за следование запросу, 2/2 за полезность и точность
и не менее 1/2 за язык. Итоговый pass требует также прохождения автопроверок.

Автопроверки — объяснимый поиск фактов и ссылок, а не семантическое понимание.
Они не доказывают правильную связь чисел с объектами, отсутствие отрицания или
естественность текста. Пока судья не оценил все ответы, отчёт явно показывает
незавершённую смысловую оценку. Код выхода runner — 1 при провале автоматической
проверки или имеющегося вердикта судьи, 0 при их прохождении; 0 без судьи не
означает подтверждённое качество смысла. Параметры генерации совпадают с
приложением, включая temperature 0.3; повторный прогон может дать другой текст.
