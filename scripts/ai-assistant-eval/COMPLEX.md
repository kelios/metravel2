# Сложные запросы: условия поездки и доступность

**Контрольные объекты вымышлены.** Их ссылки `/travels/eval-fixture-*` — тестовые идентификаторы, а не существующие страницы или советы о реальных местах. Описания входов, расписания и адаптаций не относятся к реальным объектам Кракова.

Набор: 16 запросов, в каждом по три проверяемых условия. Приоритет: следование условиям → полезность и точность → язык. `criteria.conditions` задаёт смысловые условия для судьи; `required` и ссылки — дополнительные объяснимые автопроверки.

Две отдельные части:

- **Контрольные данные (10):** факты явно заданы в карточках; проверяется выбор, расчёт времени и отказ при несовместимых условиях.
- **Реальные неполные карточки (6):** неизменённые снимки сайта от 25.10.2026 из `fixtures.quality.json`. В них нет расписаний, прогноза погоды, параметров безбарьерного пути или адаптаций заданий. Проверяется корректное признание неизвестного.

Дата «сегодня» в вопросах означает явно указанное 25.10.2026 (воскресенье); понедельник — 26.10.2026. Время — местное время Кракова (Europe/Warsaw); в минских примерах — указанное местное время Минска. Дождь — данное условие учебного сценария, не результат обращения к погодному сервису. Даты и погода не обновляются при повторном запуске.

«Лёгкий», «семейный», короткая длительность и наличие асфальта сами по себе не доказывают доступность. Доступность для коляски не доказывает пригодность для лежачей каталки. Аудиоописание не отменяет указанное в карточке требование сопровождающего. Такие неподтверждённые утверждения отмечаются судьёй как критические ошибки.

Запуск на локальной модели, Node 22:

```bash
PATH="/opt/homebrew/opt/node@22/bin:$PATH" npm run ai:assistant:quality -- \
  --cases scripts/ai-assistant-eval/cases.complex.jsonl \
  --fixtures scripts/ai-assistant-eval/fixtures.complex.json
```

Runtime-прогон выполняется после code review и общего operation gate. Прогон сохраняет промпты, карточки и сырой/показанный ответ в ignored `.codex-temp/ai-assistant-eval/`. Судья читает `judge-task.md` и для каждого условия из `criteria.conditions` фиксирует выполнено/не выполнено с причиной; недостаточно просто встретить нужное слово. Для критических условий доступности отдельно отмечается неподтверждённое обещание безопасности или самостоятельного прохождения.

Пустой ответ или отказ «не по теме» не получает баллы за условия только потому, что в нём нет опасного утверждения. Для условий о неизвестных сведениях нужен ответ по существу, явно признающий, какие данные отсутствуют; молчание об условии не считается его выполнением.

В пользовательском отчёте нужны: запрос → ожидаемый ответ → фактический ответ → выполненные условия (например 2/3); отдельно доля полностью успешных запросов и доля выполненных условий. Доли контрольных и реальных неполных карточек считаются раздельно. Это результаты маленькой фиксированной выборки, не статистическая точность модели на всём сайте. Поиск, актуальное расписание, реальная погода и фактическая доступность объектов этим прогоном не подтверждаются.

Набор не добавляется в обучение при сравнении моделей на нём. Изменение вопроса, карточек, промпта или генератора требует нового прогона соответствующих примеров; исправление ошибочного вердикта судьи пересчитывает сохранённые ответы без повторной генерации.

`scripts/ai-train/sets/assistant_prompt.py` защищает все `cases*.jsonl`, эталонные ответы и вымышленные объекты `fixtures*.json`; prepared manifest сохраняет их хеши. Перед каждой новой сборкой нужно проверить полный перечень оценки и отсутствие прямых совпадений и перефраз. Реальные карточки могут оставаться частью корпуса сайта, но оценочные вопросы и эталоны нельзя копировать в обучение. Те же навыки обучаются на других учебных объектах, расписаниях и сочетаниях чисел. Работа судьи с этим набором не разрешает новое обучение.
