# metravel-llm — собственная модель на корпусе сайта

Линия AI-ASSIST после решения владельца 17.10.2026: ответы посетителям даёт
наша модель, дообученная на статьях и квестах metravel.by, а не облачный API.
План и карточки — `docs/LOCAL_AI_ASSISTANT_PLAN.md` § 8 (#2462, #2463, #2458,
#2457, #2460).

## Окружение (MacBook M5 Pro, 24 ГБ; обучение перенесено с iMac 18.10.2026)

Папка обучения вне репозитория — `~/metravel-ai` на внутреннем APFS-диске
(нужно ~10 ГБ; exFAT напрямую не годится: AppleDouble-файлы `._*.py` ломают
`transformers`, на iMac это решали APFS-образом `hdiutil create -fs APFS -type SPARSE`).

```bash
brew install uv llama.cpp
mkdir -p ~/metravel-ai && cd ~/metravel-ai
uv venv venv --python 3.12 && uv pip install --python venv/bin/python mlx-lm huggingface_hub
venv/bin/hf download mlx-community/Qwen3.5-4B-MLX-4bit --local-dir models/Qwen3.5-4B-MLX-4bit
```

Раскладка `~/metravel-ai`: `models/` базы, `data/raw/` экспорт сайта,
`data/sources/` кэш внешних источников, `data/sets/` наборы, `data/sft-<смесь>/`
смеси для обучения (`data/sft/` — датасет v0/v1), `adapters/` результаты LoRA, `logs/` журналы, копии конфигов и отчёты
оценки каждого запуска.

### Память при обучении (mlx-lm 0.32, замер 18.10.2026)

В режиме обучения линейные слои Qwen3.5 (Gated DeltaNet) идут по запасному
пути без Metal-ядра и держат состояние рекуррентности на каждый токен для
обратного прохода. Один пример в 1024 токена при 4–6 слоях под LoRA стоит
~15 ГБ, при 8 слоях ~20 ГБ, батч 2 × 1024 — 27+ ГБ (лимит рабочего набора GPU
на 24 ГБ — 18 ГБ, на 16 ГБ M1 — ещё меньше). Поэтому конфиг: батч 1, seq 1024,
6 слоёв, без накопления градиента (два графа по 1024 токена тоже не влезают): эпоха = 7,7 тыс. шагов. Скорость — десятки токенов в секунду, полная
эпоха — часы; Metro, colima и сборки на этом Mac во время обучения не запускать.
Запуск под `caffeinate -i`, чтобы ноутбук не уснул. `train.sh` выставляет
`MLX_DISABLE_COMPILE=1`: скомпилированный шаг тренера (`mx.compile`) ломает
экономию gradient checkpointing на этих слоях — пик 20,9 ГБ вместо 15,4 и втрое
медленнее.

## Шаги

1. Экспорт корпуса (только публичный прод-API, чтение, пауза между запросами):
   `python3 -I scripts/ai-train/export_corpus.py --out ~/metravel-ai/data/raw` (≈10 мин)
   (`--quest-locales ru,pl,en` для переводов квестов; v0 — RU; для набора
   `translations` переводы выгружает свой загрузчик, `data/raw` остаётся RU).
2. Датасет — уровни «источники → наборы → смеси» (`docs/AI_TRAIN_DATASETS.md` § 2,
   #2475). PyYAML ставится вместе с mlx-lm, поэтому сборка идёт из venv:
   `~/metravel-ai/venv/bin/python -I scripts/ai-train/build_mix.py --ai-home ~/metravel-ai --mix scripts/ai-train/mixes/<смесь>.yaml`
   → `data/sets/<набор>/{train,valid,test}.jsonl` + `stats.json` (записи
   `{messages, set, key, id, kind, license}`) и `data/sft-<смесь>/` — то, что
   читает mlx-lm (`messages`), плюс `stats.json` и `manifest.json` (наборы,
   лицензии, источники, потолки). У смеси с несколькими этапами — подпапка на
   этап (`data/sft-v2/s1`, `…/s2`).
   - `sources/` — загрузчики с кэшем в `data/sources/<имя>/` (+ `LICENSE`,
     `fetched_at.json`); сеть только при явном запуске загрузчика.
     `sources/site_filters.py` — справочники сайта (транспорт, ночёвка, месяцы).
     `sources/site_translations.py` — параллельные тексты сайта: квесты с
     переводом во всех своих локалях (прод-API, ≈2,5 мин) и строки интерфейса
     из `i18n/locales/*` этого репозитория (коммит — в `fetched_at.json`).
     Открытые источники по Беларуси и Польше (v2, #2477–#2479; гонять
     venv-Python — системный 3.9 не проходит SSL-рукопожатие с Overpass):
     `sources/wikidata.py` — Wikidata (CC0) через SPARQL: населённые пункты,
     памятники, природа с названиями ru/be/uk/pl/en, типом, цепочкой
     административных единиц, координатами, статусом памятника; классы
     страновые (`город районного подчинения`, `село в Польше`), порог
     сайтлинков по классу, один класс на запрос (объединение по стране ловит
     504), свойства — пачками по 150 QID; ≈15 мин, кэш запросов в `queries/`.
     `sources/wikivoyage.py` — путеводители ru/pl/en (CC BY-SA): список
     страниц — сайтлинки Wikidata по P17, тело через API MediaWiki; у страницы
     остаются только разделы «Понять / Как добраться / Достопримечательности /
     Чем заняться», остальное отбрасывается до сборки; скан
     `scripts/content-source-denylist.json` исключает страницу целиком
     (список — в `fetched_at.json`); сайтлинк-редирект пропускается (цель —
     страница другого объекта); ≈3 мин. `clean_wikitext()` там же — листинги
     в «Название (адрес; часы): описание», без URL, таблиц и галерей; строки
     с телефоном, e-mail или чужим доменом отбрасывает уже набор.
     `sources/osm.py` — Overpass (ODbL, кэш только локальный): именованные
     POI с `wikidata` по тем же тегам, что фильтры карты, плюс вершины с
     высотой и кемпинги; тайлы 1° внутри границы страны (`area ISO3166-1`),
     ротация `overpass-api.de`/`lz4`; долго — перегруженный сервер отвечает
     по 30 с на запрос. Недоступный тайл пропускается и попадает в
     `missing_tiles` (`fetched_at.json`), повторный запуск докачивает только
     его; `--offline` собирает `pois.jsonl` из кэша без сети.
     `sources/osm_pbf.py` — тот же кэш из полных страновых экстрактов
     Geofabrik, когда публичный Overpass лежит днями (24.10–07.11.2026):
     `-latest` разрешается в датированный снимок, MD5 издателя и sha256
     проверяются, границы стран — полигоны OSM через Nominatim
     (`pbf/*-boundary.geojson`); потоковый проход pyosmium с дисковым индексом
     узлов, предикат тегов общий с Overpass (`osm.matches_tags`), центр —
     середина bbox объекта строго внутри полигона страны; relation без члена
     или с циклом отбрасывается и считается (`rejected_geometry`), объекты
     соседних стран — `rejected_country`. Публикация атомарная, старая
     диагностика тайлов остаётся в `overpass-fetched_at.json`, после этого
     `osm.py` не перезаписывает полный кэш неполным прогоном. Нужны pyosmium и
     Shapely в отдельном окружении: `python3 -m venv ~/metravel-ai/venv-osm &&
     ~/metravel-ai/venv-osm/bin/pip install osmium shapely`, запуск
     `~/metravel-ai/venv-osm/bin/python -I scripts/ai-train/sources/osm_pbf.py
     --ai-home ~/metravel-ai` (≈2,5 ГБ, ≈20 мин на M5 Pro).
   - `sets/site.py` — набор сайта: карточки и разделы статей, плюсы/минусы/советы,
     подборки по стране/месяцу/дням, карточки/точки/финалы квестов, квесты по
     городу и стране, «название → ссылка», отказы по направлениям без
     материалов, «о сайте»; с `structured: true` ещё «точки маршрута статьи →
     JSON» и «карточка маршрута по фрагменту» (дни, месяцы, транспорт, ночёвка,
     км и высоты из текста).
   - `sets/translations.py` — RU → BE/UK/PL/EN (#2476): перевод фрагментов
     квеста (интро, история и задание точки по `step_id`, финал), карточка
     квеста на языке посетителя — по вопросу на этом языке и по вставленной
     русской карточке, пачки строк интерфейса с плейсхолдерами. Весь набор
     ≈6,2 млн токенов; `kind_share` в смеси решает, что входит в бюджет 0,5 млн.
   - `sets/toponyms.py` — Wikidata-места (#2477): «как по-польски / по-белорусски
     называется X» (и обратно с иностранного написания), «в какой области /
     воеводстве X» (тип + цепочка единиц в именительном, без склонений), «что
     это за объект», «X и Y — одно и то же?» (да — другое написание, нет —
     другое место того же вида). Ключ — QID; объекты режутся по сайтлинкам
     (`max_items` на страну и группу), 10 % объектов спрашиваются
     по-белорусски — «как называется» и «где» тогда и отвечают по-белорусски.
   - `sets/wikivoyage.py` — общие сведения (#2478): по одному примеру на
     оставленный раздел страницы, вопрос и ответ на языке страницы, ответ
     начинается маркером «По открытым данным:» / «Według otwartych danych:» /
     «From open data:», длинный раздел — до двух кусков по 1800 символов;
     строки с URL, e-mail, телефоном или чужим доменом выпадают, denylist
     проверяется ещё раз на очищенном тексте. Ключ — QID места (общий с
     `toponyms`).
   - `sets/osm_intents.py` — карта (#2479): «вопрос → JSON-фильтр карты» по
     `osm_filter_schema.json` (категории `OsmPoiCategory`, радиусы
     `RADIUS_OPTIONS`, центр, ограничения dogs/camper/kids/free; схему держит
     `__tests__/scripts/ai-train-osm-filter-schema.test.ts`) — синтетика по
     шаблонам на реальных названиях (центры — поселения из кэша Wikidata,
     ключ — их QID, как в `toponyms`),
     RU со склонением названий + 10 % BE + 10 % PL; и «теги OSM → описание
     места» по реальным POI без выдуманных фактов. `validate_filter()` —
     единственный валидатор схемы, его же использует `eval.py`.
   - `mixes/toponyms.yaml`, `mixes/wikivoyage.yaml`, `mixes/osm_intents.yaml`
     — каждый новый набор отдельно с опциями как в v2.
   - `mixes/v1.yaml` — регресс: бит в бит датасет, на котором обучен v1
     (сплит по id примера, формулировки v1). После правки `sets/site.py`:
     `build_mix.py --mix mixes/v1.yaml --out <tmp>` и `cmp` с `data/sft/*.jsonl`.
   - `mixes/site.yaml` — набор `site` в редакции v2 отдельно: сплит по
     сущности (`key`: статья, квест, страна, город) — все формулировки одного
     объекта в одном сплите, в v1 52 из 205 ответов test дословно были в train;
     нейтральная подводка подборок по месяцу (гостевые статьи — не «мы ездили»).
   - `mixes/translations.yaml` — набор `translations` отдельно, с долями видов
     как в v2.
   - `mixes/v2.yaml` — S1 «фундамент» → S2 «сайт» с replay 15 %; собирается,
     когда появятся наборы #2476–#2479.
3. Обучение запускается только по проверенному prepared manifest. Сначала
   `prepare_training_data.py` сохраняет полные примеры в отдельную папку,
   затем отдельная копия конфигурации указывает на неё через `data:`.
   Исторические конфиги v0–v4 с сырым `data:` напрямую больше не запускаются:
   сохраните изменённую копию в `.codex-temp/`, не перезаписывая старую версию.
   Полная последовательность подготовки и проверки приведена в разделе
   «Кандидат v5-rag». Запуск из корня репозитория:
   `nohup caffeinate -i env AI_HOME=$HOME/metravel-ai CONFIG=<подготовленный-конфиг> RUN=<новый-run> scripts/ai-train/train.sh &`
   (конфиг `lora-qwen3.5-4b.yaml`: QLoRA rank 16 на 4-bit базе, 6 слоёв,
   seq 1024, батч 1 без накопления, loss только по ответу). Долго — часы;
   журнал `logs/train-v0.log`, чекпоинты каждые 500 шагов в
   `adapters/metravel-llm-v0/` (исторический v0; новый run требует нового
   adapter_path в конфиге). Проба перед полным прогоном использует отдельные
   RUN и путь: `… train.sh --iters 12 --steps-per-report 2 --val-batches 1 --adapter-path adapters/<новый-probe>`.
4. Проба в терминале: `ADAPTER=adapters/<версия> scripts/ai-train/chat.sh` — чат с
   моделью и адаптером (`ADAPTER= scripts/ai-train/chat.sh` — база без адаптера
   для сравнения). С #3267 `RUN` и `CONFIG` у `train.sh`, `RUN` у
   `export_gguf.sh` и `ADAPTER` у `chat.sh` задаются явно: умолчания указывали
   на v0/v1 и молча брали старую версию.
   Не запускать во время обучения на том же Mac. Разовый вопрос:
   `venv/bin/python -m mlx_lm generate --model models/Qwen3.5-4B-MLX-4bit --adapter-path adapters/metravel-llm-v0 --prompt "Какие квесты есть в Гродно?"`.
   В браузере модель откроется после экспорта в GGUF (#2463): `llama-server`
   даёт веб-чат на `http://127.0.0.1:8080`.
5. Оценка: `AI_HOME=~/metravel-ai ~/metravel-ai/venv/bin/python scripts/ai-train/eval.py --adapter adapters/metravel-llm-v0 --out logs/eval-v0`
   — все срезы из `eval_prompts/<набор>.jsonl` (`--prompts-dir`, по умолчанию
   эта папка; один файл — `--prompts`), балл по каждому срезу отдельно. Срез
   `site` — 40 вопросов (18 посетителя по материалам, 10 негативов, 2 на
   польском, 10 редакционных); база и адаптер бок о бок;
   автопроверка: все ссылки — реальные страницы metravel.by (по `data/raw`),
   без чужих сайтов, честный отказ на негативах; отчёт `logs/eval-v0/report.md`
   с колонкой для ручной оценки. Срез `translations` — 10 вопросов на
   BE/PL/UK по вставленной русской карточке квеста или статьи (квесты и статьи
   из test-сплита), `expect: lang`: ответ на языке вопроса (по буквам, без
   URL) и без выдуманных ссылок. Срезы v2: `toponyms` — 15 вопросов
   (`expect: exact`, регулярки `accept`/`reject`: написание на другом языке,
   область/повят, тип объекта, «одно и то же?»); `wikivoyage` — 10 вопросов
   по городам без наших статей (`expect: info`: ≥200 символов, ни одной
   ссылки, язык вопроса, без зацикливания); `osm_intents` — 10 запросов
   (`expect: json`: первый `{…}` в ответе проходит `validate_filter()` и
   содержит ожидаемые категории/центр). Не запускать во время обучения.

## Экспорт в GGUF и сервер llama.cpp (#2463, 18.10.2026)

MLX-адаптер работает только на Mac; прод (Linux, CPU) запускает модель через
`llama.cpp`. Экспорт — `scripts/ai-train/export_gguf.sh` (три идемпотентных шага,
~4 мин на M5 Pro):

1. `merge_lora.py` сливает LoRA в **bf16-базу** `Qwen/Qwen3.5-4B` (9,3 ГБ,
   `venv/bin/hf download Qwen/Qwen3.5-4B --local-dir models/Qwen3.5-4B`) по формуле
   `mlx_lm` `LoRALinear.fuse`: `W' = W + (scale·lora_b.T)·lora_a.T`, 26 тензоров в
   6 последних слоях, max |Δ| 0,04–0,07. Раскладка HF сохраняется (`mlx_lm fuse` пишет
   текстовую модель в своих ключах, которые `convert_hf_to_gguf` для
   `Qwen3_5ForConditionalGeneration` не принимает). Слияние в 4-bit базу не делаем —
   теряет качество; адаптер учился на 4-bit, слияние в bf16 — стандартная практика QLoRA.
2. `llama.cpp/convert_hf_to_gguf.py --outtype bf16` из исходников той же сборки, что
   бинари brew (`llama-server --version` → `build 11669`; `git clone --depth 1 --branch
   b11669 …`), нужен `torch` в venv (`uv pip install --python venv/bin/python torch`).
   Архитектура `qwen35` (Gated DeltaNet + 8 слоёв внимания) и MTP-слой `blk.32.nextn`
   переносятся; предупреждение `Unknown RoPE type: default` безвредно.
3. `llama-quantize … Q4_K_M` → `gguf/metravel-llm-v1-Q4_K_M.gguf`.

| артефакт | размер | sha256 |
| --- | --- | --- |
| `fused/metravel-llm-v1-bf16/` (HF) | 8,7 ГБ | — |
| `gguf/metravel-llm-v1-bf16.gguf` | 8,1 ГБ (8253,72 MiB) | — (хранится для переквантизации) |
| `gguf/metravel-llm-v1-Q4_K_M.gguf` | 2 783 446 880 байт (2,58 ГиБ, 5,13 bpw) | `b31d18c7d9ade88df7450b3f5dd18ded059ab791f76db489091bafa1a7157d64` |

Запуск: `llama-server -m gguf/metravel-llm-v1-Q4_K_M.gguf --port 8080 -c 8192 --parallel 2 --jinja`.
`-c` — общий KV-бюджет на все слоты (`n_ctx_slot = c / parallel`): при `-c 4096 --parallel 2`
промпт ассистента с 8 карточками и историей (~3 тыс. токенов) получает
`400 exceeds the available context size (2048 tokens)`. `--jinja` обязателен, иначе
`enable_thinking: false` не применяется. Контейнер — `services/metravel-llm/`.

### Замеры (`bench_server.py`, Mac M5 Pro, 24 ГБ; промпт 3221 токена для TTFT-long)

| CPU `-ngl 0`, 4 потока | 1,3 с | 70 с (46 ток/с) | 26 ток/с | 24,5 с, 14 + 14 ток/с | 6,1 ГБ |
| CPU `-ngl 0`, 3 потока | 1,7 с | 94 с (34 ток/с) | 21 ток/с | 19,6 с, 19 + 11 ток/с | 6,5 ГБ |

`llama-bench` CPU: pp512 52 ток/с (4 потока) / 86 (8), tg128 25 / 33. RSS на CPU
не зависит от контекста (`-c 4096 -np 1` → 5,4 ГБ, `-c 8192 -np 2` → 5,6 ГБ после
загрузки) — это mmap весов 2,65 ГБ плюс буферы бэкенда brew-сборки (BLAS+Metal
инициализируются и при `-ngl 0`); для Linux-образа без Metal ожидание ≈ 3–3,5 ГБ
(веса + KV 8 слоёв + compute), подтверждается первым запуском контейнера (#2457).

**Вывод для прода.** Узкое место CPU-инференса Qwen3.5 в llama.cpp — обработка
промпта (DeltaNet-слои без быстрого CPU-ядра): даже на ядрах M5 Pro 46 ток/с при 4
потоках, у Skylake-vCPU ожидаемо в 2–4 раза меньше (10–20 ток/с). Промпт ассистента в
500 токенов на таком сервере — TTFT 25–50 с, 3 тыс. токенов — минуты. Генерация
(5–10 ток/с на 3 потоках) приемлема. Поэтому для CPU-сервера промпт нужно держать
≤ 500–800 токенов (меньше карточек, короче сниппеты) либо выбирать площадку с GPU
(см. #2458); Docker на этом Mac нет, числа с реального Linux-хоста добавит #2457.

## Кандидат v5: совместные ограничения и неизвестные сведения

Продолжение v4 по отдельному набору `constraints`: 120 независимых вымышленных
сценариев × 4 формулировки, восемь типов — дата/остаток времени, дождь/помещение,
коляска/ширина непрерывного пути, неизвестные параметры каталки, слабовидение и
сопровождение, отсутствие подходящего варианта, неизвестная информация и
уточнение в настоящей истории диалога. Варианты одного сценария имеют общий
`key`, правильная карточка меняет позицию, все факты и отвлекающие карточки
сохраняются. Это учебные данные, не утверждения о доступности реальных мест.

`mixes/v5.yaml` сохраняет seed разбиения S1/S2 и добавляет 40% replay старых
навыков к финальной стадии. Старые списочные шаблоны `rag_answers` в неё не
пересобираются. Адаптер продолжается из v4 и пишется отдельно в
`adapters/metravel-llm-v5`; v4 не заменяется.

Подготовка (только существующие локальные модели и кэш):

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 ~/metravel-ai/venv/bin/python -I scripts/ai-train/build_mix.py --ai-home ~/metravel-ai --mix scripts/ai-train/mixes/v5.yaml
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 ~/metravel-ai/venv/bin/python -I scripts/ai-train/prepare_training_data.py --data ~/metravel-ai/data/sft-v5/s3 --model ~/metravel-ai/models/Qwen3.5-4B-MLX-4bit --out ~/metravel-ai/data/sft-v5/s3-fit --max-tokens 1024
~/metravel-ai/venv/bin/python -I scripts/ai-train/prepare_training_data.py --config scripts/ai-train/lora-qwen3.5-4b-v5.yaml --ai-home ~/metravel-ai
```

Подсчёт повторяет полную chat-template кодировку установленного `mlx_lm`,
включая последний ответ. Пример длиннее 1024 токенов исключается целиком;
цель, важные условия и фрагменты не обрезаются. Sidecar-файлы
`*.records.jsonl` сохраняют происхождение записей; manifest фиксирует хеши,
размеры, причины исключений и фактический состав смеси. Все оценочные файлы
`cases*.jsonl` и идентификаторы вымышленных `eval-fixture-*` защищены от утечки;
лексическая проверка не доказывает отсутствие произвольных перефразов —
дополнительно нужны независимое конструирование сценариев и ревью.

Подготовленный снимок 25.10.2026: **803 train / 16 valid / 5 test**; train —
460 новых ограничений, 23 off-topic и 320 replay (39,9%). Два слишком длинных
примера перевода исключены; все 480 новых записей сохранены в своих split.
Максимум полного train-примера — 1014 токенов, минимальная цель — 16 токенов.
Конфиг фиксирует одну эпоху, 803 шага; после новой сборки эти числа следует
проверить заново, не переносить их на другой снимок.

`train.sh` проверяет подготовленный снимок перед загрузкой весов и держит
общую для `AI_HOME` блокировку обучения. Изменённые данные, tokenizer или
оценочный набор требуют повторной подготовки. Нужны source checks, независимое
ревью и отдельная 12-step проба с конечными loss без OOM/обрезаний; затем
разрешён локальный запуск под `caffeinate -i`. Инференс модели на GPU и свой
Metro перед пробой освобождаются. Проба и полный запуск используют разные
adapter paths и RUN; существующий результат не перезаписывается.

Запуск обучения не доказывает улучшение. После завершения — отдельный экспорт,
тот же замороженный сложный набор и старые регрессионные срезы. Неподтверждённые
обещания доступности оцениваются отдельно; вывод о реальном объекте требует
проверенных сведений в карточке.

## Кандидат v6: S1 в самом этапе, edition 6 (#2751, 08.11.2026)

Разбор приёмки `v5-rag` 01.11.2026 показал три разных механизма, и v6 закрывает
каждый своим слоем:

1. **Пограничные вопросы («какую кашу в поход», «packing light») — отказ модели
   при карточках подбора.** На экране (`v4-targets-s29`, `v5rag-targets-s29`)
   подбор отдавал 1–6 посторонних карточек, промпт — штатный с «Материалы
   сайта:», а модель отвечала фразой отказа. Вариант «ничего не найдено» до
   модели не доходит вовсе: `useAssistantChat.ts` и `scripts/ai-assist/ask.ts`
   при пустом подборе ставят `no_sources` без вызова модели. Поэтому слой здесь —
   данные, а не `retrieval.ts`/`prompt.ts`: edition 5 убрала вид `topic`
   (его заменили канцелярские `boundary_*` «что известно из этих материалов»),
   и натуральные вопросы о еде/сборах/бюджете снова ушли в офф-топик. Edition 6
   возвращает `topic` и добавляет `TOPICS6` — естественные RU/EN/BE/UK/PL
   формулировки с посторонними карточками → «отдельного материала нет +
   ближайшая карточка».
2. **Срезы S1 (`osm_intents` 6/8, `wikivoyage` 2/2) не восстанавливаются
   случайным replay** (86/80 примеров в `v5-rag`). В `mixes/v6.yaml` эти наборы
   стоят в самом обучаемом этапе `s3` (osm_intents 353 — новая сборка 07.11 из
   PBF с ограничениями dogs/camper, wikivoyage 248), replay 25 % идёт только из
   пула `toponyms`/`translations`/`site` (пул смещён к `site`: 11 → 9 в v5-rag).
3. **«Ровно один» → два пункта без длительности; PL-ответ русскими заголовками
   (`quality` q01/q03/q08/q09).** Виды `exact_one` («ровно/только один квест
   {loc} до N минут» → одна карточка под лимитом с длительностью из карточки,
   остальные квесты места длиннее лимита) и `one_article`; в не-RU ответах у
   каждого пункта блёрб на языке ответа — компактный список русских заголовков
   автопроверка языка читает как русский ответ. К компактным не-RU вопросам
   добавлены естественные («Што паглядзець {loc} за два дні?»; вопросы контура
   после подстановки города пропускает `is_contour_question`).
4. **Вопрос про текущую страницу (#2897).** Вид `page`: карточка страницы первой
   среди ≤ 3 (`pinSourceFirst`, `AI_SOURCES_LIMIT_PINNED`), ответ только о ней
   фактами из её фрагмента (точки/длительность/сложность квеста, место и первое
   предложение статьи; приветствие авторов фрагментом не считается).

## Контур приёмки и ревью кода обучения (#3267, 11.11.2026)

Приёмка кандидата — одна команда, а не таблица из шести прогонов, собранная
руками (так было у v5-rag, v6 и v7):

```bash
# два llama-server (база и кандидат), экран контура на :8081, Node ≥ 22.6
PATH="/opt/homebrew/opt/node@22/bin:$PATH" npm run ai:assistant:accept -- \
  --base-url http://127.0.0.1:8090 --candidate-url http://127.0.0.1:8080
npm run ai:assistant:accept -- --plan                     # показать прогоны
npm run ai:assistant:accept -- --merge-judge <папка>      # после судьи
```

Она гонит базу и кандидата на одинаковых входах (целевые вопросы экрана ×3,
отложенные ×3, «не по теме» и попытки сломать, набор quality ×3, срезы
`eval.py`) и печатает «замер — база — кандидат — порог — пройдено» по
`scripts/ai-assistant-eval/acceptance.thresholds.json`. Судья — обязательный
шаг: задания лежат под слепыми метками A и B с сырым и показанным ответом, до
`--merge-judge` итог — «приёмка неполная». Подробно —
`docs/features/ai-assistant.md` → «Контур оценки».

Срезы под пороги: `eval_prompts/osm_intents.jsonl` — 44 случая (каждое
ограничение на RU и на BE или PL, пары категорий, радиусы, вся страна),
`cases.quality.jsonl` — 34, `cases.holdout.jsonl` — 34 (бывший
`cases.v5-holdout.jsonl`: первые десять случаев те же). Хеши всех оценочных
входов заморожены в `scripts/ai-assistant-eval/eval-inventory.json`
(`--freeze` обновляет опись той же правкой); новые вопросы сверены с
обучающими данными v7 — совпадений нет.

Что изменилось в оценке и подготовке по итогам ревью кода:

- **Срез `osm_intents` сравнивает фильтр с ожидаемым** (поле `expected`:
  множество категорий, включённые ограничения, радиус, если он назван числом,
  центр — по началу названия: склонённое «Познани» геокодер разрешит, другое
  название — нет). Прежняя метрика «схема + признаки в тексте» пропускала
  лишние категории и ограничения; она остаётся в `results.jsonl` как
  `pass_accept` и показывается в примечании таблицы.
- `expect=offtopic` не засчитывает отказ, за которым идёт ответ по существу
  (длиннее 1,5 эталонной фразы); `expect=rag` требует, чтобы ссылки были из
  карточек подсказки, а группа `no_material` — признания «материала нет»;
  неизвестный `expect` — ошибка, а не молчаливое `answer`.
- **Родословная адаптера.** `prepare_training_data.py` идёт по
  `resume_adapter_file` до первого адаптера и проверяет обучающие данные каждого
  звена на оценочные вопросы. Линия v4 загрязнена: в `sft-v4/s3` дословно стоят
  22 вопроса `cases.jsonl` (bd01, bd02, bd07, es01, in03–in05, mt01, of02, of03,
  of05–of10, of12–of17), в `sft-v3/s3` — ещё on02 и on18. v6 и v7 продолжают
  адаптер v4, поэтому в приёмке v7 целевые bd01 и bd07 и 17 из 27 вопросов
  «не по теме» не были отложенными. Конфиг, продолжающий такую линию, обязан
  нести `lineage_contamination_acknowledged: true`; таблица приёмки помечает эти
  id (`lineageContaminated` в файле порогов). Подготовленные данные v5–v7 чисты.
- `validate()` пересчитывает хеши входов подготовленного снимка: правка
  генератора с пересборкой смеси на месте больше не оставляет обучение на
  старом `s3-fit`. После #3267 оценочные входы изменились, поэтому снимки
  `sft-v7/s3-fit` и раньше проверку не проходят — новый круг готовится заново.
- `build_mix.py` не пишет в непустой `--out` без `--force`; `export_gguf.sh`
  сверяет sha256 адаптера перед повторным использованием `fused/` и GGUF
  (у готовых v1–v7 записи нет — `ALLOW_UNVERIFIED_REUSE=1`); набор `osm_intents`
  пропускает вопросы своего оценочного среза; `offtopic` с опцией `edition: 2`
  отделяет оценочные вопросы по хешу, а не по позиции; манифест смеси считает
  примеры `rag_answers`, отброшенные подгонкой под бюджет (у v7: many 16,
  pick 11, injected 9, quests 2).

## Диагностика остатков v7 перед кругом v8 (11.11.2026)
