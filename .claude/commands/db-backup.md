---
description: Снять дамп production-базы metravel.by на локальный диск (~/metravel-backups) с проверкой целостности
allowed-tools: Bash(npm run db:backup:prod), Bash(npm run db:backup:prod:check), Bash(bash scripts/backup-prod-db.sh:*), Bash(ls:*), Bash(du:*), Bash(gzip -t:*)
---

Снимай бэкап прод-базы **только** канонической командой:

```
npm run db:backup:prod
```

Свои `ssh`/`pg_dump`/`scp`-конвейеры не изобретай: скрипт
`scripts/backup-prod-db.sh` уже проверяет коды возврата обеих половин
конвейера, минимальный размер архива, целостность gzip и наличие маркера
`PostgreSQL database dump complete`, а недоделанный файл удаляет.

Аргументы (если пользователь просил):
- `npm run db:backup:prod:check` — только проверить, что база на проде отвечает,
  ничего не качать;
- `bash scripts/backup-prod-db.sh --out DIR` — другой каталог;
- `bash scripts/backup-prod-db.sh --keep N` — сколько последних архивов хранить
  (по умолчанию 7, старые удаляются).

После прогона отчитайся: путь, размер, время, сколько архивов осталось в
каталоге. Если скрипт упал — разбери его сообщение (ssh, gzip, размер, маркер) и
скажи, на каком шаге, а не «попробуйте ещё раз».

Чего не делать:
- не открывать содержимое дампа и не печатать данные из него — там персональные
  данные пользователей;
- не класть архивы в репозиторий (по умолчанию они в `~/metravel-backups`, права 600);
- не восстанавливать что-либо на прод — restore только в отдельную тестовую базу,
  процедура в `docs/DB_BACKUP.md`.
