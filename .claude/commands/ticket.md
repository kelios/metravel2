Запусти скилл **ticket-flow** для обработки фронтенд-тикета через общий таск-борд MeTravel.

`$ARGUMENTS`:
- число / `[FE-…]` / `[TASK-…]` — id или ключ существующего тикета на борде;
- `next` — взять верхний `area=front`, `status=todo`;
- свободный текст — завести новый тикет и прогнать по пайплайну.

Следуй раннбуку скилла `ticket-flow`: операции с бордом — только через агента `ticket-board`
(MCP `metravel-task-board`), реализация/code-level checks/ревью/QA — профильными FE-агентами. Если
борд недоступен — укажи на `docs/TASK_BOARD_MCP.md` и не продолжай вслепую.

**Карточка уже в `in_progress`/`review`/`testing` → сначала выясни, кто её ведёт.** Этот статус
означает «кто-то работает прямо сейчас», а не «брошено, доделывай» — даже когда пользователь дал
ссылку на неё. Порядок: `ListAgents` → `SendMessage` живой сессии → `git status --short` по целевым
файлам. Хук `.claude/hooks/task-claim.mjs` блокирует перехват живой карточки, но видит только сессии
этой машины.

**Взял задачу → СРАЗУ `status=in_progress` (+`assignee`), до правок кода.** Никаких
`todo → done` напрямую даже для одиночной задачи. Порядок: `todo → in_progress → review → testing (выкат на прод + приёмка на проде) → done`
— задача ведётся от начала до конца, отдельной команды на прод-деплой не ждём.

Аргументы: `$ARGUMENTS`
