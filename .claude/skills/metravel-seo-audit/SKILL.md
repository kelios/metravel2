# metravel-seo-audit

Регламент SEO-аудита и дотягивания существующих путешествий до топа поисковой
выдачи (Google + Yandex). Не путать с `metravel-travel-article` — там создание
статей из папок с фото и вся проза тела; здесь — SEO-слой УЖЕ опубликованного контента.

## Границы с `metravel-travel-article`

- SEO владеет: `title` (`name` — только с 301), `meta_description`, лидом —
  первым абзацем тела, который становится сниппетом; внутренними ссылками
  («Что рядом»); FAQ и его разметкой `<details>/<summary>`.
- Любая новая проза в теле — справка о месте, история и легенды, практика,
  эпизоды дня, добор слов под `thin-content` — не пишется здесь. Аудит
  оформляет её заданием для `travel-writer` (скилл `metravel-travel-article`):
  id статьи, что добавить, к какому объекту/фото, источники фактов. Так
  проза проходит жанр 2d, подписи «с точки зрения места» и приёмку
  `node scripts/article-acceptance-check.js --id <id>`.
- Жанр тела — 2d из `.claude/skills/metravel-travel-article/SKILL.md`: журнальный
  рассказ, практика одним списком «Если соберётесь», без рейтинговых топов и
  справочных разделов. Лид и FAQ SEO пишет в этом же жанре.

## Полномочия

Запрос SEO-аудита разрешает чтение и отчёт. Правки авторского текста, заголовков,
лида и SEO-текста выполняй только после отдельного явного подтверждения владельца
на соответствующий scope по наследуемому content gate. Уже данное разрешение
повторно не запрашивай. Подготовка текста, запись в API, публикация/снятие с
публикации и deploy — отдельные стадии; аудит или dry-run их не разрешает.
Без разрешения на редактуру заверши аудит списком проблем и предложенных изменений.
Шаги 2–3 ниже применяются только к согласованной редактуре; изменение статуса
публикации требует собственной явной команды владельца.

## Жёсткие правила

1. **Фото не меняем.** Существующие фото и обложку не трогаем. Достоверную
   информацию о месте (история, легенды, топонимика, практика) в тело добавляет
   `travel-writer` по заданию из аудита (см. «Границы»).
2. **Только достоверное.** Даты, имена, цены, часы — проверяй веб-поиском. Где не
   уверен — формулируй как «по местным преданиям…», а не как факт. Цены/часы
   помечай «актуально на <год>, уточняйте».
3. **Текст не выхолащивай.** Авторский текст не переписывай в шаблон. Заголовки
   и разделы — по жанру 2d (`metravel-travel-article` → правило 3): названия мест
   и эпизодов, практика одним «Если соберётесь»; «Вступление / Итог / Точки /
   Описание», «Что посмотреть», «Практическая информация», «Маршрут в цифрах»,
   «История», «Легенды и факты» отдельными разделами не заводятся.

## Шаг 1 — Аудит (найти проблемы)

```bash
npm run seo:audit                 # автор по умолчанию user_id=1 (Julia)
mkdir -p .codex-temp/seo
node scripts/seo-audit.js --user-id 1 --json .codex-temp/seo/seo-report.json
node scripts/seo-audit.js --user-id 1 --limit 50 --min-words 500
```

Скрипт тянет все опубликованные путешествия автора и проверяет каждое:

| Проблема | Порог | Почему важно |
|---|---|---|
| `title-too-long` | > 60 симв. | заголовок обрезается в выдаче |
| `title-too-short` | < 25 симв. | нет поискового ключа в заголовке |
| `weak-lead` | первые 160 симв. не содержат ключ из заголовка | сниппет выдачи берётся из НАЧАЛА тела; если он не по теме (личный крючок) — выдача слабая |
| `thin-content` | < 400 слов | слабая релевантность и время на странице |
| `no-headings` | 0 × h2/h3 | нет структуры под подзапросы |
| `no-internal-links` | 0 ссылок на `/travels/` | теряется ссылочный вес и обход |
| `lead-noise` | тело начинается с вывода скрипта (`DUP found`, `[object Object]`, traceback) | этой строкой открывается сниппет в выдаче |
| `faq-markup-lost` | FAQ-блок есть, `<details>`/`<summary>` нет | `buildTravelFaqJsonLd` отдаёт `null`: блок виден на странице, а `FAQPage` в выдачу не попадает |

**Важно про сниппет:** поле `meta_description` фронтендом/SSG НЕ используется —
сниппет в выдаче строится из первых ~160 символов тела описания
(`generate-seo-pages.js → buildTravelSeoDescription`). Поэтому «мету» чинят не
отдельным полем, а сильным фактическим **лидом** в начале текста (ключ + суть),
а личный рассказ автора остаётся ниже без изменений.

`priority` = число проблем × вес трафика (страницы с трафиком, но тонкие/без меты —
самый высокий ROI). Бери worklist из вывода или из `--json`.

## Шаг 2 — Согласованная редактура (по одной статье)

Только для статей из подтверждённого scope и с разрешением на запись в target API:

1. Получи текущий текст: `GET https://metravel.by/api/travels/{id}/` (поля
   `name`, `description`). Прочитай рассказ — его НЕ переписываем.
1a. **Точки `travelAddress[]`** из того же GET — карта тем статьи. Справку о
   месте (история, легенды, топонимика, практика) SEO не пишет: по каждой
   значимой точке без справки — пункт задания для `travel-writer` (см. «Границы»).
2. Проверь факты веб-поиском (Википедия, гос. кадастр, офсайты): глубина/площадь
   озера, год постройки усадьбы, часы/цены. Неуверенное — как предание.
3. **Вставляй текст ПО КОНТЕКСТУ, а не валом в конец.** Сначала прочитай тело и
   составь карту существующих разделов/фото. Каждый новый кусок ставь туда, где он
   по смыслу связан:
   - **lead** (`--prepend-file`) — 1 абзац в НАЧАЛО под `weak-lead`: ключ из
     заголовка + суть места (это и есть будущий сниппет выдачи). Естественно, не робот.
   - **справка об объекте и практика** — не SEO: задание `travel-writer`, который
     вставит её инлайн рядом с фото объекта и в «Если соберётесь» (жанр 2d);
   - **финальные блоки** (`--append-file`) — **Что рядом** (2–4 ссылки
     `<a href="/travels/{slug}">…</a>` на соседние статьи автора, slug из
     `seo:audit -- --json <путь>`) и FAQ (`<details>/<summary>`), если их ещё нет.
4. Применяй БЕЗОПАСНЫМ редактором `scripts/seo-edit.js` (`npm run seo:edit`).
   Он эхом сохраняет publish/moderation/галерею/точки/plus/minus, меняет только
   текст, делает **бэкап** перед записью, после записи **верифицирует** и при
   регрессии **авто-откатывается**.
   - Для **контекстной вставки** собери ПОЛНОЕ тело (перемести/вставь блоки в
     нужные места) и пиши через `--desc-file` (replace whole body).
   - `--prepend-file`/`--append-file` — только для лида и реально финальных блоков,
     которые не дублируют существующие разделы.
   ```bash
   node scripts/seo-edit.js --id <ID> --desc-file full.html --dry-run
   node scripts/seo-edit.js --id <ID> --desc-file full.html
   # --meta снова работает (#1759): значение пишется тем же upsert и сверяется
   # на пере-чтении. Сниппет в выдаче оно НЕ меняет — мету SSG берёт из лида.
   #
   # лид + финальные блоки (без контекстного перемещения):
   node scripts/seo-edit.js --id <ID> --prepend-file lead.html --append-file blocks.html --dry-run
   node scripts/seo-edit.js --restore <ID>   # откатить из последнего бэкапа
   ```
   Бэкапы — `scripts/.seo-backups/` (в .gitignore). Токен — owner1 через общий
   resolver (`docs/DEVELOPMENT.md` → «Operator token sessions»), секреты не логируй.
   НЕ используй `metravel_publish.py` на живых статьях — это движок черновиков;
   тело живой статьи пишется только через `seo-edit.js`.
   `title-too-long` (смена `name`) меняет slug и ломает URL — НЕ трогай заголовки
   в этом потоке без отдельного редиректа.

### Чек-лист (уроки практики)

- **Лид содержит тему.** Первые ~160 символов должны называть объект из заголовка.
  Аудит сравнивает по основе слова (стем 5 симв.), так что словоформа не важна
  («Ошмянах» ↔ «Ошмяны» засчитываются) — но сам ключ в лиде быть обязан.
- **Цель ≥ 420 слов.** Порог `thin-content` = 400; делай запас, иначе статья
  вернётся в worklist. У пограничных (300–400) факты и практику добирает `travel-writer` по заданию.
- **Повторная обработка — сперва GET, не дублируй.** Если статья уже дополнялась
  (вернулась из-за weak-lead/thin), прочитай текущее тело и правь точечно: не
  добавляй второй раз те же `<h2>`/«Что рядом». Через `--desc-file` отдавай
  чистое тело без повторов.
- **Лид не задваивай.** Главная причина «дублей после редактирования» —
  `--prepend-file` поверх статьи, где SEO-лид уже есть: на выходе ДВА вводных
  абзаца, оба определяющие объект (часто с конфликтующими фактами). `seo-edit.js`
  теперь сам ловит и ЗАМЕНЯЕТ near-dup лид (идемпотентный prepend, ≥2 общих
  3-словных фразы), но это страховка, а не индульгенция: всегда сперва GET и
  смотри первые 2 абзаца. Если оба — определения объекта («X — это…»), оставь
  ОДИН (сильный фактический), перенеси уникальные факты второго внутрь и удали
  его через `--desc-file` (чистое тело). Сверять задвоение по автору массово —
  `node scripts/seo-find-dupes.js --user-id 1` (отчёт `scripts/.seo-dupes-report.json`).
- **Спорные цифры автора не затирай молча.** Если источник расходится с числом
  автора (глубина, длина, год) — оставь авторскую формулировку и добавь
  официальную как уточнение со ссылкой/пометкой «по данным <источник>».
  Исправляй только явные опечатки в фактах (имена/топонимы: «Слацьвинских» →
  «Слотвинских», «Рерихово» → «Репиховское») — с веб-подтверждением.
- **Внутренние ссылки — только на реально существующие** опубликованные статьи
  автора из `seo:audit -- --json <путь>`; выбирай тематически/географически близкие.
- **Опечатки правим, стиль — нет.** Чини орфографию/пунктуацию/согласование, но
  сохраняй авторский голос, диалектизмы и личные обороты.

## Шаг 3 — Опорные (pillar) статьи для топа по отдельному запросу

Чтобы вытянуть кластер в топ, добавляй хабовые статьи (1500–2500 слов) со
ссылками на 8–15 существующих материалов. Сильные кластеры автора: Беларусь
(усадьбы, озёра, экотропы, веломаршруты), Польша/Краков (окрестности, купание,
Татры/Закопане), сезонные (Energylandia/парки). Создание pillar-статьи — через
скилл `metravel-travel-article` (агент `travel-writer`), в жанре 2d.

## Шаг 4 — Проверка

- `npm run seo:audit -- --limit <N>` повторно — проблемы по обновлённым статьям
  должны уйти.
- `npx jest __tests__/scripts/seo-audit.test.ts __tests__/scripts/seo-edit.test.ts`
  — зелёные тесты аудита и редактора.
- После релиза статичные страницы `dist/prod/travels/{slug}.html` обязаны нести
  свой `<title>`, `meta description`, `og:image` и текст в HTML (генерит
  `npm run seo:generate-pages`); проверь `npm run test:seo:prod`.

## Важно про прод

Per-page SEO собирается на сборке (`generate-seo-pages.js`) в статические HTML.
Если прод отдаёт ботам генерик `Путешествие | Metravel` и `og:url=.../[param]` —
значит статические страницы не передеплоены или новые статьи добавлены после
последней сборки. Зафиксируй необходимость пересборки и передай её профильному
оператору: production deploy выполняется только по явной команде владельца
и `docs/WORKFLOW_OPERATIONS.md`, а не автоматически из SEO-аудита.
