# Travel-фильм: разбор и правка

Канон для ролей `film-screenwriter` (пишет сценарий серии), `film-reviewer`
(смотрит и находит ошибки) и `film-editor` (пересобирает и проверяет
экспорт). Материал — длинные горизонтальные фильмы о
поездках автора, собранные в Filmora. Короткие мультфильмы ведёт
`metravel-animated-reels`, записи экрана приложения — `evidence-editor`.

## Неизменные правила

- Исходники, проекты `.wfp` и готовые экспорты только читаются. Результат —
  новый файл рядом с прежним, с понятным именем и датой. Перезапись и удаление
  чужих файлов требуют прямой команды владельца на конкретный файл.
- Рабочие файлы (звук, кадры, расшифровка, промежуточные куски) лежат во
  временной папке сессии. Рядом с фильмом остаются экспорт и короткий отчёт
  «Что изменено».
- Перед тяжёлым проходом проверь, что Filmora не экспортирует
  (`pgrep -fl Wondershare`, растущий файл в папке экспорта). Идущий экспорт
  не прерывай и свой рендер с ним не совмещай.
- Фильм из нескольких частей сначала раскладывается на части: длительности
  дневных экспортов в сумме дают длительность фильма, границы подтверждают
  паузы в звуке. Свежий исправленный экспорт части заменяет устаревший.

## Сценарий

Монтаж серии начинается со сценария. Его пишет `film-screenwriter` по
[справочнику](references/screenplay.md): каркас серии с интро сериала и
«ранее в сериале», конфликт дня и сквозные линии, моменты для любого зрителя,
врезки 🗂 из архивов прошлых походов и снимки экрана сервисов, файл фраз для
голоса владельца. Каждый исходник дня просматривается глазами: еда, вечера,
проходки вдвоём и быт пути без речи — тоже сцены, по 4–6 с, с доозвучкой
владельца по списку. Вместе со сценарием сдаётся отчёт
`рецензии/sN — неиспользованные кадры.md` (справочник, «Немые моменты дня»).
До плана сборки сценарий получает от `film-reviewer` оценку «сценарий» не
ниже 8 (рубрика, «Сценарий до сборки»).

## Порядок работы

1. **Посмотри фильм целиком.** `scripts/watch_film.sh <видео> <рабочая папка>`
   снимает звук, расшифровку речи, кадры каждые 5 секунд, склейки, чёрные и
   застывшие кадры, громкость. Прочитай все листы `sheets/` и расшифровку через
   `scripts/compact_transcript.py`. Суждение по части фильма без её кадров и
   речи не выносится. Команды и ловушки — в [конвейере](references/pipeline.md).
2. **Сними раскладку.** `scripts/filmora_edl.py <проект.wfp> --offset <сек>`
   показывает, какой исходник стоит в каждом месте, где музыка и где речь.
   По ней ищутся исходники для перебивок и границы музыкальных кусков.
3. **Разбери по [рубрике](references/review-rubric.md)** — начиная с
   `scripts/audit_cut.py` по плану монтажа. Каждая находка имеет
   таймкод, слой (сценарий, монтаж, звук, картинка) и предлагаемую правку.
   ОКНО — плашка заходит на окошко рассказчика того же отрезка; геометрия
   плашки и окошка — `scripts/overlay_geom.py`, общая с раскладкой плана.
   Технические ошибки и очевидные повторы чинятся сразу. Удаление сюжетной
   линии, личной темы и перестановка сцен выносятся владельцу списком.
4. **Составь план правок** файлом `plan.json`: оставляемые отрезки, перебивки
   с исходником и точкой входа, правки звука. План — единственный вход сборки,
   поэтому повторная сборка после замечаний меняет только план.
   Перебивки ставятся под слова: любой план не короче 4 с, одна перебивка на
   мысль, нет кадра по теме — остаётся говорящий. Листы кадров, каталог меток,
   мысли по стенограмме, черновой подбор и таблицу «мысль → кадр» для
   рецензента даёт `scripts/shot_catalog.py`; каталог же проверяет
   `audit_cut.py` (КОРОЧЕ 4 С, ТЕМА).
   Немые моменты дня (владелец 23.11) — тоже материал: все завтраки и ужины,
   вечер и отдых, красивые проходки, по 4–6 с под музыку; слова доозвучит
   владелец. `shot_catalog.piece_tags` добавляет к меткам «кто в кадре» и «что
   делаем»: мы-вдвоём, Юля, Сергей, проходка, еда, завтрак, обед, ужин, отдых,
   сборы, вечер. `shot_catalog.py people` даёт YOLOX-подсказку «люди-yolox».
   `scripts/unused.py report` показывает, что из дней не вошло в план, с учётом
   копий размытия, памяти, вертикалей и фото. Справка audit_cut «НЕ ВОШЛО С
   НАМИ» — клипы с нами ≥ 4 с вне плана. Проходку одного из нас, снятую с рук,
   тоже берём; номер машины — не причина отказа (размытие — после «утверждаю»).
5. **Собери.** План из исходников (монтаж с нуля, проект Filmora из того же
   плана) рендерит `scripts/render_plan.py plan.json out.mp4`: без `--size` —
   черновик 640×360 для рецензента, `--size 3840x2160 --hw` — финал аппаратным
   кодером Mac. Тяжёлые задания по исходникам — одно на машину через общий
   замок `scripts/heavy_lock.py`: рендер, `audit_frames`, поиск машин
   `scripts/vehicles.py` (номера до размытия — по плану или по фильму), размытие
   номеров `scripts/plates.py` (копия куска: номер по знакам, дорожка машины,
   минус люди, кадры 1:1 с маской); ждущий
   печатает, кто держит замок, остальные идут с nice 10 (`--no-wait` — выход
   с кодом 75; любой другой скрипт — `heavy_lock.py -- <команда>`). Рядом с фильмом он пишет `.segments.json` (таймкоды планов) и
   дорожки `_без_музыки.mov`, `_музыка.wav`, `_голос.wav` для проверок.
   Пересборку уже готового экспорта владельца (вырезки и перебивки поверх него)
   ведёт `scripts/assemble_film.py plan.json`; он сам мастерит звук к −14 LUFS
   с истинным пиком не выше −1 dBTP. У `render_plan.py` громкость задаёт сам
   план (`loud_gain` отрезков и уровни `music.cues`), рендер только ограничивает
   пики: итог сверяй `audit_tech.py`, а промах правь в плане, а не поверх
   готового звука. Долгий рендер запускай фоном.
   Кеш кусков общий на серию и размер (`sN_<H>p_parts` рядом с фильмом, серия —
   из имени плана), картинка и звук кешируются отдельно: правка громкости или
   музыки не перекодирует картинку. `--workdir` без нужды не передавай.
   Скорость: исходники 4K декодирует аппаратный декодер Mac (`--sw` — только
   для разбора расхождений), куски рендерятся по три разом (`--jobs N`), фильм
   склеивается копированием потока — кодируются только секундные растворения,
   поэтому правка одного отрезка стоит минуты и не трогает соседние. Сведённый
   звук, дорожки `_голос.wav`/`_музыка.wav` и потолок пика тоже кешируются:
   при правке одной картинки звук берётся готовым (строка «звук и музыка без
   изменений — из кеша»), при правке звука потолок стартует с прошлого. Строка
   лога «время:» раскладывает сборку по этапам: долгую сборку разбирай по ней,
   а не по догадке. Свои скрипты производных копий (размытие, вертикальные,
   «память») тоже запускай с `-hwaccel videotoolbox` перед `-i` — но только для
   HEVC и H.264 4:2:0: H.264 4:2:2 10 бит (ZV-E1) аппаратный декодер портит и
   теряет кадры без кода ошибки, такие исходники декодируй программно.
   Ключ плана `"music": {"auto_level": true}` с `--words-root` (и `--alias`)
   включает автоуровни (`scripts/auto_level.py`): под речью музыка на 13 дБ
   ниже речи, на видах — к уровню речи фильма, тихие вступления подтягиваются;
   `level_db` музыки в этом режиме не действует, ручная поправка трека —
   `auto_adj_db` у cue. Разговор — отрезок целиком (слов ≥ 3 и ≥ 0,3 в
   секунду, порог `is_talk` общий с audit_mix; слова — `real_words`, без
   галлюцинаций whisper вроде «Субтитры сделал DimaTorzok»): в паузах между фразами музыка
   не поднимается; уровень — по речи в окне ±1,5 с. Фразы голоса за кадром с
   паузой короче 2 с — одна фраза. На видах к уровню речи фильма метится сумма
   «музыка + живой звук» (громкий прибой — музыка фоном на 7 дБ ниже). Уровни
   меряются как в стерео-миксе (сумма мощностей каналов), а не по ½(L+R).
   Плашка с тем же именем, но новым текстом перерисовывается: подпись в
   `<имя>.json`, у куска картинки — отпечаток плашек `v_<ключ>.img`.
   Стык с растворением (`ASIG` edge2, нужен `--words-root`): если в запасе
   0,5 с за in входящего или за out уходящего по расшифровке есть слова, звук
   обоих кусков звучит строго внутри [in, out] с переходом ±40 мс на склейке
   (`EDGE`); иначе фон плавно перетекает acrossfade на всё растворение.
   audit_mix ХВОСТ — фильм собран раньше, и слова исходника из запаса слышны.
6. **Не крась (владелец 23.11).** По умолчанию фильм идёт как снято:
   `render_plan.py` не применяет ключи `grade` плана и пишет в лог, сколько
   пропустил; `audit_tech.py --plan` даёт справку «покраска». Осветление —
   только по прямой просьбе владельца на конкретный план: ключ `grade` с
   `"grade_owner": true`. `scripts/grade.py` (выравнивание камер и лук) —
   только по её просьбе и с явным режимом `--minimal` или `--look-on`, рендер —
   с `--grade`. Правила — раздел «Цвет» [конвейера](references/pipeline.md).
7. **Музыка.** Если трек выпадает из палитры или давит речь, замени его по
   разделу «Музыка» рубрики: ключ `remusic` плана вычитает старый трек из
   сведённого звука и кладёт новый непрерывно поверх склеек.
8. **Проверь на слух и глазами автоматически.** Проверки друг от друга не
   зависят — запускай их разом (`&` и `wait` в одном скрипте), а не по очереди:
   пять проверок 1080p подряд идут 35 минут, вместе — около 15. По собранному черновику:
   `scripts/audit_mix.py` (речь под музыкой, разборчивость, провалы),
   `scripts/audit_frames.py` (вспышки, мелькания, возврат к камере, лица) и
   `scripts/audit_color.py` (пересвет, оттенок, скачки цвета между соседними
   планами; картинки `_лента.jpg` и `_скопы.jpg`). Находки чинятся до рецензии.
9. **Проверь экспорт.** `scripts/audit_tech.py <фильм> --out audit_tech.md` —
   технический контроль для YouTube одним проходом: контейнер, кодек, метки
   цвета bt709, битрейт, громкость и пик, клиппинг, противофаза, тишина, ошибки
   декодирования, чёрные и застывшие кадры. Вердикт «НЕ ГОДЕН» — блокер выдачи.
   `scripts/verify_export.sh` снимает листы кадров результата: сверь кадры до и
   после каждой правки и речь на каждом стыке по расшифровке результата.
   Непроверенный пункт называется в отчёте прямо.
10. **Получи оценку.** Отдай результат `film-reviewer` на оценку сюжета,
    монтажа, картинки (качество и цвет), звука и музыки по 10-балльной шкале
    рубрики; шестая оценка — сценарий до сборки. Порог — 8 по каждой из шести.
    Рецензент записывает оценки `scripts/film_gate.py`, и без его допуска
    `render_plan.py` больше 640x360 не собирает (рубрика, «Допуск к сборке»).
    Блокеры правь в плане и повторяй круг. Обычный путь — черновик 360p в очередь
    сессии-рецензента (для GR21 — «GR21: рецензент всех серий фильма», см.
    `ЧТО ГДЕ ЛЕЖИТ.md`). Когда рецензент проверил правки по самому плану, его
    `plan-verdict` может открыть 1080p без черновика (решение владельца 22.11).
    После допуска собери 1080p (`render_plan.py --size 1920x1080 --hw 20M`) и
    передай готовый файл на полную рецензию. Для 4K (`--size 3840x2160 --hw 60M`)
    нужны вердикт по экспорту и прямое разрешение владельца.

## Отчёт

Сначала итоговый файл и его длительность. Затем таблица правок с таймкодами
исходного фильма, измерения звука до и после, список решений владельца с
вариантом по умолчанию и то, что осталось непроверенным. Файл «Что изменено»
рядом с экспортом повторяет таблицу правок простыми словами.
