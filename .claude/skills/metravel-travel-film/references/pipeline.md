# Конвейер: команды и ловушки

Все скрипты лежат в `scripts/` этого скилла. Исходный фильм, исходники и
проекты Filmora только читаются.

## Инструменты

- `ffmpeg`, `ffprobe` из Homebrew. В сборке нет фильтра `drawtext`: подписи на
  листах рисует Pillow, титры готовятся картинкой PNG.
- `uv` запускает Python-скрипты с зависимостями без установки в систему:
  `uv run --with pillow ...`, `uv run --with numpy --with soundfile ...`.
- Расшифровка: `uv tool install --python 3.12 mlx-whisper`, модель
  `mlx-community/whisper-large-v3-turbo`. На M1 идёт в 2–4 раза быстрее
  реального времени.

## 1. Просмотр

```bash
scripts/watch_film.sh "<фильм.mp4>" "<рабочая папка>" 5 ru "Имена и места через запятую"
```

Проход по 4K-фильму идёт примерно вдвое быстрее реального времени. Затем:

- прочитай каждый лист `sheets/sheet_NNNN.jpg` (30 кадров, шаг 5 секунд);
- прочитай расшифровку: `python3 scripts/compact_transcript.py tr/audio16k.json [от] [до]`;
- чёрные и застывшие кадры: `grep -E "black_start|black_end|freeze_start" freeze.txt`.

Ловушки расшифровки:

- С опорой на предыдущий текст модель зацикливается на музыке («И Камино» 49
  раз) и теряет речь после неё. В скрипте опора выключена.
- На музыке без речи появляются выдуманные строки вроде «Субтитры сделал…».
  Это не текст фильма.
- Бессвязная строка в месте, где человек явно говорит, означает плохую
  разборчивость: речь тонет в музыке или ветре. Это находка по звуку.
- Времена слов могут уходить на полсекунды. Границу вырезки проверяй по уровню
  звука с шагом 50 мс и ставь в паузу.

## 2. Состав фильма и раскладка

Фильм из нескольких дней обычно склеен из отдельных экспортов. Сумма их
длительностей (`ffprobe -show_entries format=duration`) равна длительности
фильма, границы совпадают с паузами из `silence.txt`.

```bash
python3 scripts/filmora_edl.py "<проект.wfp>" --offset <начало части в фильме, с> --json part.json
```

Раскладка показывает исходник каждого плана, музыку, уже сделанные вырезки
внутри длинных планов и вставки. Новая вырезка не должна оставлять между двумя
склейками обрывок короче секунды: сдвинь границу на существующую склейку.

Подбор перебивок по папке исходников дня:

```bash
uv run --with pillow --with pillow-heif scripts/library_sheets.py "<папка дня>" "<рабочая папка>/lib"
```

Жёлтая подпись — видео с длительностью, белая — фото. Узкий кадр с чёрными
полями по бокам — вертикальный, для перебивки на весь экран не годится. Номера
уже использованных исходников видны в раскладке.

## 3. Звук: измерения

- Громкость сцены: `ffmpeg -ss <от> -t <длина> -i audio_full.wav -af ebur128 -f null -`,
  строка `I:` в конце вывода (20 последних строк, не 12).
- Сравни речь по частям. Разница больше 1 LU исправляется усилением отрезка
  (`gain_db` в плане), выравнивание в мастеринге снимает остаток.
- Баланс речи и музыки внутри готового микса исправить нельзя: дорожки уже
  сведены. Такие места выносятся владельцу списком с таймкодами для правки в
  проекте Filmora.

## 4. План и сборка

Формат плана описан в начале `scripts/assemble_film.py`. Правила:

- Вырезка — это два соседних отрезка с пропуском между ними. Непрерывный
  материал с разным усилением тоже делится на отрезки: стык станет плавным.
- Перебивка, закрывающая вырезку в статичном плане, задаётся двумя записями:
  в конце отрезка до вырезки и в начале отрезка после. Для фото это бесшовно.
- Один чёрный кадр убирается отрезками до него и после него.
- Исправленный экспорт части подключается вторым источником; его времена
  считаются от начала этого файла.

```bash
python3 scripts/assemble_film.py plan.json --dry-run   # таблица отрезков
python3 scripts/assemble_film.py plan.json             # сборка, запускать фоном
```

Сначала собери короткий пробный план из мест с перебивками и вырезками
(по 8–10 секунд каждое) и посмотри его лист кадров. Полный рендер 4K идёт
примерно в полтора раза быстрее реального времени; куски кешируются, повторный
запуск после правки плана пересчитывает только изменённые отрезки.

Мастеринг внутри сборки (`scripts/master_audio.py`) делает выравнивание,
компрессию выбросов и ограничение пиков на частоте 192 кГц. Ограничитель без
передискретизации оставляет истинные пики на 2–3 дБ выше цели.

### Следующие круги: правки по таймкодам результата

Рецензент называет таймкоды готового файла. `scripts/recut_plan.py round.json`
переводит их в таймкоды источников и пишет новый план: границы вырезок
привязывает к паузам, делит перебивки по обе стороны стыка и печатает обрывки
планов короче секунды рядом с перебивками, уже вшитыми в экспорт владельца.
Обрывок убирается сдвигом границы на край перебивки или расширением вырезки.
Таймкоды вырезок выбирай по расшифровке прошлого результата; в тихую точку
границу сдвигает сам скрипт по уровню звука, расшифровку он не читает. Звук
прошлого результата для него — WAV 16 бит. Новый план пишется отдельным файлом:
базовый план нужен, пока жив собранный по нему результат.

### Титры

Титры дней собираются картинкой 3840×2160 из знаков уже существующих титров
владельца (те же шрифт, кегль и положение строк), недостающие знаки
дорисовываются шрифтом проекта из папки шрифтов Filmora. Картинка кладётся
ключом `cards` поверх старого титра. Перед сборкой все титры фильма
сравниваются на одном листе.

## 5. Замена музыки без отдельных дорожек

Отдельных дорожек в экспорте нет, но исходные музыкальные файлы известны из
раскладки (`ES_*.mp3` в «Загрузках» владельца). `scripts/remusic.py`
выравнивает исходный трек с миксом, вычитает его и подмешивает новый.

- Сначала аудит: признаки треков (темп, доля ударных, яркость) считает
  `librosa`, жанр и настроение берутся со страниц Epidemic Sound. Вердикт по
  каждому куску — оставить или заменить, с кандидатом из скачанных треков.
- Глубина подавления старой музыки проверяется там, где она звучит одна (титр
  дня, заставка). Трек из MP3 после кодирования фильма в AAC вычитается
  примерно на 16 дБ, трек из WAV — на 25 дБ. Остаток закрывает новая музыка.
- Музыка в миксах Filmora обычно тише, чем кажется по замерам «без речи»: в
  паузах слышны шаги и ветер самого плана. Неразборчивая речь на ходу чаще
  вызвана шумом записи, а не музыкой.
- В плане сборки куски старого трека задаются таймкодами источника из
  раскладки. Сборщик пересчитывает их через вырезки, поэтому новый трек не
  рвётся на склейках. Живую музыку в кадре закрывает окно `mute`.
- Новая музыка звучит только на кусках старой. Если трек стоит в раскладке
  дважды с другим материалом между кусками, это два задания: у каждого свой
  новый трек или своя точка входа `new_start`. Короткую паузу старого трека
  (пара секунд между двумя его кусками) новая музыка проходит без остановки,
  если заданию дать `bridge` длиннее этой паузы.
- Кусок трека короче секунды между двумя склейками не вычитается, сборка
  печатает предупреждение. Расширь вырезку или сдвинь её границу.
- Тот же приём убирает скачок музыки на вырезке: задание, где новый трек
  равен старому, кладёт музыку заново и непрерывно. Применять там, где музыка
  звучит на переднем плане; тихую подложку под речью достаточно свести
  кроссфейдом.
- В экспорт пишутся две звуковые дорожки: первая с новой музыкой, вторая с
  исходной. Владелец переключает их в плеере и выбирает на слух.

## 6. Проверка экспорта

```bash
scripts/verify_export.sh "<экспорт.mp4>" "<рабочая папка>/verify"
```

Скрипт декодирует файл целиком, сравнивает длительности видео и звука, ищет
чёрные и застывшие кадры, меряет громкость и пик, снимает листы кадров.
После него:

- сверь листы результата в местах правок с листами исходного фильма;
- расшифруй звук результата и прочитай текст на каждом стыке: слова не
  обрезаны, фраза до и после вырезки связана;
- сравни громкость тех же сцен до и после по таблице из шага 3.

Слух скрипты не заменяют: щелчки, «качание» громкости и качество музыки на
вырезках в отчёте помечаются как непрослушанные, владелец слушает стыки по
списку таймкодов результата.
