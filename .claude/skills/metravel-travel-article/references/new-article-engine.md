# Новая статья из папки фото — движок `metravel_publish.py`

Читается на шаге «новая статья». Движок лежит в каталоге скилла:
`.claude/skills/metravel-travel-article/scripts/metravel_publish.py` (ниже —
`scripts/` скилла, не репозитория). На живой опубликованной статье движок не
используется: там `scripts/seo-edit.js` (`live-edit-recipes.md`).

## Что движок гарантирует сам

- токен — проверенный owner1 через общий resolver (`expectedUserId: 1`); автор
  бэк ставит по токену ПРИ СОЗДАНИИ и потом не меняет;
- `upsert` берёт `year`, `month` и `created_at` из `date:` черновика; без
  `date:` новая статья не создаётся (отказ, код 2), `month: []` не пишется;
- пустые `plus`/`minus`/`recommendation`/`youtube_link` уходят `null`;
  сентинел `__draft_placeholder__` движок не пишет, встреченный — обнуляет;
- правка существующей (`--id`, `recat`, `descimg`) эхом сохраняет `publish`,
  `moderation`, `month`, тексты и фото точек — снимать с публикации она не может;
- `descimg` перезаливает фото точки в `collection=description` и ставит
  `<p><img … alt="<имя точки>">`; `address-image` в тело не попадает;
- каждая заливка ждёт ≥ max(длительность прошлого `POST /api/upload`, 10 с).

## Порядок

1. **Не дублировать.** Свои статьи за год:
   `GET https://metravel.by/api/travels/?where={"publish":1,"moderation":1,"year":"<YEAR>"}&perPage=100`
   и сопоставить по смыслу (одно путешествие бывает разбито на несколько статей).
2. **Что пропускать:** папки «Дом/ДОМ», домашние события (Рождество, Новый год,
   шашлыки), ТЦ, бытовые кадры. Однодневную поездку берём, если это место.
   Исключение: владелец сам просит рассказать, где жили, — тогда жильё отдельный
   полезный раздел (цена, что важно, можно ли с животными).
3. **Разведка папки** — `photo-pipeline.md` (архивы, EXIF, отбор глазами).
4. **Черновик** вне гита: `.codex-temp/articles/<YEAR>/NN-slug.md` (формат ниже).
5. `python3 <скилл>/scripts/metravel_publish.py upsert <draft.md> --dry-run`, затем
   без `--dry-run` (повторно — с `--id <id>`: id точек сохраняются по ближайшей
   координате, фото точек не теряются).
6. `… photos <id> "<папка>" [...] [--gallery N]` — обложка-черновик, галерея,
   фото к точкам по GPS (до 3 км). Пауза между заливками встроена.
7. **Обложка — выбрать глазами.** Авто-обложка — черновик. Открыть Read'ом 5–8
   кандидатов равномерно по съёмке, взять «открыточный»: достопримечательность,
   пейзаж, узнаваемый общий вид. `… cover <id> "<файл>"`. Никогда на обложку:
   еда/кафе, селфи и крупные люди, интерьеры/номера, машины, вывески и щиты,
   животные, таблички, бытовые кадры. В смешанной папке — только GPS-кластер места.
8. `… descimg <id>` — фото точек в текст (рядом с заголовком-тёзкой точки).
   Тело не должно остаться «только текстом»: точки сначала получают фото
   (шаг 6), потом `descimg`.
9. Подписи, «Что рядом», квесты, FAQ — `body-html.md`; галерея без мусора
   (`DELETE /api/gallery/{imageId}/`) и с подписями — `photo-pipeline.md`.
10. Приёмка: `node scripts/article-acceptance-check.js --id <id>`.

Черновик создаётся `publish=false, moderation=false`; публикацию включает
владелец. После публикации серии — выкат (SKILL.md → «Маршрутизация»).

## Формат черновика

```
---
title: "Название (≤200 симв., место + суть)"
country: Польша            # или "Польша, Чехия" — маппинг в id внутри движка
region: Регион / город
date: 2025-05-30           # обязательно: YYYY-MM-DD | YYYY-MM | 2025-05-30..2025-06-02
categories: [Поход, Хайкинг, Тур выходного дня, Самостоятельное путешествие]
---
# Заголовок
(абзац-крючок без заголовка)
## <Место или эпизод дня>
...
## Если соберётесь
- старт, км и набор одной фразой, когда идти, что проверить
(абзац-вывод без заголовка)
---
## Фото для загрузки          # заметки, в описание не идут
## Точки для карты            # | Название | lat, lng |
| Замок в Ойцове | 50.2101, 19.8297 |
```

Всё между фронтматтером и `---\n## Фото` уходит в описание (HTML); шаблонные
заголовки («Вступление», «Итог», «Точки», «Описание»…) движок срезает,
технические фразы («по GPS», «по EXIF», «по точкам съёмки») — тоже (`strip_meta`).
Без точного дня `date:` — 1-е число месяца; несколько месяцев — диапазоном,
`created_at` встаёт по самому раннему (решение владельца 23.09.2026, #2046).
Пометка `[уточнить]` допустима только в черновике: в опубликованном тексте её
ловит `article-acceptance-check`.

## Справочники и категории точек

`… facets` — актуальные id. Базовые категории: Поход=2, Хайкинг=21,
Треккинг=22, Тур выходного дня=19, Самостоятельное=20, Автопутешествие=6,
Сплав=4, Веломаршрут=24, Велопоход=7. Страны: Польша=160, Словакия=184, Чехия=215.

У каждой точки — категория (тип места) из `categoryTravelAddress`: Замок=43,
Костёл=150, Озеро=84, Гора=26, Музей=76, Площадь=187, Водопад=20, Город=184.
Движок ставит её по названию (`point_categories`), `recat <id>` дозаполняет
пустые; адекватность проверять глазами, непонятное — Город(184). Создавать
категории через API нельзя — справочник правится только в админке бэкенда.

## API-справка (ручная работа)

- Список `GET /api/travels/?where={...}&perPage=100`; деталь `GET /api/travels/<id>/`
  (автор — `userIds`).
- `PUT /api/travels/upsert/`: `id:null` — создать, `id:<n>` — обновить; точки —
  `coordsMeTravel:[{id,lat,lng,address,country,categories,image}]`; `gallery` и
  `travelAddress` пустыми = «не менять». `month` — обязательный список id
  месяцев (1–12). `created_at` в будущем → 400; сдвинуть дату позже сохранённой
  может только суперпользователь.
- `POST /api/upload` (multipart `file`, `collection`, `id`): `travelMainImage`
  (обложка, id статьи), `gallery` (id статьи), `description` (в текст, id статьи),
  `travelImageAddress` (фото точки, id точки).
- Галерея: `DELETE /api/gallery/{imageId}/`, `PATCH /api/gallery/{imageId}/`
  `{"caption": "…"}` (≤500), `POST|PATCH /api/gallery/reorder/`.
- OpenAPI: `http://localhost:8000/api/schema/` на локальном стеке (дев и прод —
  только по явному запросу владельца).
- Статья ушла под чужим автором → `DELETE /api/travels/<id>/` и пересоздать
  токеном owner1 (slug переиспользуется).
