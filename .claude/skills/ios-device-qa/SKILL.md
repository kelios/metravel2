# iOS Device QA — живой iPhone: план → тест → борд → фикс → верификация

Владелец слоя — агент `ios-tester`. Симуляторный обход живёт в
`.claude/skills/ios-qa-sweep/SKILL.md` и этим скиллом не дублируется.
Универсальные правила оценки экрана (целостность вёрстки, закрываемость
оверлеев, все состояния компонента, z-order) — пункты 9–12 чеклиста в
`.claude/skills/android-qa-sweep/SKILL.md`, применять один в один.

Проверено 01.09.2026 на iPhone 13 mini / iOS 26 / Xcode 26, сборка `by.metravel.app`
1.0.5 (6) — это исторический прогон. Кандидата определяют установленный бинарник
и выбранный в ASC/TestFlight build; текущий `app.json` не доказывает их версию.

## Когда этот скилл, а когда нет

Устройство берётся ТОЛЬКО под то, что симулятор не доказывает
(`docs/WORKFLOW_OPERATIONS.md`): камера/фото/HEIC, реальная геолокация, sharing во внешние
приложения, Keychain и сессия после холодного рестарта, биометрия, permission
allow/deny/restricted, lifecycle, Universal Links из чужого приложения, APNs,
поведение подписанной сборки, производительность.
**Safe area, клавиатура и геометрия окна iPad в этот список НЕ входят** — тот же документ
относит их к симулятору; гнать их на живой телефон значит занимать устройство зря.
Обычный «прокликать экраны» дешевле и достовернее на симуляторе — гонять его на
живом телефоне нельзя. Приёмка релиз-кандидата — отдельный слой (exact processed
TestFlight build), тоже за `ios-tester`.

## Предусловия

1. **Устройство.** `source scripts/ios-device-qa.sh && Devices`. Колонка State
   НЕ стабильна: до первого туннеля строка показывает `available (paired)`,
   после — `connected`; отбирать надо всё, кроме `unavailable` (это и делает
   `Devices`, кэшируя `IOS_QA_DEVICE` в текущей оболочке). Нет строки — просить
   владельца подключить кабель, разблокировать и подтвердить Trust.
2. **Блокировка.** `Unlocked` → `passcodeRequired` / `unlockedSinceBoot` +
   состояние подсветки. `passcodeRequired: true` = экран заблокирован: XCUITest
   не стартует (`deviceprep Code=-3 "Unlock iPhone"`), а `xcodebuild` не падает,
   а висит в `Waiting for the destination to become ready` и съедает весь
   таймаут. Перед долгим прогоном просить владельца поставить «Автоблокировка →
   Никогда». `devicectl process launch` состояние блокировки НЕ показывает — он
   успешно стартует приложение и за экраном блокировки.
3. **Сборка.** `AppInfo` → version + bundle version установленного бандла; они
   идут в отчёт вместе с происхождением бинарника и source commit кандидата.
   Совпадения version/build недостаточно для TestFlight acceptance: подтверди
   происхождение через TestFlight UI, distribution receipt или журнал установки.
   `builtByDeveloper=true` требует этой сверки и само по себе не даёт verdict.
   Для требования «актуальная стабильная ОС» запиши точную iOS/iPadOS и дату,
   сверь модель с [релизами Apple](https://support.apple.com/en-us/100100) и
   доступным обновлением в Settings → General → Software Update. Номер из
   старого отчёта и отсутствие beta сами по себе актуальность не доказывают.
   Подписанные `preview`/`production` профили ради QA не
   собираются — это `ios-deployer` по отдельной авторизации владельца.
4. **API-гейт (load-bearing).** Таргет по умолчанию — локальный бэкенд, и он
   обязан быть обновлён (`docs/WORKFLOW_OPERATIONS.md` → «3.0 Локальный стек»):
   ```bash
   git -C ../metravel-backend fetch origin master && git -C ../metravel-backend reset --hard origin/master
   bash /Users/juliasavran/Sites/metravel/run-backend.sh
   ```
   Устройство ходит не на `localhost`, а на LAN-IP мака: в `.env`
   `EXPO_PUBLIC_API_URL=http://$(ipconfig getifaddr en0):8000` и
   `EXPO_PUBLIC_IS_LOCAL_API=true`, копию `.env` вернуть после обхода.
   `EXPO_PUBLIC_*` инлайнятся при сборке → нужна пересборка dev-client и Metro
   `--clear`. **Уже установленная релизная сборка правку `.env` игнорирует и
   ходит в прод** — сверять по сетевым ответам, а не по намерению.
5. **Логин.** e2e-аккаунт разрешён постоянно, переспрашивать — ошибка; креды в
   `.env.e2e`. Используй канал ввода, который не сохраняет секреты в аргументах,
   сценарии, логе или записи. Для XCUITest сначала проверь private-input канал
   dummy-canary (см. ниже); если безопасного канала нет, нужен только вход
   владельца, после него продолжай тот же обход с действующей авторизацией.

## Инструменты — `scripts/ios-device-qa.sh`

`simctl` с физическим устройством не работает вообще; всё идёт через `devicectl`.

- `Devices` / `UseDevice <udid>` — список и выбор; `Unlocked` — проба блокировки;
- `AppInfo` — установленная версия; `Screen` — bounds в px, `pointScale`,
  ориентация (1125×2436 px при 375×812 pt → делить на 3, тапы считать в пунктах);
- `Install <App>` / `Uninstall` / `Launch` / `Kill` / `Pid`;
- `Open <url>` — диплинк и Universal Link через `--payload-url`
  (`Open metravel://map`, `Open https://metravel.by/travels/<slug>`);
- `Console [имя]` — фоновый запуск с потоком stdout/stderr приложения в
  `/tmp/ios-device-qa/<имя>.log`. Без него «крашей нет» — не утверждение, а
  отсутствие проверки: падение в фоне видно только в логе. `log stream` на этой
  macOS флага устройства не имеет, а `devicectl` syslog не отдаёт;
- `Orient p|pu|ll|lr` — ориентация; `Pull <путь>` — файл из контейнера
  приложения (проверка экспортированного PDF, кэша); `Crashes` — краш-репорты,
  которые Xcode синхронизировал в `~/Library/Logs/CrashReporter/MobileDevice`.

## Скриншоты — главное ограничение слоя

У `devicectl` нет screenshot. Варианты, по убыванию пригодности:

- **XCUITest-обвязка** — `XCUIScreen.main.screenshot()` в `XCTAttachment`
  (`lifetime = .keepAlways`), экспорт из `.xcresult`. Единственный
  автоматизируемый путь, но требует сборки UI-test bundle (см. ниже);
- **iPhone Mirroring** (macOS 26) + computer-use — нужен грант владельца на
  приложение и разблокированный телефон рядом; годится для визуальной оценки,
  не для регулярного прогона;
- **снимок владельцем** — для единичного доказательства.

Скриншот в контекст стоит 8–30k токенов: читать кроп нужной области, а не весь
экран, и только когда нужен текст или пиксельный вид.

## XCUITest-обвязка (ввод и снимки на устройстве)

Используй существующий standalone-проект `tools/ios-device-uitests/`, вне
генерируемого `ios/`. `run.sh` принимает JSON шагов и метку; операции описаны в
`MetravelDeviceUITests/RunScriptTests.swift`. Он управляет уже установленным
`QA_BUNDLE` (по умолчанию `by.metravel.app`), приложение не пересобирает.
При нескольких устройствах явно выбери `IOS_QA_DEVICE`: default берёт первое
доступное. В публичном evidence используй модель устройства, не его UDID.

- Перед запуском прочитай `run.sh` и Swift driver: wrapper выполняет
  `xcodebuild test`, собирает/устанавливает test runner и включает
  `-allowProvisioningUpdates`. Проверь operation gate из
  `docs/WORKFLOW_OPERATIONS.md` → «3.2.1 iOS testing and release operations» и
  «3.4 Координация долгих операций». Обновлять Apple provisioning этим флагом
  можно только в уже разрешённом scope; подключённое устройство само его не
  разрешает. Существующую авторизацию пользователя не запрашивай повторно.
- Если используешь готовый runner через `test-without-building`, сверь
  `.xctestrun`, test bundle и destination с журналом его сборки: source commit,
  время и hash бинарника. Кэш/установленный runner может содержать другой Swift
  driver; совпадение имени не доказывает поведение текущего source. Неизвестное
  происхождение явно укажи, не приписывай ему проверенные свойства исходника.
- Текущий source не печатает raw `QA_SCRIPT` и не dismiss-ит системные alerts
  автоматически. Старый cached runner может по-прежнему печатать
  `QA-SCRIPT-RAW` и нажимать `Allow`/`Разрешить`/`OK`/`Not Now`: безопасные
  свойства нового source не распространяются на него без проверки identity.
  Никогда не передавай секреты в QA_SCRIPT, env-значениях, аргументах или именах
  шагов. `tree`/`shot` сохраняют содержимое экрана; на экранах с секретами они
  запрещены. Логи/снимки: уникальные метка и `IOS_QA_OUT` в ignored
  `.codex-temp/`; default wrapper — `/tmp`.
- Private input: в runtime-копии `.xctestrun` задай `QA_PRIVATE_INPUT=1` в
  test environment и `SystemAttachmentLifetime=keepNever`,
  `UserAttachmentLifetime=keepNever`. Останови screen recording. Передай UTF-8
  файл с локальными правами `0600` в Documents контейнера runner:
  `qa-secret-input/<opaqueKey>.txt` (ключ: 1–64 ASCII буквы/цифры/`_`/`-`).
  Шаг `{"op":"secretClipboard","key":"opaqueKey"}` читает и удаляет файл;
  clipboard локален устройству и истекает через 60 секунд. Далее
  `longPressPlaceholder` с точным публичным `placeholder` выбирает единственное
  text/secure поле; Paste нажимается отдельным UI-шагом. После вставки выполни
  `clearSecretClipboard`; teardown также очищает ещё принадлежащий runner
  clipboard. Локальный исходный файл удали после передачи. Не используй
  `typeText(secret)` — XCTest может записать аргумент. Private mode запрещает
  `tree`, `shot`, `type`, `typePlaceholder`, `clear` и скрывает детали failures,
  но это не доказательство отсутствия системных логов: сначала на пустом поле
  прогони одноразовый dummy-canary без submit и проверь xcodebuild stdout,
  `.xcresult` и attachments на его значение. Реальные credentials вводи только
  после чистого canary; при утечке канал непригоден. Wrapper `run.sh` этот
  private manifest автоматически не настраивает.
- Permission matrix: `tapSystemAlertButton` требует ожидаемый `alertText` и
  точную подпись `button`, проверяет единственный системный alert и кнопку.
  Выбор deny/allow/paste должен быть явным шагом. Фиксируй исходное разрешение,
  выбор и результат deny → allow → Settings → retry; старый auto-dismiss
  runner эту матрицу не доказывает.
- `app.activate()` не гарантирует холодный запуск. Для соответствующего кейса
  явно выполни `terminate` → `activate` и зафиксируй запуск в evidence.

## Разрешения (TCC)

- `Uninstall` + `Install` **не обнуляет** решения: iOS возвращает прежний выбор
  пользователя, и «чистая переустановка» даёт унаследованное состояние с
  `canAskAgain = false` (карта покажет баннер «Открыть настройки» вместо диалога);
- вернуть гео в «не спрашивали»: Settings → MeTravel → Геопозиция → «Спросить в
  следующий раз». Ячейки имеют не зависящие от языка идентификаторы
  `LOCATION_SERVICES_AUTH_NOT_DETERMINED` / `_WHEN_IN_USE` / `_NEVER`;
- у камеры/фото/уведомлений такой ячейки нет: строка вообще отсутствует, пока
  разрешение ни разу не запрашивали — это и есть доказательство, что старт
  приложения их не трогает;
- общесистемный сброс приватности трогает все приложения владельца — только по
  явной просьбе;
- триггеры: гео — вход на вкладку «Карта» (запрос по фокусу экрана, не по
  кнопке); фото/камера — `photo-upload-gallery-button` / `photo-upload-camera-button`
  на шаге «медиа» мастера travel (нужен логин); уведомления — уход с экрана
  начатого квеста, причём шаг надо ответить **верно** (пропуск не считается).

## Локали

Системный диалог iOS берёт строку по языку **устройства**; per-app
«Предпочитаемый язык» на неё не влияет, и приложение его тоже игнорирует (у него
свой переключатель `header-language-switcher` со своим хранилищем). Живые снимки
be/uk/pl/en возможны только сменой языка телефона — это решение владельца;
статическую часть доказывать разбором `.lproj` установленного бинарника. Ключа
`NSUserNotificationsUsageDescription` не существует: текст диалога уведомлений
iOS формирует сам.

## Вход по email — три ловушки, дающие ложное «логин сломан»

- **маска пароля** не доказывает длину ввода. Пароль не раскрывать в записи,
  снимках или UI-дереве; результат проверять успешным входом;
- **клавиатура** перекрывает поле пароля, глазок и кнопку «Войти»: между
  полями идти клавишей `Next:`, отправлять `Done`;
- **лист «Сохранить пароль?»** после успешного входа перекрывает экран —
  «Не сейчас»; QA-пароль в связку ключей владельца не писать.

Признак успеха брать независимым от прокрутки: на вкладке профиля пропала кнопка
«Войти» (проверка «есть плитка Настройки» даёт ложный отрицательный — она ниже
сгиба). «Неверный email или пароль» показывается и на 401, и на 403 — по
сообщению причину не различить.

## Обязательный чеклист устройства (сверх пунктов 9–12 android-qa-sweep)

1. **Universal Links из внешнего приложения** (Заметки/Почта), а не только
   `Open`: `--payload-url` доказывает роутинг внутри приложения, AASA —
   переход из чужого приложения.
2. **Keychain**: сессия переживает `Kill` + `Launch` и перезагрузку устройства.
3. **Камера/фото/HEIC** реально, включая ветку отказа: отказ в опциональном
   разрешении не должен ломать несвязанный просмотр.
4. **Реальные safe area** и home indicator; жест back от левого края конфликтует
   с горизонтальными каруселями — свайп начинать дальше от бортика.
5. **Клавиатура устройства**: поле ввода видно над ней (на headless-симуляторе
   её вообще нет, поэтому такой дефект там недоказуем).
6. **Sharing, печать, экспорт** — native-пути падают там, где web работает;
   выгруженный файл проверять через `Pull`.
7. **APNs**: реальная доставка и роутинг тапа по пушу.
8. **Ориентация**: `Orient ll` — вёрстка ландшафта и возврат в `p`.
9. **Логи весь прогон**: `Console` до сценария, `Crashes` после.
10. **Офлайн**: авиарежим (переключает владелец) → состояния ошибок и восстановление.

## Пайплайн

1. **План** — какие кейсы `IOS-01..15` (`docs/MANUAL_TEST_CASES.md`) и почему
   именно слой Physical.
2. **Обход** — сценарий → evidence → оценка; после каждого действия читать
   `Console` на ошибку.
3. **Отчёт** — `artifacts/ios-qa/QA_REPORT_<ЭКРАН>.md`: таблица обхода и находки
   `### F-NN (critical|major|minor|info)` со ссылкой на файл:строку, если корень найден.
4. **Борд** — перед новым тикетом `problem-memory` (борд во всех статусах,
   включая `done`/`wont_do`), затем `ticket-board`: `[IOS-NN] суть`, `area=front`;
   причина в бэкенде/Apple-портале — связанный `area=back`.
5. **Фиксы** — `ios-expert`, домен карты — `map-expert`; общий файл не ломать
   ради native (несовместимость = `.native.tsx`/`.web.tsx` сплит), после правки
   общего файла проверить web.
6. **Регресс** — `npm run test:run`, `npm run typecheck`, `npm run lint`;
   верификация фикса — повторный прогон на устройстве, не на симуляторе.

## Что нельзя

- собирать подписанные `preview`/`production`, заливать в TestFlight, назначать
  группы, submit и релиз — только `ios-deployer` по точной авторизации владельца;
- общесистемный сброс приватности и запись QA-пароля в связку ключей владельца;
- выводить UDID, Team ID, Apple-аккаунты, токены, payload'ы пушей;
- деструктив над чужими и прод-данными вне тест-аккаунта;
- подменять слой: физический вердикт не закрывается симуляторным скрином, и
  наоборот. Обязательный слой не прогнан → `verify pending` с точной причиной,
  а не `pass` и не «визуально ок».

## Отчёт

Build (version + bundle version), модель и версия iOS, целевой бэкенд, режим
аккаунта, локаль, сценарий, ожидаемое/фактическое, путь к evidence в
игнорируемой папке. Формулировки «вроде работает» и «не воспроизводится» без
деталей запрещены (`docs/AGENT_ANALYSIS_PROTOCOL.md` §7).
