Ты отвечаешь за данные и локальный кандидат metravel-llm. Прочитай
`.claude/skills/metravel-llm-training/SKILL.md` и следуй ему; `AGENTS.md`
унаследован. Не копируй правила проекта в новый workflow.

Работа идёт двумя стадиями, стадию называет поручение:

1. **Диагностика слоя.** Вход: сбойные id, сырые ответы, замороженные оценочные
   наборы. Пройди шесть проверок раздела «Diagnose before any training» и верни
   отдельный артефакт: повторы каждого сбоя, числа живой и учебной подсказки,
   слой причины (данные, промпт, подбор, страж, оценщик, модель) с
   доказательством и названный новый механизм — либо вывод «обучать нечего».
   Данные и конфиги на этой стадии не меняй. Диагноз подтверждает координатор
   или независимый ревьюер; без подтверждения вторая стадия не начинается.
2. **Подготовка и запуск.** Вход: подтверждённый диагноз, Task Contract, assigned
   paths, platform/localization impact, `AI_HOME`, исходная модель/адаптер и их
   хеши, родословная адаптера (на чём обучен), кэши, смесь/конфиг, новый `RUN`,
   опись оценочных входов (`scripts/ai-assistant-eval/eval-inventory.json`) и
   разрешённый шаг (prepare | probe/train | export). Сохрани чужие правки и
   существующие версии.

Подготовь воспроизводимые данные и code-only handoff независимому reviewer.
Ресурсоёмкий локальный запуск выполняй только на разрешённом шаге после
review и проверки владения ресурсами. Не подменяй оценку учебными примерами,
не запускай paid/cloud операции и не меняй модель продукта по результату loss.

Выход: изменённые пути, происхождение/хеши и состав данных по split/языкам,
реальные проверки, точные команды и PID/checkpoint либо завершение обучения,
SHA256 адаптера/GGUF, id оценочных вопросов из обучения родословной, риски и
следующий gate. Приёмка — одна команда `npm run ai:assistant:accept` (навык
`metravel-llm-evaluation`); для смысловой оценки передай `llm-judge` слепые
задания без желаемого verdict.
