# Instagram @metravelby — ТЗ контент-агентов

Источник: постановка владельца от 10.10.2026. Это канонический документ стратегии контента;
агенты `.claude/agents/instagram-*` читают его нужным разделом и не копируют правила к себе.
Календарь, пакеты недель, метрики и разборы живут в `docs/INSTAGRAM_PLAN.md`; годовой резерв тем
— в `docs/INSTAGRAM_YEAR_PLAN.md`; монтаж Reels — в `docs/INSTAGRAM_REELS_BRIEF.md`.

Где этот документ противоречит более старым записям плана (ритм «3 Reels + 2 карусели»),
действует он: с 11.10.2026 сетка — один основной материал в день по разделу 1 (владелец 10.10.2026:
без переходного периода). Формат
единицы (Reel / карусель / пост) выбирается по разделу 13, а не по дню недели.

## 0. Роли и передача между агентами

Одна публикация проходит четыре роли, каждая — отдельный агент с узкой задачей:

| Роль | Агент | Делает | Отдаёт |
| --- | --- | --- | --- |
| Content Planner | `instagram-planner` | разделы 1–10, 20–21: выбирает тему дня с учётом сезона, праздников и повторов; подбирает кандидатов (статьи автора 1, квесты) | `brief.md` |
| Research & Article Editor | `instagram-researcher` | разделы 11–12: читает статью целиком, выписывает факты с цитатой-источником, проверяет внешние факты, предлагает правки статьи | `sources.md`, при необходимости `article-edits.md` |
| Instagram Creator | `instagram-creator` | разделы 13–19, 22: формат, фото, слайды/ролик, подпись, CTA, хештеги | `slides/`, `caption.txt`, `package.md` |
| Visual QA | `instagram-visual-qa` | разделы 15–17, 23: смотрит публикацию целиком, кадрирование, лица, факты против `sources.md`, маркетинг | `qa.md` с вердиктом |

Публикация, расписание, метрики и чистка подписчиков — оператор `instagram-editor`.
Оркестрирует цепочку команда `/instagram` (вызывающая сессия): planner → researcher → creator →
visual-qa; `fail` в `qa.md` возвращает пакет creator-у с нумерованными находками. Лимит кругов
считается по находке, а не по пакету (уточнение 10.10.2026): одна и та же находка не чинится
больше двух раз; находка, которую породила сама правка (новый кадр обрезал голову, новый текст
лёг на объект), получает один узкий дополнительный круг; находка QA в `sources.md` закрывается
researcher-ом, не creator-ом. Упёрлись в материал (нет кадра, нет цитаты) — пакет
останавливается, владельцу — что именно нужно (кадр, фраза, «да» на компромиссную версию).

Готовые пакеты прежней схемы (`.codex-temp/instagram/ready/…`) проходят ту же цепочку в режиме
сверки: researcher собирает `sources.md` по подписи и текстам слайдов (утверждения без
источника — раздел «Не подтверждено в пакете»), creator копирует пакет в папку поста и чинит
список сверки (файлы в `ready/` не меняются), затем Visual QA. Для постов о функциях сайта
первичный источник — код (`path:line`), публичный API и живой скриншот гостем: число со
скриншота допустимо, если скриншот стоит на том же слайде.

Рабочая папка одной публикации: `.codex-temp/instagram/posts/<YYYY-MM-DD>-<slug>/` (в git не
попадает). Каждый агент пишет только свои файлы из таблицы и читает предыдущие.

## 1. Основная недельная сетка

По умолчанию публикуется один основной материал в день.

| День | Основная тема |
| --- | --- |
| Понедельник | Возможности сайта MeTravel |
| Вторник | Квесты MeTravel |
| Среда | Беларусь |
| Четверг | Польша |
| Пятница | Тематическая подборка |
| Суббота | Другие страны |
| Воскресенье | Личный / человеческий / вовлекающий контент |

Это базовая структура, а не жёсткое ограничение. Сетку обязательно менять, если сезон, праздник,
событие или актуальная возможность дают более сильную тему.

Главная задача Instagram — не просмотры сами по себе, а: приводить людей на сайт MeTravel;
знакомить с возможностями сайта; продвигать квесты; давать идеи для реальных поездок; растить
сохранения и пересылки; сохранять аудиторию из Беларуси; постепенно наращивать контент о Польше
и привлекать русскоязычных, живущих в Польше; показывать, что за MeTravel стоят реальные
путешественники. Основной язык публикаций — русский.

## 2. Понедельник — возможности сайта MeTravel

Раз в неделю — одна возможность сайта. Не прямая реклама «заходите на сайт», а конкретная
задача пользователя → решение через MeTravel.

Пример: «Не знаете, куда поехать на выходные?» → на сайте можно выбрать страну, регион, сезон,
тип достопримечательностей (замки, музеи, природа, руины, родники), посмотреть места на карте,
найти путешествия рядом, использовать случайный выбор поездки, задать фильтры и дать сайту
предложить направление, построить маршрут из точки в точку и увидеть интересное по дороге,
погоду на карте, маршруты с собакой, поездки с детьми, связанные статьи и путешествия.

В неделю — одна функция или несколько логически связанных, не весь сайт сразу.
Формат — карусель или короткий демонстрационный Reel. Структура:
проблема → решение → как работает → пример → CTA. Пример: «Хочу куда-нибудь съездить в Польше,
но понятия не имею куда» → фильтр Польша → замки → поездка на 1 день → полученные варианты.
Цель — чтобы человек понял практическую пользу сайта.

## 3. Вторник — квесты MeTravel

Минимум одна публикация о квестах в неделю. Приоритет — Польша и Беларусь, но регулярно
показывать квесты других стран. Один квест не повторять слишком часто.

Можно рекламировать: конкретный квест; несколько квестов одного города; квесты страны; квесты
на выходные; квест для самостоятельной прогулки; квест как альтернативу экскурсии; подборку
«город + квест + что ещё посмотреть»; новые квесты; недавно проверенные лично.

Не рекламный баннер: сначала «зачем это нужно» («Хотите посмотреть город самостоятельно, но
ходить по Google Maps скучно?», «Экскурсия стоит дорого, а историю города узнать хочется»),
затем решение — городской квест MeTravel. Если автор лично проходил или тестировал квест — это
обязательно используется. Ответы на задания квеста не раскрывать.

## 4. Среда — Беларусь

Беларусь — важная часть существующей аудитории; её нельзя вытеснить из плана.
Выбирать из материалов сайта: статью, путешествие, маршрут, место, достопримечательность,
необычный объект, музей, усадьбу, замок, руины, природное место, малоизвестную точку.
Не только самое известное: предпочтение эффекту «я живу рядом / много раз был в этом регионе,
но об этом не знал». Обязательно учитывать сезон.

## 5. Четверг — Польша

Одно из основных направлений роста. Аудитория — в том числе русскоязычные жители Польши,
которые ищут: куда поехать на выходные или на один день, необычные места, маршруты рядом с
городами, замки, природу, музеи, маршруты с собакой, поездки с детьми, сезонные места.
Особый приоритет — места, до которых реально добраться на выходные.

Многие планируют выходные в среду и четверг, поэтому публикации этих дней должны особенно часто
отвечать на вопрос «Куда поехать в ближайшие выходные?».

## 6. Пятница — тематические подборки

Не обязательно одна страна. Анализировать весь каталог MeTravel: красивые замки; необычные
руины; малоизвестные музеи; озёра; родники; маршруты с собакой; с детьми; красивые ночлеги;
необычные гостиницы; места для осени; поездки на дождливый день; маршруты без машины; места в
двух часах от крупного города; заброшенные объекты; ущелья; водопады; смотровые площадки;
необычные природные объекты; места, особенно красивые осенью; романтическая поездка; идеи для
одного свободного дня.

Подборка собирается по статьям или прямо по объектам из базы MeTravel.
Главный критерий: публикацию должно хотеться сохранить.

## 7. Суббота — другие страны

Весь мир за пределами Польши и Беларуси, по странам и путешествиям, которые уже есть на MeTravel
(Италия, Грузия, Албания, Люксембург и др.): одна статья, маршрут, необычное место, личная
история, достопримечательность, часть большого путешествия. Формат — по материалу: динамичное
видео → Reel; маршрут, несколько мест, полезная информация → карусель.

## 8. Воскресенье — человеческая сторона MeTravel

Контент, создающий связь аудитории с авторами: личные истории; смешные ситуации; неудачи и
ошибки; закулисье; как создаётся маршрут; как проверяется квест; старые фото из путешествий;
«куда хотим дальше»; вопросы аудитории; голосования; мини-дневники; личный рейтинг мест;
истории Сергея или Юли; путешествия с собакой, где уместно; «ожидание / реальность»; места, куда
хочется вернуться; как появилась конкретная статья или маршрут.

Это не обязательный «экспертный» пост. Задача — напоминать, что MeTravel делают реальные люди,
которые сами путешествуют и проверяют места.

## 9. Сезонность важнее расписания

Перед любым контентом определить: текущую дату; сезон; актуальную погоду и условия региона;
ближайшие праздники и события; подходит ли поездка этому времени года.
Нельзя механически доставать старые статьи: пляжи под Краковом в феврале не рекламировать
только потому, что статья есть. Зимой — зимние поездки, осенью — осенние, весной — весенние,
летом — летние.

## 10. Праздники и специальные даты

Праздничная или сезонная тема может заменить публикацию дня. Учитывать минимум: Рождество;
Новый год; Пасху; Хэллоуин; День всех святых; День святого Валентина; Масленицу; длинные
выходные; государственные праздники Польши; важные праздники Беларуси; пятницу 13-е; начало
осени; первый снег; начало лета; каникулы; майские праздники; рождественские ярмарки; сезон
цветения; сезон отпусков.

Публикации — до события, не после. Для обычного выходного контента решение принимается в
среду–четверг. Для небольших праздников — за несколько дней. Для Рождества, Нового года,
ярмарок и крупных отпускных периодов — значительно раньше и сериями. Даты каникул и праздников
— только сверенные по официальному источнику, ссылку записать в план.

## 11. Работа со статьями MeTravel

Перед публикацией статью читать полностью, не по заголовку и первым абзацам. Определить: что
самое интересное; какие факты подходят для Instagram; какие места можно показать; есть ли
полезные детали; есть ли личная история автора; актуальна ли информация.

Если статья устарела или её можно улучшить, агент предлагает или выполняет редактуру.
Разрешено: исправлять ошибки; обновлять фактические данные; улучшать структуру; делать текст
понятнее; добавлять актуальную полезную информацию; дополнять проверенными фактами; исправлять
устаревшие сведения.

Запрещено переписывать личную историю автора: впечатления, события поездки, эмоции, что
произошло с автором, авторскую оценку места, последовательность реальных событий. Если Юля
написала, что ей что-то понравилось или не понравилось, это не заменяется другим мнением.

## 12. Дополнительная информация

Основной источник — MeTravel. Если не хватает интересного факта, исторической детали или
актуальной информации, разрешены внешние источники: информация проверена; легенды и факты не
придумываются; исторические факты — минимум по одному авторитетному источнику; часы работы,
цены и ограничения проверяются перед публикацией. Внешние факты дополняют MeTravel, а не
превращают публикацию в пересказ Википедии.

## 13. Выбор формата

Карусель — несколько мест; подборка; объяснение функции сайта; маршрут; пошаговая инструкция;
важны детали; публикацию захочется сохранить.

Reel — есть хорошее видео; важна атмосфера; место визуально эффектное; можно построить
небольшую историю; есть движение; лучше показать, чем объяснять. Reel — не набор случайных
красивых кадров: hook → развитие → интересная деталь → результат → CTA.

Обычный пост — реже: одна действительно сильная фотография или короткая история без карусели.

## 14. Работа с фотографиями

Выбирается не первая найденная, а лучшая. Источники по приоритету: фотографии статьи MeTravel;
фотоархив автора; фотографии по географии/карте в доступной фототеке; другие разрешённые
владельцем источники.

Несколько вариантов одного места — сравнивать: композиция; резкость; освещение; выражение лиц;
положение людей; фон; соответствие месту; пригодность для вертикального формата; возможность
кадрирования. Не брать фото только потому, что на нём нужная достопримечательность.

## 15. Люди на фотографиях

Если в кадре Юля или Сергей, фотография должна быть визуально удачной. Не использовать кадры,
где человек моргнул; глаза закрыты; лицо неудачно из-за момента съёмки; странная поза; кадр
выглядит случайным; обрезана голова; неудачно обрезаны руки или ноги; человек перекрывает
главный объект без художественной причины.

Лицо не обязано быть крупным: человек может идти по маршруту, стоять спиной, смотреть на
достопримечательность, быть далеко в кадре. Но фото в целом должно быть красивым.

## 16. Обязательное присутствие авторов

В каждом основном материале — человеческая сторона проекта. Последний слайд карусели или
финальная часть Reel по возможности содержит Юлю, Сергея или обоих — фотографией из этого же
путешествия. Ощущение «мы действительно здесь были», а не приклеенная фотография автора.

## 17. Проверка кадрирования

После сборки всех слайдов публикация просматривается целиком, не по одному слайду: не обрезан
ли главный объект; не обрезаны ли люди; не исчезла ли важная часть фото; хорош ли вертикальный
crop; не закрывает ли текст лицо или объект; одинаково ли читаются все слайды; нет ли случайных
плохих кадров между хорошими; выглядит ли карусель единой работой.

Особенно внимательно — люди: недопустимы половина головы после crop, случайно обрезанная нога,
человек как визуальный мусор по краю кадра.

## 18. Тексты на слайдах

Не перегружать фото текстом. Первый слайд отвечает на вопрос «Почему мне стоит открыть эту
публикацию?». Хорошо: «7 мест в Польше, куда хочется сбежать осенью», «Этот замок находится
всего в часе от Кракова», «Куда поехать на выходные, если всё известное уже посмотрели»,
«5 маршрутов, куда можно с собакой», «Не знаете, куда поехать? Пусть MeTravel выберет за вас».
Плохо: «Интересные туристические места Польши». Текст звучит по-человечески, не как
SEO-заголовок.

## 19. Стиль текста

Тон: разговорный, живой, информативный, без пафоса, туристических клише и ощущения текста от
нейросети. Запрещены фразы вида «никого не оставит равнодушным», «настоящая жемчужина», «здесь
история оживает», «идеальное место для незабываемого путешествия». Вместо них — конкретика: что
необычного, зачем ехать, кому понравится. Личный опыт — всегда, когда он есть.

## 20. Принцип выбора темы

Перед публикацией оцениваются несколько тем, не первая статья. Для каждой: сезонность;
визуальный потенциал; наличие фотографий; практическая ценность; вероятность сохранений;
возможность поездки сейчас; связь с предыдущими публикациями; как недавно тема уже была.
Instagram не превращается в поток одинаковых замков или маршрутов; темы чередуются.

## 21. Повторы

Перед недельным планом проверяются предыдущие публикации. Не повторять подряд: одну страну вне
фиксированных дней; один город; одну достопримечательность; один квест; одинаковые подборки;
одну функцию сайта.

Повтор допустим, если: новый сезон; информация существенно обновилась; место связано с
праздником; появилась новая статья; новый квест; новый личный опыт; тема показала очень
высокий интерес и есть новый угол подачи.

## 22. Что готовится для каждой публикации

Результат практически готов к публикации. Для каждого материала: тема; почему она выбрана
именно сейчас; формат (Carousel / Reel / Post); hook; структура (карусель — содержание каждого
слайда; Reel — последовательность кадров и текст на экране); фотографии/видео и почему они
выбраны; caption целиком; CTA (сохранить; отправить другу; посмотреть маршрут на MeTravel;
пройти квест; открыть карту; написать свой вариант; рассказать, были ли здесь); только
релевантные хештеги/ключевые слова.

## 23. Финальный контроль качества

Отдельное ревью на четырёх уровнях.

- Контент: факты правильные; информация актуальна; личная история автора не изменена.
- Маркетинг: понятно, зачем смотреть; есть причина сохранить или отправить; понятен следующий
  шаг.
- Визуал: лучшие ли фото; хорошо ли выглядят люди; нет ли плохого crop; сильный ли первый кадр;
  хорошо ли выглядит весь набор слайдов.
- MeTravel: понятна ли связь с MeTravel; не слишком ли рекламно; есть ли естественная причина
  перейти на сайт.

## 24. Главный принцип

Instagram MeTravel — не каталог ссылок и не энциклопедия. Каждая публикация выполняет хотя бы
одну задачу: дать идею → помочь выбрать → вдохновить → помочь спланировать → рассказать историю
→ привести к инструменту MeTravel. Лучший контент выполняет несколько сразу. Ощущение: «увидел
интересное место → понял, почему туда стоит ехать → сохранил → открыл MeTravel → построил свою
поездку».

## 25. Жёсткие правила владельца (04–06.10.2026, остаются в силе)

Эти решения приняты до ТЗ и не отменены им. Нарушение любого — `fail` у Visual QA.

### Источник контента — только статьи автора 1 и квесты площадки

- Единица делается только по опубликованной статье, у которой автор — пользователь 1 (Юля).
  Проверка каждой статьи: `curl -s https://metravel.by/api/travels/<id>/` → `userIds == "1"`,
  `publish == true`, `moderation == true`. Не совпало — статья не используется.
- Поиск: `curl -s -G https://metravel.by/api/travels/ --data-urlencode 'query=<тема>'
  --data-urlencode 'perPage=20' --data-urlencode 'where={"publish":1,"moderation":1}'`; в
  `results[].user.id` брать только `1`. Гостевые статьи не цитируются, не пересказываются, их
  фото не берутся.
- Квесты площадки: `GET https://metravel.by/api/quests/` (с пагинацией), детали
  `GET https://metravel.by/api/quests/by-quest-id/<quest_id>/`, адрес
  `https://metravel.by/quests/<city_id>/<quest_id>`.
- Статьи по теме нет — единица в план не ставится; в отчёт «нужна статья: <тема>» (пишет
  `travel-writer` по запросу владельца).

### Факты

- Каждое число (км, дни, метры, цены, часы) — из текста статьи или данных квеста с
  цитатой-источником. Нет в источнике — нет в публикации. Округлять можно («около 180 км»),
  усиливать нельзя. Цена — с годом из статьи. «Дешевле, чем…», «без очередей», «самый…» — только
  если так написано в статье.
- Легенды пересказываются только те, что написаны в статье или данных квеста.
- Статья может быть неточной: поправка владельца важнее текста статьи — записать в план и
  предложить исправить статью (раздел 11).
- Текст статьи без разметки: `curl -s https://metravel.by/api/travels/<id>/ | python3 -c
  "import json,sys,re,html; d=json.load(sys.stdin);
  print(re.sub(r'\s+',' ',html.unescape(re.sub(r'<[^>]+>',' ',d['description']))))"`.
  Поля `plus`, `minus`, `recommendation`, `gallery[].url` и подписи кадров — там же.

### Голос и формат

- Голос подписи — первое лицо Юли: «я прошла этот маршрут», «мы с Сергеем», не «Юля прошла».
- Хук — первые 2 секунды / первый слайд: название места + главное число + польза. Первая
  строка подписи — про место, словами, по которым ищут; не начинать с «Всем привет», хештега,
  даты, «Итак».
- Подпись 600–1200 знаков, абзацы 1–3 строки, 1–2 эмодзи максимум, 3–5 хештегов в конце, один
  призыв, конкретный вопрос в конце («Со словацкой или с польской стороны пошли бы вы?»).
- Один Reel — одно цельное место или маршрут; «День N», «продолжение» в Reels запрещены.
  Длина 15–40 с, вертикаль 9:16, обложка с названием, без логотипов других приложений.
  Монтаж — по `docs/INSTAGRAM_REELS_BRIEF.md`; слайдшоу из фото (`make-reel.py`) владелец не
  публикует.
- В подписи — ориентир «полный маршрут на metravel.by» (кликабельна только ссылка в профиле
  и стикер в истории).
- Семейные детали сверх статьи в подпись не выносить.
