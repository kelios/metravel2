## 3. Технические находки

### 3.1. P1 — статический HTML отдаёт краулеру обрезанное тело статьи

`scripts/ssg-skeletons.js:502` — `sanitizeArticleBodyHtml(rawHtml, maxChars = 9000)`,
вызывается без второго аргумента (`ssg-skeletons.js:617`). Тело статьи в
SSG-HTML жёстко обрывается на 9 000 символах очищенного HTML по границе блока.

Замер на 14 случайных статьях (полный текст из API против видимого текста
прод-HTML, пробы по 8 слов через каждые 40):

| Статья | Слов | % текста в статическом HTML |
|---|---|---|
| `tour-du-mont-blanc-vokrug-monblana-za-10-dney` | 4 600 | **17%** |
| `vitebsk-za-1-den-chto-posmotret-i-kuda-skhodit` | 3 387 | **35%** |
| `vena-za-1-den-i-venskii-les-chto-posmotret` | 1 233 | 84% |
| `katovitse-i-nikishovets-chto-posmotret-v-silezii` | 1 176 | 87% |
| `logoisk-dvorets-tyshkevichei-i-rodnik-…` | 1 268 | 94% |
| `split-za-odin-den-dvorets-diokletiana` | 1 259 | 94% |
| остальные 8 (≤ ~1 000 слов) | 804–1 086 | 100% |

Статьи примерно до 1 000 слов попадают в HTML целиком; всё, что длиннее,
обрезается. У Влёры (`albaniya-vler-gorod-dvuh-morey`, 1 945 слов) в HTML нет
трёх разделов — «Что рядом», «Частые вопросы: Влёра и окрестности», «Мои фото
этих мест в Instagram», — то есть ровно тех блоков, которые отвечают на
сопутствующие подзапросы.

**Масштаб**: у 150 из 306 статей (49%) очищенный HTML описания длиннее 9 000
символов, медиана по автору — 8 875 символов, то есть половина библиотеки стоит
ровно на границе. Сильнее всех режутся самые весомые материалы: Mont Blanc
(45 528 симв.), «Наш Вьетнам» (42 386), Армения (33 386), «Заброшенные усадьбы
и замки Беларуси: 38 мест» (30 751), Нижняя Силезия (30 031), Витебск (27 920),
Гродно (27 405).

Значимость: обрезанные страницы — это именно длинные материалы, а среди них
кластер «застряло на второй странице» из §4. Google дорендеривает страницу
JavaScript'ом и в итоге видит полный текст, но первичная оценка идёт по HTML,
и на тяжёлых страницах рендер откладывается.

Что делать: поднять лимит (или отдавать тело целиком для статей без медиа-мусора)
и перепроверить вес страниц после изменения — лимит вводился ради размера HTML.

### 3.2. Дополнение к #1319/#1320: 55-мегабайтная страница не в индексе

SEO-следствие, которого в тех карточках нет.

## 5. Инструментальный пробел

`npm run stats:index` (монитор индексации) **проверял 0 статей и завершался
успешно**: `scripts/index-status.js:78` читает список как
`res.data || res.items || res.rows`, а API `/api/travels/` отдаёт конверт
`{count, next, results}`. Поля `results` в списке нет → пустой список → отчёт
«Всего проверено: 0», exit code 0.

Тем же способом список читает `scripts/seo-audit.js:315` — там `res.results` есть,
поэтому контентный аудит работал, а монитор индексации молча — нет.

Фикс на одну строку (добавить `res.results` первым в цепочку). В этом аудите
индексация измерена патченной копией скрипта во временной папке; сам
`scripts/index-status.js` не менялся — `scripts/` по AGENTS.md правится только
по явному запросу.
