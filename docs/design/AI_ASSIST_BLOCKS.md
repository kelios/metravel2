# Смысловой подбор: блоки на статье, квесте и `/search` — #2459

Дата: 25.10.2026. Платформы: desktop web и mobile web (320 / 390 / 1440). Компоненты общие:
в native-сборке с тем же флагом блоки тоже появляются (адрес — origin API), поэтому флаг в
native-окружение не выставляется до отдельной карточки («Native-окно»). Флаг
`EXPO_PUBLIC_AI_PICKS=1`; без флага страницы выглядят как сейчас, запросов к `/ai/*` нет.
Служба — `metravel-assist` (#2456), same-origin `/ai/*` (nginx на проде — #2457).

## Источник данных

`GET /ai/similar?type=&id=&result_type=travel&limit=&locale=` и `POST /ai/search {q, locale, limit}`
→ `items[]` = `{type, source_id, title, url, snippet, cover, city, country}`. Обложка берётся из
индекса (поле `cover`, #2459), гидрации карточек из `/api/` нет: один запрос на блок.

## Карта блоков

| экран | блок | где | лимит | источник |
| --- | --- | --- | --- | --- |
| статья `/travels/<slug>` | «Похожие статьи» | сайдбар после «Популярные», перед стрелками похожих маршрутов | 6 (телефон показывает 3) | `/ai/similar?type=travel&result_type=travel` |
| квест `/quests/<city>/<id>` | «Статьи о местах квеста» | после гео-блока «Путешествия по этому городу» | 3 | `/ai/similar?type=quest&result_type=travel` |
| `/search` | «Подобрать по описанию» | заголовок прокручиваемого списка результатов (`listIntroContent`), над карточками каталога | 12 | `/ai/search` |

Гео-блоки «Квесты по этому городу и рядом» (статья) и «Путешествия по этому городу» (квест)
уже существуют — смысловые дубли квестов не добавляются: смысловой слой закрывает связи
«статья ↔ статья», которых у гео-блоков нет.

## Состояния

| состояние | статья / квест | `/search` |
| --- | --- | --- |
| флаг выключен | ничего не рендерится | строки нет |
| idle | — | заголовок, подсказка, поле ввода — та же шапка (`AiSearchPanelPlaceholder`) уже в первом кадре `/search` (`SearchPageSkeleton`), гидратация ничего не сдвигает |
| loading | каркас той же геометрии: столько слотов, сколько запрошено карточек (`limit`) | ряд из 3 слотов той же высоты, что карточки |
| results | заголовок + подзаголовок + сетка `UnifiedTravelCard` (квадратная обложка по `CARD_MEDIA_SLOT_RATIO`, #1674; заголовок, город/страна); на телефоне — первые 3 из запрошенных | «Подобрано по смыслу · N» + горизонтальный ряд `CardRail` фиксированной высоты, под каждой карточкой 1–2 строки `snippet` |
| empty | `null` — блока и зазора нет | строка «На сайте об этом пока нет…» |
| unavailable (сеть, 5xx, таймаут 4 с) | `null`, одна попытка, повтор не раньше чем через час | поле остаётся, вместо результатов пометка «Подбор сейчас недоступен…»; другой запрос пробует службу снова; обычный поиск работает |

`useThemedColors()`.

## CLS

Блок на статье живёт внутри `TravelDetailsDeferredTransition` с нулевым резервом
(`pending={false} placeholder={null} allowEmptyRuntime`) в конце сайдбара — тот же
механизм, что у стрелок похожих маршрутов (#2367): рост только в резерв сайдбара, пустой
ответ ничего не резервирует. Запрос уходит вместе с «Рядом» (`nearInViewport`), нового
IntersectionObserver нет. Пока запрос в полёте (`queryKeys.aiSimilarSource`), сайдбар не
сообщает устоявшийся кадр, и резерв не отпускается раньше ответа службы.
