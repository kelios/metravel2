# Приглашение поделиться поездкой из статьи (#2677)

Нормативный макет и состояния для desktop web (1440 px), mobile web (390 px) и общего native UI. Это дополнение к существующему экрану, без изменения hero, меню действий и призыва сохранить маршрут.

## Статья

```text
Существующее введение / карточка автора
┌─────────────────────────────────────────────────────────┐
│ Существующий гостевой блок «Сохранить маршрут»             │
│ Его подписи, кнопка, состояние и события без изменений    │
└─────────────────────────────────────────────────────────┘
                    существующий / token отступ
[ Были здесь? Расскажите о своей поездке                  ]
Существующий текст статьи и следующие разделы
```

Фактический блок сохранения расположен перед текстом статьи, а не после него. Новый призыв идёт непосредственно за ним: сохраняется выбранное карточкой соседство с сохранением без перестановки прежних разделов. Для вошедшего, которому гостевой блок не показывается, приглашение занимает тот же слот перед текстом.

- Одна кнопка с полным понятным действием, вторичный/soft вариант существующего `Button`; иконка Feather допустима как дополнение к подписи.
- 390 px: кнопка по доступной ширине, подпись переносится без обрезки, touch-target не меньше 44 px. Горизонтального скролла нет.
- 1440 px: выравнивание по началу существующего контента; ширина не превышает контейнер, подпись не обрезается.
- Цвета и отступы — существующие themed tokens. Фокус виден; кнопка доступна с клавиатуры и имеет полную accessibility-подпись.
- Никаких дополнительных фотографий, загрузки API или копирования текста исходной статьи.

| Состояние | Видимость и действие |
| --- | --- |
| Гость, auth загружен | Приглашение видно; регистрация с `intent=share-trip` и полным внутренним адресом создания. Переход ко входу сохраняет этот адрес. |
| Вошедший читатель | Приглашение видно; сразу создание с тем же контекстом. |
| Автор исходной статьи | Приглашения нет. |
| Auth ещё неизвестен | Приглашение не показывается до разрешения состояния, чтобы не мигать у автора. |
| Место или страна отсутствует | Приглашение доступно; отсутствующее значение остаётся пустым, не выдумывается. |

## Создание: первый шаг

```text
Существующая шапка мастера
Название путешествия [ <город или имя первой точки>      ]  редактируется
Страны путешествия  [ <страна из статьи>              v  ]  редактируется
Существующий редактор собственного текста
Существующие действия / footer
```

- Название предзаполняется именно именем места: `cityName`, затем имя первой именованной точки `travelAddress`. Заголовок исходной статьи не используется.
- Страна передаётся как положительный ID либо ISO2 из `countryCode` и точно сопоставляется каталогу в канонический `country_id`; выбор работает существующим `MultiSelectField`, данные и изменение — существующим `form.countries`.
- Поле стран на первом шаге добавляется только для входа из статьи; обычный create/edit и второй шаг сохраняют интерфейс.
- API/editorial названия мест не переводятся. Все app-owned подписи — через namespace `travel`, RU/BE/UK/PL/EN.
- Первоначальная инициализация использует существующее состояние загрузки до первого завершения запроса каталога. После ошибки доступно редактирование названия и собственного текста; локализованная ошибка допускает повтор, который не пересеивает форму. Неизвестный ID не превращается в фиктивную страну.
- Предзаполнение применяется как исходное состояние новой формы, без пользовательского изменения/автосохранения само по себе. Восстановленный черновик и уже введённые значения имеют приоритет; редактирование существующей статьи не затрагивается.
- После регистрации без автоматического входа промежуточный экран входа/регистрации сохраняет все проверенные параметры адреса создания.

## Приёмка

После reviewed/pushed SHA и выката: реальные guest → register/login → create и authenticated → create, подавление у автора, редактирование страны/названия, отсутствие копии текста/фото/координат. Скриншоты, keyboard/focus, console/network на 390 и 1440 px. Проверить длинные подписи во всех пяти локалях. Общие URL и props проверяются unit tests; отдельный native device gate добавляется при platform-specific изменениях.

События проверяются на границе аналитического транспорта с перехватом QA-запросов к счётчикам: тестовые действия не должны загрязнять защищённый замер #2659. Клиентская классификация и транспорт не меняются.
