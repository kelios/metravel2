# Шапка панели карты на ширине ≥ 768 — #2217

Нормативный макет, 05.10.2026. Поверхность — desktop-ветка `/map`: desktop web,
iPad и Android-планшет рендерят одну шапку `components/MapPage/MapPanelHeader.tsx`
со стилями `screens/tabs/map.styles.ts` (`docs/features/map.md` → «Desktop-ветка
`/map`»). Не меняются: телефонная шторка `MapMobileLayout` (< 768), полоса 56 и
сворачивание панели (#2172), содержимое вкладок, кроме кнопки «Сбросить» в
подвале фильтров.

## Почему сейчас не помещается

В одном ряду стоят сегмент из двух вкладок и три кнопки 44 × 44
(`MapPanelHeader.tsx:149-198`). Ряд действий с отступом занимает 161 px
(`panelHeaderActions`: отступ 8, поле 8, рамка, 3 × 44, 2 зазора по 6). Ещё 10 px
уходит на `tabsRow.columnGap`, 26 px — на рамку панели и поля шапки. Вкладке
на web остаётся (ширина панели − 207) / 2, на native — (360 − 205,5) / 2 = 77,3:
hairline там 0,5 pt.

Ширина панели на web — `clamp(сохранённая или 384, 300, 0,42 × окно)`
(`hooks/map/useMapPanelState.ts:9-25`) в рамках `min-width 320 / max-width 400`
(`map.styles.ts:179, 227-228`). На native ширина 360 pt.

Ниже — ширина, нужная активной вкладке с полями. Счётчик «999+», подпись 12/700,
бейдж 9/700. В скобках — нехватка.

панели 320 — 21,2. Активная «Маршрут» в RU на 820 выходит на 4,6 px. В светлой теме
иконка активной вкладки белая (`textInverse`) и на светлом сегменте за
заливкой пропадает (`.codex-temp/2217/before-pl-820.png`).

Дефект не зависит от языка. Даже без бейджа «Маршрут» на 1440 съедает поля
вкладки: нужно 91,9 из 88,5. При максимальной панели 400 вкладке достаётся 96,5
при нужных 121. Гейты его не
ловят: `guard:text-row-sizing` проверяет переносимые ряды, `guard:touch-targets` —
размеры кнопок, а e2e не сверяет содержимое вкладки с её шириной.

## Методика замера — одна для web и native

| Методика | Чем | Результат («Места» + «999+», активна, RU / PL) |
| --- | --- | --- |
| Web, DOM | Chromium против `https://metravel.by/map`, клон вкладки с `width: max-content`, текст бейджа «999+», язык через `localStorage` `@metravel/locale-preference:v1` | 113,67 / 121,14 |
| Web, формула | ширины строк в DOM-спанах со стеком приложения + поля и зазоры из `map.styles.ts` | 113,7 / 121,1 |
| Native | CoreText, `NSFont.systemFont` (SF, оптический размер Text), `.semibold`/`.bold`, NSKern 0,15 — как у RN iOS | 112,66 / 120,12 |

Формула совпадает с DOM до 0,05 px. CoreText совпадает с DOM-шириной строк до
0,2 px на 30 подписях, а на бейдже — до 0,003 px: Chromium на macOS рисует стек
`-apple-system, "system-ui", …` тем же SF.
Разница web − native = +1,0 px — рамка бейджа (hairline 1 px на web против
0,5 pt на iPad @2x). Прежний расчёт 112,7 / 117,4 / 110,7 / 120,1 / 113,8 был
сделан для активной вкладки (700) и подтверждён.

Нормативное правило: нужная ширина — максимум из SF (web и native) и границы
резервных шрифтов. В стеке web дальше идут Segoe UI, Roboto, Helvetica и Arial.
Helvetica и Arial уже SF (113,7 PL против 121,1). Верхняя граница широкого
класса (Verdana, по ширине как DejaVu в Linux) — +5 % к SF (127,5 PL). Запас
между нужной и доступной шириной — не меньше 8 px/pt на каждой ширине панели и
в каждой локали. Скрипты и данные: `.codex-temp/2217/` (`web-tab-intrinsic.mjs`,
`coretext-widths.swift`, `web-font-variance.mjs`, `budget.mjs`, `tables.mjs`).

## Принятое решение

Ряд вкладок принадлежит только вкладкам. «Фильтры» становятся третьей вкладкой.
Каждая вкладка — иконка над подписью. Два оставшихся действия уходят туда, где
живёт их смысл.

```text
┌──────────────────────────────────────────┐
│ Карта путешествий …   (H1, только web)   │
│ ┌────────────┬────────────┬────────────┐ │
│ │  ≡  999+   │     ➤      │     ⫶      │ │
│ │   Места    │  Маршрут   │  Фильтры   │ │
│ └────────────┴────────────┴────────────┘ │
└──────────────────────────────────────────┘
  карта, правый верхний угол:  (◎)  (≋)   Радиус, Слои
                                    (?)   Подсказки — под «Слоями»
```

1. Сегмент занимает всю ширину шапки: в `tabsRow` один ребёнок.
2. Три вкладки, порядок как в полосе 56: «Места», «Маршрут», «Фильтры». «Фильтры»
   и сейчас — третий вид панели (`activeTab === 'search'`,
   `screens/tabs/MapScreen.tsx:434-435`), а не действие. Свёрнутая полоса уже
   показывает их тремя иконками в этом порядке.
3. Вкладка — колонка: строка «иконка + бейдж», под ней подпись. Бейдж стоит
   справа от иконки, а не над её углом. Угловой бейдж требует 87–91 px, и запас
   при панели 320 падает до 3–7 px.
4. «Сбросить фильтры» — кнопка `filters-reset-button` в подвале вкладок
   «Фильтры» и «Маршрут». Это тот же `FiltersPanelFooter`, что в телефонной
   шторке; на desktop-ветке его прячет `hideFooterReset={!isMobile}`
   (`MapScreenDesktop.tsx:245`). Сброс там же вызывает тост и сбрасывает слои
   (`useFiltersPanelModel.ts:80-84`). Остаются и прежние пути: «Сбросить» в
   `ActiveFiltersBar` и сброс в пустом списке мест.
5. «Подсказки» — круглая кнопка 44 `map-desktop-help-button` в кластере кнопок
   карты, вторым рядом под «Слои». Работает так же, как «Слои» и «Радиус»: на
   всех платформах desktop-ветки, без `hitSlop`. Верхний ряд кластера держит не
   больше двух кнопок (`DESKTOP_MAP_FAB_TOP_ROW_SLOTS`): он делит полосу с
   пилюлей «Искать в этой области» по центру карты, и третий слот слева от
   «Радиус» на окне 768–925 px заходил под её правый край и перехватывал клики
   (P2 код-ревью #2217). Кластер растёт вниз по краю карты, а не влево.

(`MAP_PANEL_TAB_*`), бюджет из них считает `__tests__/app/mapLayout.test.ts`.

Шапка на native — 75,5 pt (расчёт). Обе высоты не меняются.

Счётчик: 0 или ещё не загружен — бейджа нет; 1–999 — число; больше 999 —

На старте выбрана «Фильтры». Сейчас при открытии `/map` ни одна вкладка сегмента

перевести на токен.

## Доступность

- `tablist` с именем «Панель карты» содержит три `tab`. Ровно одна вкладка
  `selected` в любой момент. Сейчас выбор «Фильтры» живёт на кнопке
  `role=button` с `selected` вне `tablist` (`MapPanelHeader.tsx:150-169`).
- Доступное имя начинается с видимой подписи (WCAG 2.5.3):
  - «Места (1 234)» — `${label} (${formatInteger(count)})` по образцу
    `SegmentedControl.tsx`. Полный счёт, а не «999+».
  - «Маршрут»; прежнее «Построение маршрута» уходит в `accessibilityHint`
    (на native).
  - «Фильтры».

  Сейчас имена «Список: 123 места» и «Построение маршрута», и голосовое
  управление не находит вкладку по видимому слову.
- iOS: на каждой вкладке `accessibilityShowsLargeContentViewer` и
  `accessibilityLargeContentTitle={label}` (RN 0.86). Подпись ограничена 1,35,
  на AX-размерах её показывает Large Content Viewer — идиома `UITabBar`.
- testID: `map-panel-tab-travels`, `map-panel-tab-route`,
  `map-panel-tab-filters`. Последний и есть цель шага «Настройте фильтры» в
  `MapOnboarding.tsx:117`, сейчас она висит без элемента.
- «Подсказки» — `button` с именем «Показать подсказки по карте» (существующий
  ключ `MapPanelHeader.pokazat_podskazki_po_karte_5d9bc7dd`), на web — `title`.
  Порядок чтения кластера — как на картинке: «Радиус», «Слои», затем
  «Подсказки» под ними. Пока открыт поповер «Слоёв», «Подсказки» не рисуются:
  карточка открывается на их месте, и кнопка (zIndex 1001 против корня поповера
  без zIndex) легла бы на «×» карточки и запускала бы тур вместо закрытия (P2
  код-ревью #2217, круг 2).
- Сброс в подвале: в режиме радиуса доступное имя «Сбросить фильтры» — ключ
  `FiltersPanelFooter.sbrosit_filtry_fc81efcc`, уже используется телефонной
  веткой.
- Новых строк интерфейса нет. Без читателей остаются
  `MapPanelHeader.spisok_value1_272d2a31` и `MapPanelHeader.sbrosit_filtry_06292479` —
  удалить в пяти локалях. UK-имя `tablist` (`panel_karty_951bb838`) в HEAD —
  «Панель картки», то есть «панель карточки». Соседняя правка терминов уже
  меняет его в рабочем дереве на «Панель карти»
  (`i18n/locales/uk/generated/map_02.ts:5`, 05.10). #2217 эту строку не трогает,
  при реализации — сверить.

## Паритет web, iPad и Android-планшета

Одинаковы:

- иерархия;
- сегмент из трёх вкладок в порядке полосы 56;
- размеры 44 / 52 (51 pt);
- набор действий: «Подсказки» на карте, «Сброс» в подвале фильтров;
- касание: собственный бокс 44 без `hitSlop` (#2172).

Намеренные различия:

## Плавающие элементы карты

Левый верхний угол карты desktop-ветки (web от 768 px, iPad, Android-планшет)
делят три вещи: кнопка сворачивания панели, пилюля качества геолокации и (на
web) колонка «моё место / масштаб» Leaflet. Кнопка сворачивания стоит в 4 от
правого края панели и заходит через шов 16 в карту на 32 (`top` 16, бокс 44).
Решение #2220 — сдвигать пилюлю, а не кнопку: кнопка одна и та же на всех
платформах (#2172) и в ней живёт контракт касания Android; пилюля встаёт в ту
же полосу правее кнопки (`left` 40 = 32 + зазор 8, `top` 16), колонка Leaflet —
ниже полосы (`top` 72). Числа одного источника — `screens/tabs/mapDesktopCorner.ts`;
`collapseToggleInPanel`, `locationQualityPill` и `MapControls` читают их, а не
свои литералы. Непересечение для панели 344/384 (web) и 360 pt (native) при
самой широкой пилюле (`maxWidth` 360, две строки) держит
`__tests__/components/MapPage/mapDesktopCornerStack.test.ts`, на живой странице —
«Map location-quality pill vs collapse chevron (#2220)» в `e2e/map-page.spec.ts`.

Как снимать:

- Язык web — `localStorage` `@metravel/locale-preference:v1`. В приложении язык
  меняется своим переключателем: по умолчанию стоит явный RU, системный язык не
  используется. После смены — холодный рестарт (IOS-10).
- Тема: `xcrun simctl ui booted appearance dark|light`. Шрифт:
  `xcrun simctl ui booted content_size extra-extra-extra-large` или
  `accessibility-extra-extra-extra-large`. Снимок:
  `xcrun simctl io booted screenshot .codex-temp/2217/<файл>.png`.
- Реальный «999+» гостю недоступен: при 400 км вокруг Минска API отдаёт
  `count: 778` (`.codex-temp/2217/count-probe.mjs`). «999+» на web доказывает
  подстановка в клон, на native — расчёт CoreText выше. Снимки делаются с
  реальным счётчиком.
- Физический iPad не обязателен: по решению владельца от 03.10 iPad проверяется
  на симуляторе. Устройство нужно только для ощущения касаний и жестов
  VoiceOver, если оно доступно.

## Риски

- Сброс из «Мест» и «Маршрута» — два касания вместо одного, как на телефоне. В
  пустом списке и в `ActiveFiltersBar` по-прежнему одно.
- Переход «Маршрут» → «Фильтры» очищает маршрут
  (`clearRouteAndSetMode('radius')`, `screens/tabs/MapScreen.tsx:413-416`). Так
  ведёт себя и нынешняя кнопка «Фильтры», но вкладку будут нажимать чаще. Если
  это потеря данных, нужна отдельная карточка.
- Вид по умолчанию — третья вкладка. Порядок задан полосой 56, а её #2217 не
  трогает.
- Кластер кнопок карты растёт вниз по правому краю, а не влево: верхний ряд
  делит полосу с пилюлей «Искать в этой области» (контракт — jest
  `mapLayout.test.ts`, не больше двух кнопок в верхнем ряду). #2219 ставит
  новые кнопки тоже вниз по краю.
