# Успех отправки обратной связи

Нормативные состояния `/contact` и формы на `/about` для desktop web,
mobile web, Android и iOS. Меняется только локализация известного сообщения;
порядок полей, кнопки, цвета, отступы и доступность формы сохраняются.

| Состояние | Норма |
| --- | --- |
| До отправки | Нет сообщения об успехе. |
| Отправка | Сохраняются текущие индикатор и блокировка повторной отправки. |
| HTTP 200 с известной строкой «Сообщение успешно отправлено» | Баннер показывает существующий `errorsStatic:api.misc.messageSent` выбранной локали; тост также на выбранном языке. |
| HTTP 200 с `{message: "Сообщение успешно отправлено"}` | То же поведение, что у строкового ответа. |
| HTTP 200 с неизвестной содержательной строкой | Не переводить произвольный API-контент; сохранить исходное сообщение. |
| HTTP 200 без сообщения | Существующий локализованный запасной текст `errorsStatic:api.misc.messageSent`. |
| HTTP 400/401/403/451 и сетевая ошибка | Сохраняются существующие ошибки; баннер и тост успеха не появляются. |

В BE известный успех выглядит так:

```text
[Паведамленне паспяхова адпраўлена]

Имя, email, сообщение и согласие очищены по прежнему контракту формы.
```

RU/BE/UK/PL/EN используют существующие ключи; перевод выбирается во время
обработки ответа, чтобы смена языка без перезапуска не сохраняла старую строку.
Контроль: известный серверный успех нормализуется в обеих формах ответа,
неизвестное сообщение сохраняется, ошибка не становится успехом.

Приёмка сравнивает баннер с этим состоянием на desktop 1280 и mobile web 390,
а также на iPhone в BE, где дефект был обнаружен. Общий JS-контракт покрывает
Android тестами; отдельный device gate нужен при новой native-ветке.
Письмо на production при повторной проверке отправляется только с отдельным
разрешением владельца: разрешение на одну отправку в #1784 уже использовано.
