# Короткие дневники: одна прогулка — одна страница

Нормативный сценарий для #3069, 05.11.2026. Пользователь поручил закончить
идею коротких книг. Готовые шестистраничные PDF #3040/#3041 сохраняются;
завершается их выбор и использование на сайте.

## Цель и иерархия

Гость понимает, что получает три самостоятельные поездки, выбирает одну,
открывает карту и источник, скачивает PDF и печатает нужную страницу.
После прогулки добавляет свой снимок, рисунок или заметку.

Каталог после общих фильтров:

1. «На три поездки»: краткое назначение, две компактные карточки с настоящими
   обложками A5, названиями, описанием, объёмом и языком PDF. Основное действие
   «Выбрать поездку». На desktop две карточки рядом; на mobile одна под другой.
2. «Большие книги путешествий»: отдельное назначение и существующие карточки
   полных изданий. Ссылки всех оформлений сохраняются.

Страница короткого дневника:

1. Обложка и реальная страница поездки, название, описание, объём, язык,
   бесплатность и отсутствие регистрации. Действия «Скачать дневник PDF»
   и «Выбрать поездку». Объяснение, что можно начать с одной страницы.
2. Три самостоятельные поездки. У каждой номер страницы 3/4/5, точная карта,
   исходная статья или квест, ссылка на соответствующую страницу PDF.
3. Полный состав: обложка, план, три поездки, воспоминания. Рядом настоящий
   образец страницы 3 с явной подписью и ссылка на весь PDF.
4. Три шага использования: выбрать место, распечатать нужную страницу A5
   в масштабе 100%, выполнить задание и сохранить впечатление.

Файл содержит последовательные страницы A5. Для одной прогулки достаточно
одного листа; брошюровка не нужна. Инструкция не обещает готовую A4-раскладку,
автоматическую печать или проверку в типографии.

## Состояния и доступность

- Фильтры темы и страны применяются к обоим блокам вместе. «По следам башен»
  относится к «Замкам», «Беларусь у воды» — к «Разным местам».
- При отсутствии результатов блоки не показываются, остаётся общее сообщение.
  Каталог только с коротким дневником считается доступным каталогом.
- Mobile 390 px (также контроль 320 px): сначала текст и действия, затем
  реальные страницы. Поездки и состав идут одной колонкой. Desktop 1440 px:
  hero, состав и образец в две колонки, поездки в три.
- Новые подписи и accessibility names переведены RU/BE/UK/PL/EN; editorial
  названия и PDF остаются русскими с `lang=ru`. Контроль длинных подписей — PL.
- Ссылки обычные, клавиатурные; у повторяющихся действий доступное имя включает
  название места. Якорь переводит фокус к выбору поездки. Высота действий ≥44 px.
- Превью и скачивание используют только опубликованные URI точной редакции.
  PDF не загружается автоматически; чтение и скачивание — разные действия.

## Граница данных и приёмки

Тема сайта хранится в лёгком `mini-diaries/discovery.json`, отдельно от
immutable manifest. Каталог не импортирует редакционный `source.json`.
Контроль проверяет соответствие индекса опубликованным дневникам.

Source checks: Jest каталога/мини-дневников/переводов, lint изменённых файлов,
`npm run test:i18n`, `npm run guard:external-links`, независимое code review.
В `testing` после выката: mobile → desktop, оба дневника, фильтры «Замки» /
«Разные места» / «Польша», переход к выбору, карты/источники/страницы PDF,
скачивание гостем; screenshots и console/network. Сверить build SHA и хеши
двух PDF с manifest. Печатные PDF, права и прежние QR-проверки переиспользуются
при неизменных байтах; бумажная проба не заявляется. Native и backend
не затронуты, их отдельная runtime-приёмка не требуется.
