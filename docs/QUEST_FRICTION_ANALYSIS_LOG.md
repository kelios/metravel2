# Журнал разбора трения квестов

Последнее разобранное: 2026-08-23, progress_id 358 (прогон 2026-08-23)

Постоянный журнал агента `quest-friction-analyst`. Существует ради одного:
следующий прогон должен видеть границу и не разбирать заново то, что уже
разобрано. Строка пишется на **каждое** прохождение, которого коснулись, включая
`чисто` и `данных нет` — молчание о прохождении неотличимо от «не смотрели».

Как читать колонки:

- **вердикт** — ровно один из: `дефект` / `чисто` / `drop-off без попыток` /
  `данных нет`;
- **найдено** — механизм отказа одной строкой с доказательством: `step_id`,
  отклонённый нормализованный ввод, номер попытки;
- **исправлено** — что фактически применено: `PATCH answer_pattern` с DB-id
  шага, `тикет #NNNN`, `передано quest-editor` или `ничего`; предложенное, но не
  применённое — `предложено, не применено`;
- **ссылка** — запись в `docs/PROBLEM_MEMORY.md` либо id тикета.

Анонимные игроки строки `quest_progress` не создают: у них трение видно только в
`quest_answer_attempt`. Такое прохождение идентифицируется префиксом
`session_key` (8 символов) — email в базе Fernet-шифротекст и в журнал не идёт.

Граница следующего прогона берётся так:

```sql
SELECT id, quest_id, updated_at FROM quest_progress WHERE updated_at > '<дата из шапки>';
SELECT id, quest_id, step_key, verdict, occurred_at FROM quest_answer_attempt WHERE occurred_at > '<дата из шапки>';
```
