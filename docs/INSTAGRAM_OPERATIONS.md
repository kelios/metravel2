# Instagram @metravelby — операции аккаунта

Рабочие рецепты оператора `instagram-editor`: афиша, постановка в расписание, публикация через
Graph API, метрики и чистка подписчиков. Стратегия и правила контента —
`docs/INSTAGRAM_CONTENT_SPEC.md` (раздел 0 — роли и контракт пакета), календарь и таблицы
разборов — `docs/INSTAGRAM_PLAN.md`.

## 1. Режим «только по запросу» (владелец, 11.10.2026)

- Пакет с `qa.md` → `pass` выкладывается на афишу и показывается в чате (слайды или кадры,
  подпись, предлагаемые дата и время).
- В `scheduled_content` пакет ставится или публикуется только по команде владельца на
  конкретный день, после показа. «Да» на один пост не распространяется на следующий; месячных
  «да» нет. Задачи компьютера `instagram-publish-*` без такой команды не заводятся.
- Пакет без `qa.md` → `pass` не ставится и не публикуется.
- После постановки или публикации оператор пишет `published.md` в папку пакета: дата и время,
  путь (веб, телефон, Graph API), ссылка или «в расписании», счётчик подписи N/2200.

## 2. Афиша

Страница-превью для владельца: https://claude.ai/artifact/5dsyhxSYu1eHWKNU8rzWAW, исходник —
`.codex-temp/instagram/afisha-current.html`, вставка поста — `.codex-temp/instagram/afisha_put.py`
(контрольный лист слайдов + подпись).

Обновляет вызывающая сессия команды `/instagram` (оркестратор): после `pass` пакета — вставка
поста со статусом «готов, ждёт команды», после постановки — статус «в расписании <дата
время>», после публикации — «опубликован» со ссылкой. Ни planner, ни creator, ни QA афишу не
трогают.

## 3. Постановка в расписание

Graph API не умеет откладывать публикацию, поэтому у команды «поставь на <дата>» два пути.
Один пост двумя путями не ставится; если стоят оба — задача компьютера сдвигается на +5 минут и
сначала проверяет, что пост ещё не вышел.

### 3.1. Веб `scheduled_content` (предпочтительно — владелец видит и правит сама)

Проверено на ~20 перезаливках 06.10.2026:

- Claude in Chrome, вкладка из своей группы и ВИДИМАЯ на экране: при
  `document.visibilityState=hidden` видео не обрабатывается, итог «Не удалось запланировать
  публикацию». Перед загрузкой вывести вкладку вперёд (`osascript … set active tab index …
  activate`). Экран Mac заблокирован (`ioreg … IOConsoleLocked = true`) — веб недоступен, путь 3.3.
- Загрузку файлов владелец разрешает в чате сама; разрешение, переданное через субагента,
  блокируется проверкой безопасности. `file_upload` — до 10 МБ за вызов: ролик заранее сжать
  двухпроходным x264 до ~8,5 млн байт (1080×1920, AAC 48 кГц, faststart) в
  `posts/<пакет>/web/`.
- «Запланировать публикацию контента» → файл → «Далее» ×2 → подпись.
- Подпись: поле с текстом сначала очистить настоящими `cmd+a` + Backspace (вставка дописывает,
  а не заменяет). JS-paste (DataTransfer в contenteditable) может не сохраниться, хотя в
  редакторе видна: после вставки настоящий клик в поле, `cmd+End`, пробел, Backspace — и
  сверить счётчик «N/2 200» в окне с `len()` подписи (не 0). Escape не нажимать.
- Дата: клик по полю и выбор дня; кнопка месяца — `aria-label="Next month"`. Планировать можно
  не дальше ~29 дней вперёд. Время: клик в Hours, ввод 18, клик в Minutes, ввод 00.
- «Сохранить», «Запланировать», «Удалить запланированный контент», «Удалить» — настоящими
  кликами по ref из `find`, не JS-click. Ждать «Видео Reels запланировано» (~40–50 с).
- Поиск плитки по слову подписи опасен (подпись подборки может содержать название другого
  поста) — искать по началу текста и сверять дату в окне.
- После перезагрузки страницы JS-помощники пропадают; подписи держать в
  `localStorage['__caps']` на instagram.com.
- Не больше ~8 загрузок за заход: после ~32 загрузок подряд веб отвечает «User restricted from
  uploading, please try later» — повтор на следующий день.
- После каждой постановки — открыть пост на https://www.instagram.com/scheduled_content/ и
  сверить дату, время, подпись и число слайдов.

### 3.2. Телефон (adb)

«Публикация/Reels» → подпись → «Ещё» → «Запланировать эту публикацию» → дата/время → финальная
кнопка «График» (не «Поделиться»). Кириллицу через `adb input text` и Maestro не вставить:
открыть подпись страницей на Mac (`python3 -m http.server` + `adb reverse tcp:PORT tcp:PORT`), в
Chrome телефона нажать кнопку с `navigator.clipboard.writeText`, вернуться в Instagram и
вставить `input keycombination 113 50`; сверить длину текста. Планирование Reels на телефоне
роняет приложение.

### 3.3. Разовая задача компьютера (Graph API)

Задача `instagram-publish-<пост>` с `--publish-approved` и защитой от повтора через
`instagram-insights.js`; файл задачи прямо называет пост. Выходит, только если приложение
Claude открыто. Где смотреть: приложение Claude → боковая панель → «Запланированные».

## 4. Публикация через Graph API

```bash
node scripts/instagram-post.js --carousel <пакет>/slides --caption-file <пакет>/caption.txt
node scripts/instagram-post.js --image <файл.jpg> --caption-file <пакет>/caption.txt
node scripts/instagram-post.js --reel <пакет>/reel.mp4 --caption-file <пакет>/caption.txt [--trial manual]
```

Без `--publish-approved` — репетиция: медиа загружается, контейнер создаётся, в аккаунте ничего
не появляется; так проверяется каждый пост перед показом владельцу. `--publish-approved` — только
после её «да» на этот пост в чате. `--trial manual` — «Пробный период» (ролик видят только
неподписчики). Видео больше ~4 МБ скрипт отдаёт Meta по `video_url` через временный туннель —
штатно. Истории со стикерами API не умеет — они на владельце.

## 5. Метрики

Основной путь — Graph API, без браузера:

```bash
node scripts/instagram-insights.js                      # прошлая неделя пн–вс
node scripts/instagram-insights.js --since 2026-09-28 --until 2026-10-04
```

Скрипт печатает Markdown-сводку (просмотры, охват, доля подписчиков, взаимодействия, визиты,
клики, подписчики, медиана роликов, таблица публикаций с сохранениями и репостами, лидер ≥2×
медианы и аутсайдер, страны и города, пик онлайна). Сырые данные —
`.cache/instagram/insights-<since>_<until>.json`. Цифры — только отсюда; «нет данных» так и
писать. Токен в `.secrets/` не читать и не печатать. `Token rejected` — в отчёт «обнови токен
Instagram по `scripts/INSTAGRAM_SETUP.md`» и запасной путь.

Запасной путь — браузер (только при мёртвом токене; правила раздела 7):

1. `navigate` на `https://www.instagram.com/accounts/insights/?timeframe=7`, подождать 5–6 с,
   прочитать `document.querySelector('main').innerText`. Нулевые строки панель не рисует: нет
   «Нажатия на внешнюю ссылку» — 0, нет «Истории» в «По типу контента» — 0 %.
2. Просмотры роликов — блок «Топ контента по просмотрам»; вкладку Reels — только если роликов
   больше четырёх.
3. Лайки и комментарии: `fetch('/reel/<код>/')` → `meta name="description"` «N likes, M
   comments» — только для роликов недели.
4. Сохранения, репосты, страны и города в вебе нет — «не снято: токен».

## 6. Чистка подписчиков

Решение владельца 04.10.2026: чистит агент, постепенно; тех, на кого владелец подписана, не
трогать никогда. Лимиты далеко от порога ограничений (05.10.2026: «максимально безопасно»);
поднимать их может только владелец:

- одна порция в сутки; не больше 20 проверок профилей и 30 загрузок страниц за запуск;
- не больше 10 удалений за запуск;
- паузы разной длины: 6–12 с между открытиями профилей и постов, 30–60 с между удалениями, от
  3 с между прокрутками;
- в один день с недельным разбором чистку не делать;
- после сигнала Instagram (п. 7 ниже) — перерыв 7 суток: `cooldown_until` в файле состояния.

Порядок порции:

0. Файл состояния `.codex-temp/instagram/cleanup-state.json`: запуск с сегодняшней датой или не
   истёк `cooldown_until` — ничего не делать и сообщить.
1. Профиль → «Ваши подписки», прогрузить до конца, собрать имена; число должно совпасть с
   «подписками» в шапке. Не совпало — в этот запуск никого не удалять.
2. Кандидаты: выгрузка `.codex-temp/instagram/followers_export/` (официальный «Скачать
   информацию», JSON) — самые старые непроверенные; иначе диалог «Подписчики», до 4 страниц.
3. Проверка профиля — обычным открытием по одному: `navigate` на
   `https://www.instagram.com/<имя>/`, 3 с, `document.querySelector('header').innerText` —
   «N публикаций», «N подписчиков», «N подписок» (числа вида `3 459`, `7,8 тыс.`, `1,2 млн`).
   Синяя галочка — `header svg[aria-label*="одтвержд"]`. Трёх строк нет — «не прочитан», не
   удалять. `meta description` отстаёт — по нему не решать. Скриптовые `fetch` по профилям не
   использовать. Порядок: собрать кандидатов → пройти профили → вернуться на `/metravelby/` и
   открыть «Подписчики» для удалений.
4. Удалять только при одном из числовых условий: публикаций 0 и подписок ≥ 1500; подписок
   ≥ 3000 и подписчиков в 10 раз меньше подписок; публикаций 0, подписчиков ≤ 5 и подписок
   ≥ 500; последняя публикация старше 2 лет (06.10.2026). Остаются: живые молчащие люди,
   закрытые профили с обычными числами, местные бизнесы, блогеры, аккаунты из подписок
   владельца и с синей галочкой. Сомневаешься — не удаляешь.
   «2 года без публикаций» — только у открытого профиля с публикациями ≥ 1: первая плитка без
   значка закрепления (`svg[aria-label*="акреплен"]` внутри `a[href*="/p/"]` или
   `a[href*="/reel/"]`), открыть её `navigate` и прочитать `time[datetime]`. Дату не прочитал
   или все плитки закреплены — не удалять. Открытие поста — тоже загрузка страницы в общем
   потолке 30. Профили, проверенные без поля `last_post`, можно перепроверить только по дате,
   не дожидаясь 90 дней.
5. Удаление по одному: в диалоге «Подписчики» — имя в «Поиск», в выдаче ровно эта строка, в ней
   «Удалить», текст окна подтверждения содержит это имя, подтвердить; перечитать диалог — строки
   нет. Блокировку не использовать.
6. Состояние: проверенные имена с числами, вердиктом, датой (и `last_post`), удалённые. Уже
   проверенных не перепроверять раньше 90 дней. В план — строка в таблицу «Чистка подписчиков»:
   дата, проверено, удалено, подписчиков после.
7. Стоп без повторов при 429, «Подтвердите, что это вы», «Попробуйте позже», любом незнакомом
   окне: закрыть диалог, `cooldown_until` = сегодня + 7 суток, владельцу — что случилось и на
   каком действии. Отказ системы разрешений приложения — стоп без обхода, но без перерыва.

Списки в диалогах догружаются только после кадра: «`computer` screenshot со `scale: 0.1` →
прокрутка вниз по центру диалога → ожидание 3 с», повторять. Сторонние сервисы чистки запрещены.

## 7. Браузер — сессия владельца

Панель браузера открыта под аккаунтом @metravelby: любой клик — действие от её имени.

- Без спроса — только чтение: профиль, `/metravelby/reels/`, `accounts/insights/?timeframe=7|30`,
  страницы публикаций, `scheduled_content/`.
- Единственное изменение без отдельного «да» — удаление подписчика в режиме чистки по разделу 6.
- Без явного «да» владельца на конкретное действие запрещено: публиковать, ставить в расписание,
  удалять и архивировать публикации, лайкать, комментировать, отвечать в директ, подписываться
  и отписываться, блокировать, менять профиль и настройки. Выходить из аккаунта и вводить пароль
  — запрещено всегда.
- Закрытые `/api/v1/...` и `graphql` своими запросами не дёргать (04.10.2026 — 429). Не больше
  15 загрузок страниц за прогон (в чистке — до 30), пауза от 1,3 с. 429 или проверка — стоп.
- Скриншот — только если текст не читается; обычно хватает `document.body.innerText`.
