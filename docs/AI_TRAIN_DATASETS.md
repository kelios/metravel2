# metravel-llm v2: архитектура наборов данных и дешёвый цикл дообучения

Статус: план (владелец, 18.10.2026). Продолжение `LOCAL_AI_ASSISTANT_PLAN.md` § 8.
Исполнение — карточки на борде (см. § 7). Ограничения: без платных API, без
денег на железо, обучение на MacBook (M5 Pro, 24 ГБ), 130 ток/с ⇒ 1 млн токенов
≈ 2 часа одной эпохи. Бюджет времени, а не денег.

## 1. Что показали v0/v1 и что из этого следует

- Веса 4B + LoRA на 6 слоях учат **умения и устойчивые пары**: стиль ответов,
  формат списков, формулу отказа, «название → URL» (4/4).
- Веса **не учат множества и изменчивые факты**: «какие квесты в Гродно»,
  часы работы, цены. Это закрывает индекс (RAG) в #2460 — карточки в промпт,
  валидатор URL на выходе.
- Значит, цель дообучения v2 — не «знать всё о Беларуси и Польше», а
  **уметь**: понимать топонимы на пяти языках, говорить по-белорусски и
  по-польски в голосе сайта, описывать места по структурным данным, превращать
  вопрос в фильтр для карты и подбирать из подставленных карточек.

## 2. Принцип: источники → наборы → смеси → этапы

Один монолитный `build_dataset.py` заменяется на три уровня, каждый с
собственной папкой, лицензией и срезом оценки.

```
scripts/ai-train/
  sources/         # загрузчики: по одному на внешний источник, только чтение, кэш в data/sources/<name>/
  sets/            # сборщики примеров: site.py, toponyms.py, translations.py, wikivoyage.py, osm_intents.py
  mixes/           # yaml: какие наборы, с какими долями и потолками токенов
  build_mix.py     # собирает data/sft-<mix>/{train,valid,test}.jsonl + stats.json + manifest.json
  eval_prompts/    # по файлу на набор; eval.py считает балл по каждому срезу отдельно
~/metravel-ai/
  data/sources/<name>/   сырьё (дампы, выгрузки) + LICENSE + fetched_at
  data/sets/<name>/      train/valid/test.jsonl + stats.json
  data/sft-<mix>/        собранная смесь
```

Правила уровня «набор»:

- запись = `{"messages": […], "set": "toponyms", "key": "…", "id": "…", "kind": "…", "license": "CC0"}`
  (`sets/common.py`); в `messages` служебных полей нет, они нужны только
  статистике и сплиту, в смесь для mlx-lm уходит только `messages`;
- сплит train/valid/test — по хешу `key`, как сейчас; `key` строится от
  сущности (город, статья, объект), чтобы разные формулировки одного объекта
  не расползались между train и test;
- в целевых ответах нет внешних ссылок и упоминаний чужих сайтов — только
  знание; если источник требует указания (CC BY-SA), в ответе допустима
  фраза «по открытым данным», без URL;
- каждый набор проходит тот же скан на экстремистские источники, что тексты
  сайта (Беларусь-правило из § 8): берётся только тело статей, разделы
  «Примечания», «Ссылки», «Источники» отбрасываются до сборки;
- у набора есть свой `eval_prompts/<name>.jsonl` (10–15 вопросов) и порог
  входа в смесь: срез набора растёт, срез `site` не падает больше чем на
  1 вопрос из 40.

Правила уровня «смесь» (`mixes/<name>.yaml`):

```yaml
name: v2
split: {by: key, valid_share: 0.03, test_share: 0.02}   # key — сущность; id — пример (только регресс v1)
sets:
  toponyms:     {weight: 1.0, cap_tokens: 400000}
  translations: {weight: 1.0, cap_tokens: 500000}
  wikivoyage:   {weight: 0.7, cap_tokens: 1500000}
  osm_intents:  {weight: 1.0, cap_tokens: 300000}
  site:         {weight: 1.0, cap_tokens: 4000000, options: {chunk_chars: 2600, structured: true}}
stages:                                   # учебная программа, site — последним
  - {name: s1, sets: [toponyms, translations, wikivoyage, osm_intents]}
  - {name: s2, sets: [site]}
replay: 0.15   # доля примеров предыдущих этапов, подмешиваемая в каждый следующий
```

`weight` — множитель числа примеров (< 1 — подвыборка, > 1 — повтор train);
`cap_tokens` — потолок набора (≈ символы / 3) после случайной подвыборки по
seed; `stages` — этапы (каждый набор ровно в одном), у этапа своя папка
`data/sft-<смесь>/<этап>/`; `replay` — защита от забывания: когда учится `site`,
15 % потока — примеры train уже пройденных этапов. Рабочие смеси:
`mixes/v1.yaml` (регресс: бит в бит датасет v1), `mixes/site.yaml` (набор
`site` в редакции v2 отдельно), `mixes/v2.yaml` (полный цикл).

## 3. Этапы обучения: один адаптер, учебная программа, без слияний

Вариант с отдельными адаптерами «знания» и «сайт» отвергнут: MLX не
складывает два LoRA на инференсе, а слияние этапа в bf16-базу с повторной
квантизацией — это ещё 8 ГБ на диске и лишний час на каждый цикл. Дешевле:

1. **S1 «фундамент»** — `toponyms` + `translations` + `wikivoyage` +
   `osm_intents`, ≈ 2,7 млн токенов, одна эпоха ≈ 6 часов. Переобучается
   редко: раз в квартал или при добавлении источника.
2. **S2 «сайт»** — продолжение того же адаптера (`resume_adapter_file`) на
   `site` + replay 15 %, ≈ 4,5 млн токенов ≈ 9,5 часов. Переобучается, когда
   на сайте появляется заметно новый контент (десятки статей) — примерно раз
   в месяц, ночью.
3. **Оценка** — `eval.py` по всем срезам; в карточку идёт таблица по срезам, а
   не один общий балл. GGUF для `llama-server` (#2463) собирается из
   результата S2.

Итог цикла: ~16 часов машинного времени на полный прогон, ~10 часов на
ежемесячное обновление S2 с готового S1. Денег — 0.

## 4. Наборы: что, откуда, зачем, сколько

| набор | источник и лицензия | что учим | объём, токенов | труд |
| --- | --- | --- | --- | --- |
| `site` | API metravel.by (своё) | карточки, разделы, подборки, «название → URL», отказы; + структурные задачи: «точки маршрута → JSON», «карточка маршрута из текста» (2461 точка с координатами, 2572 шага квестов, 338 статей с км/высотами) | ≤ 4,0 млн | 1 день: распил текущего сборщика + 2 новых вида примеров |
| `toponyms` | Wikidata (CC0) через SPARQL: населённые пункты, памятники, парки Беларуси и Польши — названия ru/be/pl/en, тип, область/повят, координаты | сопоставление Гродно / Hrodna / Grodno / Гародня, «где находится X», «что это за объект», склонение и транслитерация в стиле сайта | ≤ 0,4 млн | 1–2 дня |
| `translations` | 117 квестов в 5 локалях (своё, прод-API) + 7480 i18n-строк сайта, кэш `sources/site_translations.py` | RU → BE/UK/PL/EN в голосе сайта; белорусский как рабочий язык ответов | ≤ 0,5 млн (весь набор ≈6,2 млн, доли видов — `kind_share`) | 0,5 дня |
| `wikivoyage` | Wikivoyage ru/pl/en (CC BY-SA): страницы областей и городов Беларуси и Польши, тело без ссылок | общие сведения «что посмотреть / как добраться / когда ехать» как фон для подбора; ответы помечаются как общие сведения, без URL | ≤ 1,5 млн | 1 день |
| `osm_intents` | синтетика по тегам OSM (ODbL, без публикации производной базы) + выборка POI двух стран | вопрос → структурированный фильтр для карты (категория, радиус, ограничения) и тег-набор → описание места | ≤ 0,3 млн | 2 дня |

Не делаем: Википедия целиком, расписания/цены/визы (устаревают — индекс),
полные перечни материалов (не выучиваются — индекс), любые платные или
закрытые источники.

Белорусская Википедия как монолингвальный корпус — отложено: дорого по
токенам, эффект на BE-ответах сначала измеряем на `translations`.

## 5. Оценка: по срезам, не одним числом

`eval.py` получает `--prompts-dir eval_prompts/` и выводит таблицу
«набор × (база, v1, v2)». Срез `site` остаётся прежними 40 вопросами. Новые
срезы: `toponyms` (15: варианты написания, «в какой области»), `translations`
(10: ответ на BE/PL/UK по русской карточке, `expect: lang` — язык по буквам,
наша ссылка, без зацикливания; трасянку буквы не ловят — ручная колонка), `wikivoyage` (10: общие вопросы по
городам, где у нас нет статей — ответ без выдуманных URL), `osm_intents`
(10: вопрос → JSON-фильтр, проверка схемой). Порог для GGUF: срез `site` не
хуже v1, каждый новый срез лучше базы.

## 6. Экономия: где именно дёшево

- Все источники бесплатные и кэшируются один раз в `data/sources/`;
  повторные сборки не ходят в сеть.
- Потолки токенов держат полный цикл в ~16 часов; ночные прогоны, машина днём
  свободна.
- S1 переобучается редко, ежемесячный цикл — только S2.
- Факты живут в индексе: нет гонки «переобучить, потому что изменились часы
  работы».
- Если данных станет заметно больше 10 млн токенов — отдельное решение
  владельца о смене базы на чистый трансформер (Qwen3-4B/8B): гибридные слои
  Qwen3.5 делают обучение здесь в 5–10 раз дороже и держат нас на 6 слоях.
