# Макет редактора описания поездки

Статус: норматив для задачи #1601 (`trips-plan-description-editor-authoring`).
Источник: запрос владельца от 2026-08-26; макет подготовлен 2026-08-27.
Экран: `/trips/plan/:id` → «Редактировать поездку» → «Описание».
Связанные контракты: #1494 (ссылки и выделение при чтении), #874 (форма поездки),
`docs/DESIGN_SYSTEM.md` (доступные действия и мобильные панели редактора).

## Обычный режим

```text
Описание                                    [⤢ На весь экран]
┌──────────────────────────────────────────────────────────┐
│ Обычный текст описания                                    │
│ …                                                        │
│ На desktop видно не меньше восьми строк                   │
│ …                                                        │
└──────────────────────────────────────────────────────────┘
```

Символ разворачивания на схеме обозначает Feather `maximize-2`, не буквенный
символ в интерфейсе. Действие использует существующий `IconButton`: цель
нажатия не меньше 44×44 px, доступное имя «Открыть описание на весь экран»,
подсказка на desktop. На mobile подпись можно скрыть, доступное имя остаётся.

Встроенное поле занимает ширину формы; оно не меняет значения остальных полей.
Пустое состояние показывает существующую подсказку описания поездки.

## Полноэкранный режим

```text
┌──────────────────────────────────────────────────────────┐
│ [Закрыть]           Описание                  [Готово]    │
│                     N символов                           │
├──────────────────────────────────────────────────────────┤
│                                                          │
│                  Редактируемый текст                      │
│                                                          │
│             Основная часть доступной высоты               │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ [Добавить ссылку]                                         │
│ Изменения сохранятся вместе с поездкой.                    │
└──────────────────────────────────────────────────────────┘
```

- Оболочка занимает доступный viewport и расположена выше шапки/дока страницы.
- Один черновик `editValues.description` используется в обоих режимах.
- «Закрыть», «Готово», Escape на web и системное закрытие модального окна
  возвращают в форму, сохраняя черновик; сами они не отправляют `PATCH`.
- Фокус возвращается в поле/кнопку открытия. Курсор и выделение сохраняются
  при смене режима; мышь и системные copy/cut/paste работают штатно.
- На mobile учитываются Safe Area и клавиатура: нижние действия доступны над
  клавиатурой, текст прокручивается внутри редактора, страница под ним не
  прокручивается. Все действия имеют цель нажатия не меньше 44 px.
- При сохранении общей формы редактор не допускает конкурирующего ввода.
  Ошибка API не стирает черновик; повтор выполняется общей кнопкой сохранения.
- «Отмена» общей формы сохраняет существующее поведение: возврат к серверным
  значениям без отправки изменений.

## Вставка ссылки

```text
Добавить ссылку
┌──────────────────────────────────────────────────────────┐
│ https://example.com/path                                 │
└──────────────────────────────────────────────────────────┘
Текст ошибки, если адрес не поддерживается.
                                    [Отмена] [Вставить]
```

Диалог запоминает позицию/выделение до смены фокуса. «Вставить» добавляет URL
в позицию курсора либо заменяет явно выделенный фрагмент. «Отмена» возвращает
фокус и ничего не меняет. Нормализация использует существующие helpers ссылок;
опасные схемы (`javascript:`, `data:`) отклоняются наблюдаемой ошибкой.

Хранение не меняется: `description: string`, обычный текст с URL. После общего
сохранения #1494 обеспечивает настоящие ссылки и блок «Ссылки». HTML, Markdown,
форматирование текста, изображения и встроенное видео в эту задачу не входят.

## Норматив проверки

| Состояние | Что проверить |
| --- | --- |
| Пустое поле | Подсказка и доступное открытие редактора |
| Длинное описание | 2 000+ символов, текст и выделение переживают смену режима |
| URL-диалог | Вставка по сохранённой позиции, отмена без изменений |
| Ошибочный URL | Опасная схема не вставляется; ошибка доступна скринридеру |
| Общие Save/Cancel | Сохраняются/отменяются все поля формы без потери описания |
| Ошибка API | Текст остаётся в черновике и доступен для повтора |
| Повторное открытие страницы | Обычная строка и ссылки восстанавливаются из API |

Обязательные поверхности: desktop web 1440×900 и mobile web 390×844, светлая и
тёмная темы. Проверить подписи RU/BE/UK/PL/EN, отсутствие горизонтального
переполнения, клавиатуру, фокус и размеры целей нажатия. Android/iOS получают
ту же иерархию; проверка на устройстве обязательна при изменении соответствующего
Modal/Back/IME-кода, а не автоматически из-за общего файла страницы.

Поведение оболочки сопоставляется с существующим полноэкранным редактором
`components/travel/ContentUpsertSection.tsx`. Сам HTML-редактор оттуда не
переносится без отдельного контракта формата данных.
