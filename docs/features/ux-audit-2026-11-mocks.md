# Макеты по итогам UX-аудита 01.11.2026

Статус: норматив для карточек, заведённых по `docs/UX_AUDIT_2026-11-01.md`.
Платформы: desktop web и mobile web обязательны для всех разделов; native —
там, где указано. Общие правила: существующие `components/ui`, токены темы,
иконки Feather, touch-target ≥ 44 px, текст через `@/i18n`.

## 1. Экран входа по намерению гостя (T-3, A-1, A-2)

Экраны: `/login?intent=…` и `/registration?intent=…` при переходе из «Добавить в
план», «Сохранить офлайн», «В избранное», «Подписаться», «Стать автором»; гостевые
`/profile`, `/favorites`.

```text
[← назад к маршруту]

  Сохраните «Гродно за 1 день»
  Аккаунт бесплатный: маршрут попадёт в ваш план,
  будет доступен офлайн и на телефоне.

  [  Продолжить с Google  ]   ← первичная на Android/desktop
  [  Продолжить с Apple   ]   ← первичная на iOS/Safari
  [  Продолжить с Facebook ]
  ———— или по email ————
  Email  [            ]
  Пароль [            ] (👁)
  [ Создать аккаунт ]           Уже есть аккаунт? Войти

  ☐ Я принимаю Пользовательское соглашение и Правила сообщества
```

Норматив:

- заголовок зависит от `intent`: `calendar` → «Сохраните «{title}» в план»,
  `offline` → «Сохраните «{title}» офлайн», `favorite` → «Добавьте «{title}» в
  «Хочу поехать»», `author` → «Расскажите о своей поездке», без intent →
  «Войдите или создайте аккаунт»; подзаголовок — 1–2 выгоды под intent;
- для гостя по умолчанию форма регистрации (кнопка «Создать аккаунт»), ссылка
  «Уже есть аккаунт? Войти» переключает в режим входа с заголовком «С
  возвращением»; режим входа по умолчанию — только если в браузере был вход
  раньше (локальный признак);
- соц-кнопки активны всегда; согласие подтверждается первым нажатием (чекбокс
  отмечается, под кнопками — строка «Нажимая, вы принимаете …»); отдельный
  обязательный чекбокс перед кнопками убирается;
- переход на экран — без белого кадра: экран рендерится с плейсхолдером формы
  (skeleton) до гидратации, не пустым `<main>`;
- после успеха — возврат на исходный URL и выполнение намерения (маршрут
  добавлен в план / сохранён офлайн) с тостом;
- гостевые `/profile` и `/favorites`: вместо «Войдите в аккаунт» + «Войти» —
  заголовок «Ваш профиль / «Хочу поехать»», три выгоды (прогресс квестов,
  избранное на карте и офлайн, свои маршруты и книга), кнопки «Создать аккаунт»
  (первичная) и «Войти».

Состояния: guest-first-visit, guest-returning, intent-known, intent-unknown,
social-error (текст ошибки под кнопкой), email-exists (подсказка «Войти»),
loading. Native: тот же экран в приложении (`components/auth/*`).

## 2. Карточки преимуществ в hero главной (H-1)

Экран: `/` desktop ≥ 768 px (на mobile карточки скрыты — так и остаётся).

```text
[✎ За 2 минуты        ]  → /search?quick=1 (быстрый подбор: чипы настроения + радиус)
[📖 Личная книга       ]  → /export (книга из своих поездок) — гостю: экран из п.1 с intent=book
[◎ Маршруты рядом     ]  → /map?radius=60
[⬇ GPS-треки          ]  → /search?gpx=1 (маршруты с треком) — после п.3; до него карточка убирается
```

Норматив: карточки — `Pressable`/ссылки с `accessibilityRole="link"`, hover и
focus-состояния как у чипов настроения; текст не меняется. Если целевой
функции ещё нет (GPS-треки до п.3) — карточка не показывается, а не висит
декоративно.

## 3. GPS-трек и навигатор на странице маршрута (T-1)

Экран: `/travels/<slug>`, блок действий под категориями, рядом с «Добавить в
план» и «Сохранить офлайн»; native — тот же блок.

```text
[ + Добавить в план ] [ ⬇ Офлайн ] [ 🧭 Открыть в навигаторе ▾ ] [ ⬇ GPX ]
                                    └ Google Maps / Яндекс Карты / Apple Maps / OsmAnd
```

Норматив:

- «Открыть в навигаторе» строится из точек маршрута (`points`), ссылки через
  helpers `utils/externalLinks.ts`; на mobile — bottom sheet с вариантами, на
  desktop — меню;
- «GPX» доступен, если у маршрута есть трек или ≥ 2 точек (генерируется из точек
  на клиенте: waypoints + порядок); без точек обе кнопки не показываются, а в
  hero главной обещание «GPS-треки» считается выполненным только если ≥ 50 %
  маршрутов Беларуси имеют кнопку;
- гостю обе кнопки доступны без входа.

Состояния: has-track, points-only, no-points (кнопок нет), loading.

## 4. Первый экран статьи на mobile (T-2)

Экран: `/travels/<slug>` при ширине < 768 px.

```text
┌──────────────────────────────┐
│ Гродно за 1 день: что        │  ← h1, 2 строки максимум, сразу под шапкой
│ посмотреть и как доехать     │
│ Юля · Октябрь 2019 · 1 день · Беларусь · ~18 мин     │
├──────────────────────────────┤
│ [ фото 1/10 ]                │  ← галерея, высота ≤ 56 vh
│ 01 из 10 · Коложская церковь │  ← подпись точки под фото, мелко
├──────────────────────────────┤
│ [Карта] [Описание] [Точки] … │
```

Норматив: h1 — первый видимый текст на первом экране; подпись точки галереи
визуально подчинена заголовку (меньший кегль, серый); карточка оглавления не
повторяет h1 — её заголовок «Содержание». Desktop-порядок не меняется.

Состояния: with-gallery, no-photos (h1 + мета + карта), loading (скелетон той же
геометрии — LIST-SKELETON-GEOMETRY-001).

## 5. Баннер установки приложения (AppInstallBar)

Экран: mobile web, все страницы.

Норматив: баннер показывается не при входе, а после «сигнала намерения»: старт
квеста, «Сохранить офлайн», второй просмотр маршрута за сессию, ≥ 50 % скролла
статьи; текст привязан к сигналу («Квест удобнее проходить в приложении:
офлайн-карта и подсказки»); «Закрыть» молчит 14 дней; одна кнопка с магазином по
платформе. На первом экране главной баннера нет.

Состояния: hidden, shown-after-signal, dismissed (14 дней), clicked.

## 6. Первая точка квеста — мягкий старт

Экран: `/quests/<id>/<alias>` после «Начать квест», точка 1.

```text
Точка 1 из 9 · Задания 0/6
[ фото/иконка точки ]
Коложская церковь — XII век          ОБЯЗАТЕЛЬНАЯ
… легенда …
Задание: …
[ ответ ______________ ]  [Проверить]
💡 Подсказка открыта сразу: «Ответ — на табличке у входа».
Неверно → «Не совсем. Посмотрите на … Попробовать ещё раз · Открыть ответ и идти дальше»
```

Норматив: на первой обязательной точке подсказка видна сразу; после первого
неверного ответа — мягкий текст без красного и кнопка «Открыть ответ и идти
дальше» (без штрафа по прогрессу, с пометкой в телеметрии `revealed`); на
остальных точках поведение прежнее. Строгие числовые/словарные проверки — по
#2853.

Состояния: idle, hint-open, wrong-soft, revealed, correct.
