# Фича: ассистент сайта (`/assistant`)

Карточка #2460, план — `docs/LOCAL_AI_ASSISTANT_PLAN.md` § 8. Статус 18.10.2026:
клиентская часть под фича-флагом, локально включена, на проде выключена
(решение владельца 18.10.2026; сервер под модель — #2457/#2458).

## TL;DR

Посетитель задаёт вопрос, ассистент отвечает коротко и только по материалам
сайта, каждая рекомендация — со ссылкой на нашу статью или квест. Текст пишет
собственная модель `metravel-llm` (Qwen3.5-4B + LoRA на корпусе сайта, #2462)
через OpenAI-совместимый `llama-server`. Экран ходит к ней через серверный
`POST /ai/ask` службы metravel-assist (провайдер `ask`, #2884): подбор по
индексу, лимиты и блок «не по теме» на IP — на сервере; прямой `llama-server`
(провайдер `llamacpp`) остаётся для локальной отладки модели. Ссылки модели не
доверяем: их даёт подбор карточек, а страж вырезает из ответа любой адрес вне
найденных карточек.

## Фича-флаг

| переменная | dev (`.env.dev`) | prod (`.env.prod`) |
| --- | --- | --- |
| `EXPO_PUBLIC_AI_ASSISTANT` | `1` | отсутствует (выключено) |
| `EXPO_PUBLIC_AI_ASSISTANT_PROVIDER` | пусто = `ask` (`llamacpp` — прямой `llama-server`) | — |
| `EXPO_PUBLIC_AI_ASSISTANT_URL` | `http://127.0.0.1:8080` (нужен только `llamacpp`) | — |

Чтение — только `utils/aiAssistantConfig.ts` (`isAiAssistantEnabled`,
`getAiAssistantProvider`, `getAiAssistantBaseUrl`); адрес службы для `ask` —
`utils/aiPicksConfig.ts` (`getAiPicksBaseUrl`: same-origin на web, origin API на
native, `EXPO_PUBLIC_AI_PICKS_URL` переопределяет). При выключенном флаге:

- роут `app/(tabs)/assistant.tsx` отдаёт `NotFoundContent` (noindex), экран
  не грузится (React.lazy-чанк);
- пункта в `HEADER_NAV_ITEMS` нет (меню шапки, мобильное меню, меню аккаунта);
- кнопки «Спросить ассистента» на `/search` нет;
- запросов к `/ai/ask` и `llama-server` нет ни на одной платформе.

Диагностика конфигурации — `utils/runtimeConfigContract.js`:
`AI_ASSISTANT_PROVIDER_INVALID` (значение не `ask|llamacpp`),
`AI_ASSISTANT_URL_INVALID` (`llamacpp` без адреса модели),
`AI_ASSISTANT_LOCAL_URL_IN_PRODUCTION` (локальный адрес модели в
production-сборке — ошибка), для `ask` явный `EXPO_PUBLIC_AI_PICKS_URL` проходит
проверки `AI_PICKS_URL_INVALID` / `AI_PICKS_LOCAL_URL_IN_PRODUCTION` (один раз,
даже когда блоки подбора выключены), `AI_ASSISTANT_ENABLED_IN_PRODUCTION`
(предупреждение).

## Точки входа

- `app/(tabs)/assistant.tsx` — роут; зарегистрирован в `app/(tabs)/_layout.tsx`
  (`HIDDEN`) и в `APP_ROUTE_ROOTS` (`utils/siteLinks.ts`);
- `constants/headerNavigation.ts` — пункт «Ассистент» под флагом;
- `app/(tabs)/search.tsx` — кнопка «Спросить ассистента» под флагом;
- контекстный вход со страницы статьи и квеста (#2897):
  `components/assistant/AskAssistantButton.tsx` — «Спросить про этот маршрут /
  квест» (Feather `message-circle`, `UIButton` soft/sm, 44/48 px) на странице
  статьи рядом с «Добавить в план» (`components/travel/CTASection.tsx`, обе ветки —
  гостю тоже) и в футере стартовой карточки квеста (`QuestTrustBar`, проп
  `questNumericId` из `QuestWizard`). Кнопка живёт только под флагом (без него
  `null`, страница не делает запросов к `/ai/*`) и ведёт `router.push` на
  `/assistant?source=travel:816` / `quest:<id>` (`buildAssistantSourceHref` в
  `utils/aiAssistantConfig.ts` — `api/aiAssist` в сборку без флага не попадает,
  #2738). Роут читает `?source=` через `useLocalSearchParams` и отдаёт экрану
  строкой; без флага `/assistant?source=…` — та же «страница не найдена».

### Источник страницы (`source`, #2897)

- Разбор и формат — `api/aiAssist/sourceRef.ts` (`parseSourceRef`,
  `pinSourceFirst`; модуль общий с сервером, без `@/`-импортов): `type` —
  `travel|quest`, `id` — числовой PK (как в индексе и `/ai/similar`), мусор → вход
  без источника.
- `useAssistantChat({ source })`: карточка страницы грузится из каталога
  (`loadSourceCard` в `retrieval.ts`: статья — `queryKeys.travel(id)` + `fetchTravel`,
  квест — компактный каталог по `id`) и отдаётся экрану как `sourceCard`; пустое
  состояние показывает её заголовок (`ask.sourceEmptyDescription`) и примеры под
  контекст (`ask.sourceExample1..3`: «Сколько времени займёт?», «Подойдёт ли с
  детьми?», «Что рядом?»).
- На КАЖДОМ ходу диалога карточка стоит первой в списке карточек промпта, подбор
  добавляет остальные без дубля (`pinSourceFirst`): с закреплённой страницей
  карточек всего `AI_SOURCES_LIMIT_PINNED` = 3 (не 8 — проба 07.11.2026 на v4: среди
  восьми карточек «Сколько дней занимает поездка?» для статьи 816 отвечалась по
  соседней статье), а если подбор нашёл ту же страницу, первым идёт его фрагмент,
  подобранный под вопрос, а не карточка-заглушка:
  провайдер `ask` шлёт `source {type, id}` в теле `/ai/ask`, и первой её ставит
  сервер по индексу; провайдер `llamacpp` ждёт загрузку карточки и закрепляет её
  на клиенте. До первого самостоятельного вопроса заголовок карточки — опора
  уточнений («А что там рядом?» ищется вместе с названием статьи). Материала нет
  (404 в каталоге, нет в индексе) — ход идёт без закреплённой карточки.

- `AssistantAnswerText.tsx` — markdown-lite рендер ответа без зависимостей:

  дисклеймер.
- `useAssistantChat.ts` — состояние диалога и пайплайн одного вопроса.

## Провайдеры (#2884)

`useAssistantChat` держит один вопрос за раз и два пути за одним состоянием хода
(`AssistantTurn`); экран не знает, какой выбран.

- `ask` (по умолчанию) — `api/aiAssist/askProvider.ts` (`HttpAskClient`): один
  `POST {служба}/ai/ask {q, locale, history}`, `history` — завершённые пары
  (`buildHistoryFromTurns`, ≤ 3). События SSE → ход: `sources` → карточки и
  статус `streaming` (`remaining` → «осталось вопросов»), `text` → накопленный
  текст после серверного стража (не дельта), `done {status}` → `done`
  (`removed_links`, `usage`, `remaining`) / `off_topic` (`offtopic_warning` с
  номером `strikes`; `model_refusal` — без номера) / `no_sources` /
  `unavailable` / `error`. Отказы до потока: `429 limit` → вопрос снимается с
  ленты, счётчик 0 и подпись лимита; `429 offtopic_blocked` → ход с подписью
  блока, композер закрыт (блок держит сервер: обновление страницы его не
  снимает — следующий вопрос снова получит `429`); `429 busy` / `503 busy` →
  `busy` с `Retry-After`; `503 generator_unavailable`, сеть, таймаут 120 с,
  обрыв потока без `done` → `unavailable` + «Повторить». Лимит и блок с
  сервера держатся на экране до `Retry-After`; после срока следующий вопрос
  снова уходит на сервер (экран в приложении может жить дольше суток). Фильтр
  тем, подбор, лимит, журнал спроса и хранилище устройства на клиенте не
  используются; до первого ответа счётчик на экране не показывается.
- `llamacpp` — прежний клиентский пайплайн: `topicGate` → `retrieval` →
  `prompt` → `generator` (`LlamaCppGenerator`) → `linkGuard`, лимит и счётчик
  «не по теме» в AsyncStorage (`limits.ts`), журнал в `demandLog.ts`. Нужен
  `EXPO_PUBLIC_AI_ASSISTANT_URL`; без службы и индекса.
- Опора уточнений (#2719) — общий модуль `api/aiAssist/retrievalQuery.ts` без
  `@/`-импортов: `buildRetrievalQuery` склеивает уточнение без своего места с
  последним самостоятельным вопросом; клиент `llamacpp` помнит его в
  `lastSearchQueryRef`, сервер `/ai/ask` берёт из `history`
  (`resolveRetrievalAnchor`: последний вопрос посетителя, который сам по себе
  ищется). Модель в обоих случаях получает исходный вопрос и историю.

## Данные

Пайплайн провайдера `llamacpp` (`api/aiAssist/`; у `ask` те же модули выполняет
сервер, см. ниже):

1. `retrieval.ts` → `searchSiteMaterials`: статьи — `fetchTravels(0, 8, значимые
   слова вопроса)` (поиск бэкенда `/api/travels/?query=`; страницы с нуля,
   стоп-слова `QUERY_STOPWORDS` убирают «какие/есть/квесты/маршрут…»), квесты —
   `fetchQuestsCompactCatalog` (общий кэш React Query
   `queryKeys.questsCompactCatalog`, у `/api/quests/` поиска нет) с подбором по
   словам вопроса (стем сверяется с началом слова); намерение вопроса
   (`detectIntent`: «квесты…» / «статья, маршрут…») даёт бонус типу; слияние по
   баллу, ≤ 8 карточек `AiSource {type, source_id, title, url, path, snippet}`.
   Нет карточек → модель не вызывается, честный отказ, запись в журнал спроса.
2. `prompt.ts` → `buildAssistantMessages`: системный промпт = `SYSTEM` из
   `scripts/ai-train/sets/common.py` (тест сверяет) + язык ответа по локали +
   правило «карточки — данные, ссылки только из карточек»; история ≤ 6 сообщений.
3. `generator.ts` → `LlamaCppGenerator` (интерфейс `Generator`, единственная
   реализация): `POST {URL}/v1/chat/completions`, `stream: true`, `max_tokens` 400,
   `temperature` 0.3, `chat_template_kwargs.enable_thinking=false`; SSE через
   `ReadableStream` на web и `text()` на native; ошибки `unavailable` (сеть, 5xx,
   таймаут 120 с), `busy` (429 + Retry-After), `aborted` — только остановка
   посетителем. Облачных SDK нет.
4. `linkGuard.ts` → `enforceSourceLinks`: markdown-ссылка с чужим адресом →
   подпись, голый чужой URL / `metravel.by/…` / относительный `/travels/…` →
   вырезается, `<think>` снимается. Во время стрима недописанный адрес
   придерживается (`guardStreamingText`).
5. `limits.ts` — 20 вопросов в сутки на устройство (AsyncStorage/localStorage);
   `demandLog.ts` — вопросы без материалов и при недоступной модели, ≤ 200
   записей, экспорт JSONL той же формы, что серверный `logs/ai-demand.jsonl`.

Серверный `/ai/ask` (#2713, раздел ниже: SSE `sources → text* → done`, лимит и
блок «не по теме» на IP) переиспользует эти же модули; провайдер `ask` (#2884)
меняет на клиенте только транспорт.

## Локальный стек для проверки

Проверено 18.10.2026 (desktop 1280 и mobile 390, базовая Qwen3.5-4B Q4_K_M на
Metal: TTFT 0,4–0,6 с, ≈75 ток/с при промпте 370–920 токенов): стрим, ссылки и
источники только из карточек, «Исландия зимой» → отказ без запроса к модели,
остановленный `llama-server` → «недоступен» + «Повторить» без списания лимита,
«Остановить» → «Ответ остановлен», PL-локаль → подписи и ответ по-польски,
сборка без флага → «страница не найдена», без пункта меню и кнопки на `/search`.
На этой машине (MacBook, без docker и `~/Sites`) локального бэкенда нет: API
читается через `node .claude/prod-server.js 4622 dist https://metravel.by`
(read-only GET каталога), конфиги «Assistant 2460 Web 8081» / «… FlagOff Web 8082»
в `.claude/launch.json`. Клики по `Pressable` в панели браузера Claude не
срабатывают (ни у ассистента, ни у пилюли языка) — для QA кнопки нажимаются
DOM-`click()` через `javascript_tool`, якоря `<a>` кликаются обычно.

1. `llama-server -m ~/metravel-ai/gguf/metravel-llm-v1-Q4_K_M.gguf --port 8080 -c 8192 --parallel 2 --jinja`
   (brew `llama.cpp`, GGUF нашей модели — экспорт #2463, `scripts/ai-train/README.md`);
   `-c` — общий KV-бюджет на все слоты: при `-c 4096 --parallel 2` слот получает
   2048 токенов и промпт с 8 карточками и историей (~3 тыс.) отбивается `400`.
   Пока на том же Mac идёт `mlx_lm lora` — только CPU (`-ngl 0`).
2. Бэкенд `localhost:8000`, фронт `npx expo start --web` с `.env.dev`.
3. Проверка: `/assistant` desktop 1280 и mobile 390 — вопрос с материалами
   (ответ со ссылками только на карточки), «Исландия зимой» (отказ без ссылок),
   остановленный `llama-server` (состояние «недоступен», «Повторить»), флаг
   выключен (`/assistant` → «страница не найдена», пункта меню нет).
4. Встроенный веб-UI `llama-server` (`localhost:8080` в браузере) — не проверка
   модели. Он шлёт голый вопрос: без `SYSTEM`, без блока «Материалы сайта:»,
   с включённым thinking, temperature 0.8 и без `presence_penalty` 1.5. Модель
   обучена собирать ответ из переданных карточек (v3, #2712), без них она
   зацикливается, уходит в украинский и выдумывает ссылки (проба 25.10.2026:
   «Краків - Краков - Краков…» на вопрос о Кракове, тот же вопрос через
   `/assistant` — три материала со ссылками). Проверять только через `/assistant`
   или `npm run ai:assistant:eval`; для пробы по API — промпт с карточками из
   `scripts/ai-train/eval_prompts/rag_answers.jsonl` с параметрами `generator.ts`
   (temperature 0.3, presence_penalty 1.5, `enable_thinking: false`).

## Вопросы не по теме (#2711)

`api/aiAssist/topicGate.ts` → `classifyQuestion` стоит до подбора: вопрос не о
путешествиях не уходит ни в поиск, ни в модель и не списывает дневной лимит.

- Жёсткие темы — попытки переписать инструкции («игнорируй…», «системный промпт»,
  «ты теперь…») и программирование/взлом: отказ всегда.
- Мягкие темы — рецепты, политика, медицина, финансы, учёба, болтовня: отказ,
  если в вопросе нет признака поездки («поход», «маршрут», «с детьми», «виза»,
  место после предлога: «в Кракове», «w Gdańsku»). «Какую кашу взять в поход» и
  «аптечка для поездки с детьми» — вопросы по теме.
- Признаки — на RU/BE/UK/PL/EN; фраза отказа — `aiAssistStatic:ask.offTopic`
  (5 локалей), в RU она же `OFFTOPIC_REPLY_RU` в `prompt.ts`.
- Второй рубеж — модель: системный промпт велит ответить на чужую тему этой
  фразой; `isModelOffTopicReply` узнаёт её («ассистент metravel.by» без ссылок на
  карточки), ход становится `off_topic` без счётчика: модель ошибается и на
  вопросах о поездке («travel hacks», просьба о чужой ссылке — замер #2710), и
  блок за её ошибку получил бы посетитель. Просьба о чужой ссылке внутри вопроса о
  поездке по промпту — вопрос о поездке: ответ по карточкам без чужих ссылок.
- Решение второго рубежа одно для экрана и службы — `judgeModelReply`
  (`topicGate.ts`, #3216): отказ модели на вопрос с признаком поездки
  (`hasTravelSignal` запроса подбора, то есть вопроса вместе с опорой уточнения)
  — это `no_sources` («материала пока нет») и строка `no_sources` в журнале
  спроса, а не `off_topic`. Отказ модели вероятностный: на «Какую кашу взять с
  собой в поход?» с одной посторонней карточкой v4 отказывала 3 раза из 3, v6 — 2
  из 3 (замер 09.11.2026). Без признака поездки отказ остаётся `off_topic`.
- Лимит рекомендаций (`AI_MAX_RECOMMENDATIONS` = 3, `policy.ts`, #3216): при 4–6
  карточках одного города модель перечисляет все, поэтому генератор по опции
  `maxRecommendations` закрывает стрим на четвёртой (`findRecommendationOverflowCut`
  рядом с остановкой цикла `findRepetitionLoopCut`): пункт списка после трёх
  рекомендаций или строка, все новые адреса которой сверх лимита. Опцию задаёт
  только ответ ассистента (экран и `/ai/ask`); помощник автора и фильтр карты
  получают списки целиком. Остальные карточки посетитель видит в источниках.
- Эскалация (`limits.ts`, ключ `metravel.aiAssist.offtopic.v1`): 1-й и 2-й вопрос
  не по теме за день — отказ + «вопрос не по теме (N из 3)»; 3-й — запись
  `offtopic_blocked` в журнал спроса и блок поля ввода до полуночи по времени
  устройства. Вопросы по теме счётчик не сбрасывают. Клиентский блок обходится
  очисткой хранилища — настоящий держит сервер `/ai/ask` (ниже, #2713). Числа
  общие — `api/aiAssist/policy.ts`.
- Страж ссылок оставляет голое «metravel.by» без пути (название сайта во фразе
  отказа и в речи модели) и режет только `metravel.by/<путь>`.

## Серверный `/ai/ask` (#2713)

`POST /ai/ask {q, locale?, history?}` в сервисе metravel-assist
(`scripts/ai-assist/ask.ts`, образ `services/ai-assist/`) — тот же пайплайн на
сервере: фильтр тем → лимиты на IP → подбор по индексу (гибрид `/ai/search`,
≤ 8 карточек `AiSource`) → промпт → `metravel-llm` (`AI_LLM_URL`) → страж ссылок.
Фильтр, промпт, страж и клиент модели — те же модули `api/aiAssist/*`, что у
экрана: сервер и клиент не расходятся. Ответ — SSE `sources → text* → done`
(`text` несёт накопленный текст после стража, не дельту: страж может убрать уже
показанный чужой адрес).

- Счётчики на IP за календарный день по Europe/Minsk (`AI_ASSIST_DAY_TZ`) в redis
  (`REDIS_URL`, ключи `ai-ask:v1:{quota|offtopic}:<день>:<ip>` с TTL до полуночи);
  без redis и при его ошибке — память процесса. IP — `X-Real-IP`, затем последний
  адрес `X-Forwarded-For` (его дописывает nginx; начало заголовка присылает сам
  посетитель), `AI_ASSIST_TRUST_PROXY=0` — только сокет.
- Вопрос не по теме: 1-й и 2-й — `200` SSE `sources: []` + `done {status: off_topic,
  reason: offtopic_warning, strikes, strikes_to_block}`; 3-й — строка
  `offtopic_blocked` в `logs/ai-demand.jsonl` (`AI_DEMAND_LOG`) и
  `429 {error: offtopic_blocked, retry_after_sec, strikes}` + `Retry-After` до полуночи;
  до полуночи тот же IP получает `429` на любой вопрос — очистка хранилища
  клиента и прямой запрос блок не снимают. Отказ самой модели — `done {status:
  off_topic, reason: model_refusal}`, в счётчик не идёт (как на клиенте); на
  вопрос с признаком поездки — `done {status: no_sources}` (`judgeModelReply`, #3216).
- Дневной лимит 20 вопросов на IP (`AI_ASK_DAILY_LIMIT`): вопросы не по теме его
  не тратят; сверх лимита — `429 {error: limit}` + `Retry-After` до полуночи;
  занятая или упавшая модель и уход посетителя до первого токена возвращают
  списанный вопрос; обрыв после начала ответа — нет (иначе лимит обходился бы
  чтением `text` без `done`).
- Модель: `AI_LLM_URL` не задан или не ответил до первого токена → `503
  generator_unavailable` + `Retry-After: 30` (журнал `generator_unavailable`);
  очередь к модели занята дольше `AI_ASSIST_ASK_QUEUE_TIMEOUT_MS` → `429 busy`;
  обрыв посреди ответа → `done {status: unavailable}`. Источники уходят с первым
  токеном, чтобы отказ модели до него оставался честным 503.
- Проверено 25.10.2026 локально (`node --experimental-strip-types`, индекс q8, без
  `AI_LLM_URL`): «как готовить кашу» ×2 → 200 с предупреждениями 1 и 2, ×3 → 429
  `Retry-After` до полуночи и строка в журнале; «квесты в Гродно» с того же IP →
  429, с другого — 503. Тесты — `__tests__/scripts/ai-assist/ask.test.ts`.
- Экран ходит сюда провайдером `ask` (#2884, раздел «Провайдеры»); на проде
  ассистент включится после выкладки контейнеров (#2457): compose должен дать
  сервису `AI_LLM_URL`, `REDIS_URL` и том под `logs/`, не публиковать 8787
  наружу, а `location /ai/` — ставить `X-Real-IP $remote_addr` и `proxy_buffering off`.
- Опора уточнений (#2719) применяется и здесь: подбор идёт по
  `buildRetrievalQuery(q, resolveRetrievalAnchor(history))` из общего
  `api/aiAssist/retrievalQuery.ts`, модель получает исходный `q`.
- Источник страницы (#2897): необязательное поле `source {type: travel|quest, id}`
  (только объект; `id` — положительное целое) — карточка `type:id` из индекса
  (`lookupSource` в `app.ts`: фрагмент локали запроса, если квест на ней есть,
  иначе первый; `score: 0`) ставится первой в `sources` и в промпт на каждом ходу,
  подбор добавляет остальные без дубля (`pinSourceFirst`): всего не больше
  `AI_SOURCES_LIMIT_PINNED` = 3, и если подбор сам нашёл эту страницу, первой идёт
  его карточка (фрагмент под вопрос, `score` подбора) вместо заглушки; без
  закреплённой страницы лимит прежний, `AI_SOURCES_LIMIT` = 8. Без самостоятельного
  вопроса в `history` заголовок карточки — опора уточнений. Формат ответа и SSE не
  меняются. Кривой `source` → `400 bad_request` (лимит не списывается); материала
  нет в индексе (опубликован после сборки) → ход без закреплённой карточки.

## Контур оценки (#2710)

Для оценки **самой модели** на неизменных карточках есть небольшой набор из
10 пар «запрос → пример хорошего ответа»: `npm run ai:assistant:quality`
(Node 22 с type stripping). Приоритеты: следование запросу → полезность и
точность → язык и естественность. Обязательные факты и ссылки проверяются
автоматически; смысл и три отдельных балла подтверждает судья. Формулировка
эталона не требуется дословно. Команды, ограничения и формат —
`scripts/ai-assistant-eval/QUALITY.md`. Этот прогон не измеряет поиск или UI.

`npm run ai:assistant:eval` задаёт вопросы из `scripts/ai-assistant-eval/cases.jsonl`
через сам экран `/assistant` (Playwright): подбор, промпт, модель и страж работают
без подмен; перехватывается только запрос к модели — он пересылается в
`--model-url` (по умолчанию `http://127.0.0.1:8080`) и сохраняется с карточками и
сырым ответом до стража. Наборы вопросов: по теме, диалоги, языки RU/BE/UK/PL/EN,
по теме «на грани», не по теме, попытки сломать, эскалация.

- Автопроверки (`checks.mjs`): нужные карточки нашлись, отказ на чужую тему и блок
  на третьей, ссылки только из карточек, нет цикла и обрыва по `max_tokens`, нет
  шаблона карточки статьи («Страна: / Когда: / Точки маршрута:»), ≤ 3
  рекомендаций, пункты со ссылками, ≤ 1200 знаков, язык ответа. Число
  рекомендаций считается дважды: `too_many` (слой модели) — по сырому ответу,
  `too_many_shown` (слой стража, #3216) — по показанному тексту после остановки
  генератора; метрика `shownRecommendations` — в `results.jsonl`.
- У провала — слой: подбор / фильтр тем / промпт / страж / модель /
  инфраструктура; основной — первый по этому порядку (плохие карточки объясняют
  плохой ответ).
- Судья — агент по рубрике `scripts/ai-assistant-eval/JUDGE.md`: читает
  `judge-task.md` папки прогона, пишет `judge.jsonl`; `--report <папка>`
  пересчитывает проверки текущим `checks.mjs` и подмешивает вердикты.
- Metro отдаёт рабочее дерево с горячей перезагрузкой: правка кода ассистента
  посреди прогона портит замер. «До» меряется на отдельном Metro из worktree
  нужного коммита (конфиг «Assistant Eval Base Web 8085», `--base
  http://localhost:8085 --tree .codex-temp/wt-eval-base`), «после» — на своём
  дереве; модель сравнивается подменой `--model-url`.
- Цикл: прогон → судья → разбор по слоям → правка в своём слое (подбор, фильтр,
  промпт, страж) или пример в набор обучения (`rag_answers`, `offtopic`,
  `docs/AI_TRAIN_DATASETS.md`) → доучивание → повторный прогон тем же набором.

## Известные боли и TODO

- Подбор для не-RU локали слаб: `/api/travels/?query=` ищет по русскому
  контенту, а слова вопроса на PL/EN/BE/UK в него не попадают; квесты матчатся по
  переведённым названиям. «Co zobaczyć w Polsce w trzy dni?» дал один квест по
  Бресту (по «trzy dni»). Лечится смысловым индексом (#2454/#2456) или
  переводом ключевых слов на RU перед поиском.
- Стоп-слова подбора — только русские (`QUERY_STOPWORDS` в `retrieval.ts`).

- Боли подбора по словам выше касаются только провайдера `llamacpp`; у `ask`
  подбор идёт по смысловому индексу службы.
- Лимит и журнал на устройстве — только у `llamacpp`; у `ask` — на IP на сервере.
- Оценочный набор 40 вопросов на GGUF v1 (#2463, `eval.py --server`): без карточек
  в промпте модель проходит 9/40 как и MLX-адаптер (ссылки по городу/стране выдумывает),
  с карточками — все URL из списка (Гродно 8/8); поэтому подбор карточек обязателен.
- На CPU `llama-server` обрабатывает промпт медленно (~46 ток/с при 4 потоках на M5 Pro,
  генерация ~26 ток/с): 8 карточек + история ≈ 3 тыс. токенов → TTFT около минуты;
  для прод-сервера без GPU промпт нужно держать коротким (≤ 500–800 токенов) или
  ограничить число карточек — числа в `scripts/ai-train/README.md` → «Экспорт в GGUF».
