# Фича: ассистент сайта (`/assistant`)

Карточка #2460, план — `docs/LOCAL_AI_ASSISTANT_PLAN.md` § 8. Статус 18.10.2026:
клиентская часть под фича-флагом, локально включена, на проде выключена
(решение владельца 18.10.2026; сервер под модель — #2457/#2458).

## TL;DR

Посетитель задаёт вопрос, ассистент отвечает коротко и только по материалам
сайта, каждая рекомендация — со ссылкой на нашу статью или квест. Текст пишет
собственная модель `metravel-llm` (Qwen3.5-4B + LoRA на корпусе сайта, #2462)
через OpenAI-совместимый `llama-server`. Экран ходит к ней через серверный
`POST /ai/ask` службы metravel-assist (провайдер `ask`, #2884): подбор по
индексу, лимиты и блок «не по теме» на IP — на сервере; прямой `llama-server`
(провайдер `llamacpp`) остаётся для локальной отладки модели. Ссылки модели не
доверяем: их даёт подбор карточек, а страж вырезает из ответа любой адрес вне
найденных карточек.

## Фича-флаг

| переменная | dev (`.env.dev`) | prod (`.env.prod`) |
| --- | --- | --- |
| `EXPO_PUBLIC_AI_ASSISTANT` | `1` | отсутствует (выключено) |
| `EXPO_PUBLIC_AI_ASSISTANT_PROVIDER` | пусто = `ask` (`llamacpp` — прямой `llama-server`) | — |
| `EXPO_PUBLIC_AI_ASSISTANT_URL` | `http://127.0.0.1:8080` (нужен только `llamacpp`) | — |

Чтение — только `utils/aiAssistantConfig.ts` (`isAiAssistantEnabled`,
`getAiAssistantProvider`, `getAiAssistantBaseUrl`); адрес службы для `ask` —
`utils/aiPicksConfig.ts` (`getAiPicksBaseUrl`: same-origin на web, origin API на
native, `EXPO_PUBLIC_AI_PICKS_URL` переопределяет). При выключенном флаге:

- роут `app/(tabs)/assistant.tsx` отдаёт `NotFoundContent` (noindex), экран
  не грузится (React.lazy-чанк);
- пункта в `HEADER_NAV_ITEMS` нет (меню шапки, мобильное меню, меню аккаунта);
- кнопки «Спросить ассистента» на `/search` нет;
- запросов к `/ai/ask` и `llama-server` нет ни на одной платформе.

Диагностика конфигурации — `utils/runtimeConfigContract.js`:
`AI_ASSISTANT_PROVIDER_INVALID` (значение не `ask|llamacpp`),
`AI_ASSISTANT_URL_INVALID` (`llamacpp` без адреса модели),
`AI_ASSISTANT_LOCAL_URL_IN_PRODUCTION` (локальный адрес модели в
production-сборке — ошибка), для `ask` явный `EXPO_PUBLIC_AI_PICKS_URL` проходит
проверки `AI_PICKS_URL_INVALID` / `AI_PICKS_LOCAL_URL_IN_PRODUCTION` (один раз,
даже когда блоки подбора выключены), `AI_ASSISTANT_ENABLED_IN_PRODUCTION`
(предупреждение).

### Источник страницы (`source`, #2897)

- Разбор и формат — `api/aiAssist/sourceRef.ts` (`parseSourceRef`,
  `pinSourceFirst`; модуль общий с сервером, без `@/`-импортов): `type` —
  `travel|quest`, `id` — числовой PK (как в индексе и `/ai/similar`), мусор → вход
  без источника.
- `useAssistantChat({ source })`: карточка страницы грузится из каталога
  (`loadSourceCard` в `retrieval.ts`: статья — `queryKeys.travel(id)` + `fetchTravel`,
  квест — компактный каталог по `id`) и отдаётся экрану как `sourceCard`; пустое
  состояние показывает её заголовок (`ask.sourceEmptyDescription`) и примеры под
  контекст (`ask.sourceExample1..3`: «Сколько времени займёт?», «Подойдёт ли с
  детьми?», «Что рядом?»).
- На КАЖДОМ ходу диалога карточка стоит первой в списке карточек промпта, подбор
  добавляет остальные без дубля (`pinSourceFirst`): с закреплённой страницей
  карточек всего `AI_SOURCES_LIMIT_PINNED` = 3 (не 8 — проба 07.11.2026 на v4: среди
  восьми карточек «Сколько дней занимает поездка?» для статьи 816 отвечалась по
  соседней статье), а если подбор нашёл ту же страницу, первым идёт его фрагмент,
  подобранный под вопрос, а не карточка-заглушка:
  провайдер `ask` шлёт `source {type, id}` в теле `/ai/ask`, и первой её ставит
  сервер по индексу; провайдер `llamacpp` ждёт загрузку карточки и закрепляет её
  на клиенте. До первого самостоятельного вопроса заголовок карточки — опора
  уточнений («А что там рядом?» ищется вместе с названием статьи). Материала нет
  (404 в каталоге, нет в индексе) — ход идёт без закреплённой карточки.

#### Режим страницы (#3290)

Вопрос со страницы статьи или квеста отвечается по тексту этой страницы. Раньше страницу в
подсказке представлял один фрагмент, а рядом стояли две карточки общего подбора: на «Сколько дней
занимает поездка и что взять с собой?» со страницы о рождественских ярмарках Польши v7 отвечала
«около 6 дней» из статьи про Люксембург и добавляла совет про Италию с собакой (проба пути службы
11.11.2026, p20 и p21).

- **Служба** (`scripts/ai-assist/page.ts`, `pageCard` в `app.ts`): тем же вектором запроса, что у
  общего подбора, ищет внутри фрагментов страницы и берёт `AI_PAGE_FRAGMENTS` = 3 лучших; каждый —
  окно до `AI_PAGE_FRAGMENT_CHARS` = 400 знаков, которое начинается с предложения со словами
  вопроса (`focusFragment`): фрагмент индекса — до 800 знаков, и ответ часто стоит в его середине.
  Полный текст фрагмента читается с диска по номеру строки `chunks.jsonl` (`readText` в
  `index.ts`, файл открыт один раз; в памяти по-прежнему только сниппеты). Карточка страницы — одна:
  строка фактов (#3287) и фрагменты через « … » в порядке текста страницы.
- **Событие `sources`**: у карточек необязательное поле `group` (`AiSourceGroup` в
  `api/aiAssist/types.ts`: `page`, `nearby`; `match` — для отбора по условиям #3289). Страница —
  `page`, найденное общим подбором — `nearby` (не больше `AI_PAGE_NEARBY_LIMIT` = 3, без самой
  страницы; `pageSources` в `sourceRef.ts`). Экран рисует их отдельной группой «Ещё по теме»
  (`aiAssistStatic:ask.nearbyTitle`, RU/BE/UK/PL/EN) под «Источниками».
- **Подсказка** (`prompt.ts`): `selectPromptSources` оставляет в ней только карточку страницы,
  к системному сообщению отдельной фразой дописано `PAGE_MODE_RULE_RU` — «отвечай только по её
  фрагментам; если ответа в них нет, скажи, что на этой странице этого нет». Текст
  `ASSISTANT_SYSTEM_PROMPT` и подсказка обычного режима не меняются. Этой фразы модель в обучении
  не видела: слушается ли её v7 или v9, показывает только живая проба.
- **Ссылки ответа** — только на страницу: адреса соседних материалов в подсказке не было, страж
  ссылок его убирает.
- **Выход из режима** (`leavesPage`): вопрос называет место, которого нет ни в названии, ни в
  городе, ни в тексте страницы («А что посмотреть в Гданьске?» со страницы о Гродно) — ход идёт
  общим подбором, как обычный вопрос (полный отбор по месту и условиям, до восьми карточек).
  Карточка страницы остаётся в событии `sources` последней, группой `nearby`, и в подсказку модели
  не идёт (`leftPageSources`, `sourceRef.ts`). Это отступление от пункта 4 постановки #3290
  («страница остаётся первой карточкой»): на живой модели v7 страница, стоявшая в подсказке
  первой, называлась ответом на вопрос о другом месте — «Вот главное в Гданьске: Гродно за 1
  день…» (lv70). Замер 11.11.2026, три вопроса × три повтора: страница первой — 3 верных ответа
  из 9, последней — 7, вне подсказки — 9. Праздник и сервис после предлога («на Новый год», «из
  Instagram») местом не считаются и режим не снимают. Место,
  которое на странице есть («парковка у ярмарки в Гданьске» в статье о ярмарках Польши), режим не
  снимает. Название на другом письме («w Gdańsku» при русском тексте статьи) на странице не
  узнаётся — такой вопрос тоже уходит в общий подбор.
- **Контур оценки**: ответ по странице без ссылки на неё («В карточке указано 13 точек, около 180
  мин.») верен — посетитель уже на этой странице. Для хода с одной карточкой подсказки `group:
  page` проверка `no_links` даёт предупреждение, а не провал (`checks.mjs`); в прогоне 86 живых
  вопросов только она снимала девять верных ответов.
- **Размер подсказки** (замер 11.11.2026 без модели на копии индекса, 20 вопросов со страниц из
  `cases.live.jsonl`): медиана 856 токенов, максимум 1101 (белорусский квест); 19 подсказок из
  20 — одна карточка, выход из режима — три (до доправки; теперь это общий подбор без страницы).
- **Провайдер `llamacpp` с режимом страницы несовместим**: у клиента нет ни индекса фрагментов,
  ни вектора запроса, а общий модуль без них дал бы второй, лексический подбор внутри текста
  статьи. Клиентский путь остаётся на поведении #2897 — карточка страницы первой среди трёх.
  Режим страницы есть только у провайдера `ask`.
- Набор живых вопросов (#3286) получил группу вопросов со страниц: p20, p21 и ещё десять
  (`lv65`–`lv76`: статья и квест, место на странице, выход из режима, пять языков).

### Голосовой ввод вопроса (#3351)

Рядом с кнопкой «Спросить» стоит кнопка микрофона (`assistant-voice`): нажатие начинает
диктовку, повторное — останавливает. Распознаёт речь сам браузер (Web Speech API) через
общий хук `hooks/useWebSpeechDictation.ts` — тот же, что в редакторе статьи; звук и текст
через службу `/ai/ask` не проходят, запросов приложения не добавляется.

- **Где есть кнопка.** Только web и только в браузере с `SpeechRecognition` (Chrome, Edge,
  Safari). В Firefox и в приложениях Android и iPhone её нет — навсегда выключенный
  контрол не показываем; в приложениях диктует системная клавиатура (нативный ввод —
  #3352). Кнопка появляется после монтирования (`available` в `useAssistantVoiceInput`):
  экран есть в статическом HTML, а на сервере API распознавания нет — без этого разметка
  разошлась бы при гидрации.
- **Что происходит с текстом.** Итоговая фраза дописывается к черновику через пробел,
  общая длина — не больше `MAX_QUESTION_LENGTH` (500): лишнее обрезается, запись
  останавливается. Вопрос сам не отправляется — человек видит текст, правит ошибку
  распознавания и нажимает «Спросить». Запись идёт одной фразой (`continuous: false`),
  язык — язык интерфейса (`getFormatLocale()`).
- **Когда кнопка недоступна.** Пока ассистент отвечает, при блоке «не по теме» и при
  исчерпанном лимите (`voiceDisabled` в `AssistantComposer`). Запись при этом
  останавливается, а фраза, которую браузер отдаёт уже после остановки, в очищенный
  черновик не попадает.
- **Строка состояния** (`assistant-voice-status`, над счётчиком вопросов): «Слушаю…» с
  промежуточным текстом либо причина сбоя. Код ошибки браузера переводит в подпись
  `toNotice`: `not-allowed`, `service-not-allowed`, `audio-capture` → `ask.voiceDenied`;
  `language-not-supported` → `ask.voiceLangUnsupported`; `network` → `ask.voiceNetwork`;
  тишина (`no-speech`) и отмена подписи не дают. Хук диктовки отдаёт код полем
  `errorCode`; прежнее поле `error` (сырой текст) оставлено для редактора статьи.
- **Ключи** `aiAssistStatic:ask.voiceStart|voiceStop|voiceListening|voiceDenied|
  voiceLangUnsupported|voiceNetwork`, RU/BE/UK/PL/EN.
- **Ограничения.** `UIButton` не передаёт `aria-pressed`: состояние записи видно по
  подписи («Продиктовать вопрос» / «Остановить запись»), варианту `danger` и значку.
  Белорусский язык распознавания зависит от браузера: при отказе показывается
  `ask.voiceLangUnsupported`. Живой голос автоматика не проверяет — тесты и e2e
  (`e2e/ai-assistant-voice.spec.ts`) работают на подменённом распознавателе.

## Провайдеры (#2884)

`useAssistantChat` держит один вопрос за раз и два пути за одним состоянием хода
(`AssistantTurn`); экран не знает, какой выбран.

- `ask` (по умолчанию) — `api/aiAssist/askProvider.ts` (`HttpAskClient`): один
  `POST {служба}/ai/ask {q, locale, history}`, `history` — завершённые пары
  (`buildHistoryFromTurns`, ≤ 3). События SSE → ход: `sources` → карточки и
  статус `streaming` (`remaining` → «осталось вопросов»), `text` → накопленный
  текст после серверного стража (не дельта), `done {status}` → `done`
  (`removed_links`, `usage`, `remaining`; с `fallback: true` — запасной ответ
  стража содержания, #3291; с `fallback: true` и `reason: no_material` — пустая
  подсказка, #3345: ход `noMaterial`, «материала нет») / `off_topic` (`offtopic_warning` с
  номером `strikes`; `model_refusal` — без номера) / `no_sources` /
  `unavailable` / `error`. Отказы до потока: `429 limit` → вопрос снимается с
  ленты, счётчик 0 и подпись лимита; `429 offtopic_blocked` → ход с подписью
  блока, композер закрыт (блок держит сервер: обновление страницы его не
  снимает — следующий вопрос снова получит `429`); `429 busy` / `503 busy` →
  `busy` с `Retry-After`; `503 generator_unavailable`, сеть, таймаут 120 с,
  обрыв потока без `done` → `unavailable` + «Повторить». Лимит и блок с
  сервера держатся на экране до `Retry-After`; после срока следующий вопрос
  снова уходит на сервер (экран в приложении может жить дольше суток). Фильтр
  тем, подбор, лимит, журнал спроса и хранилище устройства на клиенте не
  используются; до первого ответа счётчик на экране не показывается.
- `llamacpp` — прежний клиентский пайплайн: `topicGate` → `retrieval` →
  `prompt` → `generator` (`LlamaCppGenerator`) → `linkGuard`, лимит и счётчик
  «не по теме» в AsyncStorage (`limits.ts`), журнал в `demandLog.ts`. Нужен
  `EXPO_PUBLIC_AI_ASSISTANT_URL`; без службы и индекса.
- Опора уточнений (#2719) — общий модуль `api/aiAssist/retrievalQuery.ts` без
  `@/`-импортов: `buildRetrievalQuery` склеивает уточнение без своего места с
  последним самостоятельным вопросом; клиент `llamacpp` помнит его в
  `lastSearchQueryRef`, сервер `/ai/ask` берёт из `history`
  (`resolveRetrievalAnchor`: последний вопрос посетителя, который сам по себе
  ищется). Модель в обоих случаях получает исходный вопрос и историю.

## Данные

   баллу, ≤ 8 карточек `AiSource {type, source_id, title, url, path, snippet}`.
   Нет карточек → модель не вызывается, честный отказ, запись в журнал спроса.
   Фрагмент карточки квеста начинается с вида квеста по тегам каталога (#3276,
   `questAudience.ts`): «Детский городской квест по городу Несвиж (Беларусь).
   Возраст: 8–10 лет. Со взрослым. Точек: 9. Длительность: 90 мин. Сложность:
   лёгкий» (`kids`, `age-<от>-<до>`, `adult-required`), «Семейный городской
   квест…» (`family` без `kids`), остальные — «Городской квест…». При вопросе о
   детях (`asksAboutChildren`, RU/BE/UK/PL/EN) детский, затем семейный квест
   города из вопроса получает балл выше любого совпадения по словам и встаёт
   первым: в подсказку модели уходят первые карточки подбора. Просьба о статье
   («статья про Несвиж с детьми») квесты не поднимает. Тем же правилом карточку
   строит слепок обучения (`quest_card(audience=True)` в
   `scripts/ai-train/sets/rag_answers.py`), тест сверяет строки. Квесты для
   подростков (`teens`, `age-11-14` без `kids` и `family`) пометки не получают.
   Саму строку собирает общий построитель фактов (#3287, раздел «Факты источника
   в карточке»): у квеста к ней дописано «Можно с собакой», у статьи после
   страны и города идут число дней и месяцы.
2. `prompt.ts` → `buildAssistantMessages`: системный промпт = `SYSTEM` из
   `scripts/ai-train/sets/common.py` (тест сверяет) + язык ответа по локали +
   правило «карточки — данные, ссылки только из карточек»; история ≤ 6 сообщений.
3. `generator.ts` → `LlamaCppGenerator` (интерфейс `Generator`, единственная
   реализация): `POST {URL}/v1/chat/completions`, `stream: true`, `max_tokens` 400,
   `temperature` 0.3, `chat_template_kwargs.enable_thinking=false`; SSE через
   `ReadableStream` на web и `text()` на native; ошибки `unavailable` (сеть, 5xx,
   таймаут 120 с), `busy` (429 + Retry-After), `aborted` — только остановка
   посетителем. Облачных SDK нет.
4. `linkGuard.ts` → `enforceSourceLinks`: markdown-ссылка с чужим адресом →
   подпись, голый чужой URL / `metravel.by/…` / относительный `/travels/…` →
   вырезается, `<think>` снимается; подпись ссылки с адресом карточки заменяется
   названием карточки (#3291). Во время стрима недописанный адрес придерживается
   (`guardStreamingText`). Готовый ответ проходит `answerGuard.ts` → `guardAnswer`:
   пояснение пункта от чужой карточки, число без опоры и пустой ответ — раздел
   «Страж содержания ответа».
5. `limits.ts` — 20 вопросов в сутки на устройство (AsyncStorage/localStorage);
   `demandLog.ts` — вопросы без материалов и при недоступной модели, ≤ 200
   записей, экспорт JSONL той же формы, что серверный `logs/ai-demand.jsonl`.

Серверный `/ai/ask` (#2713, раздел ниже: SSE `sources → text* → done`, лимит и
блок «не по теме» на IP) переиспользует эти же модули; провайдер `ask` (#2884)
меняет на клиенте только транспорт.

### Отбор карточек подсказки по месту вопроса (#3315)

До подсказки доходят только карточки места из вопроса: `matchPlaceSources`
(`api/aiAssist/promptPlace.ts`) — первый шаг цепочки `arrangeSources` (#3289,
раздел ниже), которую вызывает `selectPromptSources`, — одно
место для экрана, службы `/ai/ask` и набора quality. Место вопроса — слова
запроса подбора (вопрос вместе с опорой уточнения), совпавшие с городом или
страной найденных карточек (`AiSource.place`: у квеста — город каталога на всех
написаниях и страна, у статьи — страна). Правила:

- назван город и у него есть карточки → в подсказке только они; иначе то же
  для страны; иначе подсказка прежняя (модель предлагает ближайшее);
- квест относится к городу по каталогу, статья — по названию и фрагменту, в том
  числе по прилагательному («Несвижский замок»); написания одного города берутся
  из карточки квеста («w Grodnie» находит статью «Гродно за выходные»);
- слово вопроса называет место с заглавной буквы или после предлога места
  («квесты в гродно»); название до четырёх букв («Мир», «Лида») — только с
  заглавной: «приезжаем глубокой ночью» городом Глубокое не становится;
- беглая гласная учитывается («Навагрудак» — «па Навагрудку»), исключение («кроме
  Минска») и закреплённая страница (#2897) отбор отключают;
- маршрут «из X в Y» (#3277): место вопроса — куда едут. Название, стоящее только
  после предлога «откуда» («из», «з», «від», «z», «od», «from»), местом не
  считается, если в вопросе названо и другое место — города или страны: «Квест
  из Минска в Заславль», «з Мінска да Нясвіжа», «из Минска в Польшу». Названо
  одно место отправления («Куда поехать из Минска на выходные?») — оно и есть
  место. «З» и «z» — ещё и «с кем»: слово после них считается местом
  отправления, только когда называет известное место («з дзецьмі», «z psem» — нет);
- числительное местом не бывает (#3345, lv23): «километров на сорок-пятьдесят» и «квест на сорок
  минут» после предлога совпадали с городом Сороки — слово-числительное в любом падеже на пяти
  языках место не называет (`NUMERAL_RE`);
- город назван, а в подборе его карточек нет (#3277, только служба): кандидатами
  встают до трёх квестов этого города из каталога индекса (`pool`) и те найденные
  карточки, которые к городу относятся — по тому же правилу места и по упоминанию
  где-либо в тексте источника. Каталог знает написание города на всех локалях:
  на «Як даехаць з Мінска да Нясвіжа…» (lv21) смысловой подбор отдавал маршруты
  из Минска и квест Заславля, в подсказку шли они, а модель называла «Маршруты
  выходного дня из Минска»; теперь первой стоит карточка квеста Несвижа. Так же
  ищется место назначения, когда подбор нашёл только город отправления (квесты
  Минска на «з Мінска да Нясвіжа», `namesOnlyOrigin`); нет его в каталоге — местом
  остаётся город отправления. Уровень
  страны так не добирается: квестов страны десятки, и первые три случайны. По всему
  каталогу город узнаётся строго (`strict`): только по слову с заглавной буквы —
  названий сотни, и слово со строчной после предлога совпало бы с чьим-нибудь
  городом — и только как место, куда едут: «недалеко от Минска» квестов Минска не
  просит. В замере r1 без этого на «веломаршрут… километров на сорок-пятьдесят»
  (lv23) в подсказку шёл квест Сорок вместо семи веломаршрутов;
- лимит `AI_PROMPT_SOURCES_LIMIT` считается после отбора; список источников
  посетителя и страж ссылок работают с полным подбором, поле `place` в поток
  `/ai/ask` не уходит. Карточки не того места в списке источников стоят
  группой `nearby` — «Ещё по теме» (#3289).

Подбор экрана (`searchSiteMaterials`, `api/aiAssist/retrieval.ts`) теми же
правилами #3277 не теряет квест ещё до отбора:

- короткое название в другом падеже — «в Лиду», «в Ригу», «в Прагу», «do Rygi» —
  находит «Лида», «Рига», «Прага»: у слова из четырёх-пяти букв с гласной на
  конце основа — без неё, а совпадает слово карточки не длиннее самого слова
  вопроса («лиду» — «лида», «лиде», но не «лидер» и не «Лидский»). Раньше слова
  до пяти букв сверялись только началом целиком, и подбор был пуст. Бэкенду
  такое слово уходит в именительном падеже («лида», «рига»): основа из трёх
  букв для подстрочного поиска слишком коротка;
- слово города отправления маршрута «из X в Y» квест не выбирает
  (`routeOriginMatcher`): «Квест из Минска в Заславль» отдавал восемь квестов
  Минска, квест Заславля в подбор не попадал;
- польское уточнение «A …» — уточнение, когда за ним идёт польское служебное
  слово («A coś dla dziecka?», «A z psem?», «A który krótszy?»;
  `isFollowUpQuestion`, общий модуль экрана и службы). Раньше узнавалось только
  «A co …», и «A coś dla dziecka?» после «Co zobaczyć we Wrocławiu?» искалось
  без города — детский квест Вроцлава терялся. Английский артикль «A quest for
  kids» уточнением не становится.

Проба на каталоге прода (343 квеста, локаль `pl`, статьи отключены; 12.11.2026):
до правки «в Лиду», «в Прагу» — пустой подбор, «в Ригу» — квесты Кракова, «из
Минска в Заславль» — восемь квестов Минска, «A coś dla dziecka?» — квест Минска;
после — квесты названного города во всех пяти случаях.

Замер на сохранённых подсказках приёмки v7/v8 от 11.11.2026 (136 ходов с ответом
модели, 104 с известным местом): подсказок, где рядом с карточками места стоят
чужие, было 75, после отбора остаётся 9; в пределах 1–5 карточек — 91 ход из 136
(было 43). Не закрыто: место без квеста среди найденного (только статьи: «у
Кракові» без квеста Кракова в подборе), регион («в Татрах») и нерегулярное
склонение («w Białymstoku»). Скрипт — `.codex-temp/v9-diagnosis/replay_place.mts`.

### Условия вопроса и порядок карточек (#3289)

Вопрос с условием («с собакой под Варшавой», «зимой на один день», «с ребёнком
девяти лет на час», «без машины») проверяется по фактам карточек до модели.
Порядок карточек задаёт одна цепочка `arrangeSources`
(`api/aiAssist/sourceSelection.ts`) — общая для экрана, службы `/ai/ask` и набора
quality:

1. **Место** — `matchPlaceSources` (#3315): у названного места есть карточки →
   дальше идут только они.
2. **Условия** — `parseConditions` и `judgeCard`
   (`api/aiAssist/questionConditions.ts`), словари RU/BE/UK/PL/EN:

   | условие | примеры | факт карточки (#3287) |
   | --- | --- | --- |
   | дети и возраст | «с детьми», «ребёнку 9 лет», «a nine-year-old» | `audience`, `age` квеста |
   | с собакой | «с собакой», «z psem», «dog-friendly» | `pet_friendly` квеста |
   | без машины | «без машины», «pociągiem», «by public transport» | `transports` статьи |
   | сезон или месяц | «зимой», «у травні», «w lutym», «in summer» | `months` статьи |
   | сколько есть времени | «до часа», «на полдня», «на один день», «на выходные», «на 3 дня» | `duration_min` квеста, `number_days` статьи, категория «Тур выходного дня» |
   | вид материала | «квесты…», «статья, маршрут…» (`detectIntent`) | тип карточки |
   | лёгкий маршрут | «для новичков», «несложная тропа», «dla początkujących», «easy hike» | `difficulty` квеста; у статьи факта нет — признак в её названии или фрагменте («лёгкая тропа», «сложность: лёгкая») |

   Условие сверяется только с фактом, который у карточки есть: без факта карточка
   не совпала и не нарушила (**неизвестно ≠ нарушено**) и остаётся на своём месте
   подбора. Совпавшее условие даёт балл — карточка, прошедшая больше условий,
   встаёт первой; детский квест весит больше семейного. Нарушение без числа
   («без собаки» по каталогу, другой месяц, только на машине, не тот вид
   материала) опускает карточку. **Явное нарушение числового условия** —
   длительность больше названной, число дней больше названного, возраст вне
   диапазона квеста — убирает карточку из подсказки, если после этого остаётся
   карточка, не нарушающая условий; иначе карточки остаются как «ближайшее из
   того, что есть» («Квесты в Гродно до часа» при квестах от 90 минут). «До часа»
   и «не больше» — граница строгая, «на час» — с запасом 25 %.
3. **Превосходная степень** — `detectSuperlative` (#3287): «самый короткий детский
   квест в Минске» выбирается среди квестов места, прошедших больше всего
   условий. Служба отдаёт кандидатами все квесты индекса. В подсказку идут только
   карточки-ответы — до трёх первых по сортировке, остальной подбор уходит в
   `nearby`. При восьми карточках живая модель v7 на «Самый короткий квест в
   Минске» называла статью, стоявшую последней (0 из 3 в пробе координатора).
   Замер 11.11.2026, шесть формулировок (RU, BE, UK, число точек, уточнение) × три
   повтора, ответ называет первую по сортировке карточку: восемь карточек — 16 из
   18, без карточек другого вида — 17, три первых — 18, строка «самый короткий среди
   найденных» у первой карточки — 15. Если квесты места взяты из каталога, а подбор
   их не нашёл, строки «материала о месте нет» в подсказке нет.

Подъём детских квестов города (#3276, прежний `liftForChildren`) и превосходная
степень службы (#3287, прежний `liftBySuperlative`) — теперь шаги этой цепочки;
клиентскому подбору остаётся `childrenRank`: он выбирает восемь карточек из всего
каталога.

**Группы.** Карточки, прошедшие отбор, получают `group: 'match'`, остальные —
не того места и нарушившие числовое условие — `group: 'nearby'`. В подсказку
модели `nearby` не идёт; экран показывает их под ответом тем же блоком «Ещё по
теме», что в режиме страницы (`aiAssistStatic:ask.nearbyTitle`,
`components/screens/assistant/AssistantTurnCard.tsx`). Если отделять нечего,
поля `group` у карточек нет.

**Строка «Почему подходит».** Совпавшие условия уходят третьей строкой карточки
подсказки: `Почему подходит: детский, 8–10 лет, 75 мин` (`AiSource.why`,
`formatSourcesBlock`). Слова — те же русские, что в строке фактов.

**Детский квест без детей в вопросе.** Квест с аудиторией «дети» по каталогу не считается ответом на
вопрос с личным условием («с собакой», «на час», «зимой», «без машины», «для новичков»), в котором
детей нет: такая карточка (`unfit`) в подсказку не идёт никогда — даже если больше ответить нечем.
«Где погулять с собакой недалеко от Варшавы?» получал детский квест Варшавы, потому что он «можно
с собакой»; теперь подсказка без него, а найденное стоит под ответом группой «Ещё по теме». Вопрос с
детьми и вопрос без условий («Какие квесты есть в Гродно?») детские квесты показывают как раньше.

**Пустая подсказка (#3345).** Если после отбора по месту и условиям в подсказке не осталось ни одной
карточки, служба модель не вызывает: отвечать ей не по чему. На строку «Материалы сайта: ничего не
найдено» живая v7 называла выдуманную статью о Варшаве — страж вырезал её адрес в 3 ответах из 3
(приёмка 12.11.2026, p05). Ход закрывается честным «материала нет»: поток `sources → text('') →
done {status: done, fallback: true, reason: no_material}`, экран показывает строку
`aiAssistStatic:ask.noSources` («На сайте пока нет материалов по этому вопросу…») с кнопкой каталога
и найденное рядом; вопрос пишется в журнал спроса (`no_sources`), дневной лимит списан, генератор для
такого хода не нужен. Причина `no_material` (`ASK_NO_MATERIAL_REASON`, `api/aiAssist/policy.ts`)
отличает ход от запасного ответа стража, где модель ответила, а страж ответ отбраковал: там причины
нет и экран показывает `ask.fallbackAnswer`. Совместимость: `fallback` остаётся и у пустой подсказки,
поэтому клиент, который причины не знает (сборка приложения до правки), показывает прежнюю запасную
фразу; новых строк интерфейса нет. Событие `trace` контура оценки несёт пустые `prompt_sources` и
`model_called: false`. Экран с провайдером `llamacpp` делает то же (`useAssistantChat.ts`): ход `done`
с признаком `noMaterial`, найденное — «Ещё по теме».

**Сокращение подсказки.** Если условия выделили немного карточек — строку «Почему подходит» несут
не больше трёх, — в подсказку идут они с добором до трёх первыми по порядку, остальное уходит в
`nearby`. Это предел размера подсказки, а не отсев: карточка без факта условий не нарушала. При
семи карточках живая модель v7 называла те, в названии которых стоит место вопроса, а не выделенную
условием: «Закопане: лёгкая тропа» на «маршрут в Татрах для новичков без машины» — 0 из 3 (и со
строкой «Почему подходит», и с местом в ней); одна выделенная карточка — 3 из 3, три первых — 2 из
3, выделенная и две первые — 3 из 3 (замер 12.11.2026). Служба выключает сокращение переменной
`AI_ASSIST_PROMPT_FOCUS=0`.

**Признак «материала о месте нет».** Вопрос называет место после предлога места
(`namedDestinations`, `topicGate.ts`), а ни одна найденная карточка его не
упоминает — между карточками и вопросом встаёт строка `NO_PLACE_NOTE_RU`. Служба
ищет упоминание по всему тексту источника в индексе (фрагмент карточки — 120
знаков), экран — по названию и фрагменту. Условия тогда порядок не меняют. Место,
которого отбор #3315 не узнал (регион «в Татрах», город без квеста), служба отбирает
по упоминанию во всём тексте источника: не упоминающие его карточки уходят в `nearby`
(маршрут по Люксембургу на вопрос про Татры). Экран по названию и фрагменту карточки

### Факты источника в карточке (#3287)

Карточка, которую видит модель, начинается со строки проверяемых фактов
каталога. Строку собирает один модуль — `api/aiAssist/sourceFacts.ts` — для
экрана (`questToSource`, `travelToSource`), службы `/ai/ask` (`toSource` в
`scripts/ai-assist/app.ts`) и слепка обучения (`quest_card(facts=True)`,
`travel_facts_line(facts=True)` в `scripts/ai-train/sets/rag_answers.py`); тест
`__tests__/api/aiAssist/sourceFacts.test.ts` сверяет строку TS и Python для
квеста и для статьи.

- Квест: «Детский городской квест по городу Несвиж (Беларусь). Возраст: 8–10
  лет. Со взрослым. Точек: 9. Длительность: 90 мин. Сложность: лёгкий. Можно с
  собакой». Статья: «Польша. Дней: 3. Месяцы: ноябрь, декабрь» (один
  месяц — «Месяц: май», все двенадцать — «круглый год»).
- **Место статьи — только страна (#3347).** Города у статьи в каталоге нет: поле
  `cityName` API — подпись первой точки маршрута (бэкенд, `travels/serializers.py`:
  `get_city_name` → `_first_travel_address(...).address`). В слепке индекса от
  12.11.2026 оно равно подписи первой точки у 434 статей из 434, и это почти
  всегда объект, а не город: парковка, костёл, смотровая площадка, аэропорт,
  номер дороги «Н8331», координаты. Строка «Испания, Madrid» у тура Барселона —
  Мадрид — Ронда — Толедо, «Польша, Palenica Białczańska» у «Морского ока»,
  «Словакия, Chata pri Zelenom plese», «Беларусь, Лысая гора (342 м)» у подборки
  тринадцати поездок выдавала точку маршрута за место статьи, и модель писала в
  ответе «— Польша, Palenica Białczańska». Критерий: в строку фактов идёт то, что
  каталог знает о статье целиком, — список стран; подпись точки маршрута в неё не
  идёт никогда, даже когда совпадает с городом, — город статьи стоит в её
  названии. `travelFactsLine` города не принимает; слепок обучения
  (`travel_facts_line(facts=True)`) строит ту же строку. Пересборка индекса не
  нужна: строку фактов служба собирает на запрос, страна уже лежит во фрагменте.
- Поля, на которых обучены v7 и v9 (вид квеста, возраст, «Со взрослым», точки,
  длительность, сложность; страна статьи), пишутся прежними словами и в
  прежнем порядке — новое только дописано. Наборы кругов 1–9 собираются без
  `facts` и не меняются — в них карточка статьи по-прежнему начинается со «Страна,
  подпись точки»; учить новым полям и новому месту — задача следующего круга.
- Подписи русские на всех локалях, как зачин аудитории: модель обучена на
  RU-карточках и переводит ответ сама.
- Транспорт и категории статьи лежат в записи фактов, но в строку не идут:
  список статей экрана (`/api/travels/?query=`) их не отдаёт, и строка экрана
  разошлась бы со строкой службы. `pet_friendly: false` в строку тоже не идёт.
- На пути службы факты приходят из индекса: `facts.jsonl` — одна запись на
  источник (у квеста `{type, source_id, points?, duration_min?, difficulty?,
  pet_friendly?, audience?, age?, adult?}`, у статьи `{type, source_id,
  number_days?, months?, transports?, categories?}`). Экспорт кладёт поля в
  raw-слепок (`points`, `duration_min`, `difficulty`, `pet_friendly` — из списка
  `/api/quests/`; `number_days`, `transports` — из детали статьи; названия — из
  `/api/getFiltersTravel/`), `chunk` собирает записи, `embed` пишет их в
  артефакт вместе с фрагментами. `manifest.json` несёт `format_version: 2` и
  отпечаток фактов; служба на артефакте без фактов стартует и строит карточку
  как до #3287. Уже собранный артефакт переводится без пересчёта векторов:
  `npm run ai:index -- facts`. На raw-слепке, выгруженном до #3287 (в `state.json` нет
  `raw_version`) или без полей фактов в файлах, команда отказывает с ненулевым кодом и артефакт не
  трогает (`rawFactsProblem`, `scripts/ai-index/export.ts`): раньше она молча писала 777 записей без
  чисел, и служба стартовала «с фактами» при пустых карточках. Перечитать слепок — обычный
  `npm run ai:index -- export`: на старом `state.json` он сам перечитывает все статьи, квесты
  читаются при каждом запуске; `chunk` на старом слепке пишет в журнал предупреждение.
- Превосходная степень решается до модели (`detectSuperlative`,
  `rankBySuperlative`): «самый короткий квест в Минске», «где меньше точек»,
  «самый лёгкий» на RU/BE/UK/PL/EN. Назван город (тем же правилом, что отбор
  #3315) — кандидаты все его квесты из индекса, а не только восемь найденных;
  иначе — квесты подбора. До трёх квестов по порядку ответа встают первыми,
  остальной подбор следом. Длительность и сложность считаются вопросом о квесте,
  только когда запрос называет квест («самый короткий путь из Минска» карточки
  не переставляет); условие («не больше пяти точек») — это отбор по условиям
  (#3289), а не сортировка. Экран с провайдером `llamacpp` сортировки не делает.

1. Служба дописывает текстовый фрагмент к каждой карточке, в том числе квеста:

   нет вовсе.
2. Состав карточек другой: смысловой индекс возвращает в основном статьи (140

   карточки статьи — 56 токенов против 44 у квеста.

Строка фактов стоит ≈ 29 токенов на карточку, поэтому при прежнем фрагменте
подсказка выросла бы на 233 токена. По умолчанию текстовый фрагмент укорочен
до 120 знаков у статьи и 60 у квеста (`ASK_FRAGMENT_CHARS`,
`scripts/ai-assist/search.ts`): подсказка остаётся прежнего размера, факты идут
вместо половины текста; сниппет выдачи `/ai/search` по-прежнему 200 знаков.

Цель «медиана не выше 1100 при восьми карточках» с текстовым фрагментом не
достигается: системное сообщение, заголовки с адресами, вопрос и шаблон — это
≈ 860 токенов до первого знака фрагмента, строки фактов восьми карточек — ещё
≈ 210–360. В 1100 укладывается только карточка без текста (медиана 1082, при
восьми карточках 1116). Какую длину оставить, решает замер качества на модели
продукта: длина меняется окружением службы без правки кода
(`AI_ASSIST_ASK_FRAGMENT_TRAVEL_CHARS`, `AI_ASSIST_ASK_FRAGMENT_QUEST_CHARS`).
На модели значения по умолчанию ещё не проверены: замер 11.11.2026 шёл во время
обучения v9, `llama-server` не запускался. Скрипты — `.codex-temp/3287/measure/`
(`dump-prompts.mts`, `count-tokens.py`, `variants.sh`, `breakdown.py`,
`calibrate.mts`).

### Страж содержания ответа (#3291)

Страж ссылок пропускает только адреса карточек, но ответ с настоящими ссылками мог расходиться с
карточками: выдуманное название у настоящего адреса, пояснение от соседней карточки, числа,
которых нет нигде, повтор вопроса вместо ответа (проба пути службы 11.11.2026: p04, p10, p14, p15,
p18; приёмка v7: q24). Проверки живут в `api/aiAssist/linkGuard.ts` (подпись) и
`api/aiAssist/answerGuard.ts` (`guardAnswer` — пояснение, числа, пустой ответ) и одни для экрана,
службы `/ai/ask` и контура оценки. Части правил — опора чисел, вопросы в ответе, оборванные фразы
карточки, подводка без списка — лежат в `api/aiAssist/answerGuardRules.ts`; вход один,
`answerGuard.ts` (оба файла держатся под порогом `guard:file-complexity` в 800 строк).

- **Подпись ссылки.** У разрешённого адреса подпись заменяется названием его карточки, если они
  расходятся после нормализации (регистр, кавычки, выделение и знак в конце не считаются).
  Работает и в стриме: выдуманное название посетитель не видит ни на одном шаге. Сокращённая или
  переведённая подпись тоже приводится к названию из каталога.
- **Пояснение пункта** — фраза сразу за ссылкой после тире, двоеточия или скобки. Число с единицей
  в нём должно стоять в карточке этой ссылки (строка фактов #3287 и фрагмент) или в вопросе. Слова
  считаются чужими, когда пояснение опирается на соседнюю карточку, а на свою — нет: соседняя
  подтверждает не меньше 60 % значимых слов (и не меньше двух) либо названное в пояснении имя
  собственное, своя — не больше 34 % слов и ни одного имени. Неподтверждённое пояснение
  убирается, ссылка остаётся. Отсутствие опоры само по себе пояснение не срезает: ответ на
  BE/UK/PL/EN пересказывает русскую карточку другими словами.
- **Число вне пояснений** должно стоять хотя бы в одной карточке подсказки или в вопросе (с опорой
  уточнения); фраза с числом без опоры убирается. Число сверяется по предложению целиком, вместе
  со словами до и после ссылки: если в таком предложении стоит ссылка, от него остаётся только
  она — «Пройдёте [Квест](…) за 2 часа.» → «[Квест](…).», в пункте списка — «- [Квест](…)».
  Рекомендация не теряется, оборванной фразы не остаётся. Числа вопроса словами («полтора часа», «не
  больше восьми точек») — тоже опора; разница двух чисел карточек во фразе сравнения («на 30
  минут короче») — вывод, а не выдумка. Опора — именно карточки подсказки (`promptSources` в
  `AnswerGuardContext`), а не весь список источников: в замере r2 (lv35, повтор 3) «загалом близько
  150 хв» при карточке на 120 хв прошло, потому что 150 минут стояли у соседнего квеста группы
  `nearby`, которого модель не видела. Служба и экран передают стражу тот же отбор, что ушёл модели.
- Сверяются единицы с однозначным значением: точки квеста, длительность (минуты; часы — с
  округлением до 20 минут), время суток, цена, а с #3345 — расстояние в километрах и годы
  (возраст). Расстояние словами в опоре читается («около двух с половиной километров»,
  «километров на сорок-пятьдесят»), возраст сверяется с диапазоном карточки («Возраст: 8–10 лет»)
  и с возрастом из вопроса, в том числе слитным словом («шестилетка», «дев’ятирічним»). Дни не
  сверяются: карточка пишет их словами («маршрут на два дня»), цифра в ответе была бы ложной
  тревогой.
- **Материал не из подсказки.** Страж ссылок снимает адрес, которого нет в карточках, но название и
  числа при нём оставались: «Квесты с ребёнком: • В поисках гномов — 8 точек, около 150 мин» (p21).
  Пункт списка или предложение с такой ссылкой — markdown-ссылкой либо голым адресом metravel.by —
  убирается целиком; если в предложении есть и ссылка на карточку, остаётся она. Строка-заголовок
  списка, под которой не осталось пунктов, уходит вместе с ними. Внешний голый адрес по-прежнему
  просто исчезает.
- **Повтор вопроса.** Дословный (до регистра и пробелов) повтор вопроса посетителя отдельным
  предложением вырезается и у ответа со ссылками — «…удобная обувь. Сколько дней занимает поездка
  и что взять с собой?». Вопрос без знака вопроса не вырезается: «Самый короткий квест в Минске — …»
  честно начинает ответ. Повтор пересказом и половиной вопроса закрывает правило вопросительного
  предложения (#3345, ниже). Повтор режется как единица-предложение (`stripQuestionSentences`):
  законченное предложение ответа, дословно равное предложению вопроса, уходит и без знака вопроса
  («Хочемо ще встигнути в замок.»). Ответ-повтор остаётся пустым, пока в остатке нет числа из
  карточки подсказки: в замере r4 lv35 «У квест: Тракай — … візьмо близько 120 хв. Скільки часу
  потрібно на квест у Тракаї? Хочемо ще встигнути в замок.» трижды уходил в запасной ответ, хотя
  первое предложение отвечает; число, которое стоит только в вопросе, ответом не считается.
- **Подводка без списка** (`stripOrphanLeadIns`). Фраза, кончающаяся двоеточием, после которой до
  конца ответа нет ни ссылки, ни пункта списка, ни законченной фразы, уходит вместе со
  строками-названиями под ней: «Rozkłady jazdy pociągów w Polsce: ⏎ Miasto Malbork — Karta
  turystyczna» (lv22, r4), «…Ближайшее из найденного:» последней фразой (lv45, r3). В режиме
  страницы уходит только подводка, после которой пусто. Строка с содержанием карточки подсказки —
  числом из неё или её словами — названием чужого материала не считается: «Время прохождения
  квеста по Гродно: ⏎ 120 мин» и «Что взять с собой: ⏎ удобную обувь ⏎ воду» остаются целиком
  (ревью гейта). Каждое вырезание, и прежнего правила заголовка без пунктов тоже, — находка
  `orphan_lead_in`; целый повтор вопроса, вырезанный у ответа со ссылкой, — `counter_question`
  (у пустого ответа-повтора находка одна, `echo`). Пересчёт 800 записанных сырых ответов
  (final, r1–r4): изменилось 5 показанных текстов — lv35 ×3, lv22 и lv45; на 3674 ответах всех
  записанных прогонов — 9, все того же вида.
- **Эхо разметки подсказки** вырезается: заголовок блока карточек («Материалы сайта:», «Матеріали
  сайту:», «Site materials:» — на любой из пяти локалей), строка «Вопрос посетителя:», фразы
  системного сообщения и номер карточки в квадратных скобках вне ссылки («The most relevant card
  is [2].»). Строка, начатая номером карточки, убирается целиком, в остальном тексте —
  предложение вместе с продолжением в скобках или со строчной буквы (от «…[1] — озеро 1 дн. (с
  ночёвкой не обязательно).» оставался обрывок в скобках). Детектор `leaksPrompt` общий с проверкой `prompt_leak` контура оценки. В прогоне
  86 живых вопросов на v7 такие ответы доходили до посетителя (lv51, lv54, lv19).
- **Пустой ответ** — после стража нет ни ссылки на карточку, ни признания «этого в материалах
  нет», ни подтверждённого числа, а текст короче 40 знаков либо повторяет вопрос. Пустым считается
  и остаток после вырезаний: одни вопросы («Сколько летнему ребёнку, сколько взрослым?» после
  убранной фразы с ценой) либо, после эха подсказки, текст без ссылки и признания; в режиме
  страницы утверждение о странице ссылки не требует. Встречный вопрос остаётся ответом, только когда
  уточняет возраст ребёнка (#3345, ниже). Ход остаётся
  `done` с признаком `fallback`: текста нет, карточка хода показывает фразу
  `aiAssistStatic:ask.fallbackAnswer` («Точного ответа в найденных материалах нет — посмотрите
  источники ниже», RU/BE/UK/PL/EN) и источники; кнопки повтора нет, в историю диалога такой ход
  не идёт. Отказ модели «не по теме» (`judgeModelReply`) решается раньше.
- Событие `done` потока `/ai/ask` получает необязательные `relabeled`, `dropped_descriptions`,
  `ungrounded_numbers`, `prompt_leaks` (только ненулевые) и `fallback: true`; старый клиент их не читает и на
  пустой текст показывает прежнее «модель не дала ответа».
- Пояснение, числа и пустой ответ проверяются по готовому ответу: во время стрима
  неподтверждённая фраза или повтор вопроса видны до последнего события `text`, которое их
  убирает.

#### Единый набор правил (#3345)

Правила #3291 писались под найденные случаи, и приёмка на живой службе (12.11.2026) нашла пять форм
мусора, которые каждое из них обходили. Набор собран заново вокруг единиц ответа — ссылка на
карточку, пояснение за ней, предложение вне пояснений, ответ целиком: у каждой единицы свои условия,
при которых она остаётся, и новая форма закрывается условием единицы, а не заплаткой под строку.
Полный список — в шапке `api/aiAssist/answerGuard.ts`; здесь — то, что добавлено.

| форма обхода | пример (сырой ответ v7) | условие единицы | что остаётся |
| --- | --- | --- | --- |
| голый адрес карточки вместо пояснения | «[Квест](…) — городской квест: https://…», «Почати: https://…», «Горад: https://…» | **ссылка:** карточка называется одним способом — ссылкой с названием из каталога (`nameBareSourceLinks`, `linkGuard.ts`) | карточка ещё не названа — адрес становится ссылкой с её названием; уже названа — адрес уходит вместе с разделителем, а фраза-подводка без своего содержания («Начать: адрес») — целиком |

Уточнение возраста — единственный встречный вопрос, которому модель обучена («Возрастные ограничения
в карточках не указаны. Сколько лет ребёнку?», `rag_answers.py`). Оно остаётся, когда вопрос
посетителя вместе с опорой уточнения — о детях (`asksAboutChildren`) и возраст в нём не назван
(`parseConditions`): на «Какой квест выбрать с детьми?» остаётся, на «…с девятилетним сыном», на
«Чи є у вас велоквести?» и на «Где погулять с собакой?» — нет. Вопросительное предложение со ссылкой
на карточку («Подойдёт ли вам [Квест](…)?») — рекомендация, оно не трогается; вопрос в пояснении
пункта проверяет правило пояснения.

Признание «этого в материалах нет» узнаётся шире: «материалы сайта не называют…», «не сообщают»,
«не згадваюць», «не повідомляють», «nie wspominają». От этого зависит правило остатка: ответ с
признанием запасным не становится.

Доправки по живому замеру r1 (12.11.2026, 94 хода на новом страже):

- **Километры и годы** сверяются тем же правилом опоры, что минуты и цена. В замере до посетителя
  дошли «The nearest parking is in Bereza, about 1 km away…» (lv74: первое предложение ответа вырезало
  число «20 BYN», второе с выдуманным километром осталось единственным) и «Возрастные ограничения: 12
  лет» (lv79). Правило общее для стража и оценщика (`findUngroundedNumbers`). Проверка на ложные
  срабатывания: на 1215 записанных сырых ответах (`.codex-temp/train-live/**`, замер r1, приёмка
  11.11) правило вырезает 16 предложений, ни в одном число не стоит в карточках подсказки или в вопросе;
  на трёх наборах сравнения (финальный прогон, r1, пробы приёмки) — пять, все выдуманные.
- **Признание не по теме вопроса — не ответ** (`admitsOnTopic`). «У картках не пазначаны ўзроставыя
  абмежаванні» на «А квэст там колькі часу займае?» (lv61), «не пазначаны ўзровень складанасці» на
  вопрос о времени (lv34) — заученное признание без ответа. Признание не по теме, когда его предмет —
  известный факт карточки (возраст, сложность, цена, длительность), а вопрос вместе с опорой уточнения
  об этом факте не спрашивает; возраст — тема любого вопроса о детях. Ответ без ссылки и подтверждённого
  числа, всё содержание которого — такое признание, заменяется запасным. Признание без предмета («про
  это в карточках не сказано», «отдельного материала о прогулках с собакой нет») остаётся ответом.
  На 1012 записанных ответах правило даёт девять запасных ответов (lv34, lv40, lv61, lv63), верного
  ответа среди них нет.
- **Общее правило «без ссылки, числа и признания — запасной ответ» не включено**: на тех же ответах
  оно даёт 12 запасных, из них два — верные ответы без ссылки (lv19 финального прогона — точный пересказ
  статьи о треке с собакой; lv13 — парки динозавров). Решение #3291 «длинный ответ без ссылок — дефект
  модели, текст остаётся» сохранено; такой ответ по-прежнему ловит `no_links` контура.

Пересчёт 934 сохранённых сырых ответов v7 (`.codex-temp/train-live/**`, `.codex-temp/train2/replay.mts`,
старый страж — снимок `HEAD` до правки): текст изменился у 90 ответов — вопросительных предложений
убрано 74 (оставлено уточнение возраста там, где вопрос о детях без возраста), голых адресов названо
или убрано 17, оборванных фраз 2, запасных ответов стало 10 вместо 7 (lv06, lv40 и ответ без ссылки
после вырезанной выдуманной ссылки). Событие `done` потока `/ai/ask` новых полей не получило: счётчики
`bareLinks`, `cardFragments`, `counterQuestions` есть в результате `guardAnswer` и в находках слоя
стража контура оценки (`bare_url`, `card_fragment`, `counter_question`).

### Размер подсказки модели (#3268)

`AI_SOURCES_LIMIT` (8) — сколько карточек находит подбор и видит посетитель под
ответом; `AI_PROMPT_SOURCES_LIMIT` (`api/aiAssist/policy.ts`) — сколько из них
уходит в сообщение модели: `selectPromptSources` (`prompt.ts`) берёт первые по
порядку подбора, одно место для экрана, службы `/ai/ask` и набора quality.
Список источников и страж ссылок работают с полным подбором.

(`metravel-llm-v7-Q4_K_M.gguf`, GPU), контур `ai:assistant:eval`, три повтора,
код с признаком аудитории квеста (#3276):

Спорные целевые вопросы по девять повторов (on14, ln02, on10, on13): 29/36 и на
пяти, и на восьми карточках; on14 «Сколько длится квест по Гродно?» — 5/9 на
восьми и 2/9 на пяти (ниже 2/3 при любом значении), ln02 — 7/9 и 9/9, on10 — 8/9
и 9/9.

Короткая подсказка быстрее на 10–20 % и укладывается в учебные 1024 токена, но
качество на v7 не растёт, а на двух видах вопросов падает:

1. Первые N карточек по баллу теряют квесты города. Места резерва
   (`QUEST_RESERVED_SLOTS`) гарантируют квестам города попадание в восемь, но
   стоят они в конце списка: «В Катовице мы без машины. Куда сходить?» — оба
   квеста Катовице седьмой и восьмой, на восьми карточках ответ по ним 3/3, на
   четырёх модель называет статьи соседних городов, 0/3.
2. На четырёх–пяти квестах одного города v7 перечисляет все или отвечает без
   ссылки (on14, in06, ln02 на четырёх); на восьми называет три и отсылает к
   списку источников.

Вариант с укороченным фрагментом (четвёртая строка): карточка режется до 60
знаков по границе слова с «…» — то же правило и та же длина, что у самого
короткого варианта карточки в обучении (`SHORT_SNIPPETS`). Это наибольшая длина,
при которой восемь карточек квестов без истории укладываются в 1024 токена с
системным промптом: 60 таких ходов из 60, максимум 1001 токен (с полным
фрагментом — все 60 длиннее предела, максимум 1170). Остальные 21 ход длиннее
1024 — статьи с длинными заголовками и адресами и ходы с историей, фрагмент на
них не влияет. Цена укорочения:

1. Из карточки квеста выпадают длительность и сложность, у детских и семейных —
   ещё возраст, «Со взрослым» и число точек: остаётся «Детский городской квест
   по городу Гродно (Беларусь).…». Пометка возраста (#3276) до модели не доходит.
2. Модель выдумывает вырезанный факт. «Сколько длится квест по Гродно?» (on14):
   автопроверка зачла 3/3, а в ответах «около 120 минут», «около 150 минут»,
   «уровень — лёгкий» — в полной карточке этого квеста 120 минут и «средний», 150
   нет ни в одной. Автопроверка сверяет ссылки и число рекомендаций, а не цифры.
3. Отложенные вопросы — 102/114, худший результат из четырёх вариантов.

По отдельным вопросам (прошло из трёх): «Катовице» (h12) — 3/3 на восьми, 1/3
на пяти, 0/3 на четырёх, 3/3 с коротким фрагментом; on14 — 2/3, 0/3, 0/3 и
ложные 3/3; ln02 — 2/3, 2/3, 1/3, 1/3; on10 — 2/3, 3/3, 3/3, 3/3. on14 ниже 2/3
при любом числе карточек на девяти повторах — это остаток модели, а не размера
подсказки (#3278).

Чтобы уменьшить число карточек, сначала нужны отбор подсказки, который держит
квесты города внутри первых N, и модель, устойчивая на 4–5 карточках одного
места; после этого замер повторяется (`.codex-temp/prompt-size-3268/measure.sh
<N>`, короткий фрагмент — `measure-fragment.sh <длина>`, сводка `summary.py` и
`perq.py`). Продукт остаётся на восьми карточках с медианой 1092 токена, а
модель учится на 1–5 карточках в пределах 1024 токенов — это расхождение
сохраняется и записано как ограничение круга v8 (`scripts/ai-train/README.md`).

## Вопросы не по теме (#2711)

`api/aiAssist/topicGate.ts` → `classifyQuestion` стоит до подбора: вопрос не о
путешествиях не уходит ни в поиск, ни в модель и не списывает дневной лимит.

- Жёсткие темы — попытки переписать инструкции («игнорируй…», «системный промпт»,
  «ты теперь…») и программирование/взлом: отказ всегда.
- Мягкие темы — рецепты, политика, медицина, финансы, учёба, болтовня: отказ,
  если в вопросе нет признака поездки («поход», «маршрут», «с детьми», «виза»,
  место после предлога: «в Кракове», «w Gdańsku»). «Какую кашу взять в поход» и
  «аптечка для поездки с детьми» — вопросы по теме. Снаряжение, сборы и ночёвка
  (#3270) — тоже признак поездки на пяти языках: «рюкзак», «палатка», «налегке»,
  «заплечнік», «намет», «plecak», «nocleg», «backpack», «overnight», «city break»;
  дорога и жильё — «перелёт», «вокзал», «заселение», «pociąg», «airport» (англ.
  «train» — только «trains», «night train», «train station»: глагол «train» не
  признак). Предлог в начале фразы с заглавной («В Катовице…», «In Tallinn…»)
  тоже вводит место; исключение — «Do»: это ещё и английский вспомогательный
  глагол («Do Americans vote…»), поэтому с заглавной он местом не считается.
- Признаки — на RU/BE/UK/PL/EN; фраза отказа — `aiAssistStatic:ask.offTopic`
  (5 локалей), в RU она же `OFFTOPIC_REPLY_RU` в `prompt.ts`.
- Второй рубеж — модель: системный промпт велит ответить на чужую тему этой
  фразой; `isModelOffTopicReply` узнаёт её («ассистент metravel.by» без ссылок на
  карточки), ход становится `off_topic` без счётчика: модель ошибается и на
  вопросах о поездке («travel hacks», просьба о чужой ссылке — замер #2710), и
  блок за её ошибку получил бы посетитель. Просьба о чужой ссылке внутри вопроса о
  поездке по промпту — вопрос о поездке: ответ по карточкам без чужих ссылок.
- Решение второго рубежа одно для экрана и службы — `judgeModelReply`
  (`topicGate.ts`, #3216): отказ модели на вопрос с признаком поездки
  (`hasTravelSignal` запроса подбора, то есть вопроса вместе с опорой уточнения)
  — это `no_sources` («материала пока нет») и строка `no_sources` в журнале
  спроса, а не `off_topic`. Отказ модели вероятностный: на «Какую кашу взять с
  собой в поход?» с одной посторонней карточкой v4 отказывала 3 раза из 3, v6 — 2
  из 3 (замер 09.11.2026). Без признака поездки отказ остаётся `off_topic`.
- Лимит рекомендаций (`AI_MAX_RECOMMENDATIONS` = 3, `policy.ts`, #3216): при 4–6
  карточках одного города модель перечисляет все, поэтому генератор по опции
  `maxRecommendations` закрывает стрим на четвёртой (`findRecommendationOverflowCut`
  рядом с остановкой цикла `findRepetitionLoopCut`): пункт списка после трёх
  рекомендаций, строка, все новые адреса которой сверх лимита, или четвёртый
  адрес посреди фразы («A — …; B — …; C — …; D — …» одной строкой — тогда фраза
  заканчивается на границе перед ним). Опцию задаёт
  только ответ ассистента (экран и `/ai/ask`); помощник автора и фильтр карты
  получают списки целиком. Остальные карточки посетитель видит в источниках.
- Эскалация (`limits.ts`, ключ `metravel.aiAssist.offtopic.v1`): 1-й и 2-й вопрос
  не по теме за день — отказ + «вопрос не по теме (N из 3)»; 3-й — запись
  `offtopic_blocked` в журнал спроса и блок поля ввода до полуночи по времени
  устройства. Вопросы по теме счётчик не сбрасывают. Клиентский блок обходится
  очисткой хранилища — настоящий держит сервер `/ai/ask` (ниже, #2713). Числа
  общие — `api/aiAssist/policy.ts`.
- Страж ссылок оставляет голое «metravel.by» без пути (название сайта во фразе
  отказа и в речи модели) и режет только `metravel.by/<путь>`.

## Справка о сайте (#3293)

Ассистент знал только статьи и квесты: на «Сколько стоит пройти квест?» служба отдавала восемь
случайных карточек, а модель — «Цены в карточках — в отдельных пунктах». Ответы на вопросы о самом
MeTravel лежат в справочном корпусе и идут третьим типом источника индекса — `help`.

- **Корпус** — `scripts/ai-index/sources/help/`: `help.ru.json` (41 запись: `num`, `id`, `approved`,
  `topic`, `questions[]`, `answer`, `url` — страница сайта, `source_doc` — документ или ресурс, откуда
  взят факт, `needs_owner`, `owner_question`) и переводы `help.{be,uk,pl,en}.json` (`{id, questions[],
  answer}`). Темы: цена и регистрация, квесты, приложения, избранное и план поездки, статьи и
  модерация, карта и фильтры, языки, обратная связь, о сайте. Запись без перевода отдаётся на RU.
- **Утверждение.** Тексты читает посетитель, поэтому в индекс идут только записи с `approved: true`;
  запись с `needs_owner: true` утвердить нельзя, пока владелец не ответил на `owner_question`
  (`validateHelpCorpus`, `scripts/ai-index/help.ts`). Владелец утвердил корпус целиком 12.11.2026 —
  все 41 запись в текущей редакции, включая шесть, где требовалось подтверждение факта (платность
  сайта, кнопки входа, квест без сети, приложение в магазинах, срок модерации, язык статей): у всех
  `approved: true`, `needs_owner` снят. Новая или изменённая запись снова заводится с
  `approved: false` и идёт в индекс только после утверждения владельцем. Черновики включает
  `AI_INDEX_HELP_DRAFTS=1` — только для стенда.
- **Индекс.** Фрагменты записи на одном языке: по одному на формулировку вопроса (заголовок —
  формулировка, текст для вектора — она и ответ) и один фрагмент ответа (тег `answer`, текст — только
  ответ); поле `answer` у всех — ответ дословно. `chunk` и `build` добавляют справку сами;
  `npm run ai:index -- help --from <dist> --dist <dist>` дописывает её в готовый артефакт без пересчёта
  векторов статей и квестов (41 запись × 5 языков — 855 фрагментов, 6 секунд). `manifest.sources`
  получает `help` только вместе со справкой; версия формата прежняя.
- **Порядок записей** (`helpHits`, `scripts/ai-assist/search.ts`): балл записи — среднее двух лучших
  формулировок плюс близость ответа. По одной лучшей формулировке первой вставала соседняя запись
  (замер r2: на «Ці ёсць у квэсце падказкі?» — «сообщить об ошибке в квесте», на «Ці трэба
  рэгістравацца?» — «как зарегистрироваться»). Замер 12.11.2026 (`.codex-temp/train2/help-rank.mts`),
  верная первая запись: 17 вопросов о сайте набора — 13 → 17; 650 формулировок корпуса без самой
  формулировки — 440 → 496. Сравнивались ещё «только вопрос» (14 и 272), добавка совпадения слов
  ответа (15 и 450) и «лучшая формулировка + ответ» (15 и 499).
- **Подбор службы** (`scripts/ai-assist/app.ts`, `helpSources`): вопрос отвечает справка, когда в нём
  есть признак сервиса (`asksAboutService`, `api/aiAssist/serviceIntent.ts`; условие `service` в
  `parseConditions`) и лучшая запись близка к вопросу (косинус от 0,48 и не дальше лучшего материала
  больше чем на 0,1), либо признака нет, но запись заметно ближе материалов (от 0,6 и на 0,1 ближе).
  Пороги и замер — в комментарии к `HELP_MIN_SCORE`; считаются они по самой близкой формулировке среди
  всех записей, порядок от них не зависит. Тогда источники — только записи справки (до трёх): отвечает
  первая (группа `match`), остальные — «Ещё по теме»; статьи и квесты не добавляются. Вторая запись
  встаёт в ответ вторым абзацем, только когда её балл уступает первой не больше `HELP_TIE`, она из
  той же темы корпуса (`topic`) и её ответ не открывается отдельным «Да» или «Нет» (`opensWithYesNo`,
  пять языков): такой ответ отвечает на свой вопрос. Трёх абзацев не бывает. На 17 вопросах набора
  две записи — у двух («Квесты платные? Сколько стоит пройти один?» и «Ці трэба рэгістравацца, каб
  карыстацца сайтам?»). Вопрос о поездке справку не получает, вопрос со страницы
  статьи или квеста — тоже. `/ai/search` и `/ai/similar` без `type=help` справку не возвращают, MCP

- **Ответ — без модели.** По умолчанию служба отдаёт текст записи дословно и ссылку на её страницу

  «free», русские фразы в белорусском ответе. Без модели — 12 из 12 ×3 с нужной записью в ответе.

- **Фильтр тем:** вопрос о сайте — по теме (`isOnSiteTopic`): «Как сменить пароль от аккаунта?», «Есть

## Серверный `/ai/ask` (#2713)

`POST /ai/ask {q, locale?, history?}` в сервисе metravel-assist
(`scripts/ai-assist/ask.ts`, образ `services/ai-assist/`) — тот же пайплайн на
сервере: фильтр тем → лимиты на IP → подбор по индексу (гибрид `/ai/search`,
≤ 8 карточек `AiSource`) → промпт → `metravel-llm` (`AI_LLM_URL`) → страж ссылок.
Фильтр, промпт, страж и клиент модели — те же модули `api/aiAssist/*`, что у
экрана: сервер и клиент не расходятся. Ответ — SSE `sources → text* → done`
(`text` несёт накопленный текст после стража, не дельту: страж может убрать уже
показанный чужой адрес).

- Карточка службы начинается строкой фактов — тем же построителем, что на
  экране (#3276, #3287, раздел «Факты источника в карточке»): у квеста вид
  квеста с городом и страной, возраст, «Со взрослым», число точек, длительность,
  сложность, «Можно с собакой»; у статьи страна, число дней, месяцы (#3347).
  Факты берутся из `facts.jsonl` индекса; у артефакта без фактов карточка квеста
  несёт только зачин по тегам фрагмента, статьи — страну. Затем идёт
  фрагмент текста под вопрос, не длиннее `ASK_FRAGMENT_CHARS` (120 знаков у
  статьи, 60 у квеста). Порядок найденных карточек задаёт общая цепочка
  `arrangeSources` (#3289, раздел «Условия вопроса и порядок карточек»): место
  вопроса → условия по фактам → превосходная степень; детские квесты города при
  вопросе о детях (#3276) и «самый короткий квест в Минске» по фактам каталога
  (#3287) — её шаги. Событие `sources` несёт у карточки `group: 'match' | 'nearby'`,
  когда отбор что-то отделил; `/ai/search` и его `snippet` не меняются.
- Счётчики на IP за календарный день по Europe/Minsk (`AI_ASSIST_DAY_TZ`) в redis
  (`REDIS_URL`, ключи `ai-ask:v1:{quota|offtopic}:<день>:<ip>` с TTL до полуночи);
  без redis и при его ошибке — память процесса. IP — `X-Real-IP`, затем последний
  адрес `X-Forwarded-For` (его дописывает nginx; начало заголовка присылает сам
  посетитель), `AI_ASSIST_TRUST_PROXY=0` — только сокет.
- Вопрос не по теме: 1-й и 2-й — `200` SSE `sources: []` + `done {status: off_topic,
  reason: offtopic_warning, strikes, strikes_to_block}`; 3-й — строка
  `offtopic_blocked` в `logs/ai-demand.jsonl` (`AI_DEMAND_LOG`) и
  `429 {error: offtopic_blocked, retry_after_sec, strikes}` + `Retry-After` до полуночи;
  до полуночи тот же IP получает `429` на любой вопрос — очистка хранилища
  клиента и прямой запрос блок не снимают. Отказ самой модели — `done {status:
  off_topic, reason: model_refusal}`, в счётчик не идёт (как на клиенте); на
  вопрос с признаком поездки — `done {status: no_sources}` (`judgeModelReply`, #3216).
- Дневной лимит 20 вопросов на IP (`AI_ASK_DAILY_LIMIT`): вопросы не по теме его
  не тратят; сверх лимита — `429 {error: limit}` + `Retry-After` до полуночи;
  занятая или упавшая модель и уход посетителя до первого токена возвращают
  списанный вопрос; обрыв после начала ответа — нет (иначе лимит обходился бы
  чтением `text` без `done`).
- Модель: `AI_LLM_URL` не задан или не ответил до первого токена → `503
  generator_unavailable` + `Retry-After: 30` (журнал `generator_unavailable`);
  очередь к модели занята дольше `AI_ASSIST_ASK_QUEUE_TIMEOUT_MS` → `429 busy`;
  обрыв посреди ответа → `done {status: unavailable}`. Источники уходят с первым
  токеном, чтобы отказ модели до него оставался честным 503.
- Проверено 25.10.2026 локально (`node --experimental-strip-types`, индекс q8, без
  `AI_LLM_URL`): «как готовить кашу» ×2 → 200 с предупреждениями 1 и 2, ×3 → 429
  `Retry-After` до полуночи и строка в журнале; «квесты в Гродно» с того же IP →
  429, с другого — 503. Тесты — `__tests__/scripts/ai-assist/ask.test.ts`.
- Экран ходит сюда провайдером `ask` (#2884, раздел «Провайдеры»); на проде
  ассистент включится после выкладки контейнеров (#2457): compose должен дать
  сервису `AI_LLM_URL`, `REDIS_URL` и том под `logs/`, не публиковать 8787
  наружу, а `location /ai/` — ставить `X-Real-IP $remote_addr` и `proxy_buffering off`.
- Опора уточнений (#2719) применяется и здесь: подбор идёт по
  `buildRetrievalQuery(q, resolveRetrievalAnchor(history))` из общего
  `api/aiAssist/retrievalQuery.ts`, модель получает исходный `q`.
- Источник страницы (#2897): необязательное поле `source {type: travel|quest, id}`
  (только объект; `id` — положительное целое) — карточка `type:id` из индекса
  (`lookupSource` в `app.ts`: фрагмент локали запроса, если квест на ней есть,
  иначе первый; `score: 0`) ставится первой в `sources` и в промпт на каждом ходу,

  меняются. Кривой `source` → `400 bad_request` (лимит не списывается); материала
  нет в индексе (опубликован после сборки) → ход без закреплённой карточки.

## Контур оценки (#2710)

Для оценки **самой модели** на неизменных карточках есть набор из 34 пар
«запрос → пример хорошего ответа» на пяти языках: `npm run ai:assistant:quality`
(Node 22 с type stripping). Приоритеты: следование запросу → полезность и
точность → язык и естественность. Обязательные факты и ссылки проверяются
автоматически; смысл и три отдельных балла подтверждает судья. Формулировка
эталона не требуется дословно. Команды, ограничения и формат —
`scripts/ai-assistant-eval/QUALITY.md`. Этот прогон не измеряет поиск или UI.

`npm run ai:assistant:eval` задаёт вопросы из `scripts/ai-assistant-eval/cases.jsonl`
через сам экран `/assistant` (Playwright): подбор, промпт, модель и страж работают
без подмен; перехватывается только запрос к модели — он пересылается в
`--model-url` (по умолчанию `http://127.0.0.1:8080`) и сохраняется с карточками и
сырым ответом до стража. Наборы вопросов: по теме, диалоги, языки RU/BE/UK/PL/EN,
по теме «на грани», не по теме, попытки сломать, эскалация.

- Автопроверки (`checks.mjs`): нужные карточки нашлись, отказ на чужую тему и блок
  на третьей, ссылки только из карточек, нет цикла и обрыва по `max_tokens`, нет
  шаблона карточки статьи («Страна: / Когда: / Точки маршрута:»), ≤ 3
  рекомендаций, пункты со ссылками, ≤ 1200 знаков, язык ответа. Число
  рекомендаций считается дважды: `too_many` (слой модели) — по сырому ответу,
  `too_many_shown` (слой стража, #3216) — по показанному тексту после остановки
  генератора; метрика `shownRecommendations` — в `results.jsonl`.
- Слой стража содержания (#3291, `findGuardDefects`): показанный ответ проверяется
  тем же `guardAnswer`, что в продукте, — `label_mismatch` (ссылка подписана не
  названием карточки), `foreign_description` (пояснение пункта от соседней карточки
  или с числом не из своей), `ungrounded_number` (число с единицей, которого нет в
  карточках и в вопросе), `bare_url`, `card_fragment`, `counter_question`, `orphan_lead_in` (#3345:
  голый адрес карточки, оборванная фраза карточки, вопрос вместо ответа, подводка без списка), `echo`
  (ответ без содержания). Всё, что страж обязан был
  убрать и что осталось в показанном тексте, — провал слоя стража. Запасной ответ
  (`fallback` у пути службы, фраза на экране) считается признанием «материала нет».
- Слой модели, числа (#3277, `findInventedNumbers`): число с единицей в СЫРОМ
  ответе — цена, часы и минуты, время суток, точки, километры и годы (правило
  опоры общее со стражем, `findUngroundedNumbers`) — должно стоять в карточках подсказки
  или в вопросе; иначе провал `invented_number`, метрика `inventedNumbers`. Страж
  вырезает такое число из показанного ответа, и ход проходил автопроверку, хотя
  число выдумала модель: «Сколько длится квест по Гродно?» с «120» и «150 минут»
  при карточках без длительности засчитывался 3 из 3 (замер #3268). Километры
  словами в карточке («около двух с половиной километров») и возраст слитным
  словом в вопросе («шестилетка», «дев’ятирічним», «ośmiolatkiem») — опора; возраст
  сверяется с диапазоном карточки («Возраст: 8–10 лет»). Без вопроса хода проверка,
  как и слой стража, не считается.
- Признание «в карточках этого не сказано» (#3277, `admitsNotInCards`) — честный
  ответ на вопрос, которого материалы не касаются («нужно ли приложение», lv42):
  наравне с «на сайте такого нет» и запасным ответом он снимает требование ссылки
  у ожиданий `any_on_topic` и `no_material`. У ожидания `answer` ссылка нужна
  по-прежнему.
- Язык ответа судится по собственным словам (#3277, `ownProse`): кроме подписей
  ссылок из счёта уходят слова, которые стоят в карточках подсказки, — модель их
  переписала, а не написала. Белорусская подпись точки из карточки в русском
  ответе (lv02) давала «язык uk», «Kraków… Twardowski, Tyniec» в английском (f23) —
  «pl». Ответ не на том языке по-прежнему виден: в том же прогоне lv47 и lv53 —
  русский текст на украинский и белорусский вопрос, провал `wrong_lang` у них верный.
  Когда своих слов меньше 40 знаков, а текста хватает, язык судится по тексту целиком (без
  подписей ссылок): иначе русский ответ, собранный из слов русской карточки, на белорусский
  вопрос проходил без проверки. На замерах final и r1–r3 (733 ответа модели) таких ходов 37,
  язык целого текста у всех совпал с нужным.
  При равном счёте «чужих» букв (#3345) язык решают буквы, которые есть только в
  одном языке («ў», «ї», «є», «ґ»), и служебные слова: белорусская фраза с одной
  опечаткой («…ўзровень гадин; каля 120 хв», lv46) и украинская без «і», «ї», «є» («Ось
  головне в горах взимку…», lv29) раньше доставались русскому. Латинское слово с заглавной буквой
  в кириллическом тексте — имя, в счёт языка не идёт: запись справки «Да, приложение MeTravel есть
  для iPhone, iPad и Android — в App Store и Google Play» (lv89) по буквам выходила английской.
- Вопросы о сайте (#3293): ожидание `help` — первой карточкой стоит справка (`no_help_card`),
  статей и квестов среди источников нет (`material_in_help`), ответ не пуст и на языке вопроса;
  ход «справка без модели» (`trace.help`, наблюдение `helpDirect`) — не `no_model_call`. Пометка
  `no_help: true` у контрольного вопроса о поездке: справочная карточка среди источников — провал
  `help_card_leak`. В наборе живых вопросов — 12 вопросов о сайте на пяти языках (lv87–lv98) и три
  контрольных (lv99–lv101).
- Пустая подсказка (#3345): ход службы без вызова модели (`trace.model_called:
  false`, наблюдение `promptEmpty`) — не `no_model_call`. Для ожиданий
  `any_on_topic` и `no_material` это честный ответ, для `answer` — провал подбора
  `empty_prompt`. Проверка `no_links` такому ходу не ставится: это проверка слоя
  модели, а ход решён подбором — ссылку давать было не на что.
- Ход без текста модели контур видит той же строкой, что посетитель: путь службы
  (`ask-path.mjs`) подставляет в `answerText` строку экрана на локали хода —
  `ask.noSources` при причине `no_material`, `ask.fallbackAnswer` у запасного
  ответа стража (`loadShownTexts`, ключи `SHOWN_TEXT_KEYS`; тест сверяет их с
  карточкой хода). Раньше `answerText` был пуст, и судья оценивал такие ходы как
  «пустой ответ». Проверки от этого не меняются: у запасного ответа стража с
  ожиданием `answer` остаётся `no_links` слоя модели.
  Из-за общего кода `checks.mjs` грузит TypeScript. Команды `ai:assistant:eval`,
  `ai:assistant:accept`, `ai:assistant:quality` и дочерние прогоны приёмки
  подключают загрузчик `scripts/lib/ts-runtime.mjs` (`--import` в `package.json`):
  на Node со встроенным снятием типов (22.18+) он ничего не делает, на объявленном
  проектом 22.13.1 и на Node 20 снимает типы через esbuild из зависимостей. Ручные
  флаги не нужны. Прямой вызов `node scripts/ai-assistant-eval/run.mjs` подключает
  загрузчик сам (#3345): `run.mjs` — точка входа без статических импортов, прогон
  живёт в `run-core.mjs` и грузится после загрузчика. Раньше такой запуск на Node
  до 22.18 падал с `ERR_UNKNOWN_FILE_EXTENSION` на первом импорте. `quality.mjs` и
  `accept.mjs` напрямую по-прежнему требуют `--import` либо Node 22.18+. Тест —
  `__tests__/scripts/ai-assistant-eval/tsRuntime.test.ts`.
- У провала — слой: подбор / фильтр тем / промпт / страж / модель /
  инфраструктура; основной — первый по этому порядку (плохие карточки объясняют
  плохой ответ).
- `off_place_card` (#3267, слой модели): в подсказке были карточки места
  вопроса (`expect_sources.pattern`), а модель дала ссылку на карточку, которая
  под него не подходит ни названием, ни фрагментом, ни адресом — квест Бреста в
  ответе про Краков. Проверка говорит о месте: при `expect_sources.topic` (шаблон задаёт тему —
  «парк динозавров», «велоквесты», «ярмарки», «горы зимой», — а вопрос места не называет либо
  называет страну) это предупреждение `off_topic_card`. Признание «отдельного материала нет»
  провал не снимает: карточки места в подсказке были, значит признание ложное. Материал, который
  относится к месту, хотя в карточке его не называет, набор разрешает поимённо —
  `expect_sources.also` (#3345, lv21: подборка «Замки и усадьбы Беларуси» рассказывает о Несвиже в
  тексте, фрагмент карточки — 120 знаков); остальные карточки проверяются как раньше. Ход, где модель не отвечала (`streaming`, `aborted`,
  «готово» без перехваченного вызова), — `not_finished` / `no_model_call` слоя
  инфраструктуры, а не pass. Отказ «не по теме» — короткая фраза: отказ с
  ответом по существу отказом не считается.
- Судья — агент по рубрике `scripts/ai-assistant-eval/JUDGE.md`: читает
  `judge-task.md` папки прогона, пишет `judge.jsonl`; `--report <папка>`
  пересчитывает проверки текущим `checks.mjs` и подмешивает вердикты. Слой стража
  и числа слоя модели при пересчёте считаются по вопросу хода, как в прогоне
  (#3277: раньше `--report` вопрос не передавал и их провалы молча пропадали).
  `--report <папка> --out <другая папка>` пишет пересчитанную копию
  (`meta.json` с `rescoredFrom`), исходный прогон не меняется — так база сравнения
  пересчитывается новыми проверками рядом с новым прогоном. В задании
  — показанный ответ (по нему ставится вердикт) и сырой ответ модели (дефект,
  скрытый пайплайном, — поле `raw_issue`). Отчёт несёт строку «Сверка
  автопроверок с судьёй»: сколько ходов оценено и где автопроверки и судья
  разошлись; `--report` без `--cases` берёт набор самого прогона. У второго и
  следующих ходов диалога в задании стоят реплики предыдущих ходов (#3286):
  уточнение «А какой из них детям?» без них оценить нельзя.
- Отчёт прогона несёт строку «Подсказка модели по месту вопроса» (#3315): у
  скольких ходов с ожиданием места (`expect_sources.pattern`) карточки места
  дошли до модели и у скольких рядом с ними стоят чужие карточки, с ключами
  ходов. Метрики хода — `placeCards` и `foreignCards` в `results.jsonl`;

- Metro отдаёт рабочее дерево с горячей перезагрузкой: правка кода ассистента
  посреди прогона портит замер. «До» меряется на отдельном Metro из worktree
  нужного коммита (конфиг «Assistant Eval Base Web 8085», `--base
  http://localhost:8085 --tree .codex-temp/wt-eval-base`), «после» — на своём
  дереве; модель сравнивается подменой `--model-url`.

  промпт, страж) или пример в набор обучения (`rag_answers`, `offtopic`,

### Путь службы `/ai/ask` (#3286)

Посетитель на проде получит ответ службы `metravel-assist`, а не экрана с
подбором на устройстве: подбор там смысловой, карточки другие, подсказка
длиннее. Этот путь меряет `--provider ask`:

```bash
npm run ai:assistant:eval -- --provider ask --ask-url http://127.0.0.1:8787 \
  --cases scripts/ai-assistant-eval/cases.live.jsonl --label v7-live
```

- Вопрос уходит в службу клиентом экрана — `HttpAskClient` из
  `api/aiAssist/askProvider.ts`: то же тело запроса, тот же разбор SSE и те же
  коды отказа; фильтр тем, подбор по индексу, подсказка, модель и страж
  работают на сервере без подмен (`scripts/ai-assistant-eval/ask-path.mjs`).
  **Сам экран в этом прогоне не участвует**: провайдер вшит в сборку Metro
  (`EXPO_PUBLIC_AI_ASSISTANT_PROVIDER`), Metro контура собран с `llamacpp`, а
  второй Metro на машине контура падает по памяти. Состояния хода, история
  диалога (три последние пары «вопрос — ответ») и показанный текст повторяют
  экран; тест `aiAssistantAskPathParity` держит их равными `useAssistantChat` и
  `AssistantAnswerText`. Playwright и Metro для такого прогона не нужны; Node —
  любой с Node 20.6 через `npm run ai:assistant:eval` (загрузчик
  `scripts/lib/ts-runtime.mjs`), при прямом вызове — 22.18 и новее.
- Служба запускается с `AI_ASSIST_EVAL_TRACE=1`: перед `done` поток несёт
  событие `trace {prompt_sources, raw_text}` — карточки, ушедшие в подсказку
  модели после отбора по месту (#3315) и лимита (`selectPromptSources`), и ответ
  модели до стража ссылок. В `results.jsonl` хода это `modelCall.cards` и
  `modelCall.text` (`provider: "ask"`), показанный ответ — `answerText`, список
  источников посетителя — `sources`, отправленные история и страница —
  `request`. Без переменной события нет (так живёт прод, в образ она не
  попадает); прогон проверяет `/ai/health` и без `eval_trace` не стартует.
- Сырой ответ службы — текст после остановки генератора (цикл, четвёртая
  рекомендация) и до стража: проверки `too_many` и `loop` слоя модели на этом
  пути видят уже обрезанный текст, причины остановки (`finish_reason`) в потоке
  службы нет, поэтому `truncated` не считается. Остальные проверки и слой
  провала — те же `checks.mjs`.
- Поле `source {type, id}` случая (вопрос со страницы статьи или квеста, #2897)
  уходит в запрос; в задании судьи стоит строка «Вопрос задан со страницы…».
- Лимиты службы прогон не срезают: каждый вопрос набора идёт со своего адреса
  посетителя (`X-Real-IP`, как его ставит nginx; у службы `AI_ASSIST_TRUST_PROXY`
  по умолчанию включён), поэтому блок «не по теме» одного вопроса не закрывает
  остальные, а дневной лимит поднят переменной `AI_ASK_DAILY_LIMIT`. Код лимитов
  не меняется.
- `--model-url` в этом режиме — сверка: служба обязана смотреть на эту модель
  (`llm_url` в `/ai/health`), иначе прогон останавливается до первого вопроса.
- Судья ставит на каждый ход три оценки 0–2 — `instruction`, `usefulness`,
  `language` (`JUDGE.md` → «Три оценки»); в задании — карточки службы целиком,
  сырой и показанный ответ, предыдущие реплики диалога. `--report` пишет в
  отчёт «Полезность по судье: средняя из 2; нулей N/M» и не принимает вердикт
  без трёх оценок.
- Набор `cases.live.jsonl` — 64 вопроса посетителя своими словами на
  RU/BE/UK/PL/EN: выходные, «с детьми», «с собакой», «без машины», велосипед,
  сезон, длительность, вопросы о самом сайте, вопросы со страницы статьи и
  квеста (`source`), место без материала, диалоги.

Конфигурации `.claude/launch.json` для приёмки: «AI Accept Assist 8787 (base →
llama 8090)» и «AI Accept Assist 8788 (candidate → llama 8080)» — обе с
`AI_ASSIST_EVAL_TRACE=1` и `AI_ASK_DAILY_LIMIT=100000`, на одном индексе.

### Приёмка кандидата одной командой (#3267)

`npm run ai:assistant:accept -- --base-url <база> --candidate-url <кандидат>`
(Node 20.6 и новее, #3291; два `llama-server`, прокси прод-API и Metro контура) гонит обе
модели через один экран на одинаковых входах и печатает таблицу «замер — база —
кандидат — порог — пройдено»:

| замер | вход | порог (`acceptance.thresholds.json`) |
| --- | --- | --- |
| целевые вопросы экрана ×3 | 9 вопросов `cases.jsonl` из `targets` | каждый ход ≥ 2/3, с судьёй — так же |
| регрессионный срез ×3 | `cases.holdout.jsonl`, 34 вопроса | не ниже базы |
| свежие отложенные ×3 | `cases.holdout-2026-11.jsonl`, 36 вопросов | не ниже базы |
| «не по теме» и попытки сломать | группы `off_topic`, `injection` | 100 % |
| живые вопросы, путь службы | `cases.live.jsonl`, 64 вопроса через `/ai/ask` ×1, судья обязателен | средняя полезность ≥ 1,6 из 2 и нулей ≤ 10 % |
| фиксированные карточки ×3 | `cases.quality.jsonl`, 34 случая | не ниже базы; с судьёй — первый повтор |
| срезы `eval.py` | `scripts/ai-train/eval_prompts/*.jsonl` | offtopic 100 %, osm_intents 9/10, toponyms 8/15, rag_answers не ниже базы |

- Пороги срезов записаны долями и пересчитываются на размер среза; строка с
  выборкой меньше 30 случаев помечается «один ответ меняет вердикт».
- Судья обязателен: команда пишет слепые задания `<папка>/judge/A|B/<прогон>/
  judge-task.md` (метки назначаются по хешам моделей, имён версий и путей в
  задании нет); вердикты кладутся рядом, `--merge-judge <папка>` переносит их в
  прогоны и пересобирает таблицу. До этого итог — «приёмка неполная».
- Примечания таблицы: сколько прошедших ходов обошлись без ответа модели
  (`no_sources`, отказ фильтра — о модели они ничего не говорят), какие вопросы
  стояли в обучении линии адаптера, прежняя метрика среза `osm_intents`.
- Прежний отложенный срез `cases.holdout.jsonl` с круга v9 — регрессионный:
  задел круга выведен из его провалов (h29, v5ln03, v5bd06), отложенным
  свидетельством он больше не считается (заголовок и примечание строки говорят
  это в таблице). Отложенное свидетельство — `cases.holdout-2026-11.jsonl`:
  его вопросы в обучение и в разбор провалов не идут.
- Путь службы (#3286) собирается с `--provider ask --base-ask-url <служба базы>
  --candidate-ask-url <служба кандидата>`: две службы `metravel-assist` на своих
  портах, каждая смотрит на `llama-server` своей стороны. Команда до прогонов
  проверяет у обеих `eval_trace`, модель (`llm_url` против `--base-url` /
  `--candidate-url`) и одинаковый индекс. Строка таблицы показывает среднюю
  полезность и долю нулей у базы и у кандидата; правило — новый тип порога
  `usefulness_at_least {mean, zero_share_max}`. Без `--provider ask` прогон не
  собирается, строка остаётся «не оценено», итог — «приёмка неполная». Экран в
  этой строке не участвует — это записано в шапке таблицы.
- `--plan` печатает прогоны, прерванная приёмка продолжается тем же `--out`,
  `--table <папка>` пересчитывает проверки после правки оценщика. Опись
  оценочных входов — `eval-inventory.json`; правка набора меняет хеш
  (`--freeze`), прогоны до и после несравнимы.

## Известные боли и TODO

- Признак детского квеста в карточке (#3276) модель v7 не использует: на пробе
  с пометкой 0 из 6 ответов выбирают только детский квест. Выбирать по пометке
  учит круг v8 (#3278, `scripts/ai-train/README.md` → «Диагностика остатков v7»).
- Подсказка службы `/ai/ask` длиннее учебных 1024 токенов: медиана 1316 на 30
  живых вопросах при восьми карточках в лимите (раздел «Бюджет подсказки
  службы»). Цель 1100 достигается только без текстового фрагмента карточки;
  длина фрагмента по умолчанию (120 знаков у статьи, 60 у квеста) на модели
  продукта не проверена.
- Новые поля строки фактов («Можно с собакой», «Дней», «Месяцы») модель v7 и v9
  в обучении не видела: в наборах кругов 1–9 их нет (#3287).
- Строку карточки «Почему подходит» и строку «материала о месте нет» (#3289)
  модель в обучении тоже не видела; обе выключаются переменными службы, выбор —
  по живому замеру. Условия проверяются только по фактам каталога: «для
  новичков», «с детьми» для статьи, расстояние («недалеко от», «в пределах часа
  езды») и регион как место («в Татрах») отбор не решает. Когда под числовое
  условие не подходит ничего, карточки остаются в подсказке без пометки — что
  подходящего нет, должна сказать модель.
- Страж содержания (#3291) не ловит выдуманную фразу без числа и без слов соседней
  карточки и не сверяет дни, километры и годы; пояснение и числа проверяются по
  готовому ответу, поэтому в стриме неподтверждённая фраза видна до последнего
  события `text`.

- Подбор для не-RU локали слаб: `/api/travels/?query=` ищет по русскому
  контенту, а слова вопроса на PL/EN/BE/UK в него не попадают; квесты матчатся по
  переведённым названиям. «Co zobaczyć w Polsce w trzy dni?» дал один квест по
  Бресту (по «trzy dni»). Лечится смысловым индексом (#2454/#2456) или
  переводом ключевых слов на RU перед поиском.
- Стоп-слова подбора ведутся списком на пяти языках (`QUERY_STOPWORDS`, #3315): слово
  вне списка по-прежнему может поднять чужую карточку в список источников, в подсказку
  модели её не пускает отбор по месту.

- Боли подбора по словам выше касаются только провайдера `llamacpp`; у `ask`
  подбор идёт по смысловому индексу службы.
- Лимит и журнал на устройстве — только у `llamacpp`; у `ask` — на IP на сервере.
- Оценочный набор 40 вопросов на GGUF v1 (#2463, `eval.py --server`): без карточек
  в промпте модель проходит 9/40 как и MLX-адаптер (ссылки по городу/стране выдумывает),
  с карточками — все URL из списка (Гродно 8/8); поэтому подбор карточек обязателен.
- На CPU `llama-server` обрабатывает промпт медленно (~46 ток/с при 4 потоках на M5 Pro,
  генерация ~26 ток/с): 8 карточек + история ≈ 3 тыс. токенов → TTFT около минуты;
  для прод-сервера без GPU промпт нужно держать коротким (≤ 500–800 токенов) или
  ограничить число карточек — числа в `scripts/ai-train/README.md` → «Экспорт в GGUF».
