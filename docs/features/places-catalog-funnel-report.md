# Вход и действия в каталоге «Места»

Задача #3448 измеряет `/places`, отдельно от карты `/map` (#3044) и справки
`/places/help`. Сравнение трёх функций и 28-дневный повтор остаются в #3450.

## События и источники

Все события имеют `event_category=places_catalog`, `event_label=source`.
`source` принимает только `desktop_navigation|mobile_menu|direct`. В GA4
транспорт передаёт его как `ui_source`; отчёт использует уже зарегистрированный
`event_label`, а не рекламный `sessionSource`.

| Событие | Когда | Дополнительные параметры |
| --- | --- | --- |
| `places_catalog_impression` | видна хотя бы половина настоящей ссылки в desktop-навигации или открытом мобильном меню; один раз за её монтирование | нет |
| `places_catalog_entry` | обычная активация ссылки через общий обработчик навигации | нет |
| `places_catalog_opened` | каталог получил фокус и восстановил URL-параметры; один раз на открытие/изменение источника, без повторов от фильтров и рендеров | нет |
| `places_catalog_search` | непустой поиск с текущими фильтрами получил окончательный результат | `outcome=found|empty|error`; `results_count` — целое ≥0, только при успешном ответе |
| `places_catalog_collection` | выбранная подборка передана в существующий обработчик фильтров | `action=collection`, `first_action=0|1` |
| `places_catalog_open_map` | активирован переход с допустимыми координатами | `action=open_map`, `first_action=0|1` |
| `places_catalog_open_travel` | начат внутренний переход к статье либо существующий helper подтвердил открытие внешней ссылки | `action=open_travel`, `first_action=0|1` |

`first_action` отмечает первое из трёх действий текущего открытия, а не
уникального посетителя или сеанс. Отдельные имена действий позволяют читать
GA4 без регистрации дополнительного измерения `action`. Для разреза по
`first_action` в GA4 потребуется отдельное измерение; текущий отчёт на него
не опирается.

В реальные web-ссылки добавляется только конечный
`places_source=desktop_navigation|mobile_menu`; язык, остальные параметры и
фрагмент сохраняются. Это поддерживает открытие в новой вкладке. Такой переход
может иметь `opened` без `entry`, поскольку модифицированный клик обрабатывает
сам браузер. Прямая ссылка без метки или неизвестная метка получают `direct`.
Копирование уже помеченной ссылки сохраняет источник: это атрибуция ссылки,
а не доказательство того, что новый читатель видел меню.

## Поиск, согласие и приватность

Пока меняется ввод, работает пауза поиска, остаются предыдущие данные или идёт
запрос, результат не отправляется. Одна комбинация поиска, категории, страны и
сортировки даёт один окончательный исход. Пагинация и фоновый refetch не создают
новый поиск. После ошибки успешный повтор даёт один новый `found`/`empty`;
повторный ошибочный рендер не создаёт повторного события. Очистка и новый ввод
начинают новое измерение.

Текст поиска, категории/страны, названия, адреса, координаты, URL статьи и
локальный ключ сопоставления не передаются в параметры этих событий. Ключ
остаётся только в памяти хука. Граница focus — текущий экран навигатора
приложения: сохранённый неактивный экран каталога не отправляет свои события;
возврат начинает новое открытие и учёт первого действия. Общий сбор page URL —
отдельный существующий контракт счётчиков: добавляемый здесь параметр содержит
только конечный источник.

Отправка идёт через существующий `sendAnalyticsEvent`: GA4 и Метрика получают
события только при согласии на аналитику и вне автоматизации. До проверки
доставки событие видно через `metravel:analytics-intent`; браузерная приёмка
не создаёт органические наблюдения. Native-экраны не отправляют новые события.

## Повторяемый отчёт GA4 Data API

Property: `362328641`. Указать абсолютный период **полных дней** Europe/Minsk
после публикации. Общий фильтр для всех этапов:

```json
{
  "andGroup": {
    "expressions": [
      { "filter": { "fieldName": "hostName", "stringFilter": { "matchType": "EXACT", "value": "metravel.by" } } },
      { "filter": { "fieldName": "customEvent:event_category", "stringFilter": { "matchType": "EXACT", "value": "places_catalog" } } }
    ]
  }
}
```

Не добавлять фильтр `pagePath=/places` ко всем этапам: показ ссылки происходит
на предыдущей странице. Сначала получить строки по
`eventName,customEvent:event_label,deviceCategory,customEvent:outcome` с
`eventCount,totalUsers,sessions`. Проверить metadata, полный rowCount/пагинацию,
sampling, subjectToThresholding и dataLossFromOtherRow. Неизвестные значения
оставить отдельными; не приписывать их известному источнику.

Для сеансовых итогов выполнить **отдельные** запросы с тем же общим фильтром,
периодом и измерениями `customEvent:event_label,deviceCategory`, метрикой
`sessions` и следующим фильтром eventName:

| Итог | Фильтр |
| --- | --- |
| E — наблюдаемые показы | EXACT `places_catalog_impression` |
| C — активации | EXACT `places_catalog_entry` |
| O — открытия | EXACT `places_catalog_opened` |
| A — полезное действие | IN_LIST `places_catalog_open_map,places_catalog_open_travel` |
| Подборки, отдельно | EXACT `places_catalog_collection` |
| Поиск с результатом, отдельно | EXACT `places_catalog_search` и outcome EXACT `found` |

В запрос A не включать eventName в группировку: суммы сеансов по двум действиям
могут повторно посчитать один сеанс. Подборка и успешный поиск — промежуточные
действия; основной результат для #3450 — переход на карту или статью.
`first_action` не нужен для объединения сеансов.

Для конверсии среди открывших знаменатель — сеансы O, числитель — O∩A:
те же сеансы с открытием каталога и хотя бы одним переходом на карту или статью.
Нужен сеансовый сегмент GA4 с обоими условиями в одном сеансе. Независимые
агрегаты A и O не доказывают пересечение и не делятся для получения этой
конверсии. Если пересечение недоступно, доля остаётся неизвестной (`null`).
Разные границы окна/согласия и переход через полночь учитываются явно.
Пустой знаменатель — `null`, не 0%. Не складывать totalUsers разных строк.
`direct` не имеет размеченного показа E: его видимость неизвестна, а не равна 0.

## Метрика

Счётчик `62803912`, календарь Europe/Minsk, тот же период. Для семи событий
нужны одноимённые JavaScript-цели; наличие цели и параметры проверяются при
публикации. Визитный сегмент открытия задаётся достижением
`places_catalog_opened`. Числитель — **те же визиты** с достижением
`places_catalog_open_map` **или** `places_catalog_open_travel`, без суммы двух
пересекающихся групп. Параметры `source/event_label` задают продуктовый вход,
тип устройства — web-разрез. Сравнивать с GA4 отдельно: идентификаторы,
согласие и охват двух систем различаются.

Новые цели не восстанавливают исторические наблюдения. Число достижений цели
и число целевых визитов — разные метрики. Сначала проверить параметры
событий/визитов и фактическую доступность разреза; при недоступном источнике
оставить его неизвестным, не подменять рекламным каналом визита.

## Начало наблюдения и приёмка

Дата начала определяется опубликованным SHA и проверкой этой карточки в
`testing`; до этого новые события не считаются работающими на production.
Первый полный день после принятого выката — старт наблюдения для #3450.
Точные SHA, дата, готовность целей/измерений и результат первого API-запроса
фиксируются в #3448. Нулевая органическая выборка сразу после выката допустима,
но сама по себе не доказывает, что люди не выполняют действия.

Приёмка: на mobile web закрытое меню не создаёт показ; после открытия видимая
ссылка даёт один показ и один обычный переход. В каталоге проверить подборку,
поиск с найденным и пустым ответом, переход на карту и статью. Ошибку/повтор,
пагинацию, отменённый запрос и приватность проверяют целевые Jest на настоящем
слое запросов; повторять их сетевыми сбоями на production не требуется.
Desktop проверяет отдельную границу видимости горизонтальной навигации.
На `/map` и `/places/help` без активного каталога отсутствуют его
`opened/search/collection/open_map/open_travel`. Видимая глобальная ссылка на
каталог может дать navigation impression на предыдущей странице; её обычная
активация — navigation entry. Эти события учитываются отдельно от контекста
каталога и не требуют общего фильтра `pagePath=/places`.
