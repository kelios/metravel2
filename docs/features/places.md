# Фича: places

**Последняя актуализация:** 2026-11-08
**Ответственный домен:** frontend map/places

## TL;DR

`/places` - каталог отдельных точек сайта, а не путешествий. Пользователь выбирает страну,
категорию или поиск, видит карточки мест, открывает конкретную точку на карте или переходит
к путешествию, где эта точка используется.

## Точки входа

| Путь | Назначение |
| --- | --- |
| `app/(tabs)/places.tsx` | route/tab entry |
| `screens/tabs/PlacesScreen.tsx` | экран каталога, фильтры, пагинация, переходы |
| `screens/tabs/usePlacesCatalogController.ts` | состояние экрана: поиск, фильтры, статусы списка |
| `screens/tabs/usePlacesCatalogQueries.ts` | слой данных: запрос списка и его проекции в кэше |
| `api/places.ts` | клиент серверного каталога `GET /api/places/catalog/` |
| `utils/placesCatalog.ts` | разбор ответа каталога: места, итог, фасеты |
| `components/places/PlaceListCard.tsx` | карточка места |

## Контракт продукта

- Показываем именно places/точки из координат путешествий, не карточки путешествий.
- По умолчанию показываем полезную подборку: замки, дворцы, экотропы, колесо обозрения,
  водохранилища, озера, реки и ручьи.
- Без URL-параметра `category` каталог показывает стартовую подборку при пустом
  поиске и ищет по всем категориям при непустом `q`. Явный выбор сохраняется
  при очистке запроса, а пустой `?category=` закрепляет все категории.
  «Сбросить» атомарно очищает `q`, `category`, `country` одним обновлением
  адреса и оставляет все категории.
- Фильтр стран находится выше категорий и влияет на категории, счетчики и список мест.
- `Все` показывает полный каталог, но UI не должен рендерить все карточки сразу:
  список раскрывается порциями по `20` мест при скролле/кнопке дозагрузки.
- Карточка места должна иметь два основных действия:
  - `На карте` - открыть `/map` с координатами точки и малым радиусом фокуса;
  - `Прочитать` - открыть внутренний travel route, а для внешнего URL использовать
    только helpers из `utils/externalLinks.ts`.
- Ряд действий карточки (#2778, `PLACE-CARD-ACTION-OVERLOAD`, проп `actionBudget`
  у `PlaceListCard`; так же у «Мест рядом» на карте): не больше трёх плиток ВСЕГО,
  включая вход в лист — `Прочитать`, `На карте`, `Навигация` (на карте:
  `Открыть`, `Маршрут`, `Навигация`). «Сохранить» в ряду нет: точку сохраняет ♥
  на фото (08.11.2026), освободившийся слот берёт следующее основное действие.
  Навигаторы, `Скопировать координаты`, Telegram и не влезшие основные — пункты
  листа «Навигация и действия». Четыре плитки на 320 резали подписи;
  у трёх под подпись ≈70px — самая длинная («Navigation», 10 симв.) ≈60px. У гостя ♥ места активен и ведёт
  на вход с возвратом (`intent=save-point`), а не серый. Тап по фото равен тапу по
  карточке, поэтому значка «развернуть» на фото нет. Форму ряда держит
  `npm run guard:screen-actions`.

## Данные

Каталог серверный: `fetchPlacesCatalog` запрашивает `GET /api/places/catalog/` с
`page`, `perPage`, `q`, `category` (несколько значений, фильтр «или»), `country`,
`sort` и разбирает ответ через `mapPlacesCatalogResponse`. В ответе `results`
(страница мест, сгруппированных бэкендом по идентичности места), `count` (итог
под текущими фильтрами) и `facets` (число мест по категориям и странам).

Меню сортировки сохраняет варианты по умолчанию и по среднему рейтингу.
«По названию» упорядочивает названия мест без учёта регистра; «По числу
оценок» и «По числу статей» показывают сначала места с большими числами.
Каталог сортирует уже сгруппированные места на сервере до пагинации,
сохраняет страну, категории и поиск и при смене порядка начинает с первой
страницы. Для одинакового значения порядок стабилен. Число статей учитывает
доступные читателю источники.

Разбор на клиенте обязан:

- отбрасывать записи без валидных координат и без id;
- брать `title` из ответа, при пустом — адрес;
- подставлять «Другое» и «Страна не указана» для пустых категории и страны.

`facets` бэкенд считает по УЖЕ отфильтрованной выборке. Пока категории не
выбраны, ответ списка несёт итог и фасеты всего каталога (под текущими поиском и
страной). С выбранными категориями фасеты сужены до совпавших мест, а панели
категорий нужен полный набор — он берётся из кэша или одним запросом без
категорий.

## Мои точки: контракт данных

Личная коллекция `/userpoints` (`components/UserPoints/usePointsDataModel.ts`)
живёт в кэше React Query под общим ключом `userPointsAll(owner)` и делится с
♥-тогглом карты (`hooks/map/useSavedPointToggle.ts`,
`hooks/useSavedPointsCollection.ts`) и мастером travel
(`components/travel/hooks/usePointListAddPointModel.ts`). Решение владельца
08.11.2026 (#3161): «пины + детали по ids».

- Коллекция = лёгкие пины всех точек владельца одним запросом
  `GET /api/user-points/?fields=pins` (#3129): `id, latitude, longitude, color,
  status, category, category_ids` (~110 байт на точку; 2656 точек владельца —
  ~290 КБ / ~38 КБ gzip) вместо 1,1 МБ полных карточек четырнадцатью
  страницами. Тип — `UserPointPin` (`types/userPoints.ts`). Мутации пишут в
  коллекцию ту же форму (`components/UserPoints/userPointPin.ts`).
- На клиенте по пинам считаются: карта и кластеры (#3131), цвет, статус,
  радиус от геолокации, категории сайта (`category_ids`; у пина без связей —
  имя `category` через словарь имён → id), фасеты, пресеты, выделение и
  массовые действия, рекомендации, автофит карты.
- Поиск — серверный (`GET …?fields=pins&search=`, ключ
  `userPointsSearch(owner, query)`): названия, адреса и заметки в пинах не
  живут. Прежний результат держится до ответа (`placeholderData`), вкладка
  «Список» показывает «…» (`isSearching`); результат сужает коллекцию до
  найденных id, остальные поля берутся из коллекции (она свежее после
  оптимистичных правок). Упавший поиск — состояние ошибки с «Повторить», а не
  вся коллекция; геокодинг пустого результата ждёт ответа поиска.
- На телефоне (< 768) точка в списке — компактная строка `PlaceListRow`
  (миниатюра 72 px, категория, название, адрес; действия в «⋯»), шесть точек
  на экран; раскладка — `docs/design/userpoints-panel.md` (#3142).
- Полные карточки (название, адрес, фото, заметки) — окном: карточка списка и
  открытый попап заказывают свою запись у `userPointDetailsStore`
  (`components/UserPoints/userPointDetailsStore.ts`), store склеивает заказы
  одного кадра в `GET /api/user-points/?ids=…` (#3172, ≤ 200 id за запрос,
  пачки по 60) и хранит записи вне React Query (`useSyncExternalStore`). До
  прихода записи карточка рисует каркас той же геометрии
  (`PointSkeletonCard`), попап — «Загрузка…» без правки и удаления. Поля пина
  (цвет, статус, координаты) новее карточки и перекрывают её. Правка,
  создание, удаление и массовые действия обновляют store точечно
  (`upsert`/`patch`/`remove`) и инвалидируют результаты серверного поиска
  (`userPointsSearch`); импорт и смена владельца очищают store, и
  смонтированные карточки заказывают записи заново. Упавший запрос `ids=` store
  повторяет сам (2/4/8 с, три попытки). Id, которого сервер не вернул (точка
  удалена с другого устройства), помечается `gone`: карточка рисует пин без
  каркаса, модель перечитывает коллекцию (не чаще раза в 30 с). Подпись маркера
  на web (title/aria) и native-callout — из `name` пина (#3185); пин без `name`
  подписывается «Точка».
- Коллекция пинов персистится СВОИМ ключом storage
  (`utils/userPointsPersist.ts`, `metravel-rq-userpoints`, buster `v2`), а не
  в общем снимке `metravel-rq-cache`: запись только на события самой
  коллекции, потолок 10 000 точек; серверный поиск не персистится. Холодный
  заход открывает карту и список из кэша, затем один запрос пинов освежает
  коллекцию.
- Потребители вне экрана читают тот же ключ тем же запросом пинов; пока
  коллекция не прочитана, кэш не доказывает отсутствие точки — ♥-тоггл
  дожидается чтения (`fetchQuery`, дедупликация React Query) и только потом
  создаёт точку. Отметки полноты/докачки (#1706/#1709/#3130) больше нет:
  пины приходят целиком одним ответом.
- Время в пути до точки (OSRM) считает один хук `useDriveInfoQuery` (React
  Query, ключ «геолокация ~10 м → точка», 10 минут): активная карточка списка
  и открытый попап карты делят один запрос (#3135; раньше два хука слали два
  одинаковых запроса на клик). Тип `DriveInfo` — один, в `types/userPoints.ts`.
- Имена параметров фильтра — серверные (`color`, `status` — одиночные;
  `categories=1,2` — только числовые id; `search`; `ordering` из `sortBy`/
  `sortOrder`, `distance` не уходит). Серверный контракт области карты
  (`bbox`/`zoom`, #3129) экраном не используется: при выбранном варианте
  кластеры считаются на клиенте по пинам.

## Запросы каталога

Каждый запрос каталога — серверный расчёт фасетов, группировки и итога, поэтому
экран не шлёт запрос за тем, что уже лежит в ответе списка (#2184; 04.10.2026
шесть параллельных запросов на открытие и повторы после таймаута стали частью
остановки API, #2183). Правило слоя `usePlacesCatalogQueries` — «один ресурс
каталога = один запрос»:

- Сам по себе уходит только запрос списка. Открытие `/places` — один
  запрос; смена подборки, категории, страны или сортировки — один запрос; поиск —
  один запрос на паузу ввода (`PLACES_SEARCH_DEBOUNCE_MS`), а не на символ.
  Очищенный поиск и «Сбросить» применяются сразу, без запроса промежуточного
  состояния. С выбранными категориями смена поиска или страны — запрос списка
  и после его ответа запрос объёма, если его нет в кэше: два расчёта подряд.
  На web параметры адреса применяются после гидратации; до их применения запрос
  выключен, а первый кадр совпадает с SSG без параметров: категории, страна,
  поиск и статус загрузки фильтров нейтральны (`?category=` иначе давал React
  #418, #2406). При `?q=` он ждёт и применения значения после паузы ввода: первым
  уходит сразу отфильтрованный список, без предварительного общего списка.
- Итог каталога и фасеты («объём без категорий») — проекция первой страницы
  списка в кэше. Отдельный запрос объёма (`perPage=1` без категорий) допустим,
  только когда проекции в кэше нет (заход по ссылке с `?category=`), и только
  после успешного ответа списка, не параллельно с ним. Инвалидация каталога
  (блок автора) без выбранных категорий перечитывает только список: объём
  заново заполнит его первая страница.
- Для неявной стартовой подборки полный объём сначала читается только из
  совпадающего кэша. Первый фокус поиска, открытие стран или категорий запрашивает
  недостающий объём после успешного ответа списка. Прямой URL с явным `category`
  сохраняет последовательную загрузку объёма. Отфильтрованный ответ никогда не
  выдаётся за весь каталог; старый объём другого поиска/страны не подставляется.
  Неизвестные числа остаются пустыми, ошибка фильтров даёт кнопку «Повторить»;
  якорь стран доступен и во время загрузки. Повтор перечитывает только объём,
  либо сначала список, если его первая загрузка завершилась ошибкой.
- Числа всех «Интересных подборок» на измеренной ширине web ≥760 px загружаются
  одним `GET /api/places/catalog/category-groups/` после успешного, не
  placeholder-ответа списка. Параметры — выбранная `country` и повторяемые
  `group=<id>:<категории через запятую>`; ответ — `{groups: [{id, count}]}`.
  До измерения ширины, на mobile и native запрос агрегата не уходит.
  Блок «Интересные подборки» на ширине < 760 px и на native не показывается
  совсем — решение владельца продукта 11.10.2026 (#2406), сохраняющее
  ограничение #2223: узкий экран отдаёт место списку и стартовой подборке, а
  открытие каталога остаётся одним запросом списка (#2184) без агрегата. Поиск `q`
  не меняет агрегат: его кэш ограничен страной и точным составом групп.
- `count` успешно открытого списка по категориям подборки уточняет её число
  только без поискового текста и только в совпадающем scope страны/групп.
  Частичная проекция списка хранится отдельно от агрегата и не отменяет первый
  агрегированный запрос. Поздний агрегат не перезаписывает валидное уточнение.
  Placeholder старого фильтра/страны не заполняет новый scope. При сбое агрегата
  неизвестные числа остаются пустыми; честный ноль из ответа показывается.
  Сумма фасетов счётчиком не является: место с двумя категориями учитывается
  один раз бэкендом. Отдельных запросов на каждую подборку нет.
- Повторы — общая политика `heavyReadRetry` (`utils/queryRetryPolicy.ts`): не
  больше одного и только когда сервер этот запрос уже не считает (обрыв
  соединения, 502, 503 — его каталог отдаёт с `Retry-After: 1`, когда расчёт не
  уложился в бюджет). Таймаут и 504 не повторяются: сервер досчитывает брошенный
  запрос. Числовой `retry` у запросов каталога запрещён.
- Сбой первой загрузки — блок ошибки с кнопкой «Повторить» (один запрос). Сбой
  дозагрузки следующей страницы — список остаётся, в подвале текст ошибки и
  «Повторить» только для этой страницы; автодогрузка по скроллу после сбоя
  выключена.

Регрессию держит `__tests__/screens/usePlacesCatalogController.requests.test.tsx`.

## UI-правила

- Использовать существующие `Button`, `Chip`, `ImageCardMedia` и дизайн-токены.
- Не добавлять emoji-иконки и декоративные плейсхолдеры.
- Состояния loading/error/empty/list должны иметь стабильную геометрию без скачков.
- Строка итога под заголовком резервирует одну строку во всех состояниях.
  Первая загрузка и смена фильтра/поиска с placeholder показывают существующий
  локализованный индикатор загрузки, а не прежнее число под новым заголовком.
  При первой ошибке число неизвестно, строка остаётся пустой; `0` показывается
  только после успешного пустого ответа. Загрузка следующей страницы не
  заменяет известный итог первой страницы индикатором.
- Карточка места должна использовать тот же point/place template, что popup
  карты и карточка точки в travel details: доминирующее фото, затем название,
  координаты с copy, переход к связанному путешествию/странице, раскрываемая
  навигация и "мои точки" при доступности.
- Если у карточки/попапа есть координаты, набор навигации не сокращается до
  Google: показывай Google Maps, Apple Maps, Organic Maps/offline, Waze,
  Яндекс Карты, Яндекс Навигатор и OpenStreetMap. Telegram/share только
  дополнительное действие.
- Для мест, связанных с travel, статус должен быть явным: "Был здесь",
  "Хочу поехать", "Планирую" или компактная кнопка "Был / Хочу / Планирую".
- ♥ на фото карточки/попапа места сохраняет ЭТУ точку в «Мои точки» (решение
  владельца 08.11.2026): тот же переключатель по координате, что прежнее
  «Сохранить», у каждой точки своё состояние. Отдельной плитки/чипа
  «Сохранить» нет. Статья в «Хочу поехать» с карточки места не сохраняется:
  раньше ♥ сохранял статью-источник, и все точки одной статьи загорались разом.
  Статус «Был / Хочу / Планирую» остаётся за статьёй. Карточка без сохранения
  точки (сами «Мои точки») сохраняет прежний ♥ статьи. Поверхности: `/places`,
  «Места рядом» и «Популярное рядом» на карте, попап карты, точки статьи;
  везде второй тап по залитому ♥ убирает точку. Общий вид ♥ —
  `HeartToggleButton`, ♥ места — `PlaceSaveHeartButton`, проп `placeSave` у
  `RelatedTravelActionStack`.
- Mobile web, Android и iPhone не должны расходиться визуально или по поведению;
  это design-инвариант. Платформенные отличия допустимы только для safe area,
  map engine и нативных API.
- После видимых общих изменений проверять desktop/mobile web в браузере.
  Локальная Android USB-сборка нужна при изменении Android map engine, intents,
  system Back или другого Android-specific behavior; iPhone evidence — только
  при iOS-specific behavior.

## Обсуждение места

- В каталоге действие «Комментарии» открывает отдельную панель с названием
  места. Оно расположено рядом с блоком оценок и не вытесняет основные
  действия карточки. На узком экране — панель с доступным закрытием и полем
  ввода над клавиатурой; на широком — диалог с прокруткой списка и возвратом
  фокуса к кнопке карточки. Используем существующие диалог, форму и действия
  модерации.
- Список загружается при открытии: состояния загрузки, пустого списка, списка
  с продолжением и ошибки с повтором. Гость читает и видит вход для отправки;
  вошедший пользователь публикует обычный текст и может удалить свой
  комментарий. Ошибка отправки сохраняет черновик, пока панель открыта.
  Жалоба и блокировка доступны через общий механизм безопасности.
- Комментарии принадлежат месту, а не статье или оценке. При перелистывании
  материалов обсуждение не меняется. Для нескольких точек одного канонического
  места сервер возвращает один список; неподтверждённые точки не объединяются.
  В первой версии нет ответов, реакций и вложений.

## Поиск и область выдачи

Заголовок выдачи показывает область поиска. При пустой выдаче с явно
выбранными категориями доступны расширение поиска и общий сброс.

| Состояние | Что видит и может сделать человек |
| --- | --- |
| Вход в каталог без поиска и явной категории | Стартовая подборка для просмотра |
| Введён запрос без явной категории | Выдача по всем категориям в выбранной стране; под строкой поиска видно «Все категории» |
| Человек сам выбрал категории | Их названия видны рядом с выдачей на телефоне и компьютере; поиск остаётся внутри выбора |
| В выбранных категориях ничего нет | Кнопка «Искать во всех категориях» снимает только категории; запрос, страна и порядок сохраняются |
| Поиск очищен | Без явной категории возвращается стартовая подборка; явный выбор или «Все категории» остаётся |
| Сбой запроса | Повторить запрос можно с теми же введённым текстом и фильтрами |

Контрольные сценарии: известное место за пределами подборки, место внутри
подборки, ссылка с явной категорией, снятие категории при пустой выдаче,
возврат из статьи и очистка запроса. Изменение не добавляет фильтр расстояния,
новый экран, новые серверные параметры или дублирующий запрос при открытии.

## Акция «Допишем Беларусь вместе» (спринт 38)

Редакционные приглашения рассказать о месте Беларуси. Серверный контракт — #3093

| Путь | Назначение |

| `app/(tabs)/places/help.tsx` | маршрут подборки; `generateMetadata` без `robots` с #3098 (индексируется), один canonical |
| `components/places/PlaceRequestsScreen.tsx` | экран подборки, фильтр областей, карточки, `InstantSEO` без `robots` |

| `utils/placeRequestsConfig.ts` | пилот только web (`EXPO_PUBLIC_BELARUS_PLACE_CONTRIBUTIONS !== 'false'`) |

Приглашения — данные production (`place` + `place_request`), не код. Первая волна
(#3098) — восемь карточек четырёх областей, вторая (#3116) — восемь по измеренному
спросу (просмотры ru.wikipedia, показы GSC, сверка с каталогом), приоритеты 22…15.
Новая волна: иллюстрация 960×640 WebP в `public/assets/images/place-contributions/`
(регистрация в `scripts/guard-public-files.js`), выкат web, затем на развёрнутом
Django создание `Place` и `PlaceRequest` с `full_clean`, переводами `name_translations`
и `prompt_translations` (be/uk/pl/en) и полным `preview`; сначала прогон в транзакции
с откатом и выводом канонических точек в радиусе 1 км. Метод отбора и список —
`openspec/changes/add-belarus-place-contributions/pilot-research.md`.

История места и призыв (#3140/#3141, решение владельца 08.11.2026). У приглашения
есть редакционное описание места: `description` + `description_translations`
(be/uk/pl/en, ≤1500 знаков), API отдаёт `description` по `Accept-Language` так же,
как `prompt`; пустое описание — нормальное состояние, карточка его не показывает.
В подборке описание обрезается до четырёх строк со ссылкой «Подробнее о месте»
(переход в `?request=<uuid>`), в детальном режиме и на карте — целиком. Главная
кнопка — «Рассказать о поездке» (полная статья, формат редактора по умолчанию),
заметка вторична. Страница обещает: лучшие истории покажем в Instagram
@metravelby и отметим автора только с его согласия — согласие собирает письмо о
публикации вклада (#3106, ответ «да»). Тексты описаний пишутся по ≥2 независимым
источникам на факт, без запрещённых в РБ изданий.

Внешние ссылки акции несут `utm_campaign=belarus_place_stories`
(`utm_source=instagram`, `utm_medium=organic_social|story`, `utm_content` по
формату) — полный пакет и календарь в `docs/design/belarus-place-contributions.md`
→ «Пакет запуска». `robots.txt` закрывает `/*?utm_*`; sitemap остаётся
backend-owned, подборка в него не входит.

Еженедельная сводка пилота (#3107) считается на сервере по приглашениям,
привязанным черновикам, публикациям, зачётам, медалям и новым авторам, без

Как читать: `requests[]` — по каждому приглашению `status`, `drafts`, `pending`,

## Проверки

Для изменений только в каталоге мест:

```bash
npm run check:fast
```

До него запускаются ближайшие tests для `api/places.ts`,
`utils/placesCatalog.ts` и `PlaceListCard` по затронутому scope. Видимый web UI
проверяется в desktop/mobile браузере; native point/place flow проверяется на
той платформе, чьё platform-specific поведение изменено.

Если меняются переходы `На карте` / `Прочитать`, дополнительно:

```bash
npm run guard:external-links
npm run governance:verify
```
