# Фича: places

**Последняя актуализация:** 2026-10-04
**Ответственный домен:** frontend map/places

## TL;DR

`/places` - каталог отдельных точек сайта, а не путешествий. Пользователь выбирает страну,
категорию или поиск, видит карточки мест, открывает конкретную точку на карте или переходит
к путешествию, где эта точка используется.

## Точки входа

| Путь | Назначение |
| --- | --- |
| `app/(tabs)/places.tsx` | route/tab entry |
| `screens/tabs/PlacesScreen.tsx` | экран каталога, фильтры, пагинация, переходы |
| `screens/tabs/usePlacesCatalogController.ts` | состояние экрана: поиск, фильтры, статусы списка |
| `screens/tabs/usePlacesCatalogQueries.ts` | слой данных: запрос списка и его проекции в кэше |
| `api/places.ts` | клиент серверного каталога `GET /api/places/catalog/` |
| `utils/placesCatalog.ts` | разбор ответа каталога: места, итог, фасеты |
| `components/places/PlaceListCard.tsx` | карточка места |

## Контракт продукта

- Показываем именно places/точки из координат путешествий, не карточки путешествий.
- По умолчанию показываем полезную подборку: замки, дворцы, экотропы, колесо обозрения,
  водохранилища, озера, реки и ручьи.
- Фильтр стран находится выше категорий и влияет на категории, счетчики и список мест.
- `Все` показывает полный каталог, но UI не должен рендерить все карточки сразу:
  список раскрывается порциями по `20` мест при скролле/кнопке дозагрузки.
- Карточка места должна иметь два основных действия:
  - `На карте` - открыть `/map` с координатами точки и малым радиусом фокуса;
  - `Прочитать` - открыть внутренний travel route, а для внешнего URL использовать
    только helpers из `utils/externalLinks.ts`.

## Данные

Каталог серверный: `fetchPlacesCatalog` запрашивает `GET /api/places/catalog/` с
`page`, `perPage`, `q`, `category` (несколько значений, фильтр «или»), `country`,
`sort` и разбирает ответ через `mapPlacesCatalogResponse`. В ответе `results`
(страница мест, сгруппированных бэкендом по идентичности места), `count` (итог
под текущими фильтрами) и `facets` (число мест по категориям и странам).

Разбор на клиенте обязан:

- отбрасывать записи без валидных координат и без id;
- брать `title` из ответа, при пустом — адрес;
- подставлять «Другое» и «Страна не указана» для пустых категории и страны.

`facets` бэкенд считает по УЖЕ отфильтрованной выборке. Пока категории не
выбраны, ответ списка несёт итог и фасеты всего каталога (под текущими поиском и
страной). С выбранными категориями фасеты сужены до совпавших мест, а панели
категорий нужен полный набор — он берётся из кэша или одним запросом без
категорий.

## Запросы каталога

Каждый запрос каталога — серверный расчёт фасетов, группировки и итога, поэтому
экран не шлёт запрос за тем, что уже лежит в ответе списка (#2184; 04.10.2026
шесть параллельных запросов на открытие и повторы после таймаута стали частью
остановки API, #2183). Правило слоя `usePlacesCatalogQueries` — «один ресурс
каталога = один запрос»:

- Сам по себе уходит только запрос списка. Открытие `/places` без фильтров — один
  запрос; смена подборки, категории, страны или сортировки — один запрос; поиск —
  один запрос на паузу ввода (`PLACES_SEARCH_DEBOUNCE_MS`), а не на символ.
  Очищенный поиск и «Сбросить» применяются сразу, без запроса промежуточного
  состояния. С выбранными категориями смена поиска или страны — запрос списка
  и после его ответа запрос объёма, если его нет в кэше: два расчёта подряд.
- Итог каталога и фасеты («объём без категорий») — проекция первой страницы
  списка в кэше. Отдельный запрос объёма (`perPage=1` без категорий) допустим,
  только когда проекции в кэше нет (заход по ссылке с `?category=`), и только
  после успешного ответа списка, не параллельно с ним. Инвалидация каталога
  (блок автора) без выбранных категорий перечитывает только список: объём
  заново заполнит его первая страница.
- Счётчик подборки («Интересные подборки») — `count` списка, открытого по её
  категориям. Отдельных запросов-счётчиков нет, сумма фасетов счётчиком не
  является (место с двумя категориями подборки посчиталось бы дважды), клиент
  число не выдумывает: до открытия подборки место под счётчик пустое. Счётчики
  всех подборок сразу — только одним агрегированным запросом бэкенда.
- Повторы — общая политика `heavyReadRetry` (`utils/queryRetryPolicy.ts`): не
  больше одного и только когда сервер этот запрос уже не считает (обрыв
  соединения, 502, 503 — его каталог отдаёт с `Retry-After: 1`, когда расчёт не
  уложился в бюджет). Таймаут и 504 не повторяются: сервер досчитывает брошенный
  запрос. Числовой `retry` у запросов каталога запрещён.
- Сбой первой загрузки — блок ошибки с кнопкой «Повторить» (один запрос). Сбой
  дозагрузки следующей страницы — список остаётся, в подвале текст ошибки и
  «Повторить» только для этой страницы; автодогрузка по скроллу после сбоя
  выключена.

Регрессию держит `__tests__/screens/usePlacesCatalogController.requests.test.tsx`.

## UI-правила

- Использовать существующие `Button`, `Chip`, `ImageCardMedia` и дизайн-токены.
- Не добавлять emoji-иконки и декоративные плейсхолдеры.
- Состояния loading/error/empty/list должны иметь стабильную геометрию без скачков.
- Карточка места должна использовать тот же point/place template, что popup
  карты и карточка точки в travel details: доминирующее фото, затем название,
  координаты с copy, переход к связанному путешествию/странице, раскрываемая
  навигация и "мои точки" при доступности.
- Если у карточки/попапа есть координаты, набор навигации не сокращается до
  Google: показывай Google Maps, Apple Maps, Organic Maps/offline, Waze,
  Яндекс Карты, Яндекс Навигатор и OpenStreetMap. Telegram/share только
  дополнительное действие.
- Для мест, связанных с travel, статус должен быть явным: "Был здесь",
  "Хочу поехать", "Планирую" или компактная кнопка "Был / Хочу / Планирую".
- Mobile web, Android и iPhone не должны расходиться визуально или по поведению;
  это design-инвариант. Платформенные отличия допустимы только для safe area,
  map engine и нативных API.
- После видимых общих изменений проверять desktop/mobile web в браузере.
  Локальная Android USB-сборка нужна при изменении Android map engine, intents,
  system Back или другого Android-specific behavior; iPhone evidence — только
  при iOS-specific behavior.

## Проверки

Для изменений только в каталоге мест:

```bash
npm run check:fast
```

До него запускаются ближайшие tests для `api/places.ts`,
`utils/placesCatalog.ts` и `PlaceListCard` по затронутому scope. Видимый web UI
проверяется в desktop/mobile браузере; native point/place flow проверяется на
той платформе, чьё platform-specific поведение изменено.

Если меняются переходы `На карте` / `Прочитать`, дополнительно:

```bash
npm run guard:external-links
npm run governance:verify
```
