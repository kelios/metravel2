# Мобильная оболочка экрана: шапка, действия, отклик, пустые состояния

Норматив для эпика `[MOBILE-SHELL]` #2105, 2026-09-24. Повод — отчёты TestFlight
1.0.5 (10) от владельца: заголовок «Мои поездки» трижды на экране, полноразмерные
«Редактировать»/«Удалить», нет печати на телефоне, сердечко без отклика, белая
полоса в тёмной теме, CTA пустого состояния под доком. Все пять — не баги
отдельных экранов, а отсутствие общего слоя. Этот документ задаёт слой.

Область: мобильный web (< 1024 px на native, < 1280 px на web — тот же
`getIsHeaderMobile`), Android, iPhone. Desktop сохраняет текущий вид страниц.
Правило паритета из `docs/RULES.md` → «Component reuse» действует полностью:
мобильный web и приложения показывают один и тот же порядок блоков и действий.

## 1. Слои и их владельцы

| Слой | Владелец | Что решает | Чего экран больше не делает сам |
| --- | --- | --- | --- |
| Фон экрана и статус-бар | тема навигации в `app/_layout.tsx` | цвет под любым прозрачным участком, overscroll | не красит корень и не ставит `StatusBar` |
| Нижний резерв | `useBottomChromeInset()` | отступ под док, плашки и safe area | не считает `insets.bottom + 56` |
| Шапка экрана | `useScreenHeader()` → `HeaderContextBar` | заголовок, (i), главное действие, «⋯» | не рисует H1 + описание + CTA на мобильном |
| Действия экрана | слот действий шапки + `ActionListSheet` | правка, удаление, печать, экспорт | не ставит полноширинные кнопки под заголовком |
| Отклик на действие | `useActionFeedback()` | тост, «Отменить», тактильный отклик, VoiceOver | не вызывает `showToast` и haptics вразнобой |
| Пустое состояние | `components/ui/EmptyState` (`density`) | размер и видимость CTA | не держит свои `empty*`-стили |

## 2. Шапка вложенного экрана (#2099, #2100)

Вложенный экран — любой, где `HeaderContextBar` показывает «←» (всё, кроме
корневых разделов дока). Заголовок живёт ровно в одном месте — в строке «←».

Сейчас (`/trips/my`, iPhone 16 Pro, первая карточка начинается на ~64% высоты):

```text
[лого] [RU]            [аватар Julia Savran] [≡]     ← бренд-строка 64
[←] Мои поездки                                     ← строка экрана 52
Мои поездки                                         ← H1 (повтор 2)
Организуйте свои поездки отдельно от участия…       ← описание
[поиск] [+ Организовать поездку ───────────────]  ← поиск №1 + CTA
[Организую (1)] [Участвую] [Заявки]
Поездки, которые я организую                        ← H2 (повтор 3)
Маршрут, участники и подготовка…                    ← описание 2
[поиск: Поиск по моим поездкам      ] [фильтр]  ← поиск №2
┌ карточка поездки ┐
```

Норматив #2099:

```text
[лого] [RU]            [аватар] [≡]                 ← бренд-строка (до #2100)
[←] Мои поездки (i)                        [+]      ← единственный заголовок
[Организую (1)] [Участвую] [Заявки]
[поиск: Поиск по моим поездкам      ] [фильтр]  ← единственный поиск
┌ карточка поездки ┐
```

Норматив после #2100: на вложенных экранах бренд-строки нет. Корневые
разделы дока её сохраняют; аккаунт открывается вкладкой «Профиль», язык —
новым пунктом «Язык» в меню «Ещё» (сегодня переключатель есть только в шапке и
в настройках вошедшего пользователя):

```text
[←] Мои поездки (i)                        [+]
[Организую (1)] [Участвую] [Заявки]
[поиск: Поиск по моим поездкам      ] [фильтр]
┌ карточка поездки ┐
```

Правила строки экрана:

- заголовок одной строкой с многоточием; на web это элемент заголовка первого
  уровня (SEO и скринридер), на native — `accessibilityRole="header"`;
- (i) — кнопка 44×44 pt с подписью для скринридера «Подробнее о разделе»;
  открывает нижний лист (раздел 3). Нет описания — нет (i);
- справа не больше двух иконок действий по 44×44 pt: главное действие экрана
  (например «+» = «Организовать поездку») и «⋯». Каждая иконка несёт
  `accessibilityLabel` и web-`title` с полным текстом действия;
- описания разделов (H2 + подзаголовок) на мобильном не выводятся в теле: их
  текст уходит в тот же лист (i) отдельным абзацем;
- поиск на экране один. Иконка поиска в шапке, открывающая чужой каталог,
  снимается.

Desktop (≥ порога) получает из той же декларации `useScreenHeader()` прежний
вид: H1, описание и кнопки с подписями в теле страницы. Одна декларация — два
представления, текст и действия не дублируются в коде.

## 3. Лист «Подробнее» (i) (#2099)

```text
┌──────────────────────────────────────────┐
│ Мои поездки                         [×]  │
│ Организуйте свои поездки отдельно от     │
│ участия в чужих.                         │
│                                          │
│ Организую — маршрут, участники и         │
│ подготовка к ближайшим поездкам.         │
│ Участвую — поездки, куда вас приняли.    │
│ Заявки — ваши заявки на чужие поездки.   │
└──────────────────────────────────────────┘
```

Нижний лист на основе `ActionListSheet`/Modal, одинаковый на web и native.
Хинт-тултип только для web (`FormFieldWithValidation`, `IconButton`) для этой
роли не годится: в приложении он не открывается.

## 4. Действия экрана деталей (#2101)

Сейчас (`/trips/plan/:id`):

```text
[←] Test
Планируется · На велосипеде · Личная
Test
[правка: Редактировать] [корзина: Удалить]   ← две полноширинные
[карта] [люди] [загрузка] [… Ещё]   ← вкладки-иконки, подпись у активной
```

Норматив:

```text
[←] Test                                [правка] [⋯]
Планируется · На велосипеде · Личная
[Маршрут] [Участники] [Экспорт] [Отчёт]              ← все вкладки с подписью
```

«⋯» открывает лист с подписанными пунктами:

```text
┌──────────────────────────────────────────┐
│ [принтер]     Распечатать план           │
│ [загрузка]    Экспорт GPX / KML          │
│ [поделиться]  Поделиться                 │
│ ───────────────────────────────────────  │
│ [корзина]     Удалить поездку (красным)  │
└──────────────────────────────────────────┘
```

- правка — иконка в шапке, только владельцу;
- удаление — последним пунктом «⋯», через существующий `ConfirmDialog`;
- печать есть на всех платформах (раздел 7);
- вкладки на мобильном показывают иконку и короткую подпись у каждой, а не
  только у активной; вкладка «Ещё» переименовывается по содержимому.

## 5. Отклик на действие в одно касание (#2103)

Избранное, «Был / Хочу / Планирую», подписка, награда, сохранение точки:

```text
                                   ┌───────────────────────────────┐
                                   │ [сердце] Добавлено в избранное  Отменить │
                                   └───────────────────────────────┘
[ Маршруты ] [ Карта ] [ Квесты ] [ Профиль ] [ Ещё ]
```

- состояние меняется сразу; тост над доком с кнопкой «Отменить» для
  обратимых действий; тактильный отклик на iPhone/Android; объявление для
  VoiceOver/TalkBack;
- активное сердечко отличается не только цветом контура: заливка кружка-подложки
  (иконка Feather `heart` без заливки, поэтому различие даёт подложка);
- гость получает лист входа с объяснением, а не тишину: касание до готовности
  авторизации (`!authReady`) не теряется;
- все варианты `FavoriteButton` (включая `overlay` на карточке каталога и в
  карточке места) ведут себя одинаково.

## 6. Пустое состояние внутри вкладки (#2104)

Сейчас (профиль → «Маршруты», iPhone 16 Pro): круг 88 pt, `minHeight: 260`,
кнопка «Создать маршрут» под доком, пустой экран приходится прокручивать.

Норматив, `EmptyState density="compact"`:

```text
[ Маршруты ] [ Опубл. ] [ Черновики ] [ Подп… ]
  (карта)  Ваши маршруты появятся здесь
        Поделитесь маршрутом, фото и впечатлениями.
  [ + Создать маршрут ─────────────────────── ]
  [ Начать квест ──────────────────────────── ]
                                                 ← до дока остаётся место
[ Маршруты ] [ Карта ] [ Квесты ] [ Профиль ] [ Ещё ]
```

- круг 56 pt, иконка 28, без `minHeight`, отступы вдвое меньше;
- на экране 390×844 CTA целиком выше дока без прокрутки;
- `density="full"` остаётся для самостоятельного пустого экрана.

## 7. Печать (#2102)

Одна точка входа `printHtml(html)`: на web — текущее окно браузера, на
iPhone/Android — системный диалог печати (`expo-print`, `printAsync({ html })`).
Печатный HTML уже строится платформенно-независимо
(`components/trips/planning/print/tripPlanPrintHtml.ts`). Проверка
`Platform.OS !== 'web'` в кнопках печати снимается.

## 8. Фон, статус-бар и нижний резерв (#2095, #2097)

- тема Expo Router собирается из `useThemedColors()`: под прозрачной частью
  любого экрана и при overscroll виден фон темы, а не светлый
  `rgb(242,242,242)` по умолчанию;
- статус-бар задаёт только корневой layout;
- нижний отступ прокрутки = `useBottomChromeInset()` + собственный зазор
  экрана. На native это измеренная высота дока (сегодня `BottomDock` меряет её,
  а `app/_layout.tsx` значение выбрасывает), на web —
  `max(var(--mt-dock-h), var(--mt-consent-h))`. Двойного резерва на web
  (спейсер 56 px и собственный отступ экрана) нет.

## 9. Измеримые нормы (#2094, e2e на 390×844 и 402×874)

| Норма | Сейчас | После |
| --- | --- | --- |
| Верх первого элемента контента на вложенном списке | ~64% высоты (`/trips/my`) | ≤ 40% после #2099, ≤ 30% после #2100 |
| Сколько раз заголовок экрана виден в первом экране | 3 | 1 |
| Полей поиска на экране | 2 | 1 |
| CTA пустого состояния над доком без прокрутки | нет | да |
| Точка у нижнего края контента в тёмной теме | светлая | цвет фона темы |
| Отклик на сердечко в карточке каталога | цвет контура 16 pt | тост + отклик + подложка |
| Иконка действия без подписи для скринридера | встречается | 0 |
