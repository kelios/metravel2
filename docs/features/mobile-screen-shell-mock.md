# Мобильная оболочка экрана: шапка, действия, отклик, пустые состояния

Норматив для эпика `[MOBILE-SHELL]` #2105, 2026-09-24. Повод — отчёты TestFlight
1.0.5 (10) от владельца: заголовок «Мои поездки» трижды на экране, полноразмерные
«Редактировать»/«Удалить», нет печати на телефоне, сердечко без отклика, белая
полоса в тёмной теме, CTA пустого состояния под доком. Все пять — не баги
отдельных экранов, а отсутствие общего слоя. Этот документ задаёт слой.

Область: мобильный web (< 1024 px на native, < 1280 px на web — тот же
`getIsHeaderMobile`), Android, iPhone. Desktop сохраняет текущий вид страниц.
Правило паритета из `docs/RULES.md` → «Component reuse» действует полностью:
мобильный web и приложения показывают один и тот же порядок блоков и действий.

## 1. Слои и их владельцы

| Слой | Владелец | Что решает | Чего экран больше не делает сам |
| --- | --- | --- | --- |
| Фон экрана и статус-бар | тема навигации в `app/_layout.tsx` | цвет под любым прозрачным участком, overscroll | не красит корень и не ставит `StatusBar` |
| Нижний резерв | `useBottomChromeInset()` | отступ под док, плашки и safe area | не считает `insets.bottom + 56` |
| Шапка экрана | `useScreenHeader()` → `HeaderContextBar` | заголовок, (i), главное действие, «⋯» | не рисует H1 + описание + CTA на мобильном |
| Действия экрана | слот действий шапки + `ActionListSheet` | правка, удаление, печать, экспорт | не ставит полноширинные кнопки под заголовком |
| Отклик на действие | `useActionFeedback()` | тост, «Отменить», тактильный отклик, VoiceOver | не вызывает `showToast` и haptics вразнобой |
| Пустое состояние | `components/ui/EmptyState` (`density`) | размер и видимость CTA | не держит свои `empty*`-стили |

## 2. Шапка вложенного экрана (#2099, #2100)

Вложенный экран — любой, где `HeaderContextBar` показывает «←» (всё, кроме
корневых разделов дока). Заголовок живёт ровно в одном месте — в строке «←».

Сейчас (`/trips/my`, iPhone 16 Pro, первая карточка начинается на ~64% высоты):

```text
[лого] [RU]            [аватар Julia Savran] [≡]     ← бренд-строка 64
[←] Мои поездки                                     ← строка экрана 52
Мои поездки                                         ← H1 (повтор 2)
Организуйте свои поездки отдельно от участия…       ← описание
[поиск] [+ Организовать поездку ───────────────]  ← поиск №1 + CTA
[Организую (1)] [Участвую] [Заявки]
Поездки, которые я организую                        ← H2 (повтор 3)
Маршрут, участники и подготовка…                    ← описание 2
[поиск: Поиск по моим поездкам      ] [фильтр]  ← поиск №2
┌ карточка поездки ┐
```

Норматив #2099:

```text
[лого] [RU]            [аватар] [≡]                 ← бренд-строка (до #2100)
[←] Мои поездки (i)                        [+]      ← единственный заголовок
[Организую (1)] [Участвую] [Заявки]
[поиск: Поиск по моим поездкам      ] [фильтр]  ← единственный поиск
┌ карточка поездки ┐
```

Норматив после #2100: на вложенных экранах бренд-строки нет. Корневые
разделы дока её сохраняют; аккаунт открывается вкладкой «Профиль», язык —
новым пунктом «Язык» в меню «Ещё» (сегодня переключатель есть только в шапке и
в настройках вошедшего пользователя):

```text
[←] Мои поездки (i)                        [+]
[Организую (1)] [Участвую] [Заявки]
[поиск: Поиск по моим поездкам      ] [фильтр]
┌ карточка поездки ┐
```

Реализация (#2100): решение — `shouldShowBrandRow(pathname, isPhone)` в
`components/layout/customHeaderModel.ts` поверх `isTopLevelSectionPath`
(тот же источник, по которому строка решает «←»); параметры запроса не
учитываются, чтобы статический HTML и гидратация совпадали. Web до гидратации:
метка `data-header-brand="phone-hidden"` + правило critical CSS ниже 768 px,
резерв слота — вариант `mobile-screen` (52) в `headerLayoutContract.ts`. Язык —
пункт «Язык интерфейса» в «Ещё» — подэкран того же листа (`BottomDockMoreList` +
общий `LanguageOptionList`; второй Modal поверх «Ещё» iOS не показывает).
Тема и бургер-меню остаются на разделах дока.

Правила строки экрана:

- заголовок одной строкой с многоточием; на web это элемент заголовка первого
  уровня (SEO и скринридер), на native — `accessibilityRole="header"`;
- (i) — кнопка 44×44 pt с подписью для скринридера «Подробнее о разделе»;
  открывает нижний лист (раздел 3). Нет описания — нет (i);
- справа не больше двух иконок действий по 44×44 pt: главное действие экрана
  (например «+» = «Организовать поездку») и «⋯». Каждая иконка несёт
  `accessibilityLabel` и web-`title` с полным текстом действия;
- описания разделов (H2 + подзаголовок) на мобильном не выводятся в теле: их
  текст уходит в тот же лист (i) отдельным абзацем;
- поиск на экране один. Иконка поиска в шапке, открывающая чужой каталог,
  снимается.

Desktop (≥ порога) получает из той же декларации `useScreenHeader()` прежний
вид: H1, описание и кнопки с подписями в теле страницы. Одна декларация — два
представления, текст и действия не дублируются в коде.

## 3. Лист «Подробнее» (i) (#2099)

```text
┌──────────────────────────────────────────┐
│ Мои поездки                         [×]  │
│ Организуйте свои поездки отдельно от     │
│ участия в чужих.                         │
│                                          │
│ Организую — маршрут, участники и         │
│ подготовка к ближайшим поездкам.         │
│ Участвую — поездки, куда вас приняли.    │
│ Заявки — ваши заявки на чужие поездки.   │
└──────────────────────────────────────────┘
```

Нижний лист на основе `ActionListSheet`/Modal, одинаковый на web и native.
Хинт-тултип только для web (`FormFieldWithValidation`, `IconButton`) для этой
роли не годится: в приложении он не открывается.

## 4. Действия экрана деталей (#2101)

Сейчас (`/trips/plan/:id`):

```text
[←] Test
Планируется · На велосипеде · Личная
Test
[правка: Редактировать] [корзина: Удалить]   ← две полноширинные
[карта] [люди] [загрузка] [… Ещё]   ← вкладки-иконки, подпись у активной
```

Норматив:

```text
[←] Test                                [правка] [⋯]
Планируется · На велосипеде · Личная
[Маршрут] [Участники] [Экспорт] [Отчёт]              ← все вкладки с подписью
```

«⋯» открывает лист с подписанными пунктами:

```text
┌──────────────────────────────────────────┐
│ [принтер]     Распечатать план           │
│ [загрузка]    Экспорт GPX / KML          │
│ [поделиться]  Поделиться                 │
│ ───────────────────────────────────────  │
│ [корзина]     Удалить поездку (красным)  │
└──────────────────────────────────────────┘
```

- правка — иконка в шапке, только владельцу;
- удаление — последним пунктом «⋯», через существующий `ConfirmDialog`;
- печать есть на всех платформах (раздел 7);
- вкладки на мобильном показывают иконку и короткую подпись у каждой, а не
  только у активной; вкладка «Ещё» переименовывается по содержимому.

## 5. Отклик на действие в одно касание (#2103)

Избранное, «Был / Хочу / Планирую», подписка, награда, сохранение точки:

```text
                                   ┌───────────────────────────────┐
                                   │ [сердце] Добавлено в избранное  Отменить │
                                   └───────────────────────────────┘
[ Маршруты ] [ Карта ] [ Квесты ] [ Профиль ] [ Ещё ]
```

- состояние меняется сразу; тост над доком с кнопкой «Отменить» для
  обратимых действий; тактильный отклик на iPhone/Android; объявление для
  VoiceOver/TalkBack;
- активное сердечко отличается не только цветом контура: заливка кружка-подложки
  (иконка Feather `heart` без заливки, поэтому различие даёт подложка);
- гость получает лист входа с объяснением, а не тишину: касание до готовности
  авторизации (`!authReady`) не теряется;
- все варианты `FavoriteButton` (включая `overlay` на карточке каталога и в
  карточке места) ведут себя одинаково.

## 6. Пустое состояние внутри вкладки (#2104)

Сейчас (профиль → «Маршруты», iPhone 16 Pro): круг 88 pt, `minHeight: 260`,
кнопка «Создать маршрут» под доком, пустой экран приходится прокручивать.

Норматив, `EmptyState density="compact"`:

```text
[ Маршруты ] [ Опубл. ] [ Черновики ] [ Подп… ]
  (карта)  Ваши маршруты появятся здесь
        Поделитесь маршрутом, фото и впечатлениями.
  [ + Создать маршрут ─────────────────────── ]
  [ Начать квест ──────────────────────────── ]
                                                 ← до дока остаётся место
[ Маршруты ] [ Карта ] [ Квесты ] [ Профиль ] [ Ещё ]
```

- круг 56 pt, иконка 28, без `minHeight`, отступы вдвое меньше;
- на экране 390×844 CTA целиком выше дока без прокрутки;
- `density="full"` остаётся для самостоятельного пустого экрана.

### 6.1. Шапка профиля на узком экране (#2141)

Узкий экран — ширина меньше 360 (класс `isSmallPhone`: 320 web, Android
320–359 dp). Сейчас (`/profile` → «Опубл.», 320×640, прод 04.10.2026):

```text
[лого] [RU]      [аватар Сергей] [≡]               ← 0–56
┌ обложка 132 ──────────────────────── [⋮] ┐        ← 76–208
(аватар 84) Сергей
            [Ур.2 · Путешественник]               ← до 281
[чат] [поезд.] [точки] [календ.] [+]               ← отдельный ряд 64
[Маршруты 1]                                        ← вкладки столбиком:
[Опубл.]                                              11 строк, 464 px
[Черновики 1]  …  [История]                         ← до 821
  (заголовок заглушки на 909, кнопка на −497 под доком)
```

Норматив:

```text
[лого] [RU]      [аватар Сергей] [≡]
┌[чат][поезд.][точки][календ.][+]──────── [⋮] ┐        ← обложка 88, действия
│                                          │          полосой у верхней кромки
(аватар 56) Сергей
            [Ур.2 · Путешественник]
[Маршруты 1] [Опубл.] [Черновики 1] [Подп…→        ← одна прокручиваемая строка
  (карта)  Опубликованных маршрутов пока нет
  [ Создать маршрут ──────────────────────── ]     ← над доком без прокрутки
[ Маршруты ] [ Карта ] [ Квесты ] [ Профиль ] [ Ещё ]
```

- телефонная раскладка у общих компонентов — `isPhoneLayout` (`utils/phoneLayout.ts`):
  телефон включает класс < 360; идиому `isPhone || isLargePhone` держит guard
  `__tests__/utils/phoneLayout.test.ts`;
- геометрия шапки — `resolveProfileHeaderLayout(width)`
  (`components/profile/profileHeaderLayout.ts`), один источник для своей шапки,
  чужой и скелета: обычная — обложка 132, аватар 84, действия у нижней кромки
  рядом с аватаром; узкая — обложка 88, аватар 56, полоса действий у верхней
  кромки слева от «⋮», чипы ≥ 44 px (зазор подложки 2);
- нулевой кадр до гидратации получает обычную геометрию и не-телефонную раскладку.

## 7. Печать (#2102)

Одна точка входа `printHtml(html)`: на web — текущее окно браузера, на
iPhone/Android — системный диалог печати (`expo-print`, `printAsync({ html })`).
Печатный HTML уже строится платформенно-независимо
(`components/trips/planning/print/tripPlanPrintHtml.ts`). Проверка
`Platform.OS !== 'web'` в кнопках печати снимается.

## 8. Фон, статус-бар и нижний резерв (#2095, #2097, #2120)

- тема Expo Router собирается из `useThemedColors()`: под прозрачной частью
  любого экрана и при overscroll виден фон темы, а не светлый
  `rgb(242,242,242)` по умолчанию;
- статус-бар задаёт только корневой layout;
- нижний отступ прокрутки = `useBottomChromeInset()` + собственный зазор
  экрана. На native это измеренная высота всего дока вместе с нижней
  safe-area (`BottomDock` меряет обёртку `footer-dock-wrapper`, а не ряд
  иконок), на web — `max(var(--mt-dock-h), var(--mt-consent-h))`. Двойного
  резерва на web (спейсер 56 px и собственный отступ экрана) нет.
- тосты native (`ToastHost`) берут отступ из того же резерва
  (`useDockReservePx()` + 12 px; без дока — над home indicator), по умолчанию
  снизу и верхним слоем; отдельного канала «высота дока для тостов» нет
  (#2161, #2168).
- содержимое полноэкранного `Modal` (редакторы описания, редактор точки, карта
  мира) лежит в `components/ui/ModalSafeArea`: шапка окна ниже статус-бара и
  выреза, фон темы; нативный `SafeAreaView` внутри `Modal` запрещён
  (`guard:modal-safe-area`, #2120).

**Закреплённая часть экрана (#2147).** `firstContentTop` не отличает шапку,
уезжающую вместе с содержимым, от шапки над внутренним прокручиваемым блоком.
`pinnedChromeRatio` = (закреплённый верх + нижний док) / высота окна:

- закреплённый верх — максимум из (а) верха ближайшего прокручиваемого предка
  метки первого содержимого (`overflow-y: auto|scroll` и либо `scrollHeight >
  clientHeight`, либо высота блока ≥ 40% окна — короткий финал квеста блок не
  переполняет, а шапка над ним та же) и (б) низа видимых `fixed`/`sticky`
  элементов у верхнего края окна (верх ≤ 1 px, низ в верхней половине, ширина
  ≥ половины окна) — это экраны с прокруткой документа и липкие шапки;
- док — реальный `footer-dock-wrapper` от его верха до низа окна, если
  отрисован (`--mt-dock-h` задан медиа-запросом и не знает, есть ли док на
  маршруте).

Экран прохождения квеста меряется гостем в трёх состояниях: до «Начать квест»,
шаг 1 и финал (квест — эталон `luxembourg-melusina`, если он есть в каталоге,
иначе первый с 10+ точками и ролями). Порог — только у него (0,29 и
`firstContentTop` ≤ 0,245 после #2149, по прод-замеру с запасом 2–5 px; до #2149 —

## 10. Состояния точки маршрута квеста (#2146)

Нормативно для mobile web, Android и iPhone; desktop (пилюли от 600 px и
сайдбар) — те же цвета, значки и подписи. Вид и подпись точки собирает одна
функция `resolveQuestStepVisualState` (`components/quests/questStepVisualState.ts`);
web-only градиентов и теней у состояний нет. Цвета — токены `useThemedColors()`,
панель ряда — `surface`.

| Состояние | Заливка | Контур | Значок | Подпись для диктора |
| --- | --- | --- | --- | --- |
| пройдена | сплошная `success` | — | галочка, `textInverse` | «Точка 3 из 14, пройдена» |
| текущая | сплошная `brandDark` | — | номер (старт ▷, финал — флаг), `textOnPrimary` | «Точка 4 из 14, текущая» |
| доступна | `surface` | 1,5 px `textMuted` | номер, `text` | «Точка 5 из 14, доступна» |
| закрыта | `surface` | 1,5 px `disabled` | номер, `disabledText` | «Точка 9 из 14, закрыта» |
| отложена (долг маршрута, #1633) | `surface` | 2 px `warning` | «вернуться», `warning` | «Точка 2 из 14, отложена, ждёт ответа» |
| необязательная (роль точки) | как у состояния | у контурных — пунктир | как у состояния | + «; необязательная» |

Пороги (держит `__tests__/components/quests/questStepVisualState.test.ts` в
светлой и тёмной теме): значок/номер на своей заливке ≥ 4,5:1 у всех активных
состояний; граница точки (контур, если он есть, иначе заливка) против панели
≥ 3:1; соседние состояния различаются яркостью заливки или контура ≥ 3:1 либо
формой (сплошная ↔ контур, галочка ↔ номер ↔ значок) — цвет никогда не
единственный признак. «Пройдена» и «текущая» по яркости близки в обеих темах
(1,45:1 и 1,12:1), поэтому у пройденной галочка вместо номера. «Закрыта» —
неактивный элемент, порог контраста к ней не применяется (WCAG 1.4.3/1.4.11),
от «доступна» она отличается контуром (3,98:1 / 5,73:1).

## 11. Полоса маршрута и лист «Маршрут» (#2149)

Телефон, ширина < 600 px (mobile web, Android, iPhone). От 600 px остаются
пилюли шагов из §10 и полоса прогресса.

```
┌───────────────────────────────────────────┐
│ Точка 12 из 14 · Задания 10/11          ⌄ │  ← одна кнопка ≥ 44 pt
│ ▬▬ ▬▬ ▬▬ ▬▬ ▬▬ ▬▬ ‒‒ ▬▬ ▬▬ ▬▬ ‒‒ ▬▬ ▬▬ ▬▬⚑ │  ← сегмент на точку
└───────────────────────────────────────────┘
```

- **Текст:** позиция — «Старт квеста» / «Точка N из M» / «Финал» (M — точки
  маршрута без стартовой карточки); «Задания X/Y» — прогресс по обязательным из
  той же модели счётчика (`buildQuestCountModel`). У квеста без явных ролей
  (`source: 'fallback'`) — только позиция.
- **Шкала:** сегмент на каждую точку, вид — `resolveQuestStepVisualState` (§10).
  Роль — формой: обязательная — сегмент 6 px, необязательная — 3 px, финальная
  точка — сегмент и флажок за ним.
- **Нажатие** открывает лист «Маршрут». Подпись для диктора: «Маршрут: Точка 12
  из 14, задания 10 из 11».
- **Лист «Маршрут»** — тело общего листа `ActionListSheet` (как `InfoSheet`, §3):
  строка ≥ 44 pt на старт, каждую точку и финал — маркер состояния (§10), номер,
  название, роль («Обязательная точка», «Точка по желанию», «Финальная точка») и
  состояние. Нажатие по доступной, пройденной, отложенной или текущей точке
  открывает её, по финалу — финал; лист закрывается. Закрытая точка не
  нажимается и озвучивается с причиной («сначала пройдите предыдущие точки»).
- **Закреплено:** полоса заменяет полосу прогресса (7 px), ряд кружков (56 px) и
  счётчик «Задания» в ряду действий. Цель вместе с #2148 (строка экрана вместо
  ряда действий) — закреплено ≤ 110 px, верх задания ≤ 0,20 высоты окна
  (390×844 и 402×874); числа держит `e2e/mobile-screen-budget.spec.ts` (§9).
