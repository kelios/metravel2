# Вкладка «Маршрут» планировщика: раскладка mobile и desktop

Норматив от 2026-09-23 для карточек разбора скринов `/trips/plan/47` —
#2053–#2060, список в разделе «Карточки». Экран: `/trips/plan/:id` → шапка поездки и вкладка
«Маршрут». Компоненты: `app/(tabs)/trips/plan/[id].tsx`, `RouteBuilderLayout`,
`RouteBuilderMobile`, `RoutePointsSection`, `RouteSummaryBar`,
`TripPlanRouteMap(.web)`, `TripRouteImportPanel`, `TripRouteDownloadButtons`,
`components/ui/ToolActionsRow`.

Эталонный случай — поездка владельца trip 47: 61 точка в 17 днях,
`transport_mode=walk`, KML-оригинал 181 КБ, описание 6 274 знака, маршрут
деградировал в прямую линию (`routing_state.fallback_reason = ors_http_404`).
В поездке четыре переезда поездом и самолётом: 647 + 431 + 990 + 172 км.

## Решение по вариантам (23.09.2026)

Варианты A/B/C для трёх блоков нарисованы на холсте Claude Design
«Вкладка „Маршрут“ — варианты» (https://claude.ai/artifact/PQwaecXdgodRXyPHGHJqHH,
приватный; палитра — дизайн-система MeTravel,
https://claude.ai/artifact/Y44ZGzZidWVF3uxmqsqqfJ). Выбор по UI/UX:

| Блок | Выбран | Почему не другие |
| --- | --- | --- |
| «Файл маршрута» (#2053, #2054) | A — стопка: загрузка во всю ширину, GPX и KML поровну, карточка оригинала со своими действиями | B смешивает загрузку и скачивание в одну сетку; C выше на треть и стрелками обещает переход, которого нет |
| Точки по дням (#2058) | A — сворачиваемые дни плюс кнопка «на карте» из B | B прячет остальные дни и меняет строку точки; C держится на правилах про ночёвки и дороже в реализации |
| Карта (#2059) | A — шапка из трёх строк над картой | B кладёт надписи на подложку карты: они спорят с кнопками карты и прячут причину за лишним нажатием |

Разделы ниже описывают выбранные варианты и нормативны для карточек.

## 0. Подписи кнопок не обрезаются

Во вкладке «Маршрут» ни одна подпись кнопки не обрезается многоточием и не
сжимается до нуля: у каждого текстового узла внутри кнопки
`scrollWidth ≤ clientWidth` на 320, 390 и 1440 px. Узкий ряд переносит кнопки
или переходит в сетку, длинная подпись переносится на вторую строку. До правок
правило нарушают «Импорт», «GPX», «KML», «Оригинал» в «Файле маршрута» и
«Предложить оптимальный порядок» на mobile.

## 1. Блок «Файл маршрута»

Одинаково для mobile (контент 332 px, на 320 — 288 px) и колонки шагов
desktop (380 px):

```text
Файл маршрута
Загрузите трек GPX/KML или скачайте построенный маршрут.

[ ⤒ Загрузить трек (GPX/KML)                 ]   во всю ширину
[ ⤓ Скачать GPX       ] [ ⤓ Скачать KML       ]   один variant, по 50 %
Линия приблизительная — в файле будут прямые отрезки.   (только при approximate)

┌────────────────────────────────────────────┐
│ Mullerthal_Trail_Routes_1-3.kml            │   имя до 2 строк
│ Оригинал · 181,2 КБ                        │
│ [ ⤓ Скачать оригинал ]       [ 🗑 Удалить ] │   «Удалить» — danger (#2054)
└────────────────────────────────────────────┘
```

- Ни одна подпись кнопки не обрезается: у каждой подписи
  `scrollWidth ≤ clientWidth` на 320, 390 и 1440. Не хватает ширины — кнопки
  переносятся в следующий ряд, текст не сжимается.
- Однотипные соседние действия (GPX, KML) — один `variant` и равная ширина.
- «Скачать оригинал» живёт в карточке оригинала. Строка «Исходный файл
  маршрута: …» над кнопками удаляется: имя файла уже есть в карточке.
- Оригиналов у поездки ноль или несколько (#2069): карточка повторяется на
  каждый файл в порядке бэкенда, со своими «Скачать» и «Удалить».
- «Удалить» открывает `ConfirmDialog`: «Удалить оригинальный файл?» /
  «Точки и построенный маршрут останутся. Скачать исходный файл после удаления
  будет нельзя.» / «Удалить» (danger) и «Отмена». Удаление без подтверждения
  запрещено.
- Про приблизительную линию блок говорит одной короткой строкой про экспорт,
  полной фразы статуса здесь нет (см. §2).

## 2. Статус приблизительного маршрута — в одном месте

| Поверхность | Что показывает |
| --- | --- |
| Шапка карты (desktop) | чип «⚠ Приблизительно», причина до 2 строк, «Повторить» только для временной причины |
| Строка итога под картой (mobile) | ⚠ и цифры, причина одной строкой под ними, «Повторить» только для временной причины |
| Pill с цифрами в шапке поездки | только ⚠, фразы под pill нет |
| Шаг «Итог маршрута» | только чип, без фразы |
| «Файл маршрута» | короткая строка про экспорт (§1) |

Текст причины выбирается по коду из `routing_state.fallback_reason` и
`routing_state.warnings[].code` (источник кодов — `routing/services.py` бэкенда):

| Код | Смысл | Текст (RU) | «Повторить» |
| --- | --- | --- | --- |
| `ors_http_404`, остальные `ors_http_4xx`, кроме 401/403/429 | дорога между точками не найдена | «Не получилось проложить маршрут {пешком / на велосипеде / на машине} между всеми точками — часть отрезков показана по прямой. Так бывает на перелётах и переездах.» | нет |
| `ors_http_5xx`, `ors_http_401/403/429`, `ors_request_failed`, `ors_response_invalid`, `ors_not_configured`, `ors_url_template_invalid`, `route_provider_unavailable`, `routing_provider_unavailable` | сервис недоступен | «Сервис построения маршрутов временно недоступен — линия показана приблизительно.» | да |
| `not_enough_points`, `schematic` | без изменений | без изменений | — |

Цифры прямой линии (`provider=direct`) не выдаются за маршрут: дистанция
подписана «≈ 2 429 км по прямой», время в пути не показывается нигде (его
считает бэкенд делением расстояния на скорость, `_route_duration_s`),
плитка «Набор» без значения скрыта. Плитки итога — «Дистанция» и «Остановки»
в один ряд.

## 3. Список точек: дни сворачиваются

Mobile 390 и колонка шагов desktop:

```text
2  Точки маршрута                               ✓ Готово
   (кнопка порядка и подсказка «до 50 точек» — без изменений, #1899)

   ▾ День 1 · 25 сентября · 1 точка
     ≡ ① 🛏 Ночь 1 · ночной поезд Краков → Мюнхен   ✎
          …строка точки без изменений…
   ▸ День 2 · 26 сентября · 3 точки · 466 км        [⌖]
   ▸ День 3 · 27 сентября · 6 точек · 22 км         [⌖]
   …
   [ + Добавить точку ]
```

- Дни собираются по `day_number` (`routePointDays.ts`). Больше 15 точек —
  все дни свёрнуты по умолчанию. Разворачивается день точки, выбранной на
  карте, день, куда только что добавили точку, и день редактируемой точки.
  Состояние живёт в сессии экрана, на бэкенд не уходит.
- Заголовок дня — кнопка ≥ 44 px: номер, дата (`i18n/format.ts`), число точек
  (plural), дистанция дня, если известна.
- `[⌖]` на mobile прокручивает к карте и подгоняет её под точки дня. На desktop
  разворот дня сам подгоняет липкую карту, без прокрутки страницы.
- Строка точки не меняется. Desktop сохраняет собственный скролл списка
  (решение #1600), но в свёрнутом виде список помещается в него почти целиком.
- Перестановка перетаскиванием работает внутри развёрнутого дня, перенос в
  другой день — полем дня в форме точки, как сейчас.

Цель на эталоне trip 47: mobile 390×844 — верх «Итог маршрута» ≤ 2 500 px
(было 12 086); desktop 1440×900 — содержимое списка со свёрнутыми днями
≤ 1 200 px (было 10 684).

## 4. Карта маршрута

```text
Карта маршрута                                 61 точка
🚶 Пешком · ≈ 2 429 км по прямой   [⚠ Приблизительно]
Причина одной строкой (§2)
┌──────────────────────────────────────────────┐
│  ①②③ … номера как в списке, кластеры «12»     │
│                                    [слои][⛶] │
│ ─ оригинальный трек (легенда внутри карты)    │
└──────────────────────────────────────────────┘
```

- Маркер показывает номер точки из списка, активный маркер крупнее. На малом
  масштабе близкие маркеры собираются в кластер тем же механизмом, что на
  `/map`.
- Шапка карты — не больше трёх строк: заголовок и счётчик с подписью
  («61 точка», plural), строка способа и цифр с чипом статуса, причина из §2.
  Подсказка «Маркер можно перетащить…» уходит из постоянного текста в
  `accessibilityHint` и пустое состояние. Легенда оригинального трека — внутри
  карты, не в шапке.
- Desktop ≥ 1280: рабочая область вкладки «Маршрут» шире колонки шапки
  (до 1 200 px), карта занимает `calc(100dvh − 180px)`, но не меньше 420 и не
  больше 760 px. Шапка поездки и описание остаются шириной 860 px.

## 5. Шапка поездки

- Описание сворачивается и на desktop: 8 строк плюс «Показать полностью»
  (`TripPlanCollapsibleText`, на mobile по-прежнему 2 строки). Цель на trip 47
  при 1440×900: верх табов ≤ 900 px (было 2 116).
- Кнопки «Редактировать поездку» и «Удалить поездку» остаются как есть.

## 6. Переезды внутри поездки (черновик до BE-контракта)

```text
▾ День 4 · 28 сентября
  ③ Аэропорт Мюнхена (MUC)
     ✈ Перелёт → ④ Аэропорт Luxembourg Findel · 431 км
```

- У точки есть способ, которым до неё добираются от предыдущей: «как вся
  поездка» (по умолчанию), поезд, самолёт, автобус, паром, трансфер.
- Отрезки-переезды не прокладываются по дорогам. На карте это пунктирная дуга,
  в итоге они считаются отдельно: «Пешком ≈ 189 км · Переезды 2 240 км».
- Точные поля и расчёт итога задаёт связанная BE-карточка.
