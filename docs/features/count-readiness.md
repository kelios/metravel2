# Подтверждённое количество: профиль, рулетка, главная

Контракт задач #2335, #2336, #2337. Применяется к desktop web и mobile web390;
общие компоненты сохраняют тот же смысл на Android/iOS. Тексты берутся из
существующих RU/BE/UK/PL/EN словарей.

Количество известно только после успешного ответа своего запроса. Ошибка HTTP
или сети не является успешным нулём. Фасеты также отклоняют неверный формат
ответа; нормализация успешных ответов профиля и главной остаётся прежней.
React Query хранит последнее
подтверждённое значение для того же ключа; смена автора, пользователя или
фильтров не переносит данные прежней области запроса.

| Поверхность | Первый запрос | Первый сбой | Успешный ноль | Сбой обновления |
| --- | --- | --- | --- | --- |
| Публичный автор | Вкладка без числа, пилюля с иконкой | «—» и локализованная недоступность | Настоящий 0 в пилюле | Прежнее число и маршруты, текущая ошибка в списке |
| Фильтры рулетки | Локализованная загрузка без числа | Локализованная ошибка без 0 | «0 путешествий» | Прежнее число и признак ошибки |
| Нижний блок главной | Нейтральный общий текст, «Добавить путешествие» | Тот же нейтральный вариант | «Добавить первую поездку» | Прежний подтверждённый вариант |

Действия публичного профиля и фильтры остаются доступны при неизвестном числе.
На главной неизвестное количество не обещает наличие книги или отсутствие
поездок. Нейтральное действие ведёт в `/travel/new`, подтверждённый непустой
вариант — в `/export`; гостевой сценарий сохраняется.

Справочники рулетки и числовой результат фасетов — независимые запросы.
`suppressErrors` управляет журналом, а не успешностью ответа. Остальные
потребители фасетов должны корректно работать без данных первого запроса.

Постоянные проверки используют реальные query и числовые UI-потребители:
pending/error/0/>0, ошибка обновления и смена области запроса. Браузерная
приёмка после review/push/deploy фиксирует SHA, desktop/mobile390 screenshots,
console/network; сетевые задержки и abort не подменяют успешные серверные данные.
