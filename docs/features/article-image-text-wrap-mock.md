# Обтекание изображений текстом в статье и печатной версии

Статус: норматив для задачи #1602 (`travel-richtext-single-image-text-flow`).
Источник: запрос владельца и скриншот от 2026-08-26 23:18:37.

## Проблема и границы

На пользовательском скриншоте печатной версии, в разделе «Где искать печати»,
портретное фото выровнено вправо, но следующий абзац начинается только под ним.
Слева остаётся незаполненное место. Аналогичное поведение обычной статьи сообщил
владелец; локальный код обеих поверхностей реализует боковое выравнивание без
обтекания. Сам пользовательский blob-документ локально не воспроизводился.

Норматив относится к одиночным изображениям в тексте статьи с раскладкой
`float-left`/`float-right`, а не к обложке, фотогалерее, карте или карточкам маршрутов.
Принцип журнальной вёрстки одинаков для desktop web и печати; это не требование
показывать весь сайт как белый печатный лист или менять существующую тему.

## Широкая колонка: desktop web и печать

Правое изображение:

```text
Заголовок раздела
Вводный абзац на всю ширину.

Текст идёт рядом с фото,       ┌─────────────────┐
занимая свободное место.       │                 │
Следующие строки продолжают   │       Фото      │
обтекать изображение, не      │                 │
касаясь рамки и подписи.      ├─────────────────┤
                             │ Подпись, если есть│
                             └─────────────────┘
После изображения текст снова занимает всю доступную ширину.

Следующий заголовок начинает отдельный раздел на всю ширину.
```

Для `float-left` расположение зеркальное. Порядок абзацев, фотографий и подписей
в исходном содержимом не меняется.

- Фото вместе с подписью занимает не более 45% доступной ширины; между ним и
  текстом остаётся не менее 16 px на экране / 4 mm на бумаге.
- Если такой размер не оставляет читаемой текстовой колонки, применяется
  одноколоночное расположение. Нельзя сжимать текст до нескольких символов.
- Изображение сохраняет пропорции, не обрезается и не растягивается. Высоту
  нельзя искусственно увеличивать ради заполнения свободного места.
- Обтекание относится к соседним абзацам. Следующий заголовок, таблица,
  полноширинное фото, галерея и отдельный смысловой блок прекращают обтекание.
- При коротком тексте допустимо свободное место: задача не требует добавлять,
  повторять или переставлять абзацы ради заполнения страницы.
- Варианты `p > img`, `figure > img` и `figure + figcaption` сохраняют назначенные
  сторону, размеры, альтернативный текст и подпись при обработке и экспорте.

## Узкая колонка и mobile web

```text
Заголовок раздела
Вводный абзац.
┌───────────────────┐
│       Фото        │
└───────────────────┘
Подпись, если есть.
Следующий абзац на всю ширину.
```

На mobile web ≤768 px обтекание отключено. Фотография и текст идут одной колонкой,
без горизонтального скролла и боковой полосы из нескольких букв. На desktop
адаптация учитывает реальную ширину колонки, а не только ширину окна.

Печатный A4 не должен случайно получать мобильное правило из-за экранного
брейкпоинта: решение для печати определяется доступной шириной печатной полосы.

## Печать и разрывы страниц

- Проверять и экранный предпросмотр экспортированного HTML, и результат
  печати/сохранения в PDF A4 с обычными полями.
- Не разрезать фотографию и её короткую подпись между страницами; слишком
  высокое изображение вписать целиком с сохранением пропорций.
- Не переносить весь длинный раздел одним неделимым блоком: текст продолжает
  течь на следующую страницу без пропусков, наложений и дубликатов.
- Заголовок не остаётся один внизу страницы. Окончание обтекания не переносит
  следующий раздел на пустой лист без необходимости.

## Состояния и регрессионные проверки

| Состояние | Норматив |
| --- | --- |
| Портрет справа/слева + несколько абзацев | Текст действительно идёт рядом, затем возвращается на всю ширину |
| Фото с подписью | Подпись остаётся с фото; текст не накладывается на рамку |
| Полноширинный пейзаж / группа фото | Существующая блочная/галерейная раскладка сохранена |
| Два боковых фото подряд | Нет наложения изображений, пересечения подписей или потери порядка |
| Короткий текст / нет следующего текста | Фото не растягивается, контент не дописывается |
| Загрузка / ошибка изображения | Существующий доступный fallback; нет перекрытия текста и бесконечного загрузчика |
| Mobile 390 px / узкая desktop-колонка | Одна читаемая колонка без горизонтального скролла |
| Печать A4 / граница страницы | Полные фото, сохранённые подписи и естественное продолжение текста |

Проверка в браузере: desktop 1440 px и mobile 390 px, светлая и тёмная тема.
Для печати — тот же набор содержимого и A4. Приёмка сравнивает не только классы
CSS: координаты хотя бы одной строки следующего абзаца должны попадать в
вертикальный диапазон бокового изображения и не пересекать его по горизонтали.
После низа фото строки снова используют полную ширину. Для `single-wide` и
mobile контроль противоположный: следующий абзац начинается под изображением.

Все текущие локали RU/BE/UK/PL/EN сохраняются; новых подписей интерфейса этот
макет не вводит. Android/iOS runtime не входит в задачу, если реализация не
затрагивает платформенные рендереры.
