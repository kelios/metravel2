# Воронка планировщика поездки

Отчёт задачи #3449 связывает переход в планировщик, готовую форму, подтверждённое
создание поездки и первую сохранённую точку. Он использует события web-клиента;
серверное число поездок и черновые точки не подменяют результаты этой воронки.

## Запуск

```bash
npm run stats:ga4 -- --property 362328641 --trip-planner --days 7
npm run stats:ga4 -- --property 362328641 --trip-planner --start-date 2026-11-16 --end-date 2026-11-22 --json
```

Относительное окно заканчивается вчера и содержит указанное число полных дней
по часовому поясу ресурса GA4. Явные даты включают обе границы. Для сравнения
периодов выбирайте полные дни после выката событий, подтверждённого в #3449.
Наличие событий в старом окне не означает наличие нового контракта.

Нужна существующая авторизация `stats:login` или доступ сервисного аккаунта к
ресурсу. Команда только читает данные; не создаёт события и цели. JSON содержит
раздел `tripPlanner` с периодом, строками, итогами и качеством ответа.

## Измерения и строки

Запрос фильтруется по `event_category=trip_planner` и списку имён событий.
Используются уже зарегистрированные event-scoped измерения `event_category`,
`event_label`, `auth_state`, `outcome` и стандартное `eventName`. В Data API имена
пользовательских измерений имеют префикс `customEvent:`. При приёмке проверить
наличие этих измерений через metadata API. Новые измерения для отчёта не нужны.

`event_label` содержит только `travel|quest|assistant|navigation|direct`.
Это источник входа в продукт, не рекламный канал GA4. Транспорт отдельно
переименовывает параметр `source` в `ui_source`; отчёт не зависит от регистрации
этого дополнительного измерения.

`auth_state` — состояние при начале пути: `guest|authenticated`. Оно сохраняется
для последующих шагов, поэтому создание после авторизации входит в ту же
гостевую строку. Это не состояние аккаунта в момент каждого отдельного события.
Отчёт всегда показывает пять источников и оба состояния.

## Что подтвердилось при проверке входов

Кнопка `TravelStatusButton` «Добавить в план» открывает выбор статуса поездки
в календаре. Она не ведёт на `/trips/plan/create`, поэтому её действие нельзя
считать входом в планировщик. В `CTASection` кнопка организации поездки в
планировщике показывается только вошедшим. Такое различие путей само по себе
не доказывает причину исторического нуля созданий.

`trip_planner_impression.outcome=visible` считает фактически видимые кнопки
планировщика в статье для вошедших, кнопку открытия плана и кнопку квеста в
помощнике. Это частичное покрытие (`impressionCoverage=partial`) для
`travel/authenticated` и `assistant`. Гостевая статья, самостоятельный `quest`,
`navigation` и `direct` не имеют такого счётчика (`not_instrumented`): их
`impressions=null` означает отсутствие покрытия, а не нулевую видимость.
Календарные кнопки статуса в показы планировщика не включаются.

`entryPerImpression` отдельно делит переходы строки на её наблюдаемые показы.
Это диагностическое отношение событий, не замкнутая когортная конверсия;
частичное покрытие не позволяет переносить его на все поверхности источника.
Показы не меняют общий знаменатель следующих этапов — число переходов.
Общий итог показов и `entryPerImpression` остаётся `null`, поскольку у
источников разное покрытие.

| Столбец | Событие и исход | Расчёт |
|---|---|---|
| Показы | `trip_planner_impression`, `visible` | частичное покрытие кнопок; отдельное отношение переходов к показам |
| Переходы | `trip_planner_entry`, `opened|auth_required` | знаменатель строки |
| Нужен вход | `trip_planner_entry`, `auth_required` | число и доля от переходов |
| Форма готова | `trip_planner_form_view`, `ready` | число и доля от переходов |
| Создано | `trip_created`, `success` | подтверждённое создание и доля от переходов |
| Первая точка сохранена | `route_point_added`, `first_saved` | подтверждённое сохранение и доля от переходов |
| Ошибки | `trip_create_failed`, `error` | число попыток; повтор может дать несколько ошибок |

`route_point_added.outcome=draft` и показ гостевого гейта
`trip_planner_form_view.outcome=auth_required` не увеличивают успешные шаги.
Их общий счёт показан отдельно как `excludedEventCount`. Неизвестные значения
попадают в `unknownRows` и `unknownEventCount`, не в приписанные источникам
итоги. Неограниченные неизвестные строки не печатаются: выводится причина
пробела без возможного частного текста.

## Как читать доли и нули

Все доли внутри строки делятся на одно число переходов этой строки. Итоги
складывают известные источники и состояния; неизвестная атрибуция остаётся
отдельной. Ошибки считаются попытками, поэтому их может быть больше переходов.
При нулевом знаменателе доля отсутствует, а не равна нулю.

Это отношения событий за календарное окно, не замкнутая когорта посетителей.
Путь может начаться до окна и завершиться внутри него или начаться в последний
день и завершиться позже. Поэтому отношение может превышать 100%; отчёт его
не обрезает. Разность `1 − доля` не доказывает точную долю ушедших. Для точной
когортной конверсии требуется отдельное связывание событий по времени начала.

Все события требуют аналитического согласия. Согласие посреди пути не досылает
предыдущие шаги и может изменить соотношения. Под автоматизацией события доступны
через `metravel:analytics-intent`, но в GA4 и Метрику не отправляются.
Браузерная приёмка поэтому проверяет последовательность, а не создаёт строки
для отчёта. Подробности — [словарь событий](analytics-events.md).

Контекст входа действует 30 минут. Результаты после этого срока могут остаться
без атрибуции и не войти в воронку. В URL и redirect входа переносится только
конечный `planner_source`, а случайный id входа остаётся локально. Форма ищет
последний неистёкший контекст по локальному отпечатку канонического адреса.
При согласии на аналитику и доступном session storage это сохраняет исходный
когортный вход через авторизацию и перезагрузку; без хранилища — только в памяти
страницы. Несколько одновременно открытых одинаковых форм в одной вкладке
используют последний вход этой цели, поэтому это не уникальная когорта каждой формы.

Пустой полный ответ означает «за окно не зафиксировано», а не «никто не
пользовался». При неполной пагинации, порогах, семплировании, потере строк,
некорректных счётчиках или повторяющихся агрегированных строках числа и доли
остаются `null`; `quality` сохраняет причину. Ошибка API завершает команду
ошибкой и не заменяется пустым успешным отчётом.

## Метрика

В счётчике `62803912` проверить JavaScript-цели с точными именами
`trip_planner_impression`, `trip_planner_entry`, `trip_planner_form_view`, `trip_created`,
`trip_create_failed`, `route_point_added`. Параметры цели содержат источник,
состояние входа и исход. Для первой сохранённой точки нужен фильтр
`outcome=first_saved`; историческая цель `route_point_added` без этого фильтра
включает черновые добавления. Отчёт CLI читает GA4; наличие целей Метрики и
подтверждение доставки фиксируются отдельно при приёмке.
