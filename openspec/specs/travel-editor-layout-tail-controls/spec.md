# travel-editor-layout-tail-controls Specification

## Purpose

Keep the web article editor's accessibility presentation separate from authored
content and preserve editing history through acknowledged updates and focus changes.
Reconsider retained article flow safely when viewport or scroll-owner geometry
changes.

## Requirements

### Requirement: Presentation alt does not become editorial content
The web editor SHALL retain app-generated fallback alt for accessibility while
excluding that generated value from serialized content, editing history and HTML
clipboard exports. It SHALL preserve authored alt, even when equal to the fallback.

#### Scenario: History recreates an unlabelled image
- **WHEN** Undo or redo recreates an image whose alt was generated by the editor
- **THEN** the image remains accessible and saving does not persist that fallback

#### Scenario: Clipboard transfers the image inside the editor
- **WHEN** a generated-alt image is cut/copied and pasted through the editor's HTML clipboard
- **THEN** the transferred HTML and saved content contain neither fallback alt nor a provenance marker

#### Scenario: An author deliberately supplies the same label
- **WHEN** original content or an explicit image format supplies alt equal to the fallback
- **THEN** that authored alt is preserved in history, clipboard and serialized content

#### Scenario: A direct editor DOM export bypasses the text-change callback
- **WHEN** HTML mode, manual save or a toolbar/media helper reads the current editor DOM
- **THEN** the shared serializer excludes only proven generated alt from emitted content

#### Scenario: Independent HTML input deliberately supplies the fallback label
- **WHEN** an authored HTML replacement differs from the current live editor DOM
- **THEN** its authored alt is preserved even when equal to a generated label in the live DOM

### Requirement: An intentionally empty editor retains its history
An intentionally empty article SHALL retain editing history without restoring
previously removed content. Nonempty expected initial content missing from the
editor SHALL remain recoverable.

#### Scenario: An author removes all content
- **WHEN** the author deletes all text and images and the editor contains only an empty paragraph
- **THEN** the editing session and history remain intact and Undo can restore the removed images without serializing generated alt

#### Scenario: Nonempty initial content is missing
- **WHEN** accepted nonempty initial content has not appeared in the empty editor
- **THEN** the existing initial repair can restore that content

### Requirement: Initial synchronization respects local editing ownership
Delayed initial synchronization SHALL complete a healthy initialization and SHALL
NOT replay stale external HTML after a local edit. A genuinely accepted external
content change SHALL retain initial synchronization and repair.

#### Scenario: Parent acknowledgement follows a local cut
- **WHEN** the author cuts all content while the controlled parent still carries the earlier HTML
- **THEN** delayed initial synchronization does not reinsert that earlier content and the editing session retains Undo and redo

#### Scenario: New external content arrives after initialization
- **WHEN** a genuinely new external HTML value is accepted after an initially empty or already initialized editor
- **THEN** the editor displays the new content through the existing synchronization path

### Requirement: Internal editor focus changes do not flush the parent early
Focus moving within the web editor, including its own toolbar, SHALL NOT
publish a pending change early and disrupt the intended control action. Focus
leaving the editor for an external or unknown destination SHALL immediately
publish the pending change, including when leaving the toolbar. This behavior
SHALL hold in normal and fullscreen editing.

#### Scenario: A native click moves focus to Undo
- **WHEN** focus moves from the editor content to its own Undo button during a native pointer gesture
- **THEN** the pending empty value is not published early and the intended native Undo click reaches its control

#### Scenario: Focus leaves the whole editor
- **WHEN** focus leaves the content or toolbar for an external element or an unknown destination
- **THEN** the pending parent change is flushed immediately

### Requirement: Retained height responds safely to geometry changes
A retained web flow height SHALL be reconsidered after viewport resize, orientation
change or scroll-owner size change through the existing release transaction. It
SHALL keep visible unanchored slack held and SHALL NOT continuously poll.

#### Scenario: A stationary reader's resize makes slack safe
- **WHEN** an owner or viewport geometry change moves retained slack offscreen
- **THEN** the existing coalesced release removes the obsolete height without a scroll

#### Scenario: Resize leaves visible unanchored slack
- **WHEN** the geometry changes but the slack remains visible without a safe anchor
- **THEN** the height remains held and no continuous retry loop is scheduled

### Requirement: A late client-only consent banner uses its actual first-visible viewport
A consent banner mounted only after client startup SHALL use the actual viewport for its first visible frame. It SHALL appear without an extra visibility delay
and retain hydration-safe behavior on surfaces rendered before client startup.

#### Scenario: Late desktop mount precedes a hydration transition
- **WHEN** the client-only banner becomes visible on a desktop viewport before deferred startup work completes
- **THEN** its first visible layout uses the desktop viewport

#### Scenario: A narrow viewport mounts the banner
- **WHEN** the banner becomes visible at a narrow mobile width
- **THEN** it retains the healthy narrow layout
