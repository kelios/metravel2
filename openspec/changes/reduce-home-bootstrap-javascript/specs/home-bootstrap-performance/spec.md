## Purpose

Обеспечить быструю загрузку главной на мобильном интернете, исключая раннюю загрузку неиспользуемой нижней формы и сохраняя прежнюю готовность первого экрана и подписки.

## ADDED Requirements

### Requirement: Код нижней подписки загружается по видимости

На web с доступным IntersectionObserver система SHALL не инициировать загрузку кода, используемого исключительно нижней формой подписки, пока её секция не достигает существующей границы предзагрузки по видимости. Если IntersectionObserver недоступен, система SHALL сохранять прежнюю немедленную загрузку секции через штатный fallback useProgressiveLoad. Данные и видимые секции первого экрана SHALL сохранять прежние условия готовности.

#### Scenario: Холодное открытие без прокрутки
- **WHEN** гость открывает главную на desktop web или mobile web с доступным IntersectionObserver и форма остаётся вне границы предзагрузки
- **THEN** страница сохраняет первый экран и не скачивает отдельный код нижней формы до её видимости

#### Scenario: Пользователь быстро прокручивает до формы
- **WHEN** пользователь достигает границы предзагрузки нижней подписки
- **THEN** загрузка формы начинается и форма появляется с прежним резервом места и прежними текстами, без дополнительного ожидания взаимодействия

### Requirement: Подписка сохраняет совместимость

Система SHALL сохранять обязательное явное согласие, канонический адрес страницы, локализованные ошибки и прежние HTTP поля/статусы подписки во всех RU/BE/UK/PL/EN. Native SHALL сохранять прежний порядок доступности формы.

#### Scenario: Отправка после загрузки формы
- **WHEN** пользователь вводит валидный email, даёт согласие и отправляет форму
- **THEN** запрос содержит прежние email/source/page_url/consent/consent_version и результат отображается прежним способом

#### Scenario: Отсутствие согласия или отказ API
- **WHEN** пользователь не дал согласие либо API отвечает 400/429
- **THEN** форма сохраняет прежнюю блокировку отправки без согласия и локализованную обработку ошибок

### Requirement: Результат проверяется на production

Решение SHALL подтверждаться холодными production измерениями на desktop web и mobile web, с зафиксированными before/after SHA и одинаковыми версиями и профилями. Внутри каждой серии оба web-таргета SHALL проверять один и тот же выкаченный SHA. Подтверждение SHALL включать реальную загрузку формы после прокрутки, весь сетевой журнал, LCP candidate и TBT; расчётный score SHALL не заменять измерение applied main-thread blocking.

#### Scenario: Приёмка оптимизации
- **WHEN** изменение выкачено на production и проводится приёмка
- **THEN** измерения показывают исчезновение доказанных ранних зависимостей, отсутствие ухудшения первого экрана/CLS и отдельно фиксируют остаточный TBT относительно бюджета 400 мс

#### Scenario: Остаточная блокировка выше бюджета
- **WHEN** TBT остаётся выше 400 мс после уменьшения ранних зависимостей
- **THEN** проблема PageSpeed не объявляется полностью исправленной и продолжение требует source evidence причины остаточной блокировки
