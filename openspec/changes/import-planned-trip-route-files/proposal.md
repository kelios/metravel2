## Why

Планировщик поездок сейчас принимает маршрут только через ручное добавление точек, поэтому готовый GPX/KML-трек нельзя использовать как черновик планируемого маршрута. Задача #1492 добавляет локальный импорт с предварительным просмотром и явным подтверждением, сохраняя существующую модель «редактирование черновика → предпросмотр → отдельное сохранение».

## What Changes

- Добавить в инструменты маршрута выбор одного файла `.gpx` или `.kml`: скрытый web file input на web и системный document picker на Android/iPhone.
- Разбирать геометрию через существующий `parseRouteFilePreviews`, отдельно извлекать именованные waypoint/Placemark-точки и показывать локальный предпросмотр поверх текущего маршрута с расстоянием, числом точек и списком именованных точек.
- Перед применением предложить два явных режима: заменить текущий черновик или добавить импорт к нему; ни выбор файла, ни применение не выполняют PUT автоматически.
- Преобразовывать импортированный трек в допустимый список точек планируемого маршрута: сохранять точные начало/конец и именованные точки, упрощать остальную геометрию Douglas–Peucker до общего лимита 50 точек, после чего использовать штатный live preview и кнопку сохранения.
- Различать ошибки неподдерживаемого типа, слишком большого файла, пустого маршрута и повреждённого содержимого; ограничить локальный импорт размером 20 MiB.
- Добавить переводы RU/BE/UK/PL/EN, доступные подписи/состояния и тесты web/native parsing, preview, replace/append, simplification и ошибок.
- Не хранить и не показывать исходный файл после применения: серверное хранение и повторное скачивание остаются в фазе 2 (#1493/#1496).

### Goal

Пользователь может безопасно загрузить GPX/KML, оценить результат, применить его к локальному черновику и сохранить маршрут только явным действием.

### Non-goals

- Серверная загрузка, хранение, список и скачивание исходных файлов.
- Импорт форматов, отличных от GPX/KML, или одновременный импорт нескольких файлов.
- Изменение backend-контракта `PUT /trips/planned/{id}/route/`.
- Автоматическое сохранение, фоновая синхронизация или новая маршрутизация вне существующего preview-потока #1490.

### Dependencies and fallback policy

- Используются существующие `parseRouteFilePreviews`, route draft в `RouteBuilder`, live preview #1490, `expo-document-picker` и штатный PUT маршрута.
- Лимит 50 точек — консервативный frontend-бюджет, подтверждённый реальным routed PUT; он ограничивает стоимость маршрутизации и не объявляется жёстким максимумом backend API.
- Mock- или server-upload fallback не добавляется. Ошибка чтения/разбора/ёмкости оставляет текущий черновик без изменений и показывает локализованную причину.

## Capabilities

### New Capabilities

- `planned-trip-route-import`: Выбор, разбор, предпросмотр и управляемое применение GPX/KML к черновику маршрута планируемой поездки.

### Modified Capabilities

Нет: в основной папке `openspec/specs/` пока нет существующего capability-контракта планировщика, а backend API не меняется.

## Impact

- **Platform impact — shared:** desktop web, mobile web, Android и iPhone; различается только системный механизм выбора файла, UX и результат едины.
- **Localization impact — all current locales:** новые строки добавляются для RU/BE/UK/PL/EN, RU остаётся fallback.
- **User-visible:** новый инструмент импорта, preview-карточка/карта, режимы replace/append, прогресс чтения и специализированные ошибки.
- **Code:** `components/trips/planning/*`, сфокусированные import/parser/simplification helpers, trip planner tests и i18n resources.
- **API/data:** backend-контракт и схема данных не меняются; после применения сохраняются обычные `RoutePoint[]` существующим PUT.
- **Accessibility:** picker и действия доступны с клавиатуры/скринридера, состояния и ошибки объявляются текстом; touch targets используют проектные примитивы.
- **Performance:** XML читается локально с пределом 20 MiB; preview и draft получают не более 50 итоговых route points, тяжёлая геометрия упрощается до рендера штатного live preview.
- **Security:** принимаются только GPX/KML, XML с `DOCTYPE`/`ENTITY` отклоняется, содержимое не исполняется и не отправляется до явного сохранения маршрута.
- **Analytics:** новые события не добавляются, потому что у plan-route инструментов нет согласованного event-контракта.
- **SEO:** не применимо — авторизованный интерактивный экран не является индексируемой поверхностью.
