## Why

Контракт описания карточки общего MCP task board существует только прозой: `docs/TASK_BOARD_MCP.md`
(664 строки), `.claude/agents/ticket-board.md` (268 строк), `.codex/skills/metravel-ticket-board`,
`.codex/skills/metravel-task-contract`. Ни один гейт не смотрит на текст `description`, поэтому
соблюдение примерно сорока правил зависит от того, вспомнит ли их агент в момент создания карточки.

Замер 2026-08-22 по всем 80 открытым карточкам борда: **46 (58%) нарушают собственный контракт
проекта**. Дефект не исторический — из 12 карточек, созданных 2026-08-19, дефектны 8. Наблюдаемая
цена уже реализовалась:

- Флаг `needs_human` сменил смысл: он стоял у **9 из 14 открытых `area=back` карточек против 8 из
  344 закрытых** (2%). Флаг означает «агент не закрывает задачу сам», поэтому бэкенд-очередь
  выпала из приёмки и осела в `blocked_by`.
- 12 карточек записали поля контракта как `**Scope.**` вместо `Scope:`. Содержание есть, но для
  приёмки, гейтов и governance-тестов, которые ищут строку `Имя:`, контракт невидим.
- 20 карточек не имеют ни одного из семи обязательных разделов; 8 стоят в `blocked_by` без
  названного блокера, причём текст двух прямо говорит, что ничего не блокирует.

Две из этих поломок порождены не невнимательностью, а **противоречием в самих правилах**: одно
требует `Task Contract` для каждой `area=front|back`, другое запрещает контракт на карточке
`needs_human=true` — там, где применимы оба, корректной карточки не существует. Граница между
«ручное действие человека» и «инженерная работа владельца бэкенда» не проведена нигде.

## What Changes

- Ввести машинную проверку контракта описания: один модуль-валидатор, общий для аудита и гейта,
  чтобы трактовка правила не могла разойтись между инструментами.
- Не давать создать дефектную карточку: PreToolUse-гейт на `metravel_task_create`,
  `metravel_task_update` с `description` и на перевод карточки в `todo`. Обновления evidence,
  assignee и связей гейт не трогает — борд не должен вставать из-за исторического долга.
- Разделить дефекты по тому, чем они чинятся: дефект текста (структура, формат, язык) блокирует
  запись описания; дефект поля (спринт, блокер, исполнитель) сообщается, но запись текста не
  запрещает — иначе карточка со `status=blocked_by` без блокера навсегда заперта в плохом описании.
- Дать аудит всего борда одной командой и проверку черновика до отправки.
- **Развести противоречие `needs_human`:** флаг и `Task Contract` объявляются взаимоисключающими;
  реализация backend-задачи владельцем бэкенда перестаёт быть `needs_human` (владельца уже кодирует
  `area=back`).
- **Объявить имя поля контракта идентификатором:** `Scope:` с начала строки; `**Scope.**`,
  `- Scope:`, `__Scope__:` равносильны отсутствию поля.
- Зафиксировать, что `none` — законное значение для `Localization impact`, `Platform impact`
  (с обоснованием) и `Regression control` (контент, разовые операции, исследования), а заглушкой
  считаются прочерк, `TBD` и многоточие.
- Привести уже открытые карточки в соответствие контракту, не теряя ни одного факта из их журналов.

### Goal and user-visible result

Наблюдаемый результат для человека, который открывает борд: карточка отвечает на семь вопросов —
что не так, почему, что делаем, как проверяем — и её нельзя завести иначе. Для исполнителя:
задача, взятая в работу, не требует переспроса. Для приёмки: `Done gate` виден инструментам,
которые его проверяют. Продуктовых экранов сайта изменение не касается.

### Platform impact

`none` — обоснование: изменение целиком лежит в слое инструментов разработки (валидатор, хук
харнесса, npm-скрипт, тексты правил и карточки на борде). Ни один файл приложения, ни один экран,
маршрут, запрос или строка UI не затронуты, поэтому ни desktop web, ни mobile web, ни Android, ни
iPhone не имеют наблюдаемой поверхности для проверки.

### Localization impact

`none`. Переводимых строк приложения (`@/i18n`) изменение не добавляет и не меняет; `npm run
test:i18n` не относится к scope. Тексты правил и сообщений гейта пишутся по-русски — это язык
проектной документации, а не locale-контракт продукта.

### Dependencies and fallback/mock policy

- Зависимостей от бэкенда, API-контракта и миграций нет. Борд читается существующим
  `GET /api/tasks/`, пишется существующим `PATCH /api/tasks/<id>/`; `../metravel-backend` остаётся
  read-only, задача `area=back` не требуется.
- Гейт не должен подменять проверку моком: аудит и хук обязаны применять один и тот же модуль,
  а не две копии правила.
- Порог не понижается ради зелёного прогона: карточка, не проходящая контракт, чинится текстом,
  а не ослаблением проверки. Обход `BOARD_TASK_GATE_BYPASS=1` допустим только по явной просьбе
  владельца и остаётся видимым в выводе.
- Сбой инфраструктуры (нет токена, нет сети) не превращается в тихий пропуск: хук обязан сказать,
  что контракт не проверен.

### Existing behavior to preserve

- Гейт код-ревью `.claude/hooks/review-gate.mjs` и его цепочка `review → testing → done`.
  Новый гейт встаёт рядом и не меняет его поведение.
- Обязательный pre-create Problem Memory verdict и правило «у каждой задачи — спринт».
- Журнальная природа `description`: evidence дописывается, прошлые записи не переписываются.
- Возможность вести борд напрямую через REST, когда MCP-коннектор недоступен.

### Out of scope / Non-goals

- Реализация самих задач с борда: change нормализует карточки, но не выполняет их содержание.
- Изменение статусов, `kind`, `area`, приоритетов и связей карточек по существу — кроме
  исправления полей, прямо противоречащих контракту (спринт, ошибочный `needs_human`, исполнитель).
- Расщепление смешанных карточек «человек + агент» на пары связанных карточек: правило
  зафиксировано, массовое применение выносится отдельно.
- Изменение схемы борда на бэкенде, добавление серверной валидации `description`.
- Любой деплой, публикация и перенос статусов в `done`.

### Open questions

Нет вопросов, меняющих scope. Одно решение принято явно и записано здесь: карточки, где остаётся
ручное действие владельца, получают статус по фактическому состоянию работы, а не `blocked_by` без
блокера; расщепление таких карточек на пары вынесено из scope.

## Capabilities

### New Capabilities

- `board-task-description-contract`: наблюдаемый контракт карточки общего MCP task board — какие
  разделы обязательны и в каком порядке, какие поля являются идентификаторами, как соотносятся
  `needs_human` и `Task Contract`, что считается заглушкой, какие дефекты блокируют запись, а какие
  только сообщаются, и в какой момент проверка обязана сработать.

### Modified Capabilities

Нет. `openspec/specs/` сейчас пуст, живой capability под контракт борда не существует — этот
change заводит первый.

## Impact

- **Ожидаемый scope:** `scripts/lib/boardTaskContract.mjs` (валидатор),
  `scripts/audit-board-tasks.mjs` (аудит), `.claude/hooks/task-quality-gate.mjs` (гейт),
  `.claude/settings.json` (регистрация хука), `package.json` (команда `board:audit`),
  `__tests__/scripts/board-task-quality-gate.test.ts` (тест инварианта), правила в
  `docs/TASK_BOARD_MCP.md`, `docs/CODEX.md`, `.claude/agents/ticket-board.md`,
  `.codex/skills/metravel-ticket-board/SKILL.md`, `.codex/skills/metravel-task-contract/SKILL.md`,
  шаблоны `.claude/skills/metravel-issue/*` и их зеркала в `.agents/skills/`.
- **Data/API:** без изменений. Ни один endpoint, поле, код ошибки или формат ответа не меняется;
  используются существующие чтение и запись карточек.
- **SEO, accessibility, performance, analytics:** не затронуты — изменение не попадает в бандл
  приложения и не выполняется в браузере пользователя.
- **Security:** токен борда читается из `.secrets/metravel-task-board.env` или окружения и никогда
  не печатается; новых сетевых назначений, кроме уже используемого `metravel.by/api/tasks/`, нет.
- **Данные борда:** описания открытых карточек переписываются под контракт. Риск — потеря фактов
  при переупаковке; контроль — правка только `description`, сверка неизменности служебных полей
  после каждой записи и запрет выдумывать причину.
