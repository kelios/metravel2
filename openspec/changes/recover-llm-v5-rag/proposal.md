# Proposal

## Why

В #2751 требуется устранить пограничные отказы о поездках, длинные BE/UK-списки
и потерю прежних навыков. Подготовленный ранее v5 обучался на `constraints`
без исправленного `rag_answers`: базовый контроль улучшился с 3/10 до 8/10,
сложный ухудшился с 7/16 до 5/16; эти результаты не закрывают контракт #2751.

## What Changes

- Исправить генератор `rag_answers` edition 5: цели только по видимым фактам
  карточек, компактные списки на всех языках, явный языковой баланс и EN/RU
  примеры различения вопроса о поездке и посторонней темы.
- Подготовить отдельную смесь и кандидата `v5-rag` **от v4** с replay S1.
  Существующие v4/v5, их данные, веса и отчёты сохраняются.
- Заморозить оценку до генерации данных, включая 10 новых вопросов
  `cases.v5-holdout.jsonl`, старые основные и сложные наборы; проверить утечки.
- После независимого code review выполнить локальную пробу, обучение,
  отдельный GGUF-экспорт и сравнение по каждому gate #2751 с независимым судьёй.
  Провал любого обязательного gate означает no-go кандидату.

Non-goals: изменение app-промптов, retrieval, фильтра тем, backend, UI, текущей
модели продукта, production/store/cloud operations или обещание улучшения до
приёмки. Старые вопросы/ответы оценки не становятся обучающими примерами.

## Capabilities

### New Capabilities

Нет. `skip_specs: true`: это восстановление существующего контракта ответов
#2751 через генератор данных и локальный процесс обучения, без новой app/API
возможности и без смены модели продукта. Создавать нормативное требование
исключительно ради validation не требуется.

### Modified Capabilities

Нет. В текущем инвентаре OpenSpec нет LLM capability; требования существующих
app capabilities не меняются. Измеримые условия приёмки сохраняются в Task
Contract #2751 и явно перечислены в design/tasks этого recovery.

## Impact

- Paths: `scripts/ai-train/sets/rag_answers.py`, отдельные mix/config
  `v5-rag`, тест генератора; новые holdouts и LLM workflow skills/role prompts.
- User-visible result: локальный кандидат должен выполнять прежний контракт;
  результат ещё не доказан. Platform impact: none в app-коде; модель shared.
  Localization impact: RU/BE/UK/PL/EN в данных и оценке; UI i18n не меняется.
- Data/API: прежний формат `sets/common.py`, prepared manifests и GGUF SHA256;
  новых endpoints и backend-изменений нет.
- Accessibility: проверяется отсутствие неподтверждённых выводов по карточкам;
  реальные маршруты и native accessibility этим заданием не подтверждаются.
- SEO/analytics/security UI: none — app-код и внешние интерфейсы не меняются.
  Performance: локальные память, время обучения/инференса измеряются, а не
  обещаются; production latency и browser performance вне scope.
- Dependencies: локальные base model/tokenizer, v4 adapter и кэши;
  #2710/#2712/#2731 и S1-срезы #2479. Fallback/mock policy: только локальная
  модель и замороженные карточки, без платных API или подмены ответов.
- Authority: пользователь поручил «делай» и LLM skills; planning проверяется
  до следующего применения. Commit/board handoff ведёт root по правилам задачи;
  отдельный frontend deploy для локального model-only scope не нужен.
- Existing behavior to preserve: предыдущие модели/отчёты, формат набора,
  все обязательные S1/S2-навыки и отказы на посторонние темы/эскалацию.
  Open questions: материальных вопросов о границах нет; достижение порогов
  определяется фактической оценкой и не предполагается заранее.
