## Context

Мотивация и границы продукта — [proposal.md](proposal.md). Наблюдаемые требования —
[ready-travel-books](specs/ready-travel-books/spec.md) и
[travel-book-print-packages](specs/travel-book-print-packages/spec.md).
Нормативные визуальные материалы — `docs/design/travel-memory-books-v1.md`,
редакционный и продуктовый контракт — `docs/features/travel-memory-books.md`.

Сейчас `/export` выбирает личные статьи и ограничивает mobile web
(`app/(tabs)/export.tsx:32,95`). `BookSettings` описывает оформление статьи, но не
готовое издание и физический формат (`types/bookSettings.ts:11`). Генератор
фиксирует A4 (`services/pdf-export/generators/v2/runtime/pdfRuntimeMarkup/htmlDocument.ts:54`),
worker также использует A4 (`workers/book-renderer/measurement.ts:270`). Это
подтверждённые ограничения, а не основание масштабировать старую книгу.

Общий печатный адаптер уже существует для web и приложений
(`utils/printHtml.types.ts:28`, `docs/features/export.md`, раздел «Печать — одна
точка»). Серверные задания/скачивание также существуют: `api/bookExportApi.ts`
принимает selection из `travel_ids`. Старое утверждение профильного PDF skill о
web-only/отсутствии серверного PDF не описывает текущий код.

## Goals / Non-Goals

**Goals:** один версионированный источник содержания и геометрии для предпросмотра
и файлов двух изданий; точные размеры вместо масштабирования A4; публичное
скачивание без доступа к приватному экспорту; независимость готовой печатной книги
от сети, аккаунта и текущего ответа API.

**Non-Goals:** миграция общего экспорта статей, изменение существующего API
заданий, пользовательские загрузки фото, native-печать нового раздела, постоянный
рендер по запросу посетителя, обещание PDF/X/CMYK без допечатной проверки,
приём/передача заказа и платежей. Бэкенд для v1 не меняется; будущий заказ требует
отдельной `area=back` задачи и проверки провайдера.

## Decisions

### 1. Отдельная публичная коллекция готовых изданий

Добавить `/books`, `/books/[slug]`, выбор формата и страницу/состояние предпросмотра.
Гость имеет те же файлы, что вошедший пользователь. Статический manifest и
артефакты публикуются одной ревизией; каталог показывает только готовые ревизии.
Файлы скачиваются непосредственно, без создания задания экспорта.

Переиспользовать существующие `components/ui`, контейнеры, тему и доступные
состояния. Пункт «Книги путешественника» добавляется через
`constants/headerNavigation.ts`; mobile получает его через существующее «Ещё»
(`components/layout/bottomDockModel.ts:75,96`), без шестой кнопки дока. Ссылки из
релевантных статей/квестов ведут к конкретному изданию только при подтверждённом
соответствии источника.

Альтернатива — расширить приватный `/export`: отвергнута, поскольку он связан со
своими статьями, авторизацией и иной мобильной доступностью. Названия и объяснение
различают готовые книги и существующую книгу личных путешествий.

### 2. Типизированный фиксированный снимок, без новых серверных endpoints

Предлагаемые task-owned paths: `types/readyBook.ts`, `data/travelBooks/**`,
`services/book/readyBooks/**`, `components/books/**`, `app/(tabs)/books/**`,
`scripts/build-ready-books.mjs`, `scripts/validate-ready-books.mjs`, тематические
тесты и ресурсы `books` в пяти локалях.
Подготовленные артефакты размещаются по версионированным публичным URL в
разрешённом проектом хранилище; большие исходники не дублируются в app-бандле.
Решение о размещении фиксируется до публикации, без нового облачного рендера.

```ts
type CountryCode = 'BY' | 'PL';
type BookProfileId = 'pocket-150x100' | 'album-a5';
type ArtifactPurpose = 'read' | 'home-rings' | 'home-sewn' | 'print-shop'
  | 'stickers' | 'instructions' | 'print-passport';
type SourceRef = { kind: 'place' | 'travel-address' | 'quest-step'; id: string; url: string };
type BookStop = {
  id: string; title: string; lat: number; lng: number;
  source: SourceRef;
  text: { compact: string; album: string }; fact: string; legend?: string;
  references: { url: string; checkedAt: string }[];
  image: { uri: string; sha256: string; credit: string; rights: string; illustrated: boolean };
};
type PrintProfile = {
  id: BookProfileId; widthMm: number; heightMm: number; // обрезной размер книги
  bleedMm: 0 | 2 | 3; safeMm: number; bindingMm: number;
  binding: 'rings' | 'spiral' | 'sewn';
};
type BookArtifact = {
  id: string; revision: string; profileId: BookProfileId;
  purpose: ArtifactPurpose;
  component: 'body' | 'cover' | 'stickers' | 'instructions' | 'passport';
  outputPageMm: { width: number; height: number };
  imposition: 'single-pages' | 'a4-cut' | 'a4-signatures';
  uri: string; mime: string; sha256: string; bytes: number; pageCount: number;
  printProfile: PrintProfile; providerProfileId?: string;
};
type ReadyBook = {
  schemaVersion: 1; id: string; slug: string; revision: string;
  title: string; country: CountryCode; contentLocale: 'ru';
  stops: BookStop[]; bodyPageCount: 56; coverPageCount: 4;
  artifacts: BookArtifact[];
  preview: { revision: string; profileId: BookProfileId; pages: { number: number; uri: string; alt: string }[] }[];
};
```

Размер страницы PDF задаёт outputPageMm отдельно от обрезного размера книги:
например, A4 для home/stickers/instructions, trim+bleed для типографии.
Раскладка и карта реза/сгиба задаются явно; pageCount — страницы конкретного
файла, bodyPageCount — внутренний блок книги.

Manifest проверяет уникальность ID, 12 мест, последовательность страниц, диапазон
координат, разрешённые URL, права/атрибуцию, контрольные суммы и наличие всех
артефактов. Источники `/places`, адреса статей и квесты используются при подготовке
снимка, не при открытии каталога. Цены/часы работы не фиксируются как бессрочная
гарантия: QR и текст отправляют к актуальному официальному источнику.

Уточнение A1 (27.10.2026): перед `ReadyBook` существует отдельный
`EditorialBookDraft` со статусом `editorial-draft`, без файлов и фиктивных image/hash.
Обязательные поля готового `ReadyBook` не ослабляются; его статус — `ready`.
Официальные первичные источники используют `source.kind: official`, внутренние
виды источников сохраняются. Координаты сопровождаются `coordinateAccuracy` и
`coordinateSource`; непроверенные сведения черновика перечислены в `gaps`.
Изображение требует `rightsBasis`, `rightsSource`, `printAllowed: true` и подпись.
Легенда представлена `{label:'Легенда',text,sourceUrl}`. Полный актуальный контракт
типов выводится из схем `data/travelBooks/schema/` в `types/readyBook.ts`.

Preview имеет `component: body|cover`, `sourceSha256` точного файла `read` и
номер/URI/SHA-256/bytes/alt каждой страницы. На профиль приходится 56 страниц
блока и отдельные 4 стороны обложки, всего четыре группы preview. Это исключает
смешение 60 файловых страниц с внутренней пагинацией. Домашняя обложка — отдельный
`home-rings:cover`, подходящий также для A5 с прошитыми тетрадями.
Внутренние body-файлы дома имеют не менее 28 выходных A4-страниц, обложка — не
менее двух; контрольные страницы могут увеличивать это число. Их точный порядок
и количество проверяет B3, а не предположение по счётчику manifest.

Альтернатива — каждый раз собирать книгу из живого API: отвергнута из-за изменений
содержания между preview и PDF, сетевых ошибок и отсутствия контракта ready-book в
приватном API. Существующие `BookSettingsDto`/`BookDocument` v1 не расширяются
несовместимыми полями.

### 3. Семантические страницы и два самостоятельных макета

Общая модель описывает тип страницы, содержание и порядок, а профиль задаёт
физическую геометрию. 150×100 мм — альбомный компакт, 148×210 мм — портретный A5.
Размеры шрифта, объём текста и композиция задаются для каждого, а не выводятся из
коэффициента уменьшения A4. Старый A4 остаётся значением по умолчанию его сценария.

Внутренний блок 56 страниц: 1 — титул, 2 — подготовка, 3 — использование,
4 — содержание, 5 — обзорная карта; места занимают 6–53, по четыре страницы.
Для места n от 0 до 11: `6 + 4*n` — левая информационная страница,
`7 + 4*n` — правая страница памяти, две следующие — заметки/коллаж.
54–56 — свободная страница, чек-лист и выходные сведения. Обложка из четырёх
сторон отдельно; печатная нумерация не смешивается с номером страницы файла.

Компакт предлагает фото 70×100 мм; A5 — рамку 108×158 мм, пригодную и для
номинальных 100×150, и для 102×152 мм. Горизонтальный снимок на портретном A5
поворачивается либо размещается отдельным вкладышем; он не обрезается молча.
Открытка не имеет единого гарантированного размера: инструкция просит измерить
её, предлагает карман/вкладыш и сохраняет область крепления свободной.

Переиспользовать `escapeHtml`, `buildSafeImageUrl`, печатную обработку изображений
и генерацию HTML; новые рендереры страниц подключать через отдельный адаптер
готовых изданий. Не копировать монолит старого экспортера. Карту/QR можно
переиспользовать из печатного квеста, но готовые ресурсы включаются в артефакт:
ссылка `quickchart.io` из существующего helper не остаётся зависимостью печати.

### 4. Отдельные пакеты для разных способов производства

Для дома: A4 без вылетов, белые непечатные поля, масштаб 100%, контрольная линейка
и тест двухсторонней подачи до полного тиража. Для компакта две страницы 150×100
мм располагаются одна над другой: ширина разворота 300 мм не помещается в A4 и
не предлагается как домашний буклет. После разрезания страницы собираются на
кольца/спираль по карте порядка. A5 получает готовую раскладку для колец и
отдельный сшиваемый вариант с тетрадями 16+16+16+8 страниц. Половина A4 —
148,5 мм: точный A5 требует обрезать внешние 0,5 мм после сгиба либо
предварительно обрезать лист до 296 мм. Инструкция различает
раскладку и последовательные страницы; драйверный режим «буклет» поверх готовой
раскладки не включается.

Режим переворота листа определяется подписанным тестом для выбранного пакета и
принтера. Непечатные поля конкретного устройства не компенсируются скрытым
масштабированием: при несовместимости предлагается другой поддержанный способ.
Бумага, переплёт и припуск под вклеенные фото проверяются бумажным макетом;
рекомендации по плотности не выдаются за совместимость любого принтера.

Типография получает последовательные страницы блока, отдельную обложку и лист
технических параметров. Профиль хранит конкретные вылеты 2 либо 3 мм, безопасную
зону от 5 мм и область крепления 15 мм как исходные значения, подлежащие сверке
с провайдером. Один универсальный «типографский PDF для всех» не заявляется.
Полный v1 требует хотя бы один подтверждённый провайдерский профиль для каждой
страны и каждого формата; домашний комплект без этого не закрывает всю приёмку.
PDF/X, ICC и CMYK получают статус подтверждения только после проверки точного
профиля и готового файла; обычный PDF браузера не маркируется PDF/X.

Наклейки — два самостоятельных листа A4 на страну с контуром ручной резки,
контрольной линейкой и вариантом без цветного фона. Готовая сетка не обещает
совместимость с произвольной преднарезанной бумагой. Наклейки не увеличивают
страничность внутреннего блока.

### 5. Каталог типографий отражает проверенные возможности

Статический справочник покрывает Минск, Брест, Витебск, Гомель, Гродно, Могилёв
и 18 административных центров 16 воеводств Польши. Для каждого варианта хранить
`country`, `city`, `providerName`, `url`, `fulfillment: local | delivery`,
`checkedAt`, `sourceUrls: string[]`, `supportedProfiles: string[]`,
`acceptsRuPdf: yes | no | unknown`, `contactLanguages: string[]`,
`deliveryCoverage: string[]`, `minimumCopies: number | null`,
`verification: published | sample-confirmed`. Неизвестное значение не становится
подтверждённым boolean. Доставка по стране не называется местным филиалом.

В v1 действия — скачать пакет и открыть сайт/форму провайдера. Ни файлы, ни
контакты пользователя автоматически не передаются. Интеграция, договор,
стоимость, согласие на передачу данных, callback/idempotency и обработка ошибок
заказа планируются отдельной будущей цепочкой. API/договор нельзя выводить из
наличия формы загрузки на сайте типографии.

### 6. UI, локализация, доступность и обнаружение

App-owned подписи, ошибки, размеры, a11y и форматирование — namespace `books` в
RU/BE/UK/PL/EN. Содержание/PDF — `ru`; язык явно указан до скачивания и не
зависит от переключения интерфейса. Будущие переводы — новые редакционные
ревизии, без автоматического перевода русской книги клиентом.

Предпросмотр имеет одиночную страницу на телефоне, разворот на широком экране,
номера, текстовый список мест/страниц, управление клавиатурой и масштабом.
Изменение масштаба/сворачивание панели не теряет выбранную страницу; закрытие
возвращает фокус на открывший элемент. Ошибки/пустые/медленные состояния различимы.
Изображения имеют содержательный `alt`, заголовки и кнопки — семантику, контраст
и размеры касания по действующим UI-контрактам.

SEO использует действующие metadata/canonical helpers, стабильные URL и обычные
ссылки на издания. RU-содержание не выдаётся за перевод; локализованные UI URL
следуют текущему router-контракту. Основные сведения доступны в первом HTML.
Файлы предпросмотра не создают конкурирующих индексируемых страниц.
`robots.txt`/`sitemap.xml` вручную не правятся; редиректы и новая structured data
для v1 не требуются, поскольку старые URL не заменяются.

### 7. Производительность, безопасность и наблюдение

Каталог загружает обложки с заданной геометрией; PDF и все страницы preview не
загружаются до действия пользователя. Предпросмотр подгружает текущую страницу
и ограниченное соседство. Один слот получает один подходящий URL; тяжелый
генератор отсутствует в initial bundle каталога. До реализации снять baseline
каталожной оболочки; после — сравнить одинаковые production условия и запросы.
Проверяемые бюджеты: ноль автоматических загрузок PDF на входе; не более трёх
страниц preview в первом запросном окне; отсутствие вызова render job API.

Все редакционные строки экранируются; URL проходят общие проверки, изображения
и шрифты в PDF встроены. Запрещены удалённые скрипты/ресурсы в готовом печатном
файле, произвольные redirect URL и передача личных данных типографии.
Внешние действия проходят `utils/externalLinks.ts`; токены/секреты не нужны.
Новый WebView/deep-link контракт не вводится.

События: `ReadyBookViewed`, `ReadyBookPreviewOpened`, `ReadyBookProfileSelected`,
`ReadyBookDownloadStarted`, `ReadyBookDownloadFailed`, `ReadyBookInstructionsViewed`,
`ReadyBookProviderOpened`. Параметры: `book_id`, `revision`, `country`, `profile_id`,
`artifact_purpose`, `ui_locale`, `content_locale`; у провайдера — публичный ID.
Без PII и пользовательских заметок. Скачивание/переход не считается печатью или
заказом; download success сообщается лишь при наблюдаемом завершении, иначе
измеряется начало. Существующие события экспортера не переопределяются.

## Risks / Trade-offs

- [Готовые PDF расходятся с preview] → одна ревизия/план страниц, контрольные
  суммы, сравнение полного комплекта до публикации.
- [Компакт становится нечитаемым] → самостоятельная композиция, редакционный
  лимит текста, проверка напечатанного образца 100%.
- [Вклейка фото раздувает переплёт] → кольца по умолчанию, бумажный макет с
  заполнением и отдельная проверка сшиваемого варианта.
- [Отсутствует доступ к физической пробе] → цифровые размеры не заменяют её;
  запросить конкретный доступ к принтеру/образцу. Платный заказ сначала проходит
  действующий operation gate, само планирование расход не разрешает.
- [Исторический факт/легенда или координата неверны] → источники и дата проверки
  на каждое место, легенда отдельно, неподтверждённое утверждение исключается.
- [Провайдер сменил условия] → дата/источник, статус unknown и понятный внешний
  запрос; переоценка перед выпуском, без гарантии цены/срока.
- [Регресс старой A4-книги] → отдельный адаптер и неизменённый default; общие
  функции меняются только с целевыми regression checks.

## Migration Plan

1. Зафиксировать содержание, права и нормативные макеты; проверить печатные
   профили и технический тест на бумаге.
2. Подготовить manifest, валидатор, сборку/preview и все артефакты одной ревизии.
3. Внедрить публичный каталог, страницу издания и навигацию; пройти независимый
   code review и code-level проверки. Runtime QA — только стадия `testing`.
4. По штатному pipeline задачи опубликовать ту же ревизию и принять на production
   после разрешённого выката, сверив SHA приложения и manifest/PDF.
5. Откат: атомарно вернуть предыдущий manifest и frontend SHA. Версионированные
   файлы не перезаписывать, действительные ранее скачанные PDF остаются читаемыми;
   ошибочную ревизию убрать из каталога и обозначить замену на странице издания.

### Validation matrix

| Контракт | Проверка и evidence | Почему достаточно / когда расширять |
| --- | --- | --- |
