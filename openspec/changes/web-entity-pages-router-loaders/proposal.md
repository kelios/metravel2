# Proposal: тело SEO-страниц штатными загрузчиками Expo Router 58 вместо генератора (#2766)

Статус: **решение владельца — модель A или B** (рекомендация спайка: A). До решения apply не начинается.

## Problem

Каждый выкат web-фронтенда заново рендерит ~1 400 per-entity страниц (431 статья, ~470 страниц
квестов и городов, ~520 локализованных — по `https://metravel.by/sitemap.xml` 26.10.2026)
собственным генератором `scripts/generate-seo-pages.js` (~4 000 строк вставки HTML поверх экспорта).
Код и контент выпускаются одним неделимым артефактом:

- правка квеста во время сборки отклоняет выкат кода (`R1 ≠ R2`, `scripts/lib/questSeoContract.js:255`;
  26.10 — дважды);
- каждое поколение сайта несёт весь контент (#2762: пик 1 060 из 1 536 МиБ, бюджет не поднимаем);
- тело страницы для поисковиков — параллельная статическая разметка генератора, которую React
  скрывает после гидрации, а не рендер самого экрана.

В #2740 генератор оставили, потому что экспорт «не пререндерит тело». В SDK 58 есть штатные
`loader` + `useLoaderData`, `generateStaticParams`, `generateMetadata` и `output: "server"`.
Спайк #2766 проверил обе модели на маршруте `/travels/[param]` (цифры и пути — `design.md`).

## Goal

Per-entity страницы рендерит сам Expo Router из данных маршрута; выкат кода не зависит от правок
контента; SEO-контракт (`docs/features/seo-static-metadata.md`) сохраняется без потерь.

## Варианты на решение владельца

**A. Рендер на запрос** (`web.output: "server"` + `loader`): Node-процесс на проде рендерит
страницу из API при запросе, nginx кеширует ответ. Выкат — только код; правка статьи или квеста
видна без выката; поколения HTML и генератор уходят.
Цена: новый долгоживущий процесс рядом с Gunicorn на слабом хосте; правка nginx (кеш, прокси) —
только через `area=back` карточку; до запуска обязателен фикс удержания памяти в SSR (ниже).

**B. Рендер при сборке** (`output: "static"` + `loader` + `generateStaticParams`): React сам рендерит
тело при экспорте. Цена: контент остаётся запечённым в сборку (главная цель не достигается);
в SDK 58 «как есть» экспорт падает по памяти уже на 350 страницах; нужен собственный патч
`@expo/cli`; SPA-переход на статью, опубликованную после сборки, ломается без серверного фолбэка.

**Рекомендация: A.** B не устраняет связку код↔контент и требует поддерживать патч ядра сборки;
A работает на штатном SDK, а выявленные риски A конкретны и закрываются задачами (design.md → «План A»).

## Non-goals

- Изменения бэкенда и nginx без отдельной `area=back` карточки (для A — прокси, кеш, процесс,
  сигнал сброса кеша при правке контента).
- Смена SEO-контракта: title/description/canonical/hreflang/JSON-LD остаются по
  `docs/features/seo-static-metadata.md`.
- Native (Android, iOS): loaders и SSR — только web.
- iOS signed build / store — не затрагиваются.

## Impact

- **Platform impact:** desktop web и mobile web — меняется способ рендера per-entity страниц;
  Android, iOS — none (общий код экрана правится только в web-ветках и SSR-безопасности).
- **Localization impact:** all current locales (RU/BE/UK/PL/EN) — локализованные страницы квестов и
  hreflang должны сохраниться; app-owned строки не добавляются.
- **SEO:** паритет head/тела/JSON-LD по подписи до/после — обязательный гейт каждого маршрута.
- **Performance:** HTML с данными loader'а тяжелее (спайк: 2,5–3,8× сырого, 2,2× gzip) — payload
  урезается до полей экрана; на мобильной ширине нужна адаптивная вёрстка без JS-ветвления по ширине,
  иначе гидрация пересоздаёт поддерево (CLS/TBT).
- **Security:** серверный рендер только гостевого состояния; модульные синглтоны (React Query,
  стора) не должны переносить данные между запросами.
- **Analytics:** без изменений.
- **API/data:** без изменений контрактов; запрос `by-slug` на страницу (A — на промах кеша).

## Dependencies

Решение владельца A/B. Для A — `area=back` карточка: Node-процесс под supervisor/compose, nginx
`proxy_pass` + `proxy_cache` + `stale-while-revalidate`, сброс кеша по событию правки контента.

## Fallback / mock policy

До переключения маршрута генератор продолжает обслуживать его без изменений; маршрут
переключается только после зелёного SEO-diff и проверки гидрации. Откат — возврат маршрута на
генератор (A: nginx снова отдаёт статический HTML).
