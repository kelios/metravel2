## Purpose

Per-entity web-страницы (статьи, квесты, города, страны, локализованные квесты) рендерятся штатным механизмом роутера из данных маршрута; выпуск кода не зависит от правок контента, SEO-контракт сохраняется.

## ADDED Requirements

### Requirement: Тело страницы рендерит экран маршрута
Система SHALL отдавать в HTML per-entity страницы до выполнения JavaScript H1, текст статьи или квеста и JSON-LD, отрендеренные тем же экраном, который затем гидрируется, без параллельной статической разметки.

#### Scenario: Статья без JavaScript
- **WHEN** краулер запрашивает опубликованную статью без выполнения JavaScript
- **THEN** HTML содержит H1 с названием, не менее 90 % слов текста статьи, JSON-LD Article, BreadcrumbList и FAQPage (если в тексте есть вопросы), а title, description и canonical совпадают с прежними значениями

### Requirement: Гидрация без расхождений на всех ширинах
Система MUST гидрировать серверный HTML per-entity страницы без ошибок расхождения React на ширинах 390, 768 и 1440 px.

#### Scenario: Мобильная ширина
- **WHEN** обычный браузер открывает статью на ширине 390 px
- **THEN** консоль не содержит ошибок гидрации, и первый кадр не перестраивается после гидрации

### Requirement: Выкат кода не зависит от правок контента
Система SHALL выпускать код web-фронтенда без отказа из-за правок статей или квестов, сделанных во время сборки.

#### Scenario: Правка квеста во время выката
- **WHEN** редактор сохраняет квест, пока идёт сборка и выкат кода
- **THEN** выкат завершается успешно, а страница квеста показывает либо прежнюю, либо новую редакцию целиком

### Requirement: Новый контент доступен без пересборки
Система SHALL открывать статью или квест, опубликованные после последнего выката, и прямым заходом, и переходом внутри приложения.

#### Scenario: Переход на свежую статью
- **WHEN** пользователь внутри приложения переходит на статью, опубликованную после выката
- **THEN** открывается статья, а не главная страница или ошибка загрузки данных
