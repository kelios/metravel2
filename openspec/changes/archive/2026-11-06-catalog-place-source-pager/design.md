## Context

`utils/placesCatalog.ts` сохраняет id точки для рейтинга и ссылки, но теряет поля физического места. В `screens/tabs/PlacesScreen.parts.tsx` один набор свойств описывает и место, и материал. Общий механизм карты уже умеет разбирать идентификатор, объединять первичный источник с ответом и читать страницы из одного кэша.

## Goals / Non-Goals

Разделить свойства места и материала на границе карточки и сохранить контракт каталога для других потребителей. Миграция мест, голосов и разрешений принадлежит #3075.

## Decisions

- Переиспользовать `readMapPlaceMarkerFields`, `usePlaceSourcePagerState` и `PlaceSourcePager`. Отдельная карусель каталога продублировала бы обработку пагинации, состояния, кэш и доступность.
- Оставить запрос карты включаемым при открытии. Для списка дать тому же хуку запуск по стрелке с переходом в запрошенном направлении после ответа. После первого действия только наблюдатель выбранного места остаётся активным, чтобы реестр блокировок обновлял видимые статьи. При инвалидации показываем первичный источник до актуального ответа. На первом рендере каталога сеть и геометрия медиа остаются такими же, одновременно используется только активное фото.
- `GET /api/places/catalog/` несёт `id: number`, `place_id: string | null`, `source_count: number`, `primary_source` и `rating`. `GET /api/map/places/{place_id}/sources/?cursor=...` возвращает `results` и `next`. Выбираем ключ места только по серверным данным и сохраняем `id` точки для рейтинга, действий с точкой и ссылок из каталога. При повторе запроса используется тот же ключ React Query, что и в карте.
- В `PlaceListCard` использовать общий pager внутри карточки. Стрелки остаются на одном месте независимо от наличия фото и состояния сети. Сохраняем размер цели 44, клавиатурную активацию, объявление состояния, привычную геометрию фото и лимит основных действий. Переход к статье проходит через текущий нормализатор маршрута и шлюз внешних ссылок.
- SEO, URL каталога, данные JSON-LD, авторизация, аналитика, сервер и платформенные движки используют прежние контракты. Изменения в `utils/placesCatalog.ts`, `screens/tabs/PlacesScreen*`, компонентах карточки каталога и общем pager.

## Risks / Trade-offs

- Частичный ответ может содержать только дополнительную статью. Объединение по серверному ключу источника удерживает первичную первой и пересчитывает счётчик по доступным материалам.
- Общий pager используется на карте. Изменения режима запуска ограничены опцией каталога, а существующие тесты проверяют режим карты и кэш.
- Вариант без медиа использует тот же блок управления, поэтому остаётся путь назад с помощью стрелок.

## Migration Plan

Фронтенд принимает старый ответ и использует прежнюю карточку при отсутствии идентификатора. Откат коммита восстанавливает одиночную карточку, миграции клиента нет. После #3075 проверяем Гольшанский замок через живой API.

## Validation

Jest для контракта каталога, карточки, пагинации и соседнего popup, lint, проверка типов и локализаций. После ревью mobile web и desktop web на одном опубликованном target с console, network и screenshots. Android и iOS используют те же компоненты, отдельная платформенная граница не меняется.
