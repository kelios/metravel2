## Context

See proposal.md for motivation and scope. Existing sources are standalone Node scripts: unified Google token resolver (`scripts/lib/google-token.js:6`), GSC request adapter (`scripts/fetch-gsc-stats.js:34`) and GA4 report adapter (`scripts/fetch-ga4-stats.js:64`). GSC currently auto-runs on import (`:163`); GA4 already has a main guard and exports (`:266`). GA4 property discovery chooses the first account property (`:19–30`), which requires explicit identity handling for an owner summary. Existing publication filters are `where={publish:1,moderation:1}` (`scripts/generate-sitemap.js:229–233`). Public quest metadata exposes completion counters (`api/quests.ts:40`) but no catalogue creation timestamp (`:138–181`). Jest discovers `.test.ts`/`.test.tsx`, not `.test.js` (`jest.config.js:16`).

## Goals / Non-Goals

**Goals:** deterministic pure aggregation/rendering functions around injectable source collectors; source-specific missing-data states; all-history community assessment; preserved neighboring CLIs.

**Non-Goals:** generic analytics SDK, backend edits, app runtime/UI changes, exact historic author acquisition, sums of monthly active users presented as distinct yearly users.

## Decisions

1. **Calendar and source contracts.** Derive month labels from the run date in Europe/Warsaw and construct month boundaries with UTC arithmetic to avoid DST/day rollover. Use inclusive ISO dates for Google reports and record their source timezones (GSC source calendar and GA4 returned property timezone); do not imply timezone-normalized raw events. Output 12 completed month rows plus comparison values from the preceding 12. An injected clock makes boundaries testable. Reject rolling `--days` subprocess reuse because it cannot represent exact month windows.
2. **Reuse Google request adapters.** Add a GSC main guard and explicit query export; export GA4 runReport while preserving all current exports and CLI defaults. Reuse `getAccessToken` with required readonly scopes, never duplicate OAuth flows. Prefer explicit `--property`/GA4_PROPERTY_ID; any automatic resolution must make property identity visible and avoid silently selecting among multiple properties. Keep existing rolling-stat CLI behavior unchanged. The CLI exposes optional `--end-month YYYY-MM`, `--property ID` and `--json`; JSON supplements the same saved Markdown report.
3. **Source isolation and availability.** Collect source outcomes independently with status, period, identity, quality and safe failure reason. Deadlines and bounded pagination prevent hangs. Parse finite nonnegative metrics; absent rows are not by themselves evidence of complete zero coverage. Preserve Google quality flags; thresholding, sampling, truncation and retention gaps disable definitive comparisons. Check official source retention/availability contracts before production collection. GSC requests use finalized data where available; the immediately preceding month can still be partial near month-start. Do not infer historical availability simply from a successful empty API response.
4. **Minimal reports.** Use three bounded GA4 `yearMonth` reports for headline totals, channels and requested events across the 24-month span, with `allRows` pagination and quality preservation; fetch monthly activeUsers directly because users are nonadditive across slices. Preserve raw precision until display. GSC uses date rows (row limit 25000), not query/page dimensions: aggregate clicks and impressions additively, CTR as summed clicks divided by summed impressions, and position weighted by impressions. Restrict requests to full months after a conservative retention cutoff, withholding the oldest partially retained month. Requested event names are case-sensitive; a missing event in an otherwise demonstrably complete measured period can be described as no observed events, not emitter failure. Yandex is an optional read-only adapter with explicitly configured credentials/counter; no login workflow or secret discovery by printing files. Extract the existing optional token reader into `scripts/lib/yandex-token.js` and reuse it from `scripts/analytics-health-check.js`, preserving its previous resolution behavior. Separate pure aggregation/rendering (`scripts/lib/metrics-summary.js`) from collection (`scripts/lib/metrics-summary-sources.js`).
5. **Current content snapshot and community approximation.** Public production reads traverse publication-filtered travels and quests through all pages. Support observed array/data/results envelopes and numeric totals/next pointers, enforce same-origin pagination for credential safety, deduplicate by stable ID, detect loops/repeated pages and record incomplete totals. Do not copy sitemap collector's premature-short-page termination (`:244`). Snapshot counters are current values, never historical monthly acquisitions. Compute author-1 share over all current articles, track unknown author IDs explicitly, and parse supported author aliases already represented in `types/types.ts:260–273`, including stable IDs from a comma-separated userIds list. Missing identity or undated rows can make a monthly first-author or non-owner-publication total uncertain; those affected monthly totals remain unavailable rather than presenting the classified subset as complete.
6. **Dates and first observations.** If the catalogue advertises publication timestamps, use that date contract and treat missing publication dates as unresolved. Only when that field is unavailable globally use valid created_at values with an explicit trip-date-proxy label and coverage counts; do not silently mix two date meanings into one community series. Preserve the complete valid date; reject impossible calendar dates. A missing/invalid date is unresolved, not epoch/zero. Read all history before filtering reporting months. An author with any undated current article has unknown first-observed month. All remaining newAuthors are first observed among currently public content, never true signup dates; deleted/unpublished articles and retroactive moderation remain unrecoverable. Compute publicationsNotAuthor1 only with identifiable non-owner identity and usable date. Unknown identity/date rows remain explicit gaps. Do not infer monthly quest creations from missing catalogue dates.
7. **YoY and report.** Counts use `(current-prior)/prior*100` only for finite values and prior > 0; zero/unknown baseline renders non-calculable. CTR/bounce changes use percentage points, average position raw delta with lower-is-better meaning. Render explicit missing cells and quality notes. Write the dated Markdown to `.codex-temp/metrics-summary/`, keeping generated data untracked. Document that rerunning the same date refreshes that snapshot. Sanitize error strings and Markdown cells rather than copying raw upstream auth bodies.

## Risks / Trade-offs

- Current public content cannot reconstruct publication history → qualify every community history section and show date/identity coverage.
- Source retention and analytics initialization can truncate YoY → preserve unavailable months and never fill them with zero.
- Different source timezones and consent/adblocking create incomparable totals → report provenance and avoid cross-source identity claims.
- Partial pagination can fabricate author firsts and shares → mark catalogue incomplete and withhold definitive aggregate claims.
- New helper abstraction can grow unnecessarily → use one focused module only if pure logic would make the CLI unwieldy; no generic framework.

## Migration Plan

No data migration or runtime rollout. Add a command/package entry and documentation. Rollback reverts task-owned source/docs paths; ignored reports remain local evidence. Commit/push and board handoff follow repository gates; CLI-only source acceptance uses the production data endpoints without requiring an app rebuild to exercise the command.

## Validation Matrix

- Node CLI: focused Jest `.test.ts` with injected clock/source responses; month/year/leap boundaries, YoY unavailable/zero, pre-window authors, undated-history blocker, date proxy, empty/partial responses, pagination cycles, report escaping/gaps and auth import safety. Source cancellation propagates through the shared Google token resolver to both OAuth and service-account token HTTP exchanges; stalled-token tests check the deadline and both resolver branches.
- Neighboring consumers: existing GA4 tests and GSC/GA4 `node --check`; import guards prevent API execution during unit testing.
- Static: task-scoped ESLint, package JSON parse, OpenSpec strict validation, required governance checks and prompt audit for planning/docs.
- Independent review: review-auditor then code-review-gate because scripts and exported adapters change.
- Testing after review: run the real summary against readonly production data/Google APIs; inspect generated Markdown sources/windows/gaps. Inaccessible optional credentials remain a gap, not a fake pass. No browser/device/i18n gate: no product UI or platform behavior changes.
- SEO, accessibility, Core Web Vitals, media and app analytics emission: unchanged; no corresponding runtime gate.
