## Решение и границы
Task type: изменение UX-контракта #3313/#3452.
Task-owned paths: hooks/usePhotoUpload.ts; components/travel/PhotoUploadWithPreview.tsx; components/travel/stepRoute/PointEditorSheet.tsx; связанные native unit-тесты; i18n/locales/{ru,be,uk,pl,en}/generated/travel_03.ts; docs/features/travel.md; этот OpenSpec change.
Platform impact: Android | iOS. Localization impact: все текущие локали.

Хук распознаёт машинный тип таймаута транспорта и передаёт отдельное событие владельцу UI; переведённая строка не служит идентификатором ошибки. Компонент загрузки сообщает редактору о таймауте и о новом файле только после выбора файла с URI. Редактор хранит флаг и показывает компактный блок в footer над сохранением внутри KeyboardAvoidingView. Существующий IconButton закрывает сообщение; текст переносится без усечения. Загрузчик привязан key к ID точки, ошибка очищается при смене/закрытии редактора.
Альтернатива: дублировать сообщение в прокручиваемой области фото. Отклонена: ошибка могла бы скрыться за пределами viewport.

Data/API: multipart file, collection, id без изменений; сервер read-only.
Risk/operation gates: общий хук не должен менять web и другие коллекции; существующие uploadSeq/queueEpoch сохраняются. Риск stale callback при смене точки закрывается remount загрузчика. Откат: revert только явных путей задачи.

## Validation selection gate
Changed contract → сохранение/закрытие/новый выбор/отмена/новая точка → реальные компонент+хук unit-тесты с mock транспорта; lint, typecheck, test:i18n. Runtime: один iOS simulator — новый native footer с клавиатурой и длинным текстом; Android тот же RN layout, отдельного нового поведения/разрешений нет, unit исполняет обе OS. Историческая матрица двух OS уточнена по docs/TESTING.md, а не принята автоматически. Web только регрессионные unit-тесты: web ветка не меняется. Данные/провайдер локали не меняются, cold restart и пять runtime-локалей не требуются. Совместимых runtime-доказательств нового состояния пока нет. Изменение native layout/keyboard/picker веток потребует соответствующего повторного прогона.

## Runtime-сценарий после review → testing
Локальный backend по регламенту; свой черновик и сохранённая точка. Выбрать реальное фото, транспорт задержать до настоящего таймаута без подмены callbacks/state. После исчезновения тоста (>4 с) сообщение и закрытие видны над Save; с клавиатурой поля адреса тоже. Закрыть сообщение; повторить таймаут; отменить picker (ошибка остаётся); выбрать другое фото (ошибка очищается); сменить точку (старой ошибки нет). Нормальная загрузка и сохранение сохраняют фото. Без runtime PASS карточка не done.
