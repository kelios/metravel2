## Context

Мотивация и граница текущего этапа — [proposal.md](proposal.md).
В `components/quests/QuestPrintable.tsx` подсказка печатается вместе с шагом,
а в конце — таблица ответов ведущего. Это действующий контракт, не дефект.
В `services/book/readyBooks/composition.ts` страновые книги требуют 30 мест
и используют три страницы на место. Квестовый пилот из восьми шагов нельзя
вставить в этот manifest обходом порога или выдуманными повторными местами.

## Goals / Non-Goals

Goals: проверяемый отбор двух кандидатов, отдельный player/host-контракт,
сохранённые пробелы и исполнимый порядок следующих действий.
Non-Goals: сейчас не реализуются адаптер, новые схемы публикации, рендер или UI;
исходные рассказы/задания, живые квесты и страновые книги не меняются.

## Decisions

### Отбор и содержательная ревизия

`data/travelBooks/quests/pilots.json` — редакционный список кандидатов,
не `ReadyBook` и не новый публикационный manifest. В него включены конкретные
идентификаторы шагов, координаты, роли и честные readiness-поля.
Полный ответ API не копируется: пользовательские данные/счётчики не входят.
Снимок и хеш определены в соседнем `README.md`; это локальная ревизия содержания,
а не выдуманный `updated_at` бэкенда. Сохраняются точный query `lang=ru` и дата.

Альтернатива — хеш полного ответа API — отклонена: просмотры/рейтинг делают
его нестабильным без изменения квеста. Хеш не подтверждает истинность текста.

### Будущий адаптер — явная проекция проверенных полей

Будущий `questAdapter.ts` принимает исходный снимок и связанную с ним
редакционную ревизию. Источники игрока и ведущего — разные строгие схемы;
`...rawStep` и `Omit<RawStep, 'answer_pattern'>` не обеспечивают границу.
Поля player: точные step ID/роль/координаты, отдельно проверенные title/location/
story/task, разрешённые медиа/QR. Поля host добавляют проверенные hint/answerKey/
критерии свободного ответа. Отсутствие точного ответа блокирует соответствующий
host-ключ; шаблон онлайн-checker не выдаётся за полевое доказательство.
Итоговый player-пакет целиком, включая PDF text/metadata и preview, проверяется
на отсутствие host-данных. Редактор проверяет смысловые утечки текста/картинок.

Альтернатива — скрыть ключ CSS или вырезать его из общего готового PDF —
отклонена: скрытый слой/метаданные остаются источником спойлеров.

### Геометрия отдельного квестового издания

Постановка F1 задаёт четырёхстраничный блок; страновой v1 остаётся трёхстраничным.
Предлагаемые роли: место/история → задание/ответ игрока → свободное фото → дневник.
Это проект макета, а не утверждение нового дизайна. Для 8 шагов это 32 страницы
блоков плюс ещё не согласованные служебные страницы и отдельные 4 стороны обложки.
Итоговые folio, физические поля, padding и тетради определяются после образца.
Необязательная пауза не становится загадкой только ради одинакового блока.
Используются те же физические профили 150×100 и A5 и общий низкоуровневый
рендер/вёрстка; новая схема композиции не должна ослаблять страновой manifest.

### Подготовка до v1, применение после него

Сейчас сохраняются только документы и список кандидатов. После #2807:
редакционная/географическая проверка, права и образец; затем адаптер/схема,
полный player/host-комплект и preview из фактических reading PDF.
Публичный manifest пополняется только подготовленными изданиями после
независимого review/code-review-gate и принятой версии кода.

## Risks / Trade-offs

- [Смысловой спойлер в обычном story/title] → отдельный проверенный текст player,
  а не эвристика по имени поля. Новая формулировка согласуется отдельно.
- [Неподтверждённый возраст] → `audience=null` в кандидатах; не назначать family
  из-за короткого маршрута или отсутствия детского тега.
- [Публичная обложка не разрешает печать] → отдельная лицензия/разрешение и
  проверка реального разрешения; отсутствие image на шагах остаётся пробелом.
- [Координата на объекте не доказывает наблюдаемость детали] → отдельные география
  и проверка ответа; нет заявления о точном входе без evidence.
- [Разрастание подготовки] → два кандидата, без каталога planned-книг,
  генератора-заглушки или попутного изменения действующего экспорта.

## Migration Plan

Текущий этап не импортируется runtime. Откат — удалить новый список и документы,
не меняя опубликованные издания. Следующая реализация обязана проверить прежний
manifest, старые URL, shared pagination/imposition и границы player/host;
публикация — отдельная immutable-ревизия с откатом указателя без удаления файлов.

Validation сейчас: сверка candidate JSON с точными публичными API-источниками,
структура/отсутствие PII/ответов в списке, OpenSpec strict, `audit:prompts`,
независимое чтение полного diff. Browser/device/build/deploy к docs-only
подготовке не применяются. Будущий code-level gate: адаптер, stale revision,
ложная готовность, источники/права; затем PDF QR/text/fonts/boxes и в testing
production mobile390→desktop1440. Повтор общей логики — один раз; native не меняется.
