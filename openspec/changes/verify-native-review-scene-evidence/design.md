## Phased authentication decision

Reuse the existing public runner with --rehearsal and its private QA_PRIVATE_INPUT=1 diagnostic mode through its exported in-process main. Host owns one quality gate; each runner phase reuses that legitimate gate and acquires/releases its existing non-reentrant device lock. Do not take a host device lock or put the runner inside a second process-group timeout that could kill its cleanup while detached xcodebuild remains active. Give each phase the remaining budget minus a bookkeeping reserve; refuse dispatch below the runner's minimum rather than extending the deadline. Validate total budget and the named registration activation receipt path before output or any phase starts. The host checks installed version/build through devicectl before and after every private phase and records separate observations, never fabricating observedCandidate in the diagnostic report. Each phase must have intended XCTest completion, script hash and exact counts; zero private assertions are permitted, empty dispatch and skipped tests are not.

All authentication phases require IOS_QA_ATTACHMENTS=none, including public assertions immediately after private input: both system and user attachments use keepNever even on failure. This strict optional runner policy also rejects explicit shot/tree operations before activation, patches only the runtime xctestrun copy and records both lifetimes in the report; the whole-flow validator rejects missing or downgraded policies. Unrelated runner calls retain their existing defaults. Runner source hashes change legitimately and require a fresh qualified helper/cache and dummy-canary receipt; no existing pinned helper or canary is promoted. This prevents the first public credential-form absence failure from retaining automatic credential screenshots. Independent canary/privacy verification remains required.

A strict receipt binds ordered manifest phases, report/scenario hashes, predecessor entry hash, device model, opaque random account reference, candidate version/build/source/origin, API/locale/role and current orchestrator/runner hashes. Phase execution times must be fresh, sequential and nonoverlapping. A private phase binds the exact credential form selector: preceding public phase ends with that form present/hittable, private dispatch submits then explicitly navigates away and clears clipboard, and the next public phase starts with the same form absent; no capture, tree, assertion or literal input operations are permitted in private phases. No recording is orchestrated. A separate matching dummy-canary privacy attestation is mandatory before secret input. External activation receipt is tied to the disposable account and the flow before post-register navigation back to login. Registration uses exactly pre-register → registration-input → post-register → activation-login-input → registered; the external web activation does not install native credentials, so the second private login reuses the same disposable account. Preserve the native incoming-link allowlist and AASA; no app defect is inferred from intentional routing. The host waits only for an explicitly named receipt file within the existing total deadline; an independently authorized external activation owner must write it atomically after registration. Missing evidence times out, stale/malformed/wrong-fixture evidence fails immediately; the host never activates or accesses email. Hash consistency cannot independently prove TestFlight provenance, source, transport, account role or privacy.

Draft manifests have no coverage. Execution is allowed only after literal production fixture selectors, private exit boundary, and coverage are reviewed and frozen. Whole auth coverage is limited to explicit complete stage sequences; isolated public phases cannot self-promote. Preserve single scene and six-child UGC validation without aggregation.

## Native rejection correlation and pre-dispatch context

Before every driver call, atomically publish a unique 0600 phase context beside, not inside, that phase's runner output directory. It contains only public candidate/environment/runner/flow identities, opaque random run/account references, phase/scenario/predecessor hashes and dispatch timestamp. Bind its raw hash and path into the phase chain; verify its identity and publication time against the actual report. This allows an independently authorized native network observer to correlate the real request while it happens. Never put a target identifier, credentials, secret-link URL or credential digest in this context.

For relogin-input, the previous public phase must assert the exact EN normalized rejection `Invalid email or password` (without period) absent immediately before the final credential-form assertion. The private scenario submits, performs a bounded exact tap of that non-secret error, then leaves via Back and clears the clipboard. Require rejectionStep strictly after submitStep and before leaveStep and its exact tapText/timeout contract. The existing Swift tap waits for a unique hittable target; it is synchronization through a harmless actual tap, with zero private assertion count, not public evidence of inline text.

After private completion and before failed-relogin public execution, reuse the existing bounded prerequisite wait for one explicitly named rejection receipt. Require exact run/account/phase/context/candidate/source/API/device-runner bindings and independent native network evidence digest. Its distinct opaque request references prove prior valid native login, successful native deletion inside the delete phase, and actual native POST login 401 invalid_credentials inside the relogin-input phase, in order on the same disposable fixture. The receipt is an independently reviewed attestation, not a new secret verifier implementation; host-only probes or self-labelled JSON without that real evidence do not qualify. Public final state remains credential-form absent plus guest profile, not a captured inline-error claim.

Match the app's normalizeApiBaseUrl contract: environment.apiUrl may be an origin or an already suffixed /api base, but native request endpoints must contain exactly one /api before /user/login/ or /user/delete-account/. Missing or duplicated prefixes are rejected.

The native rejection event must explicitly name classificationBasis. native-response-body requires rawResponseBodyObserved=true and independently reviewed actual native body evidence. native-ui-source-classification requires rawResponseBodyObserved=false, real correlated native/server 401, the exact private rejection step, scenario/report/completed-execution hashes, candidate source and a digest of current API normalization, auth failure/rendering and EN error-copy source. This latter code is derived from the actual native UI and source; it does not claim the native body was captured. The operator must independently establish that the current normalizer digest belongs to the declared app candidate. Neither basis permits a separate host POST or self-authored synthetic proof. The external native verifier remains unimplemented and no real attestation is supplied.

Fresh login/registration drafts require empty forms, unaccepted Terms and no autofill. The composed disposable deletion draft instead starts immediately after successful native login of the same fixture in the unchanged app process. LoginForm remains mounted: its Terms stay accepted and its Email/Password values remain filled after logout. Therefore deletion verifies the Terms hint absent without toggling, and private re-login replaces each entire existing field using Select All → Paste before submitting. This is a declared same-session precondition, not a general form-reset workaround. A fresh signed-in process or different actor does not qualify. Before secrets, qualify exact EN system edit-menu behavior with non-secret dummy prefilled email and secure-password values, checking replacement through a non-secret boolean comparison only; no Cut, unknown clipboard readback, screenshot or whole accessibility tree. Drafts remain unreviewed for runtime and grant no coverage until that canary, actual selectors and external evidence qualify.
