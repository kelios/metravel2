## Context

Ассистент отвечает по карточкам индекса сайта: подбор (`scripts/ai-assist/app.ts`, `retrieve`) → цепочка порядка (`api/aiAssist/sourceSelection.ts`) → подсказка (`api/aiAssist/prompt.ts`) → модель → страж (`api/aiAssist/answerGuard.ts`). Служба `/ai/ask` до этого изменения посетителя не различала: лимиты считаются на IP, тело запроса — `{q, locale, history, source}`.

Данные вошедшего пользователя отдаёт API сайта, все адреса уже есть:

| что | адрес | кому отвечает |
| --- | --- | --- |
| кто я | `GET /api/user/me/` → `{id, name, email, …}` | владельцу токена |
| отметки статей | `GET /api/user/{id}/travel-statuses/` → строки `{status: visited/planned/wishlist, planned_date, visited_date, travel: {id, name, countryName}}` | только себе (`_ensure_self_or_superuser`) |
| избранное | `GET /api/user/{id}/favorite-travels/` → `{results: [{id, name, countryName}]}` | только себе |
| поездки | `GET /api/trips/planned/me/` → `[{start_point_name, start_date, end_date, …}]` | владельцу токена |
| свои статьи | `GET /api/travels/?where={"user_id":id,"publish":1,"moderation":1}` | всем (открытый каталог) |

Бэкенд принимает токен двумя способами (`metravel/common/authentication.py`, `CookieTokenAuthentication`): заголовок `Authorization: Token …`, а если его нет — cookie `authToken` (HttpOnly, SameSite=Lax, Secure). Приложения шлют заголовок из защищённого хранилища; **web токена не видит** — сессия там только в cookie (`utils/authPlatform.ts`).

### Замер на проде (15.11.2026, только GET, e2e-аккаунт помощника прод-проб)

| запрос | медиана, мс | худший из 6, мс | размер |
| --- | --- | --- | --- |
| `/user/me/` | 64 | 66 | 96 Б |
| `/user/{id}/travel-statuses/` | 72 | 150 | 2,2 КБ на 4 отметки |
| `/user/{id}/favorite-travels/` | 62 | 129 | 52 Б (пусто) |
| `/trips/planned/me/` | 153 | 317 | 71 КБ на 3 поездки (с геометрией маршрута) |
| `/travels/?where=…` | 64 | 83 | 150 Б (пусто) |
| **«кто я», затем четыре параллельно** | **258** | **550** | — |
| все пять параллельно (id известен) | 204 | 390 | — |

Гостю четыре личных адреса отвечают 401, каталог статей — 200. Четырёх запросов хватает с запасом в десятки раз к бюджету; отдельный сводный адрес бэкенда не нужен. Единственное наблюдение для `area=back`: `/trips/planned/me/` отдаёт геометрию маршрутов, которая сводке не нужна (71 КБ на три поездки) — не блокер.

## Goals / Non-Goals

**Цели:** ответ вошедшему с учётом его отметок, избранного, планов и статей; личность — только из ответа API; ни токен, ни сводка не покидают службу; гость — без изменений до байта; любой отказ профиля — ход гостя.

**Не цели:** новые адреса бэкенда и правка `nginx`; хранение сводки вне памяти процесса; лимиты по пользователю; личный контекст у провайдера `llamacpp`; дообучение модели; живая проверка на стенде (стадия `testing`).

## Decisions

Решения 1–9 приняты архитектором до проектирования; здесь — как они ложатся на код и что отвергнуто. Решения A–D принял исполнитель там, где ответа в списке не было.

- **1. Личность — только из ответа API на токен посетителя.** `scripts/ai-assist/visitorProfile.ts` читает токен из заголовков запроса и первым делом спрашивает `GET /api/user/me/`; идентификатор из тела и параметров запроса к `/ai/ask` не читается нигде — поля `user_id`, `userId`, `visitor` в теле служба просто не знает. Отвергнуто: клиент присылает `userId` рядом с токеном «для экономии запроса» — служба стала бы местом, где подменой id читается чужая сводка, если бэкенд когда-нибудь ослабит проверку владельца.
- **2. В памяти — `sha256(токен)` → пользователь и сводка на 4 минуты.** Две карты: `sha256(токен) → {userId, срок}` и `«userId:sha256» → {сводка, срок}`; до 500 посетителей, вытеснение — просроченные, затем самые старые. Сам токен живёт только в замыкании запроса к API. Отвергнуто: redis, как у счётчиков лимитов, — сводка там пережила бы процесс и стала бы данными, за хранение которых надо отвечать; при 4 минутах жизни выигрыша нет.
- **3. Любой отказ профиля — ход гостя.** Нет токена, 401/403, 5xx, не JSON, ответ больше 2 МБ, таймаут — `resolve` возвращает `null` и не бросает; отказ не кэшируется. Общий бюджет сбора — 1,8 с (`AI_ASSIST_PROFILE_TIMEOUT_MS`), «кто я» → четыре запроса параллельно. Отвергнуто: частичная сводка «что успело прийти» — посетитель с пропавшим списком «был» получал бы совет поехать туда, где уже был, и это выглядело бы как ошибка ассистента, а не сети.
- **4. Строка «О посетителе» — до 120 токенов, русские подписи.** `api/aiAssist/visitorContext.ts`, `formatVisitorBlock`: «Статей на сайте: N (страны). Хочет посетить: «…». Запланировано: «…» (месяц год). Ближайшие поездки: место (месяц год). В избранном: «…». Уже посещено: «…».» Части добавляются по важности для вопроса «куда поехать»: сначала каждая с одним названием, затем, если место осталось, со вторым; не влезла — числом. Размер оценивается по 2,8 знака на токен (строже замеренных 3,2 для русского и 2,87 для белорусского). Строка стоит между карточками и вопросом, как строка «материала о месте нет»; правило к ней дописывается к системному сообщению. Отвергнуто: сводка отдельным сообщением роли `system` — шаблон чата модели обучен на одном системном сообщении, второе меняет форму подсказки сильнее, чем строка в сообщении посетителя.
- **5. Подбор.** Вопрос о своём (`detectOwnPlacesQuestion`: первое лицо рядом со словом сохранённого или планов, пять языков) — кандидатами встают материалы посетителя, которые есть в индексе (`personalSources` в `app.ts`): на вопрос о сохранённом — «хочу», избранное и запланированное, на вопрос о планах — только запланированное (живой замер 15.11.2026: «хочу» рядом с запланированным модель называла планом — 11 ответов из 15); место и условия вопроса среди них выбирает та же цепочка `arrangeSources`. На просьбу о рекомендации (`asksWhereToGo`) посещённое и собственные статьи переставляются в конец подбора (`demoteSeen`) до цепочки порядка. Отвергнуто: удалять посещённое из подбора — на «что посмотреть в Гомеле» у человека, который был в Гомеле по одной статье, не осталось бы материала о городе.
- **6. Выключатель и строка на экране.** `AI_ASSIST_PROMPT_PROFILE=0` — `main.ts` не создаёт сборщик сводки: токен не читается, запросов к API нет. Признак для экрана — `profile: true` в событии `done` хода, в котором служба собрала непустую сводку. Отвергнуто: признак в `/ai/health` — здоровье говорит о службе, а не о посетителе: вошедший с протухшей сессией видел бы строку, хотя его ход шёл как у гостя. `/ai/health` несёт только `profile: true` «блок включён» — для пробы стенда.
- **7. Лимиты — на IP, ответ не кэшируется.** Счётчики не меняются; тест сверяет, что два аккаунта с одного адреса расходуют один счётчик. Поток и отказы уже отдаются с `cache-control: no-store`; заголовков CORS у службы нет, заголовки личности в ответ не отражаются. Прокси Metro передаёт службе все заголовки запроса (`metro.config.js`: `...req.headers`) — `Authorization` и `Cookie` доходят. Отвергнуто: лимит на пользователя — вошедший с двух устройств получил бы общий счётчик, а гость за тем же NAT — отдельный; правило лимитов стало бы зависеть от входа.
- **8. `llamacpp` личного контекста не получает.** Сводку собирает только служба; клиент `askProvider.ts` подтверждает личность только в `POST /ai/ask`. Отвергнуто: собирать сводку на клиенте для `llamacpp` — у клиента эти данные есть, но строка и правило разошлись бы между двумя путями, а `llamacpp` — стенд разработки.
- **9. Набор оценки.** Отдельный файл `scripts/ai-assistant-eval/cases.personal.jsonl`: 12 личных вопросов на пяти языках с ожиданием по источникам и два контрольных. Вопрос с `profile: true` уходит службе с заголовком `Authorization` из переменной `AI_ASSIST_EVAL_PROFILE_TOKEN`; значение нигде не печатается. Отвергнуто: добавить группу в `cases.live.jsonl` — этот набор целиком входит в приёмку модели (`acceptance.thresholds.json`, прогон `live`), и её числа стали бы зависеть от отметок тестового аккаунта.

Решения исполнителя:

- **A. Web подтверждает личность cookie сессии, а не заголовком.** Скрипт страницы токена не видит, поэтому заголовок `Authorization` на web собрать не из чего. Запрос к `/ai/ask` того же origin несёт cookie `authToken` сам; служба берёт токен из заголовка `Authorization`, а если его нет — из cookie (имя — `AI_ASSIST_AUTH_COOKIE`, по умолчанию как у бэкенда) и пересылает API тем же заголовком `Authorization: Token …`. Подделка запроса с чужого сайта не проходит: cookie помечена `SameSite=Lax` и на межсайтовый POST не уходит, а ответ службы чужому origin не читается (CORS-заголовков нет). Отвергнуто: отдать токен скрипту страницы (отдельный адрес «дай мой токен» или не-HttpOnly cookie) — это сняло бы защиту сессии от XSS ради одной подписи в подсказке.
- **B. Приложение шлёт токен только службе на origin API сайта.** `api/aiAssist/askAuth.ts`: адрес службы из переменной сборки (`EXPO_PUBLIC_AI_PICKS_URL`), если он не совпадает с origin API, токена не получает. Отвергнуто: слать токен на любой настроенный адрес службы — сборка для стенда уносила бы токен боевой сессии на чужой хост.
- **C. Запрос собственных статей идёт без токена.** Опубликованные статьи — открытый каталог; токен нужен четырём запросам из пяти. Отвергнуто: единообразно слать токен всем пяти — лишняя передача секрета туда, где он ничего не меняет.
- **D. Страж узнаёт материал сводки по названию.** `visitorTitlesOutside` отдаёт стражу названия материалов сводки, которых нет среди карточек ответа: полное, обрезанное (как в строке) и часть до подзаголовка, не короче 12 знаков. Название в ответе получает ту же метку, что вырезанная ссылка, — дальше работает действующее правило «материал не из подсказки» (предложение или пункт уходит целиком). Отвергнуто: не называть материалы в строке вовсе, оставив счётчики, — модель не смогла бы ответить «вы хотели в Минск — вот карточка рядом».

## Risks / Trade-offs

- **Токен проходит через службу.** Служба — новое место, где токен сессии бывает в памяти процесса на время запроса. → Не хранится, не логируется, уходит только на `BACKEND_URL` методом GET с `redirect: 'error'`; при `BACKEND_URL` без https вне своей сети служба пишет предупреждение при старте. Служба ассистента стоит на домашнем сервере владельца (#2458): cookie сессии web-посетителя идёт туда по каналу вместе с любым запросом `/ai/*` — так было и до этого изменения, но теперь служба её читает.
- **Суперпользователь.** Тестовый аккаунт 104 — суперпользователь и может читать чужие отметки по чужому id. → Служба запрашивает только id из `/user/me/`; чужой id ей взять неоткуда.
- **Строка в стриме до стража.** Правило стража о материале сводки работает по готовому ответу; в потоке посетитель может на долю секунды увидеть название, которое последний `text` уберёт. → То же ограничение у пояснений и чисел без опоры (#3291); ссылка на такой материал вырезается уже в стриме.
- **Модель не обучена на строке.** → Выключатель; сравнение на стенде — стадия `testing`.
- **Ложное «вопрос о своём».** «Я хотела бы посмотреть замки» не должно включать личный подбор. → Шаблоны требуют первого лица рядом со словом сохранённого или планов; контрольные формулировки — в тестах. Ошибка стоит одного ответа по сохранённому вместо общего подбора.
- **Задержка первого вопроса.** Холодный сбор сводки добавляет ≈ 0,26 с (худший замер 0,55 с) перед подбором; следующие 4 минуты — ноль. → Бюджет 1,8 с, затем ход гостя.
- **Политика конфиденциальности.** Текст о том, что ассистент использует данные аккаунта, — решение владельца, вне этого изменения.

## Migration Plan

Изменение обратно совместимо: тело запроса прежнее, новые поля событий необязательны. Порядок выката — служба, затем фронт; до выката фронта web-посетитель уже получает личный контекст (cookie уходит и так), строки на экране ещё нет. Откат — `AI_ASSIST_PROMPT_PROFILE=0` у службы без пересборки.
