## ADDED Requirements

### Requirement: Личность посетителя определяет только API сайта

Служба ассистента SHALL узнавать, кто задал вопрос, только из ответа API сайта на запрос с токеном самого посетителя. Идентификатор пользователя из тела, параметров или заголовков запроса к `/ai/ask` MUST NOT использоваться. Токен берётся из заголовка `Authorization: Token …`, а при его отсутствии — из cookie сессии сайта.

#### Scenario: Вошедший пользователь приложения

- **WHEN** приложение шлёт вопрос с заголовком `Authorization: Token …`
- **THEN** служба запрашивает `GET /api/user/me/` с этим токеном
- **AND** остальные запросы сводки идут за идентификатором из ответа

#### Scenario: Вошедший пользователь web

- **WHEN** страница сайта шлёт вопрос на `/ai/ask` того же origin и браузер прикладывает cookie сессии
- **THEN** служба берёт токен из cookie и запрашивает API тем же заголовком `Authorization`
- **AND** скрипт страницы токена не читает и не передаёт

#### Scenario: Чужой идентификатор в теле запроса

- **WHEN** запрос несёт в теле `user_id`, `userId` или готовую сводку
- **THEN** служба эти поля не читает
- **AND** без токена ход идёт как у гостя, а с токеном другого пользователя — по сводке владельца токена

### Requirement: Сводка посетителя и строка «О посетителе»

Для вошедшего посетителя служба SHALL собрать сводку: страны и число его опубликованных статей, отметки «был», «хочу», «запланировано», избранное и ближайшие поездки. В подсказку модели сводка идёт одной строкой «О посетителе» не длиннее 120 токенов. Строка MUST NOT содержать имени, почты и идентификаторов. В режиме страницы и в ответе справки строки нет.

#### Scenario: Вошедший спрашивает, куда поехать

- **WHEN** вошедший посетитель с отметками и планами спрашивает «Куда съездить на выходные в Беларуси?»
- **THEN** сообщение посетителя в подсказке несёт строку «О посетителе» между карточками и вопросом
- **AND** системное сообщение несёт правило: это сведения о человеке, а не карточки

#### Scenario: Большая сводка

- **WHEN** у посетителя сотни статей и десятки отметок
- **THEN** строка остаётся не длиннее 120 токенов: части сокращаются до одного названия или до числа

#### Scenario: Вошедший без данных

- **WHEN** у вошедшего нет статей, отметок, избранного и поездок
- **THEN** строки в подсказке нет и ход идёт как у гостя

### Requirement: Подбор учитывает личное

На вопрос о своих местах («из того, что я сохранила», «мои планы», «куда я хотела поехать» — на русском, белорусском, украинском, польском и английском) служба SHALL отдать карточками сохранённые и запланированные материалы посетителя, которые есть в индексе. На просьбу о рекомендации материалы, отмеченные «был», и собственные статьи посетителя SHALL встать после остальных, но MUST NOT удаляться из подбора.

#### Scenario: Вопрос о сохранённом

- **WHEN** вошедший спрашивает «Куда мне поехать из того, что я сохранила?»
- **THEN** источники ответа — его материалы «хочу», избранное и запланированное

#### Scenario: Вопрос о планах

- **WHEN** вошедший спрашивает «Что у меня в планах на поездки?»
- **THEN** источники ответа — только запланированные материалы, ранняя дата первой
- **AND** материалы «хочу» и избранное карточками не становятся

#### Scenario: Планы без притяжательной формы

- **WHEN** вошедший спрашивает «Планы на выходные в Минске» или пишет «Я планирую поездку в Краков, что посмотреть?»
- **THEN** вопрос идёт обычным подбором по месту

#### Scenario: Просьба о рекомендации

- **WHEN** вошедший спрашивает «Куда поехать на выходные?»
- **THEN** материал, отмеченный «был», стоит в подборе после остальных и остаётся в списке источников

#### Scenario: Вопрос со страницы материала

- **WHEN** вопрос задан со страницы статьи или квеста
- **THEN** личный подбор не применяется: ответ даётся по странице

### Requirement: Материалы сводки — не карточки

Модель MUST NOT рекомендовать материал из строки «О посетителе», которого нет среди карточек ответа. Страж SHALL вырезать из ответа ссылку на такой материал и предложение или пункт с его названием.

#### Scenario: Модель даёт ссылку на материал сводки

- **WHEN** ответ модели содержит ссылку на материал сводки, которого нет среди карточек
- **THEN** ссылка и предложение с ней вырезаются

#### Scenario: Модель называет материал сводки без ссылки

- **WHEN** ответ модели называет такой материал по названию, полному или сокращённому
- **THEN** предложение или пункт списка с названием вырезается

#### Scenario: Материал сводки есть среди карточек

- **WHEN** материал из сводки найден подбором и стоит среди карточек
- **THEN** ответ с ним остаётся без изменений

### Requirement: Токен и сводка не покидают службу

Служба MUST NOT хранить токен посетителя: в памяти остаётся только `sha256(токен)` с идентификатором пользователя и сводкой на срок от трёх до пяти минут, с потолком числа записей и вытеснением. Токен SHALL уходить только на адрес API сайта, только методом GET и без перенаправлений. Токен и содержимое сводки MUST NOT попадать в события потока, журнал спроса, журнал службы и сообщения об ошибках. Сводка одного пользователя MUST NOT выдаваться другому.

#### Scenario: Два аккаунта подряд

- **WHEN** два вошедших пользователя по очереди задают один и тот же вопрос о своём
- **THEN** каждый получает карточки и строку только из своей сводки

#### Scenario: Что видно снаружи

- **WHEN** вошедший задаёт вопрос
- **THEN** событие `done` несёт только признак `profile: true`
- **AND** событие `trace` контура оценки несёт только `profile: true|false`
- **AND** строка журнала спроса не отличается от строки гостя

#### Scenario: Повторный вопрос

- **WHEN** тот же посетитель задаёт вопрос в пределах срока жизни сводки
- **THEN** служба к API за сводкой не ходит

### Requirement: Отказ профиля — ответ как гостю

Ошибка, таймаут либо ответ 401 или 403 любого запроса сводки SHALL приводить к ответу как гостю, без ошибки 5xx. Сбор сводки MUST укладываться в общий бюджет не больше двух секунд; не уложился — ход идёт как у гостя.

#### Scenario: Сессия истекла

- **WHEN** API отвечает 401 на токен посетителя
- **THEN** посетитель получает тот же ответ, что и гость, с кодом 200

#### Scenario: API не отвечает

- **WHEN** один из запросов сводки не отвечает
- **THEN** по истечении бюджета ход идёт как у гостя

### Requirement: Гость — без изменений

Для посетителя без токена подсказка модели, подбор, события потока и строка журнала MUST совпадать с поведением до этого изменения. Лимиты SHALL по-прежнему считаться на IP.

#### Scenario: Гость задаёт вопрос

- **WHEN** гость задаёт вопрос службе с включённым личным контекстом
- **THEN** поток и подсказка совпадают со службой без личного контекста
- **AND** служба к API за сводкой не ходит

#### Scenario: Два аккаунта с одного адреса

- **WHEN** два вошедших пользователя задают вопросы с одного IP
- **THEN** они расходуют один дневной счётчик

### Requirement: Выключатель и строка на экране

Переменная `AI_ASSIST_PROMPT_PROFILE=0` SHALL выключать личный контекст целиком: служба не читает токен, не ходит за сводкой, строка и личный подбор не применяются. Экран SHALL показывать строку «Ассистент учитывает ваши статьи и сохранённое» только вошедшему посетителю и только когда служба подтвердила личный контекст в последнем ходе. Провайдер `llamacpp` личный контекст MUST NOT получать.

#### Scenario: Блок выключен

- **WHEN** служба запущена с `AI_ASSIST_PROMPT_PROFILE=0` и вошедший задаёт вопрос
- **THEN** ответ совпадает с ответом гостю и признака `profile` в `done` нет

#### Scenario: Строка на экране

- **WHEN** событие `done` несёт `profile: true`, а посетитель вошёл
- **THEN** над полем вопроса стоит строка о личном контексте
- **AND** после выхода из аккаунта строка исчезает

#### Scenario: Служба не подтвердила

- **WHEN** посетитель вошёл, но событие `done` признака не несёт
- **THEN** строки на экране нет
