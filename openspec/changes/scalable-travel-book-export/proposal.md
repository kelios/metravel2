## Why

Владелец не может собрать PDF-книгу своих путешествий за 2012–2013 годы и явно требует убрать ограничения количества фото и путешествий. Сейчас frontend блокирует книги после 200 изображений, 30 изображений на путешествие, 50 путешествий и порогов текста; существующий серверный экспорт намеренно реализует только HTML с собственными ограничениями и отдельной упрощённой вёрсткой.

## What Changes

- Ввести на desktop web полный v2 экспорт любой конечной выбранной книги без продуктовых лимитов на фотографии, путешествия, текст или точки. Пользователь получает один PDF; самостоятельное разбиение на несколько книг не требуется.
- Расширить существующий `/api/exports/books/` версионированным контрактом выбора, полного снимка данных, настроек и доступных возможностей. Большой выбор передаётся постранично или серверным selection reference, а не одним неограниченным HTTP-запросом.
- Собирать большие книги асинхронно ограниченными по ресурсам порциями с checkpoint/retry, затем объединять в один PDF. Объём книги увеличивает время и дисковое хранение, а не размер DOM и декодированных фото на компьютере пользователя.
- Переиспользовать каноническую модель, темы и рендереры книги; учитывать реальные физические страницы, перенос текста/галереи, итоговое оглавление и нумерацию.
- Показывать этапы, возможность отмены, восстановления после перезагрузки и скачивание готового файла. Обрыв polling не означает отказ задания и не запускает второй локальный экспорт.
- Заменить проверки количества на маршрутизацию по доступности безопасного движка и на контроль полноты. Запретить тихий экспорт неполных карточек или пропущенных фото.
- Сохранить текущую печать небольших книг и native-путь. Удалять локальные защитные пороги только одновременно с проверенным безопасным маршрутом.

## Capabilities

### New Capabilities

- `large-travel-book-export`: полный, восстанавливаемый экспорт больших выбранных книг без ограничений количества; единый результат, настройки, полнота, безопасность и ресурсный контракт.

### Modified Capabilities

Нет существующего frontend OpenSpec capability экспорта книги. Серверные исторические контракты #713/#788/#1133 меняются новым связанным capability, а не объявляются сломанными задним числом.

## Impact

- **User-visible result:** владелец выбирает свои путешествия за оба года и получает полный PDF со всеми включёнными фотографиями, текстом и порядком; большая книга может готовиться дольше.
- **Platform impact:** desktop web; shared renderer — regression на mobile web, Android и iOS. Новый серверный download flow первой поставки — desktop web. Каталог на mobile web остаётся недоступным по действующему правилу; native download/share не добавляется этим change.
- **Localization impact:** all current locales RU/BE/UK/PL/EN, fallback RU; статусы, ошибки и форматирование через i18n; авторский контент не переводится.
- **Affected frontend paths:** `api/bookExportApi.ts`, `hooks/usePdfExport*.ts`, `components/listTravel/hooks/useListTravelExport.ts`, `components/listTravel/ListTravelExportControls.tsx`, `components/export/**`, `services/book/**`, `services/pdf-export/**`, `types/book.ts`, `types/pdf-export.ts`, релевантные тесты и i18n. Реальная ownership уточняется по карточкам; чужой поезд #2229 не затрагивается без координации.
- **Data/API:** расширение существующих export jobs, capabilities, selection/snapshot, versioned settings, counters, retry/cancel/resume и защищённого файлового артефакта. Старый HTML-контракт сохраняется до миграции потребителей.
- **Dependencies:** backend owner реализует `area=back` задачи; worker размещается только после замера доступной изолированной мощности. Текущий VPS 1 CPU / 1.8 GB из истории #754 не считается автоматически пригодным для Chromium. Provisioning/покупка мощности этим планом не разрешаются.
- **Fallback/mock policy:** небольшой локальный экспорт допустим только при доказанной пригодности и полноте; большая книга при unavailable/permission/expiry не маскируется локальной попыткой. Mock только для unit/contract checks, Done требует реального PDF.
- **Performance:** лимиты concurrency, bytes/pixels на порцию, RSS, очередь и TTL являются внутренними ресурсными бюджетами, не лимитами общей книги. В частности, одна очень большая статья должна дробиться внутри главы.
- **Security:** owner-scoped jobs и selection, снимок доступных данных, повторная проверка доступа перед download, SSRF/XSS isolation, приватное хранение и очистка артефактов.
- **Accessibility:** доступные статусы, keyboard/focus, отмена и повтор без focus theft; подписи/alt сохраняются в книге.
- **Analytics:** этапы, длительность, агрегаты полноты и причина отказа без авторских текстов, URL медиа и download secrets.
- **SEO:** неприменимо; публичные статьи, URL/canonical, robots/sitemap не меняются, артефакты приватны.
- **Existing behavior to preserve:** настройки/темы/premium, ручной порядок, размер и пропорции фото, штатная печать небольших книг, native печать и отмена, квэст/GPX/KML.
- **Non-goals:** выполнение реализации сейчас, создание production jobs, экспорт настоящей книги владельца в этом анализе, изменение фотографий/авторского текста, новый paywall, принудительные тома, переезд hosting, native large-file sharing, рефакторинг несвязанного экспорта.
- **Evidence boundary:** скриншот показывает 25 выбранных путешествий, но не IDs и не точное число фото за 2012–2013. Механизм подтверждён исходниками; конкретная книга не воспроизведена runtime и должна стать отдельным acceptance fixture после разрешённого запуска реализации.
- **Open questions:** материальных продуктовых вопросов для планирования нет. Размещение worker и измеренный бюджет выбирает backend owner в prerequisite-карточке до включения capability; это operational gate, не основание вернуть count cap.

Планирование выполнено по запросу владельца. Apply/реализация требует отдельного следующего запроса.
