Правила закрытия: 2xx и 404 закрывают намерение, прочие постоянные 4xx закрывают с предупреждением, в чужой сессии попытки нет. Одна попытка на запись. ## 2. Хук синхронизации экрана

- [x] 2.1 `resetProgress(runServerId)`: удаляется строка экрана или поколение стёртой копии визарда. `progressIdRef` и `progress` обнуляются сразу, отметка каталога снимается сразу. Durable-удаление; `progressMissing = true` только по подтверждению и на том же квесте; результат — «удаление ещё ждёт»
- [x] 2.2 Чтение при открытии квеста сначала закрывает намерения квеста. Если намерение ждёт, состояние сервера считается неизвестным. После успешного чтения — снятие записей закончившихся поколений (R1)
- [x] 2.3 Тесты хука: офлайн-сброс сохраняет намерение и повторяет `DELETE` после появления сети и после перезапуска; новое прохождение не уходит PATCH-ем в старую строку и после удаления создаёт новую; чтение не отдаёт старую строку; экран без прочитанной строки удаляет поколение визарда
- [x] 2.4 Регресс существующих наборов: `useQuestProgressSync.reset/offline/catalog/questSwitch/blur`, `useQuestsApi`, `api/quests`, `questProgressQueue`, `questProgressMerge`, интеграционный `quest-progress-login-race`
- [x] 2.5 Находки код-ревью (design D5a): счётчик сбросов по квестам (`resetCountsRef`). Флаш и чтение, отправленные до «Сбросить», не отдают экрану строку стёртого прохождения. Упавший флаш не возвращает его снапшот ни в отложенные, ни на диск. Владелец намерения — текущая сессия (`useAuthStore.userId`), `ownerIdForQueue()` — только для снятия очереди
- [x] 2.6 Тесты D5a: ответ PATCH после сброса, упавший после сброса флаш, чтение, отправленное до сброса, смена аккаунта на открытом экране; все четыре падают на коде до исправления
