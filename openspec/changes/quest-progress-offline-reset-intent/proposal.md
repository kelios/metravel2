## Why

«Сбросить» в шапке квеста, нажатое без сети, пропадает. Приложение сразу пишет «Прогресс очищен» и стирает прохождение на устройстве, но `DELETE /api/quest-progress/<id>/` падает, а повтора нет. Строка прохождения на сервере остаётся. Когда игрок снова начинает квест, новое прохождение сливается в эту строку, и возвращаются старые ответы и «Пройден» (борд #2043).

Механизм по коду `main` @ `6098a7e40`:

- `hooks/useQuestsApi.ts` `resetProgress`: при сетевой ошибке `DELETE` только `console.warn`. Намерение удалить нигде не сохраняется, а `progressIdRef` и `progress` остаются на старой строке R.
- Следующее сохранение уходит со снапшотом без поколения (`serverId = 0`). `withQuestProgress` законно отдаёт писателю строку R (путь #1803), а `mergeQuestProgress` объединяет новое прохождение со старым: `completed = local || server`.
- Если квест открыт без сети, экран строку не прочитал. Тогда `DELETE` не отправляется вовсе, даже одной попыткой: `progressIdRef` пуст, а поколение копии знает только визард.

Для обычного сохранения прогресса есть очередь на диске с ретраями (#1922), для удаления — нет. Контракт поколения #2033 работает штатно, и этот случай он явно вывел из скоупа («Известная дыра» QUEST-PROGRESS-RESET-LINEAGE-001).

## What Changes

- Намерение «удалить строку R квеста Q игрока O» сохраняется на устройстве до запроса и повторяется, пока сервер не подтвердит, что строки нет (204 или 404). Повтор идёт в те же моменты, что и доставка прогресса: старт приложения, возврат в него, появление сети, вход в аккаунт, таймер повтора. Намерение переживает перезапуск приложения и выполняется только в сессии того, кто нажал «Сбросить».
- Пока удаление не подтверждено, новое прохождение этого квеста не пишется в строку R. Писатель сначала доводит удаление, затем создаёт новую строку. Экран квеста не показывает содержимое R как состояние сервера. Это касается и миграции гостевого прогресса после входа. Ответы нового прохождения ждут на устройстве и в очереди доставки.
- Если экран открыт без сети и строку не прочитал, удаляется строка, с которой согласована стираемая копия визарда, то есть её поколение по #2033.
- Тост после сброса говорит правду: «Прогресс очищен», если сервер подтвердил удаление, и «Прогресс очищен — с сервера он удалится, как появится сеть», если удаление ещё ждёт. Экран при этом сбрасывается сразу.
- Хвост #2033 (R1): когда сервер при открытии квеста подтверждает, что прежнего поколения больше нет, запись этого поколения сразу снимается с очереди доставки. Иначе новое офлайн-прохождение сливается в неё и выбрасывается вместе с ней.
- Не входит:
  - изменения бэкенда: API прежний, `DELETE` уже отвечает 204 или 404;
  - копия без поколения на экране без прочитанной строки. Устройство не знает, какую строку удалять, и удаление не отправляется, как и раньше;
  - гонка «сброс во время первой, ещё летящей и в итоге успешной отправки прохождения, которое не встречало сервер» — строка создаётся уже после сброса. Ответ такой отправки экран не принимает, а упавшая отправка снапшот обратно не ставит (design D5a);
  - прочие одноразовые мутации прогресса — они перечислены в отчёте карточки для отдельной задачи.
- Зависимости: нет. Контекст — закрытые #2033, #1922, #1803.
- Fallback/mock policy: моков и заглушек нет. Без сети сброс сразу локальный, а серверный — при появлении сети. 404 на `DELETE` значит, что строки уже нет, и считается успехом. Постоянный отказ сервера (прочие 4xx, кроме 401, 403 и 429) снимает намерение по политике очереди #1922, чтобы одно намерение не заткнуло доставку остальных квестов.

**Platform impact**: shared. Общий JS прогресса работает на web, Android и iOS, нативного кода нет. Моменты пробуждения очереди — это существующий `useQuestProgressQueueRuntime` (#1922). Проверка — desktop web и mobile web с эмуляцией офлайна. Device gate не нужен.

**Localization impact**: all current locales. Новая строка тоста добавляется сразу в RU/BE/UK/PL/EN через `@/i18n`, существующая «Прогресс очищен» не меняется.

### Modified Capabilities

- `quest-progress-reconciliation`: добавлены требования к сбросу без сети — durable-намерение удаления, запрет писать в строку до подтверждения удаления и честное сообщение игроку. Требование «Копия удалённого прохождения не возвращает его на сервер» получает сценарий снятия записи закончившегося поколения из очереди при открытии квеста.

## Impact

- **Код**:
  - `utils/questProgressQueue.ts`: список намерений удаления, общий с очередью цикл загрузки и доставки, проверка в писателе, снятие записей закончившихся поколений;
  - `hooks/useQuestsApi.ts`: `resetProgress` (строка для удаления, durable-удаление, исход для тоста), чтение при открытии квеста ждёт удаления;
  - `components/quests/useQuestWizardProgress.ts`: сброс передаёт поколение стёртой копии и отдаёт исход удаления на сервере;
  - `components/quests/QuestWizard.tsx`: выбор тоста и тип пропса;
  - `app/(tabs)/quests/[city]/[questId].tsx`: визард получает `resetProgress` напрямую;
  - `components/quests/useGuestQuestFlow.ts`: миграция гостевого прогресса ждёт удаления;
  - `i18n/locales/*/generated/quests_01.ts`: строка тоста;
  - тесты этих модулей, `docs/PROBLEM_MEMORY.md`, `docs/features/quests.md`.
- **API/данные**: эндпоинты и поля прежние. Новый локальный ключ AsyncStorage `quest_progress_deletions_v1` хранит записи `{ questId, ownerId, progressId, queuedAt }`. Формат очереди `quest_progress_queue_v2` не меняется.
- **Видимое поведение**:
  - сброс без сети после появления сети удаляет строку на сервере;
  - новое прохождение получает новую строку без прежних ответов и без «Пройден»;
  - тост без сети говорит, что с сервера прогресс удалится при появлении сети.
- **SEO**: none. Экраны прохождения за авторизацией, публичные URL и разметка не меняются.
- **Доступность**: тост — текст через существующий `notifyQuest`, новых элементов нет.
- **Производительность**: в сети добавляются две записи в AsyncStorage на нажатие «Сбросить»: намерение и его снятие. Без намерений чтение при открытии квеста и отправка снапшота не делают новых запросов, только проверку в памяти. Пока удаление не подтверждено, повтор `DELETE` идёт по общему бэкоффу очереди, 2 с → 60 с.
- **Безопасность и приватность**: на диске лежат только `id` своей строки прохождения, `quest_id` и `id` владельца. Этот же `id` владельца очередь уже хранит.
- **Аналитика**: none.
