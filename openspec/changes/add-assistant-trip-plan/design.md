## Context

Ассистент отвечает по карточкам индекса сайта: подбор (`scripts/ai-assist/app.ts`) → цепочка порядка (`api/aiAssist/sourceSelection.ts`) → подсказка → модель → страж. Навык «текст → проверяемая структура» у службы уже есть: `/ai/intent` (#2887) — модель отвечает JSON, `osmFilterSchema.ts` его проверяет. Карточка несёт факты (#3287: длительность квеста, число дней статьи) и координаты (#3295).

Планировщик (`docs/features/trips.md`): форма `/trips/plan/create` создаёт поездку без маршрута (`POST /trips/planned/`), точки добавляются в конструкторе уже созданной поездки и сохраняются полным `PUT /trips/planned/{id}/route/`. **У точки маршрута есть номер дня** — `RoutePoint.dayNumber` 1–60 (#1845), конструктор группирует по нему список. Значит, разбивка плана по дням ложится в маршрут без изменений бэкенда; а вот точек форма создания не принимала (#3416 п.1).

## Goals / Non-Goals

**Цели:** на просьбу о плане — план по дням из материалов одного места; план есть при любом поведении модели; один шаг до черновика поездки с точками по дням; квест из ответа — точкой маршрута (#3416 п.1).

**Не цели:** время в пути по дорогам, бронирование, бюджет, маршруты мира в плане, личный контекст в плане, набор обучения и срез оценки с порогом, изменения бэкенда, живой прогон в браузере.

## Decisions

Решения 1–6 приняты архитектором до проектирования; A–F принял исполнитель.

- **1. План собирается всегда.** Конвейер `plan.ts`: число дней из вопроса кодом → карточки места и региона → модель → проверка схемы → доводка кодом. Ответ модели не прошёл проверку, модель занята или недоступна — план из тех же карточек собирает код (`assemblePlan`), ответ несёт `assembled: 'code'`. `422 invalid_plan` остаётся одному случаю: карточек меньше двух. Отвергнуто: `422` при любом сбое модели — посетитель остаётся без плана из-за навыка, которого у модели пока нет (56 % по схеме).
- **2. Кто собирает по умолчанию — код; путь модели включается правилом из двух условий.** Правило: по схеме не меньше 90 % ответов И содержание не беднее сборки кодом на том же наборе — доля дней с 2–4 материалами и число покрытых дней не ниже кодовых (замер — `.codex-temp/3298/plans-side-by-side.md`). Сейчас не выполнено: по схеме 94 % (51 из 54), но дней с 2–4 материалами у модели 18 из 36 (50 %) против 37 из 41 (90 %) у кода, покрыто дней 36 из 49 запрошенных против 41; модель взяла меньше материалов во всех 18 вопросах. Поэтому `PLAN_MODEL_DEFAULT = false`, путь модели — `AI_PLAN_MODEL=1` (рабочий: мягкое `note` в дне, доводка, запасная сборка кодом). Навык «план по дням: 2–4 материала в дне, все запрошенные дни» — задача круга обучения #3358 с этими числами; набор `trip_plan` и срез оценки с порогом в этой карточке не делаются. Отвергнуто: включать путь модели по одной доле ответов по схеме — схема проверяет форму, а не полноту: модель прошла её в 94 % ответов и при этом дала план вдвое беднее кодового.
- **3. Свой счётчик и журнал.** `AskLimits` с префиксом `ai-plan:v1`, 10 планов в сутки на IP; отказ запрос возвращает. Журнал спроса — новый вид записи `{ts, plan, locale, q, days_requested, day_ids}` без IP; прежние записи и отчёт не меняются. Отвергнуто: списывать план со счётчика вопросов — отказ плана уводит вопрос в `/ai/ask`, и один вопрос стоил бы два списания.
- **4. Намерение — на экране, узкое.** `detectPlanIntent`: просьба составить; «план/маршрут/программа на N дней, выходные, неделю»; число дней от двух вместе с «что посмотреть»; короткая фраза без вопроса с числом дней и местом. Вопрос о самом числе дней, выбор места («куда съездить на два дня»), вопрос о наличии материалов и вопрос о своём (#3354) — не план: правило сверено с вопросами наборов оценки — из 316 вопросов планом становятся шесть вида «что посмотреть в городе за N дней». Сбой `/ai/plan` → `/ai/ask` тем же вопросом. Отвергнуто: определять намерение на службе внутри `/ai/ask` — поток SSE пришлось бы научить третьему виду ответа, а старый клиент получил бы пустой ход.
- **5. Планировщик принимает точки без изменений бэкенда.** У поездки дни есть (`dayNumber`), поэтому точки плана идут в маршрут с номером дня, а текст по дням — ещё и в описание (его видно до создания). Форма создания получает `routeDraft` и после `POST /trips/planned/` сохраняет точки существующим `useUpdateTripRoute`. Отвергнуто: новый адрес бэкенда «создать поездку с маршрутом» — `area=back`, а нужный результат достигается двумя существующими запросами.
- **6. Границы.** Бронирование, дороги, бюджет, маршруты мира и личный контекст в план не входят. Отвергнуто: добавить в кандидаты плана маршруты мира (#3357) — у них нет координат точки и страницы на сайте, в планировщик они точкой не встают.

Решения исполнителя:

- **A. Регион отбирает код до модели.** Кандидаты — карточки места не дальше 50 км от медианы их координат; материалы индекса в 25 км от середины добавляются после найденных; не больше 12. Отвергнуто: доверить «один город» модели и проверять после — проверка «чужой город» по названию ненадёжна, а по координатам она и есть этот отбор, только позже.
- **G. Материал на несколько дней и регион при малом числе карточек (живая QA 15.11.2026).** Материал с фактом «два дня и больше» занимает день целиком, а в план на один день не берётся, пока есть другие кандидаты. Регион, когда отбор по медиане не оставил никого (две карточки в разных городах), — самое плотное скопление; при равенстве его задаёт квест. Язык материалов план не отбирает: он согласован с обычным подбором, который показывает квест без перевода в его единственной версии. Отвергнуто: не брать в план квест без версии на языке вопроса — посетитель терял бы план и всё равно видел те же квесты в обычном ответе; причина русских квестов у польского вопроса — отсутствие переводов, а не подбор.
- **B. Часы — из фактов, иначе оценка.** Квест — длительность из фактов; статья на несколько дней — 8 часов (целый день); у однодневной статьи часов в фактах нет — берётся оценка модели в пределах 0,5–8 ч, а в сборке кодом — 4 часа. День — не больше 10 часов и 4 материалов. Отвергнуто: считать однодневную статью целым днём — тогда в каждом дне один материал, а сценарий просит 2–4.
- **C. Сколько дней хватает — по часам.** Сборка кодом берёт дней не больше запрошенного и не больше `ceil(сумма часов / 6)`: два квеста Лиды по полтора часа — это один день, а не два «дня» по одному квесту. Отвергнуто: день на материал — «пять дней в Лиде» превращались бы в два дня по полтора часа.
- **D. Схема строгая, кроме поля `note` в дне (решение архитектора 15.11.2026).** Модель v7 повторяет в дне верхнее поле `note`. Схема принимает в дне необязательную строку `note` и отбрасывает её; любой другой неизвестный ключ, чужой id, повтор, лишние дни, часы вне пределов — отказ. Фраза модели (`note` верхнего уровня) посетителю не выводится: это непроверенный текст, он остаётся в `trace`; поле `note` ответа — только кодовая фраза (сейчас пусто), подписи и фразу о нехватке пишет код через i18n. Отвергнуто: пропускать любые лишние поля дня — через «безвредное» поле в ответ мог бы поехать текст или адрес, если код когда-нибудь начнёт его читать.
- **E. План между экранами — в хранилище, в адресе только идентификатор.** `utils/tripPlanDraft.ts`: одна запись в `AsyncStorage` (как `guestPlanIntent`), живёт сутки, читается по идентификатору из `?source=plan&draft=<id>`, удаляется после сохранения маршрута. Отвергнуто: компактный параметр с точками в адресе — девять точек с названиями не помещаются в разумную длину, а вопрос посетителя попадал бы в историю браузера, `Referer` и журналы.
- **F. Общий приём точек и #3416 п.1.** Экран создания собирает `routeDraft` из двух источников одним контрактом: черновик плана либо одна точка материала параметром `sourcePoint=<lat>,<lng>`. Вторым воспользовался `buildTripPlanCreateHrefFromQuest`: квест из карточки под ответом встаёт точкой маршрута. Отвергнуто: класть одну точку квеста тоже в хранилище — ссылка «В план поездки» строится синхронно, а пара координат помещается в адрес и не раскрывает ничего сверх названия материала, которое там уже есть.

## Risks / Trade-offs

- **Два запроса при создании.** Поездка создаётся, маршрут сохраняется вторым запросом и может не сохраниться. → Форма не создаёт вторую поездку: кнопка отправки выключается, вместо неё «Сохранить точки ещё раз» и «Открыть поездку без точек»; черновик остаётся в хранилище.
- **Часы однодневной статьи — оценка.** → Заголовок дня говорит «около N ч»; под планом строка, что порядок и время правятся в планировщике.
- **Порядок по прямой.** Расстояние между материалами — по координатам, без дорог. → Не цель карточки; в планировщике маршрут пересчитывает движок.
- **Ложное намерение.** «Маршрут на выходные из Минска» уходит в план и получает материалы Минска. → Правило узкое, обе стороны покрыты тестами на пяти языках; отказ плана незаметен посетителю.
- **Регион у страны.** «План на неделю в Польше» берёт самый плотный регион карточек, а не всю страну. → Соответствует «одного места или региона»; фраза о нехватке дней честно называет, на сколько хватило.
- **План модели беднее плана кода.** В пробе модель взяла меньше материалов во всех 18 вопросах; дней с одним материалом — 18 против 4. → По умолчанию собирает код; путь модели — только переменной `AI_PLAN_MODEL=1`, навык — в круг обучения #3358.
- **Вес страницы статьи.** Ссылку на форму поездки (`utils/tripPlanLinks.ts`) грузит страница статьи; статический импорт хранилища черновика и приёма точек оттуда добавил ей eager-запрос (19 при потолке 18), и выкат `86702b04c` остановил страж бюджета. → Модули разведены: `tripPlanLinks.ts` — сборка ссылки без новых импортов (`formatSourcePoint` — чистая функция), `tripPlanDraft.ts` — хранилище с одной зависимостью `AsyncStorage` (экран ассистента и форма), `tripPlanDraftIntake.ts` — точки маршрута и подстановка формы (только форма). Граф импортов закреплён тестом; пробная прод-сборка — eager-запросы всех маршрутов равны `a782e6721`.
- **Существующие вопросы e2e.** Вопрос с намерением «план» в прежних e2e-сценариях теперь сначала стучится в `/ai/plan`; без мока — отказ и прежний путь.

## Migration Plan

Обратно совместимо: новый адрес службы и новые необязательные пропсы формы. Порядок выката — служба, затем фронт; фронт без службы получает отказ `/ai/plan` и идёт прежним путём. Откат — фронтом (намерение не вызывается); у службы выключателя не требуется.
