## Context

Мотивация — proposal.md → «Why». Требования — `specs/quest-ssg-route-digest/spec.md`.

Что есть сейчас (`scripts/generate-seo-pages.js`):

- `injectQuestIntroSection` (`scripts/generate-seo-pages.js:2144`) кладёт в `<body>` секцию
  `data-ssg-quest-intro`: кикер, `h1`, лид, абзацы `intro.story`, четыре факта и блок перелинковки
  (#1756). Секция скрывается после гидратации через `html.rnw-styles-ready`.
- `buildQuestIntroSectionModel` (`:2046`) уже разбирает бандл: `getQuestSteps` (`:2026`) и
  `getQuestIntro` (`:2031`) снимают JSON-поля, `parseQuestJsonField` (`:2014`) терпит и объект, и
  строку.
- Бандлы всех квестов уже загружаются сборкой (`:3510`), поэтому данные точек в момент генерации
  на руках и новых сетевых запросов не нужно.

Разбор корпуса на всех 165 квестах прода (04.09.2026, `/api/quests/by-quest-id/<slug>/`):

| величина | значение |
| --- | ---: |
| точек (включая вступление) | 1 601 |
| `story` целиком | 221 285 слов, в среднем 138 на точку |
| точек с конкретным ожидаемым ответом (`exact`, `exact_any`, `range`) | 953 |
| из них ответ дословно встречается в `story` | 17 |
| предложений в `story` всего | 11 164 |
| из них обращены к игроку (императив, второе лицо) | 1 732 (16%) |

## Goals / Non-Goals

**Goals:**

- Отбор безопасных предложений — чистая функция без сети и файловой системы, покрываемая юнит-тестом.
- Гейт на раскрытие игровой части работает на всех 165 страницах в каждой сборке, а не на выборке.
- Ни строки новой прозы: публикуется подмножество существующего `story`.

**Non-Goals:**

- Правка авторских текстов квестов, включая те 17 точек, где ответ упомянут в `story`, — их
  предложения отсеиваются на генерации, а не переписываются.
- Морфологический разбор русского языка: отбор остаётся лексическим фильтром с запасом в сторону
  «выкинуть лишнее».

## Decisions

### 1. Единица отбора — предложение, а не абзац

Первая проверенная гипотеза была «первый абзац `story` описывает объект, дальше идут наводки», и она
**не подтвердилась**: обращения к игроку встречаются в первом абзаце даже чаще, чем в последующих —
506/1 601 (31,6%) против 853/3 460 (24,7%). Абзац как единица публикации протаскивал бы наводки на
трети точек.

Отбор по предложениям на том же корпусе выкидывает 1 732 предложения из 11 164 (16%) и не оставляет
без текста ни одной из 1 436 точек. Отвергнутая альтернатива — публиковать `story` целиком: 221 285
слов авторского текста в блоке, скрываемом после гидратации, меняют природу блока и повышают риск
трактовки как скрытого контента.

### 2. Спойлер — это задание, подсказка и значение ответа, но не сам рассказ

`task`, `hint` и `answer_pattern` не публикуются как поля никогда. Из `story` дополнительно
выбрасывается предложение, содержащее значение ожидаемого ответа: варианты `exact_any`, значение
`exact`, любое число из `range`. На корпусе это 17 предложений — правило не косметическое.

Название и место точки чистятся одним и тем же правилом: уточняющий хвост после тире снимается,
если он несёт ответ («Памятник Тысячелетия — ангел над городом» → «Памятник Тысячелетия»). Правило
обязано покрывать оба поля, потому что место сплошь и рядом повторяет полное название объекта (14
точек корпуса), и чистка одного названия вернула бы снятый хвост вторым куском заголовка. Там, где
ответом назван сам объект, снимать нечего — это 11 предупреждений сборки и работа редактора.

Типы `any`, `any_text`, `any_number` конкретного ответа не задают, и раскрывать у них нечего.

### 3. Лимит — 2 предложения и 60 слов на точку

Замер на корпусе: 1 предложение → в среднем 133 слова уникального текста на квест, 2 → 297, 3 → 450,
весь отфильтрованный `story` → 968. При текущих 104–291 слове вне общего шаблона лимит в
2 предложения даёт кратный рост и оставляет страницу анонсом. Лимит по словам страхует случай, когда
два предложения оказались абзацем на 200 слов; обрыв — только по границе предложения, чтобы в HTML
не попадала фраза без конца.

### 4. Гейт живёт в генераторе, а не в отдельном верификаторе

`scripts/verify-static-quest-seo.js` уже сверяет `dist` с живым каталогом на деплое, но бандлы точек
он не тянет — спойлер-проверка стоила бы ему 165 дополнительных запросов к API и добавила бы деплою
зависимость от их доступности. Генератор же держит и бандл, и готовый HTML в один момент времени,
поэтому проверка встраивается туда: сверка идёт перед записью файла, по всем квестам, без сети.

Проверка независима от отбора: она сверяет готовую страницу с **сырыми полями** бандла, поэтому
ошибка в самом фильтре ею ловится, а не маскируется. Контуры разные, и это измерено: `task`/`hint`
сверяются с **итоговым HTML** целиком, а ответ — только с **опубликованным описанием точки**, потому
что у 194 точек ответ числовой и число вроде «7» неизбежно стоит в общем шаблоне страницы
(«Маршрут: 7 точек»). Ответ, звучащий в самом названии или месте точки, даёт предупреждение, а не
ошибку: остановка сборки его не исправит, это правка контента.

### 5. Подписи блока остаются в генераторе, а не в `@/i18n`

Статический срез собирается один раз на языке контента квеста (RU), как и существующий блок
`data-ssg-quest-intro` с его «Городской квест Metravel» и «Куда дальше». Заводить `@/i18n` ради
строк, которые никогда не рендерятся приложением, значит создать вторую точку правды.

## Risks / Trade-offs

- **Лексический фильтр пропустит наводку в необычной формулировке** → гейт ловит только дословные
  совпадения с `task`/`hint`/ответом, поэтому пропущенная наводка не обрушит сборку. Смягчение:
  список маркеров обращения к игроку покрывает и глаголы-указания, и второе лицо; выборочная сверка
  итогового текста шести URL из #1763 входит в приёмку.
- **Фильтр окажется слишком строгим и точка останется без описания** → на корпусе таких нет ни
  одной, но код обязан пережить этот случай: точка без уцелевших предложений публикуется одним
  названием и местом, без пустого абзаца.
- **Рост скрытого после гидратации текста** → лимит в 2 предложения удерживает блок в размерах
  анонса; ~400–590 слов уникального текста сопоставимы с городской посадочной, которую Google берёт.
- **17 точек с ответом в `story` — сигнал о качестве контента** → сборка их обезвреживает, но сам
  факт стоит отдельного разбора редактором; это не входит в объём change.

## Migration Plan

Выкат — обычная пересборка статики: `npm run seo:generate-pages` внутри прод-сборки. Схема данных не
меняется, обратной миграции не требуется. Откат — возврат коммита генератора и пересборка; страницы
вернутся к сегодняшнему срезу.

## Validation Matrix

| поверхность / локаль | проверка |
| --- | --- |
| генератор, все 165 квестов | прогон генерации на живом каталоге; спойлер-гейт зелёный; замер слов до/после |
| юнит | отбор предложений, лимиты, отсутствие `task`/`hint`/ответа, точка без уцелевших предложений, точка без `poi_info` |
| desktop web | статический HTML страницы квеста до гидратации: точки на месте, заданий нет |
| mobile web | тот же срез в мобильном вьюпорте: блок не ломает вёрстку до гидратации |
| после гидратации (web) | блок скрыт, экран квеста работает как прежде |
| Android / iOS | не затронуты — блок статический и живёт только в web-сборке |
| локали RU/BE/UK/PL/EN | новых app-owned строк нет; `npm run test:i18n` как регрессия |
