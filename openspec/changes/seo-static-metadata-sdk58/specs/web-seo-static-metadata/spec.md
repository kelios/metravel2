## Purpose

Статический HTML каждого web-маршрута несёт полные SEO-метаданные до выполнения JavaScript, объявленные штатным API роутера из одного источника строк.

## ADDED Requirements

### Requirement: Head каждого экспортированного HTML объявлен маршрутом
Система SHALL формировать title, description, robots, canonical, Open Graph и Twitter теги каждого экспортированного web-документа из объявления метаданных файла маршрута, без патчей рендерера роутера.

#### Scenario: Статический маршрут
- **WHEN** экспортируется статический маршрут (главная, поиск, карта, квесты, о проекте, юридические и приватные страницы)
- **THEN** HTML содержит ровно один непустой `<title>`, одну `meta[name=description]`, canonical (кроме 404 и приватных без canonical), og:* и twitter:* с теми же значениями, что до миграции

#### Scenario: Шаблон динамического маршрута
- **WHEN** экспортируется шаблон динамического маршрута без данных сущности
- **THEN** HTML несёт title/description «не найдено», `robots: noindex, follow` и не содержит canonical

### Requirement: Один источник строк статических маршрутов
Система SHALL брать строки статических маршрутов для экспорта и для SSG-генератора из одного модуля; текст не меняется относительно текущего прод-HTML.

#### Scenario: Паритет генератора и экспорта
- **WHEN** генератор переписывает head статического маршрута
- **THEN** title, description, robots, canonical и og:image равны значениям, объявленным маршрутом

### Requirement: Per-entity страницы без потерь
Система MUST сохранять для статей, квестов, городов, стран и локализованных квестов тот же набор head-тегов и JSON-LD, что до миграции.

#### Scenario: Diff до/после
- **WHEN** сравниваются подписи head всех HTML сборки с патчем и сборки без патча
- **THEN** ни одно значение title/description/robots/canonical/og/twitter/hreflang/ld+json не потеряно
