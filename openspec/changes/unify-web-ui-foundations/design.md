## Context

Справочник действующих примитивов находится в [DESIGN_SYSTEM.md](../../../docs/DESIGN_SYSTEM.md). Инвентаризация, предлагаемые размеры и схема состояний находятся в [веб-макете](../../../docs/design/web-ui-foundations.md).

## Goals / Non-Goals

**Goals.** Общая геометрия для панелей одной роли, повторное использование контролов и изолированные примеры, которые помогают расширять покрытие по страницам.

**Non-Goals.** Смена визуального бренда, правил навигации, контента или API. Полноэкранная карта, прохождение квеста, редакторы и оглавление статьи сохраняют свои композиции и подключают общие элементы по их роли.

## Decisions

1. **Токены.** Использовать `METRICS` для геометрии, `useThemedColors()` для тематических цветов, `Typography` для текста. Сначала сопоставить две шкалы отступов по значениям и назначению. Общие размеры конкретного паттерна хранить в его модели, единым источником для React и критического CSS. Массовая замена одноимённых ключей меняла бы фактические размеры, поскольку `xs` означает 4 и 8 в разных шкалах.
2. **Панель.** Композиция в `components/layout` принимает заголовок, действия и содержимое. Модель геометрии даёт режим, ширину колонки, отступы и резерв для первого кадра. Модель не знает о данных, URL и правах. Контроллеры поиска, мест и квестов сохраняют выбор, сброс и возврат. Перенос всей страницы в один контроллер связал бы разные правила данных и жизненного цикла. Динамические пороги у публичных страниц проходят через `defineBreakpointLayout`, а static shell, заглушка и готовая панель используют ту же геометрию.
3. **Действия.** Канонические `Button`, `IconButton`, `Chip` и `LinkPressable` остаются точками входа. Строка меню имеет именованные роли по семантике. Если текущий примитив не поддерживает нужное состояние, добавить узкое совместимое расширение после проверки вызывающих компонентов. Ссылки по якорям сохраняют прокрутку, внешние назначения проходят через `utils/externalLinks.ts`. Замена всех строк на `Button` нарушила бы ссылочную семантику и работу новой вкладки.
4. **Каталог.** Выбрать изолированный локальный вход вне `app/`. Демонстрации импортируют продуктовые компоненты напрямую, используют локальные фикстуры и имитируют состояния загрузки и ошибок без сетевых зависимостей. Отдельный вход позволяет исключить каталог из экспортированных страниц и основного графа импорта. Маршрут под feature flag внутри основного Expo Router оставил бы риск его попадания в манифест и export. Новый пакет для каталога нужен только при доказанном ограничении существующего инструментария.
5. **Миграция.** Сначала согласовать эталон и кнопку/ссылку, параллельно проверить геометрию на поиске и местах. После пилота подключить квесты и пригодные части карты, затем оглавления, рабочие страницы, списки и карточки. Для оставшихся экранов вести таблицу охвата с маршрутом и причиной исключения.

## Risks / Trade-offs

- [Сдвиг карточек и видимая загрузка] → проверить холодный HTML с задержанной гидратацией и повтор после неё. Допуск для позиции начала колонки при одинаковом состоянии — ±1 CSS px. Не ухудшить действующие проверки поиска и квестов.
- [Меньше места для списка или карты] → проверить крайние ширины и количество карточек в ряду. Карту подключать по совместимому паттерну, её полноэкранный режим документировать отдельно.
- [Потеря клавиатурного управления, фильтра или истории] → сравнить фокус, раскрытие, URL, Back/Forward и варианты клика до и после. Сохранить отсроченную загрузку и правила карты при изменении размеров.
- [Общие изменения заденут приложения] → проверить вызывающие компоненты и общую семантику в Jest. Добавлять симулятор или эмулятор при изменении соответствующей platform-specific ветки.
- [Каталог или фикстуры попадут в export] → проверить web manifest, sitemap и граф импорта. Действующие бюджеты бандла остаются порогом.

## Migration Plan

Два поезда по три карточки. Первый закрепляет эталон, общие действия и пилотную панель. Второй расширяет подключение и закрепляет охват и проверки. Компоненты подключаются по экрану, поэтому при регрессии можно вернуть прежнюю композицию отдельного маршрута. Если проблема в общем контракте, откатывается коммит соответствующего поезда штатным процессом выката.

Статическая проверка — адресные Jest и guards с независимым ревью. Приёмка видимых изменений — mobile web, затем desktop web на выкаченном SHA. Для каталога — локальные интерактивные примеры и подтверждение отсутствия в production-артефактах. Матрица и нормативные состояния находятся в [макете](../../../docs/design/web-ui-foundations.md).
