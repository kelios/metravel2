## Purpose

Сделать фильтры, действия и ссылки предсказуемыми при переходе между разделами MeTravel и дать команде воспроизводимый каталог этих паттернов.

## ADDED Requirements

### Requirement: Shared catalog filter frame

Однотипные фильтры каталогов MUST использовать согласованные ширину, отступы, заголовок и размещение при одинаковой ширине окна. Каркас MUST резервировать одинаковое место до загрузки данных и после неё. Выбор и сброс фильтров MUST сохранять действующую семантику каждого раздела.

#### Scenario: Desktop filters at first paint

- **WHEN** посетитель напрямую открывает поиск или места на широком экране
- **THEN** панель слева и начало списка занимают согласованные позиции, а загрузка фильтров не меняет ширину панели или положение списка

#### Scenario: Narrow filter interaction

- **WHEN** посетитель открывает фильтры на телефоне, выбирает значение и закрывает панель
- **THEN** фильтры доступны без горизонтальной прокрутки, выбранное значение применяется по правилам раздела, а фокус возвращается к открывающему контролу

### Requirement: Consistent action and link semantics

Поверхности миграции MUST одинаково отображать действия одной роли, выбранный пункт, клавиатурный фокус и недоступное состояние. Ссылки на другие страницы MUST сохранять адрес и штатные возможности браузера. Фильтры и действия на месте MUST иметь соответствующую семантику управления.

#### Scenario: Keyboard and browser navigation

- **WHEN** посетитель открывает ссылку обычным кликом или с клавиатуры либо вызывает контекстное меню ссылки
- **THEN** браузер видит действительный адрес, фокус различим, обычный переход сохраняет поведение приложения, а новая вкладка открывает тот же адрес

#### Scenario: Long localized action label

- **WHEN** подпись обычной текстовой кнопки в поддерживаемой локали не помещается в одну строку
- **THEN** подпись переносится, кнопка растёт, а соседние элементы остаются доступны

### Requirement: Isolated interactive component catalog

Команда MUST иметь локальный интерактивный каталог с примерами реальных общих компонентов в узком и широком режимах, светлой и тёмной темах и ключевых состояниях. Каталог MUST запускаться без аккаунта и запросов к рабочим данным и отсутствовать в production-маршрутах, sitemap и пользовательских чанках.

#### Scenario: Preview a disabled action and loading panel

- **WHEN** разработчик запускает каталог с локальными примерами и переключает тему и ширину
- **THEN** он может проверить те же компоненты, которые используют страницы, включая клавиатурный фокус, недоступное действие и каркас загрузки

### Requirement: Adopted web page patterns retain route behavior

Мигрированные страницы MUST сохранять адреса, заголовки, режимы фильтрации, возврат из деталей и предусмотренные для них исключения по компоновке.

#### Scenario: Return from a catalog item

- **WHEN** посетитель открывает результат из отфильтрованного каталога и возвращается назад
- **THEN** восстанавливается предусмотренное для маршрута состояние фильтра и списка
