## Goals / Non-Goals

Goals: диск VPS не растёт от публикаций книг; адреса и SHA файлов текущих
изданий неизменны; загрузка и наличие файлов проверяются машинно до активации
manifest и до выката; в S3 только текущий manifest (решение владельца
03.11.2026), откат — переключение метаданных плюс повторная загрузка из кеша.

Non-goals: CDN, подписанные ссылки, приватность книг, дедупликация по содержимому в
S3, перенос остальной статики фронта.

## Decisions

1. **Хранилище — `metravelprod`, префикс `travel-books/`, ключ = путь URL.**
   Бакет уже публично читаем целиком (фото статей), регион eu-north-1, versioning
   выключен. Книги бесплатные и публичные, отдельный приватный бакет не нужен.
   Ключ совпадает с путём URL, поэтому nginx проксирует `$uri` без таблицы
   соответствий. Отвергнуто: ключи по SHA содержимого — экономили бы
   дубликаты между ревизиями (≈0,7 ГБ при всех ревизиях; при одном текущем
   manifest — меньше), но требуют map-файла в nginx, синхронного с каждой публикацией.
   Отвергнуто: отдельный бакет — новый ресурс и политика ради того же публичного
   чтения.

2. **Отдача — nginx, сначала локальный файл, затем прокси в S3.**
   ```nginx
   location = /travel-books/manifest.json { try_files $uri =404; # no-cache }
   location ^~ /travel-books/ {
       limit_except GET HEAD { deny all; }
       try_files $uri @travel_books_s3;   # immutable-заголовки
   }
   location @travel_books_s3 {
       resolver 127.0.0.11 1.1.1.1 8.8.8.8 valid=300s ipv6=off;
       set $travel_books_s3 "https://metravelprod.s3.eu-north-1.amazonaws.com";
       proxy_pass $travel_books_s3$uri;          # без query
       proxy_set_header Host metravelprod.s3.eu-north-1.amazonaws.com;
       proxy_ssl_server_name on;
       proxy_max_temp_file_size 0;               # PDF не спулятся на диск VPS
       proxy_intercept_errors on;                # 403/404 S3 -> 404 сайта
       proxy_hide_header x-amz-*; Set-Cookie;
   }
   ```
   `try_files` делает переключение независимым от порядка: пока в релизе есть
   файлы, отдаются они; когда релиз несёт только manifest — S3. `rollback-code` на
   релиз со старым manifest требует, чтобы его файлы были на диске или снова
   загружены в S3 (после `prune` их там нет). Range проходит до S3
   (206 для просмотрщиков PDF). Предпросмотры webp можно класть в существующий
   `metravel_cache` (≈0,4 ГБ максимум, бюджет зоны решает бэк); PDF не кэшируются.
   Отвергнуто: 302 на `*.amazonaws.com` — меняет ответ адреса (не 200), CSP
   `img-src`/`connect-src` и не даёт кэша предпросмотров. Отвергнуто: отдача через
   Django (`X-Accel-Redirect`) — лишний воркер на каждый запрос без пользы для
   публичных файлов.

3. **Загрузка — `scripts/books/storage.cjs`, SigV4 без SDK.**
   PUT одного объекта с `x-amz-checksum-sha256` (S3 сам отвергает тело с другим
   SHA), `If-None-Match: *` (существующий ключ не перезаписывается),
   `Content-Type` по расширению, `Cache-Control` immutable. Перед PUT — HEAD:
   тот же размер и `ChecksumSHA256` — пропуск; иной — ошибка «Immutable
   publication asset changed in storage». Байты читаются только из локального кэша и проверяются по SHA до
   отправки. Креды — медиа-ключ из `local_env.sh` бэкенда или окружения
   `METRAVEL_BOOKS_S3_*`, в лог не выводятся. Отвергнуто: `@aws-sdk/client-s3` —
   +зависимость ради двух запросов; AWS CLI на маке нет.

4. **Проверка наличия — анонимный HEAD к S3 с `x-amz-checksum-mode: ENABLED`.**
   Совпадение `Content-Length` и `x-amz-checksum-sha256` с manifest = файл на месте,
   тело не скачивается (HEAD ≈ $0,0004 за 1 000). Подтверждённые пары
   `путь+sha` кэшируются в `.codex-temp/books-storage-verified.json` канонического
   чекаута: объект неизменяем, повторная сборка проверяет только новые ревизии.

5. **Сборка: `copy-publication.cjs` больше не копирует файлы.** Сохраняет все
   проверки манифестов (`collectAssets`, `bookContentsIndex`, SHA снимков),
   требует подтверждения хранилища для каждого файла текущего manifest и пишет
   только `travel-books/manifest.json`. Гейт: после записи каталог `travel-books` релиза
   содержит ровно `manifest.json`, иначе сборка падает.

6. **Публикация: отдельный шаг `storage.cjs upload --manifest <staged>`** после
   `publish.mjs`; `upload` без флагов (manifest чекаута) — для активации через
   `augment-publication.mjs`, отката и разового переноса. `publish.mjs` не меняется: его SHA входит в ID ревизии
   (`publisherHash`), правка поменяла бы ревизии уже подготовленной публикации
   `0baed26…`. Пропущенный шаг ловит гейт сборки (решение 5).

7. **Хост: общий store опустошается штатно.** `web-ssr-publication.sh stage`
   больше не делает `--link-dest`-заливку книг; `web-ssr-release-audit.sh books`
   отказывает, если в релизе в `travel-books` что-то кроме `manifest.json`, и
   всегда чистит store (сейчас при отсутствии каталога он выходит раньше чистки).
   Место освобождается, когда `finalize` удалит последние релизы с файлами книг:
   ≈ через два выката после переключения; затем store пуст и удаляется.

8. **Только текущий manifest; `prune` (решение владельца 03.11.2026).** S3 держит
   файлы, которые сайт предлагает скачать или показывает, — без прежних ревизий и
   рабочих материалов. `storage.cjs prune` перечисляет `travel-books/`
   (ListObjectsV2 с пагинацией) и оставляет объекты manifest чекаута, живого
   `https://metravel.by/travel-books/manifest.json` (недоступен — отказ) и
   необязательного `--keep-manifest <staged>`; остальное попадает в отчёт
   `.codex-temp/books-storage-prune-<время>.txt` и удаляется только с `--apply`.
   Ключ вне `travel-books/` или с неожиданными символами останавливает чистку.
   Подтверждения удаляемых ключей стираются из кеша до удаления. URL удалённой
   ревизии отвечает 404: ни QR, ни заказы на URL ревизий не ссылаются. Откат
   публикации — переключение метаданных и `storage.cjs upload` откатанной ревизии
   из кеша `.codex-temp/books-publication`. Отвергнуто: хранить все ревизии —
   объём растёт на ≈2 ГБ с каждой публикацией всех изданий.

## Оценка стоимости (gate §3.4.1)

Цены AWS eu-north-1 по прайс-листу (сверить в Billing): хранение S3 Standard
$0,023/ГБ·мес; PUT $0,005 за 1 000; GET/HEAD $0,0004 за 1 000; исходящий трафик в
интернет — первые 100 ГБ/мес на аккаунт бесплатно, затем $0,09/ГБ.

| статья | объём | оценка |
| --- | --- | --- |
| хранение: текущий manifest | ≈2,4 ГБ | ≈ $0,06/мес |
| рост на публикацию всех 12 изданий | ≈0 после `prune` (до него — до +≈2,4 ГБ) | ≈ $0 |
| разовая загрузка | 3 278 PUT + ≈10 000 HEAD | ≈ $0,02 |
| проверка на выкат | ≤ 3 278 HEAD (кэш — только новые) | < $0,01 |
| `prune` | LIST по 1 000 ключей + DELETE (бесплатно) | < $0,01 |
| приёмка: полная проверка SHA всех файлов через сайт | ≈2,4 ГБ трафика | $0 в пределах 100 ГБ, иначе ≈ $0,22 |
| чтения читателями | средний PDF 5,7 МБ; предпросмотры из кэша nginx | 1 000 скачиваний PDF ≈ 5,7 ГБ ≈ $0,51 сверх бесплатных 100 ГБ |

Неизвестно: фактический трафик `/travel-books/` (чтение прод-логов в этой сессии
не разрешено) и сколько из бесплатных 100 ГБ уже расходуют фото статей (Django
читает их из того же S3). Ограничители: `limit_req` на `/travel-books/` в nginx,
предпросмотры из кэша; условие остановки — письмо бюджета $8 или трафик книг
> 50 ГБ/мес по Cost Explorer: тогда кэш PDF на VPS или CDN отдельным решением.

## Risks / Trade-offs

- [S3 недоступен] → файлы, которых нет на диске, отвечают 502/504; страницы
  `/books` работают (manifest локальный). Повтор скачивания в UI уже есть.
- [Креды загрузки] → медиа-ключ шире, чем нужно (весь `metravelprod`); принято
  владельцем ради отсутствия нового IAM. Запись только `If-None-Match: *`;
  удаляет только `prune --apply` и только под `travel-books/`.
- [Чистка и откат] → после `prune` файлов прежней ревизии в S3 нет: откат
  публикации и `rollback-code` на релиз со старым manifest требуют повторного
  `storage.cjs upload` из локального кеша; без кеша эти байты не восстановить.
  `prune` без `--keep-manifest` между загрузкой подготовленной публикации и её
  активацией удалит её файлы — сборка тогда остановится на гейте.
- [Публичный бакет] → любой объект под `travel-books/` публичен — туда кладутся
  только файлы из manifest после `checkContent`.
- [Ретеншен] → диск освобождается не сразу, а после выхода из ретеншена релизов с
  книгами; `asset_release` может держать старый релиз дольше.

## Migration Plan

1. Gate §3.4.1: подтверждение владельца (бакет, креды, бюджет).
2. `area=back`: nginx `location` из решения 2 — выкат бэка без изменения поведения
   (все файлы ещё на диске).
3. Код фронта (решения 3–7) — ревью, коммит, но выкат только после шага 4.
4. Перенос: `storage.cjs upload` из кэша, затем `verify` (100 % SHA текущего
   manifest). Проверка через сайт файла, которого нет на диске.
5. Выкат фронта без файлов книг; приёмка всех URL текущего manifest через
   `https://metravel.by` (200, размер, SHA тела). Затем `prune` (отчёт) и
   `prune --apply` — владелец из своего терминала.
6. Два штатных выката → `finalize` удаляет релизы с книгами; `books`-аудит
   опустошает store; замер `df -P /` до/после в `docs/ops/prod-disk-growth.md`.

Откат: вернуть прежние `copy-publication.cjs`/`web-ssr-publication.sh` — релиз
снова несёт файлы всех снимков (≈3 ГБ на диске, нужно место; байты — из кеша); nginx-`location` откатывать не
нужно — локальный файл имеет приоритет.
