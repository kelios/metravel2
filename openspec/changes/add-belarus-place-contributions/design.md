## Context

См. [цель пилота](proposal.md). Каталог строится из публичных источников путешествий и группирует точки по идентичности места. Маркер существующей точки предполагает источник с материалом. [Контракт каталога](../../../docs/features/places.md) · [Контракт карты](../../../docs/features/map.md)

Короткая заметка уже поддерживает загрузку 1–10 фото, одну точку и рассказ от 50 видимых символов. Мастер полной статьи остаётся доступен для длинного рассказа. В текущем интенте из статьи требуется `source_travel_id`. [Заметка](../../../docs/features/travel.md#короткая-заметка-о-поездке-2666) · [Интент](../../../utils/travelArticleCreateIntent.ts)

## Goals / Non-Goals

- Провести читателя из «Мест» или карты в черновик с понятной задачей.
- Дать редактору управляемый список запросов и обеспечить появление настоящей публичной точки после первого вклада.
- Сохранить текущий контракт источников, модерации, фото и обычной выдачи. Достаточно существующих заметок и статей.

## Decisions

### Путь путешественника

1. В «Местах» перед выдачей компактная ссылка **«Допишем Беларусь вместе»**. Показывать без страны и при BY, в том числе рядом с пустой белорусской выдачей. Сохранять выбранные фильтры при возврате.
2. Отдельная страница `/places/help` с заголовком и вопросом **«Были в одном из этих мест? Поделитесь своими фотографиями и коротким рассказом. Ваш опыт поможет другим спланировать поездку.»** Сначала активные карточки, ниже объяснение «Фото → несколько предложений → модерация». Телефон — одна колонка, планшет — две, широкий экран — три. Области — фильтр подборки. Карточка показывает регион, один вопрос и две функции, **«Поделиться фото и историей»** и **«На карте»**. Опциональная полная статья в экране входа в редактор.
3. Карта получает слой **«Ищем историю»** через существующие «Слои и настройки карты». Выключен при обычном заходе. Переход из подборки включает и фокусирует слой через ID запроса. Бордовое сердце внутри пина и текстовая легенда. Сердце избранного остаётся отдельной кнопкой. Карточка на мобильном в существующей нижней панели. Координаты и навигация только для подтверждённой публичной точки.
4. Вторичные входы — `/become-author` и 2–3 близких по области или теме белорусских материала. Первые ссылки — из [статьи о Витебске](https://metravel.by/travels/vitebsk-za-1-den-chto-posmotret-i-kuda-skhodit) в Витебскую область и из [статьи о Бенице](https://metravel.by/travels/benitsa-zabroshennye-podzemelia-i-staryi-khram) в Гродненскую. Ссылка ведёт в региональную подборку. Действующий призыв «Были здесь?» остаётся связан с местом самой статьи. Использовать существующий `ContributionBanner` для тематической ссылки, без новой вкладки. При недостатке охвата пилота проверить компактную ссылку на главной.
5. Для превью брать проверенное документальное фото с лицензией и подписью, иначе явно подписанную иллюстрацию или нейтральное место под медиа. Авторская галерея начинается с собственных фотографий пользователя. Открытое приглашение не обещает, что редакция лично там не была. Копирайт про отсутствие первого рассказа зависит от проверенного статуса покрытия.

При реализации переиспользовать `ResponsiveContainer`, `Button`, `Chip`, `ImageCardMedia`, существующие focus/dialog helpers, Feather и дизайн-токены. Апповые строки и a11y labels в отдельном namespace, все пять локалей. Закрытая ссылка отображает публичный рассказ. Ошибка загрузки даёт повтор, пустой регион — сброс. Выделение сердца проверяется без цвета. У пина есть имя места, видимый фокус и область касания от 44 px.

### Данные и переход в каталог

- Канонический `Place` задаёт идентичность и проверенные координаты. Отдельный `PlaceRequest` хранит FK на `Place`, ключ редакционной категории, область, сортировку, локализуемый вопрос, дату проверки доступа, источник и права превью. Один открытый запрос на каноническую точку, архивная ссылка остаётся стабильной. Модератор управляет видимостью и приостановкой в существующем админ-контуре.
- Предлагаемый контракт `GET /api/places/requests/?country=by` возвращает ограниченный список активных записей. `GET /api/places/requests/<uuid>/` разрешает одну ссылку в `open`, `fulfilled` с публичным URL или `paused` без источника. Закрытые/private авторские материалы и контакты в публичный ответ не попадают. Ошибки API видимы. Обычный каталог и его фасеты не выполняют дополнительный запрос ради баннера. Слой загружается при включении.
- После публикации сервер связывает подходящий публичный `TravelAddress` с тем же `Place`. Квалифицируется совпадающая точка, у материала есть подтверждённое авторское фото и содержательный рассказ. Редакционное покрытие учитывает и подходящую публикацию из обычного потока, если она связана с тем же каноническим местом. Для метрики пилота атрибуция входа через запрос остаётся отдельной.
- Связь и публичная проекция согласованы с модерацией. Переход идемпотентен, история запросов и черновиков сохранена. При скрытии последнего публичного источника запрос приостанавливается до проверки куратором. Целевой сброс кэша распространяется на список запросов, карту и каталог.
- Точка короткой заметки сейчас формируется с пустыми категориями и без изображения. Для вклада сервер присваивает согласованную категорию, а миниатюра обычной карточки берётся из разрешённого медиа опубликованной заметки, без копирования и смены владения файлом. Предустановка должна приводить к фактическому появлению в правильной категории. [Формирование точки заметки](../../../components/travel/note/useTravelNoteFlow.ts)

Обычная карточка без источника была рассмотрена для ускорения запуска. Такой вариант смешал бы разные обещания пользователю и потребовал бы менять группировку, пагинацию, счётчики и действия «Читать».

### Привязка в редакторе

Использовать `/travel/new?mode=note&place_request_id=<uuid>` как предлагаемый внутренний URL. Новый тип безопасного интента, данные места читаются с сервера. Возврат из auth переносит только ID, режим и ограниченный код источника. Точка загружается в начальное состояние формы один раз. Переход не запускает upsert, а восстановленный черновик имеет приоритет над предзаполнением. Ключ восстановления включает аккаунт, запрос и режим до появления ID сохранённой статьи. Закрытие запроса после старта позволяет автору закончить ранее созданный черновик. [Маршрут редактора](../../../components/travel/upsert/UpsertTravelRoute.tsx) · [Восстановление](../../../hooks/useDraftRecovery.ts)

Существующий upsert принимает необязательный ID запроса и проверяет каноническую точку и права в том же сохранении. Для старых клиентов поля опциональны. История создания из статьи сохраняет свой контракт. Пустой редактор после перехода был рассмотрен, но повторный ручной выбор места теряет контекст и мешает сопоставить публикацию с запросом.

### Уведомление редакции

Уведомление использует действующий путь модерации #2716. После успешного перехода материала акции в очередь на проверку штатное письмо уходит на настроенный адрес редакции `metraveldev@gmail.com`. Оно содержит название материала, публичное имя автора, время отправки и ссылку в админку. Адрес хранится в серверном `SystemConfig.moderator_email`. При autosave, откате и повторе той же отправки письма нет. Приёмка включает адрес и доставку отдельно от факта записи в очередь.

### Авторские медали

- Общий статус отображается как **«Автор MeTravel»** по существующему достижению `first-travel`. Исторические записи, ID, XP и текущие ранги сохраняются. Перед запуском сверить существующих авторов и восполнить пропуски штатным пересчётом или точечным идемпотентным backfill с dry run. Критерий для восполнения — как минимум одна подтверждённая публичная заметка или статья. [Текущий seed](https://github.com/sergey-savran/metravel/blob/master/achievements/management/commands/seed_badges.py)
- **«Сердце карты»** — отдельный автоматический `belarus-map-contributor`, категория вклада в путешествия, 0 XP на старте. Условие — серверная связь автора с приглашением, установленная при сохранении черновика, совпадающий канонический объект и подходящий материал, доступный гостю. UTM, клик, черновик и отправка на модерацию сами по себе не подтверждают награду. Оба автора с ранее привязанными черновиками могут получить медаль после публикации. Повторная публикация или вклад в ещё одно место не создают вторую запись награды. Обычное снятие материала сохраняет историю полученной медали. Ошибочную выдачу или злоупотребление обрабатывает администратор.
- Публичные метки строятся по `earned_badges` существующего ответа достижений. Порядок — «Автор», затем «Сердце карты». В карточке автора и шапке публичного профиля — компактные медали с текстом. Тап открывает штатные подробности. Переиспользовать запрос и кэш достижений, разделить с верификацией и держать устойчивую геометрию строки имени. История медалей в галерее сохраняется. [Дизайн и продвижение](../../../docs/design/belarus-place-contributions.md)

### Пилот и измерение

Воронка по источнику `places | map | author_page | related_travel` и ID запроса, отдельно внешняя метка Instagram `utm_campaign=belarus_place_stories`: видимый показ → CTA → возврат после auth → старт → сохранённое фото → отправка → публичный материал. Для гостя auth-ступень считается только для гостевых входов. Публикации и первая публикация автора — серверная сверка, потому что `travel_publish` в текущем редакторе срабатывает после отправки на модерацию. [Событие заметки](../../../components/travel/note/useTravelNoteFlow.ts#L190)

Ориентир на 4 недели — ≥3 закрытых запроса через вклад пользователей и ≥2 авторов с первой публичной публикацией. Еженедельно смотреть абсолютные числа по всем ступеням и время модерации. При малом охвате пилот даёт слабый сигнал, отчёт показывает объём выборки. Порог — рабочее допущение, а не прогноз. Точечные кандидаты и метод отбора в [редакционной сверке](pilot-research.md).

## Risks / Trade-offs

- Дубликат из-за алиаса, широкой территории или неточной точки → сверка каталога, карты, ближайших точек и связанных текстов перед активацией.
- Чужое, вводящее в заблуждение или устаревшее изображение → права, подпись, дата съёмки и проверка авторства при модерации. Уязвимые места исключаются или показываются только у разрешённого входа.
- Потеря контекста или черновика при входе → типизированный интент и изоляция черновика. Обязательны пробы A → B, обновление страницы, отмена auth, закрытие запроса при открытом редакторе.
- На карте и в каталоге могут временно расходиться статусы → серверный источник покрытия и общая инвалидация. Из API нет перехода к приватной статье.
- Не выпускать SEO-страницы на каждый неподтверждённый объект. У содержательной подборки один canonical после проверки public route и SSR. Динамические выбранные карточки живут в состоянии страницы.

## Migration Plan

Сначала отдельная backend-задача `area=back` с добавочной моделью, read API и контрактом upsert. Затем web-страница и авторский путь. Затем слой карты, автоматическая выдача и видимые медали. Сквозная проверка охватывает реальную публикацию и появление обеих медалей. Продвижение стартует после этой проверки. Включение пилота после сверки редакционного списка и проверки mobile web, desktop web, клавиатуры и консоли. Нативный rollout планируется отдельно при изменении нативного слоя или route entry. Откат отключает подборку и слой, существующие черновики и публичные материалы сохраняются.
