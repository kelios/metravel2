## Context

Мотивация — [proposal.md](./proposal.md), наблюдаемое поведение —
[planned-trip-route-map-editing/spec.md](./specs/planned-trip-route-map-editing/spec.md).
Постоянный Task Contract — карточка борда #1781.

Черновик маршрута живёт в `components/trips/planning/RouteBuilder.tsx:246`
(`const [route, setRoute] = useState<RoutePoint[]>(trip.route)`). Список точек
уже умеет `onEdit`/`onDelete`/`onMove` (`RouteBuilder.tsx:968-971`), сохранение —
единственная явная кнопка (`handleSave`, `RouteBuilder.tsx:855`).

Карта — платформенная пара с общим контрактом пропов
(`components/trips/planning/tripPlanRouteMap.types.ts`):

- web: `TripPlanRouteMap.web.tsx`, react-leaflet 5, маркеры `<Marker>` с
  `<Popup>`; в popup уже есть кнопка «Редактировать» (`:600`);
- native: `TripPlanRouteMap.tsx` → `components/MapPage/Map` (`Map.ios` ←
  `Map.android`) → WebView с инлайновым Leaflet
  (`components/MapPage/Map/nativeMapHtml.ts`). Точки маршрута там рисуются как
  `L.circleMarker` (`nativeMapHtml.ts:558-569`) — без обработчиков вовсе.

Геометрия/статус/сводка принадлежат `useTripRouteDisplay`: как только
координатная сигнатура маршрута расходится с сохранённой
(`routeShapeMatchesSaved`, `RouteBuilder.tsx:313`), тройку отдаёт preview-движок
с debounce 500 мс, у которого в комментарии прямо назван сценарий
«перетаскивание точки» (`useTripRoutePreview.ts:33-38`). Инвариант
`TRIPS-PLAN-SAVED-ROUTE-TRUTH-001` выполняется этим же владельцем и новых
проверок не требует.

## Goals / Non-Goals

**Goals:**

- Оставить `RouteBuilder` единственным владельцем черновика: карта только
  сообщает намерение (`переместить`, `редактировать`, `удалить`).
- Держать web- и native-контракт пропов карты идентичным, как требует
  `tripPlanRouteMap.types.ts`.
- Не заводить второй путь мутации точки: перемещение с карты обязано попадать в
  тот же `setRoute`, что и правка из списка, включая открытый редактор.

**Non-Goals:**

- Не трогать `useRoutePointDrag.ts` (перетаскивание строк списка, #1303).
- Не менять маркеры на общей карте `/map`: интерактивность включается только для
  `mode === 'route'` планировщика.
- Не рефакторить `RouteBuilder` за пределами двух новых обработчиков.

## Decisions

### 1. Контракт карты расширяется двумя колбэками

В `tripPlanRouteMap.types.ts` — общий тип запроса перемещения:

```ts
export type RoutePointMove = { index: number; lat: number; lng: number };
```

Оба платформенных файла получают `onMovePoint?: (move: RoutePointMove) => void`
и `onDeletePoint?: (index: number) => void` рядом с существующими `onEditPoint`
и `onAddPointFromMap`. Альтернатива — отдавать наружу целиком новый
`RoutePoint[]` — отвергнута: карта не знает про `placeId`, тип точки и открытый
редактор, а второй владелец списка точек — прямой путь к рассинхрону.

### 2. Координата округляется до 6 знаков в момент перемещения

`RouteBuilder` уже нормализует ввод и сигнатуру через `formatCoordinateInput`
(6 знаков). Перетаскивание даёт сырой float, поэтому `handleMovePoint`
округляет его тем же шагом. Иначе список, поля редактора и сигнатура показывали
бы три разных значения одной точки.

Если редактор открыт на этой же точке, обработчик синхронно обновляет `editLat`/
`editLng`: без этого «Сохранить» в редакторе вернуло бы точку в дотасковую
позицию — прямое нарушение требования «одно состояние маршрута».

### 3. Web: `draggable` на существующем `<Marker>`, удаление — в popup

`draggable={!readonly}` плюс `eventHandlers.dragend`. Из ключа маркера убираются
координаты (`${point.id}-${index}`): react-leaflet обновляет `position` пропом,
а прежний координатный ключ на каждое перетаскивание пересоздавал маркер прямо
в момент завершения жеста.

Кнопка «Удалить» встаёт рядом с существующей «Редактировать» в том же popup —
новая поверхность не заводится.

### 4. Native: `L.marker` вместо `L.circleMarker` и два новых сообщения моста

Leaflet умеет перетаскивать только `L.Marker`; у `L.CircleMarker` нет
`Draggable`. Поэтому точки маршрута рисуются `L.marker` с `divIcon`, который
повторяет прежний вид (диаметр `2 * radius + weight`, `border-box`, заливка —
прежний `fillColor`, рамка — прежний `ROUTE_SURFACE`). Побочный плюс: маркер
переезжает из `overlayPane` (400) в `markerPane` (600) и больше не может быть
перекрыт линией.

Мост получает `ROUTE_POINT_MOVED { index, lat, lng }` и `ROUTE_POINT_TAP { index }`
в `nativeBridge.ts` — с той же проверкой конечности координат, что у `MAP_CLICK`.
Тап по маркеру обязан гасить всплытие (`L.DomEvent.stopPropagation`), иначе
существующий `MAP_CLICK` добавит поверх выбранной точки новую.

Интерактивность включается флагом payload `routePointsInteractive`: у гостя
маркеры остаются `interactive: false`, то есть ровно сегодняшнее поведение.

### 5. Native-действия — RN-карточка, а не HTML-popup внутри WebView

Тап по маркеру поднимает индекс в `TripPlanRouteMap.tsx`, который рисует
карточку действий поверх карты обычными RN-примитивами. Альтернатива — popup
внутри WebView — отвергнута: пришлось бы инжектить переводы и токены темы в
инлайновый HTML, а доступность и тесты остались бы вне RN-дерева.

### 6. Ручное перемещение выключает авто-подгонку кадра

Подгонка кадра ведётся по содержимому (`fitToken` на web,
`map.fitBounds` в route-ветке native). После перетаскивания геометрия
пересобирается — и кадр прыгнул бы ровно в момент, когда пользователь наводил
точность. Поэтому первое же перетаскивание маркера ставит защёлку
(`fitLockedRef` на web, `map.__metravelRouteFitLocked` в WebView), и дальше
подгонка только запоминает токен, но кадр не двигает. Центрирование по тапу в
списке (`focusPoint`) идёт мимо этой логики и продолжает работать.

Альтернатива «подавлять ровно одну подгонку» отвергнута: после дропа токен
меняется дважды (сразу — по точкам, затем через 500 мс — по новой геометрии), и
счётчик подавлений оказался бы гонкой.

## Risks / Trade-offs

- **Смена примитива маркера на native.** Внешний вид повторяется вручную, а не
  вычисляется Leaflet. Митигируется тем, что радиусы/цвета/веса берутся из тех
  же констант, что и прежний `circleMarker`.
- **Защёлка кадра живёт до размонтирования карты.** После первого
  перетаскивания карта больше не подгоняется под маршрут в этой сессии экрана.
  Это сознательный выбор в пользу ручной точности; возврат кадра доступен тапом
  по точке в списке.
- **Случайное перетаскивание вместо панорамирования на телефоне.** Маркер
  небольшой, жест начинается строго с него; отмена — обратное перетаскивание
  или правка координат в списке.

## Migration Plan

Изменение чисто клиентское, данные и контракт не мигрируют. Откат — возврат
diff: старая карта продолжает работать с тем же набором пропов, новые
необязательны.
