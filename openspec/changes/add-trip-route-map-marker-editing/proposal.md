## Why

Карта конструктора маршрута поездки сегодня односторонняя: точку можно только
добавить тапом по пустому месту. Позиция уже существующей точки правится
исключительно вводом широты/долготы в списке «Точки маршрута», удаление и
редактирование живут там же. Тестировщик на сборке 1.0.5 (8) (iPhone 16 Pro,
iOS 26.6.1, 05.09.2026) просит ровно обратного: тянуть маркеры по карте и
править/удалять точку с самой карты (#1781).

Пробел заметнее всего в map-first раскладке телефона: карта занимает экран
целиком, а единственный способ сдвинуть точку на сто метров — открыть список,
найти строку и вручную набрать координаты.

## What Changes

- Маркер точки маршрута становится перетаскиваемым у владельца поездки: после
  отпускания координаты точки обновляются в черновике маршрута, линия и сводка
  пересчитываются существующим preview-движком.
- Взаимодействие с маркером открывает действия «Редактировать» и «Удалить» —
  те же операции, что доступны в строке списка. На web это popup Leaflet, на
  native — RN-карточка действий поверх карты.
- Native-карта получает интерактивные маркеры точек маршрута: `L.circleMarker`
  (недоступен для перетаскивания в Leaflet) заменяется на `L.marker` с divIcon
  той же геометрии и цвета, плюс два новых сообщения WebView-моста.
- После ручного перемещения маркера карта перестаёт авто-подгонять кадр под
  маршрут: подгонка кадра существует для смены формы маршрута, а не для того,
  чтобы отменять точную ручную настройку вида.
- Гость (readonly) не получает ни перетаскивания, ни действий: маркеры остаются
  ровно такими же, как сейчас.

### Goal

Пользователь правит геометрию маршрута там, где он на неё смотрит — на карте, —
не переключаясь в список и не набирая координаты руками.

### Non-goals

- Переупорядочивание точек перетаскиванием в списке (уже сделано в #1303).
- Изменение алгоритма построения маршрута между точками.
- Новые поля контракта точки маршрута и новый endpoint частичного обновления.
- Перетаскивание маркеров на общей карте `/map` и на карте статьи.

### Dependencies and fallback policy

- Используются существующие `RouteBuilder` (владелец черновика), live preview
  `useTripRoutePreview` (debounce 500 мс уже описан как «перетаскивание точки»)
  и штатное сохранение `PUT /trips/planned/{id}/route/`.
- Частичного обновления координаты на бэкенде нет и не добавляется:
  перетаскивание меняет локальный черновик и попадает на сервер тем же явным
  сохранением, что и правка через список. Существующий индикатор несохранённых
  изменений (`hasUnsavedRouteChanges`) покрывает и этот путь.
- Mock-режим не добавляется.

## Capabilities

### New Capabilities

- `planned-trip-route-map-editing`: правка точки маршрута непосредственно с
  карты планировщика — перетаскивание маркера, редактирование и удаление точки.

### Modified Capabilities

Нет: в `openspec/specs/` нет существующего capability-контракта планировщика
маршрута, backend API не меняется.

## Impact

- **Platform impact — shared:** desktop web, mobile web, Android, iPhone.
  Реализации две (react-leaflet и WebView+Leaflet), наблюдаемое поведение одно.
- **Localization impact — all current locales:** новые статические ключи
  `plan.map.*` для RU/BE/UK/PL/EN, fallback RU.
- **User-visible:** перетаскиваемые маркеры, действия «Редактировать»/«Удалить»
  с карты, подсказка о жесте в шапке карты, отсутствие рывка кадра после
  ручного перемещения.
- **Code:** `components/trips/planning/*`, `components/MapPage/Map.ios.tsx`,
  `components/MapPage/Map/nativeMapHtml.ts`, `components/MapPage/Map/nativeBridge.ts`,
  i18n-ресурсы, focused-тесты планировщика.
- **API/data:** контракт `RoutePoint` и PUT маршрута не меняются.
- **Accessibility:** действия карты — обычные кнопки с доступным именем;
  клавиатурная и списочная правка остаются полноценной альтернативой жесту.
- **Performance:** новых сетевых запросов нет; пересчёт маршрута идёт через
  существующий debounce 500 мс, поэтому серия микро-перетаскиваний даёт один
  запрос маршрутизации.
- **Security:** новых внешних данных нет; сообщения WebView-моста проходят через
  существующий типизированный парсер с проверкой конечности чисел.
- **Analytics:** новых событий нет — у route-инструментов нет согласованного
  event-контракта.
- **SEO:** не применимо, экран авторизованный и не индексируется.
