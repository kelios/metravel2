## Purpose

Определяет, как email-подписка передаёт проверяемое доказательство явного согласия пользователя, сохраняя совместимость существующего API и локализованной формы.

## ADDED Requirements

### Requirement: Explicit consent payload
Система SHALL добавлять в запрос подписки `consent: true` и непустой стабильный `consent_version` только после явного действия пользователя на обязательном checkbox.

#### Scenario: Пользователь явно отметил согласие
- **WHEN** пользователь отмечает checkbox и отправляет валидный email
- **THEN** запрос подписки содержит `consent: true` и непустой `consent_version`

#### Scenario: Согласие отсутствует
- **WHEN** явное согласие отсутствует, ложно или не содержит непустой версии
- **THEN** запрос подписки не содержит ни `consent`, ни `consent_version`

#### Scenario: Отправка по Enter без согласия
- **WHEN** пользователь отправляет email по Enter, не отметив checkbox
- **THEN** запрос подписки не выполняется и интерфейс сообщает, что нужно отметить согласие

### Requirement: Wording-bound consent version
Система MUST использовать один централизованный version-id, который однозначно представляет показанный набор локализованных формулировок RU/BE/UK/PL/EN и меняется при изменении любой из них.

#### Scenario: Одна версия во всех путях фиксации
- **WHEN** явно согласившийся пользователь отправляет форму
- **THEN** subscription payload и запись action consent используют один и тот же version-id

#### Scenario: Изменение локализованной формулировки
- **WHEN** меняется формулировка email-согласия в любой текущей локали
- **THEN** regression control требует новый version-id для нового набора формулировок

### Requirement: Backward-compatible subscription responses
Система SHALL сохранять существующую обработку успешных ответов `created` и `exists`, а ошибки подписки не должны превращаться в успешное состояние или analytics-success event.

#### Scenario: Новая подписка создана
- **WHEN** сервер отвечает `201` со статусом `created`
- **THEN** frontend возвращает `created` и отправляет существующее success-событие с этим статусом

#### Scenario: Подписка уже существует
- **WHEN** сервер отвечает `200` со статусом `exists`
- **THEN** frontend возвращает `exists` и сохраняет существующее already-subscribed состояние

#### Scenario: Сервер отклонил запрос
- **WHEN** сервер возвращает ошибку
- **THEN** frontend показывает существующую локализованную ошибку и не отправляет success-событие
