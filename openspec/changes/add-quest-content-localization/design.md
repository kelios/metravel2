## Context

Мотивация — в `proposal.md`. Факты, от которых зависит решение (замер и чтение исходников 04.10.2026):

- **Бэкенд** (`../metravel-backend`, только чтение). Шаги — отдельные строки, не JSON:
  `Quest.title`, `QuestStep.{title,location,story,task,hint,answer_pattern,poi_info}`,
  `QuestFinale.text`, `QuestCity.name` (`quests/models.py:88-326`). Язык запроса не читается:
  нет `LocaleMiddleware`, `?lang=`, `Accept-Language`. Единственный задел —
  `normalize_quest_result_locale` и набор `{ru,be,uk,pl,en}` для карточки результата
  (`achievements/share_cards.py:24,467`), плюс поля `QuestResultShareCard.locale` и
  `QuestAnswerAttempt.locale`.
- **Кэш бэка.** Списки кэшируются по полному URL (`quests/views.py:239-247`), `Vary` покрывает
  только `Authorization`/`Cookie`; `near-location` отдаётся с публичным `s-maxage=3600`.
- **Проверка ответа — на клиенте.** Сервер записывает вердикт клиента, не перепроверяя
  (`quests/services/answer_telemetry.py:263`). Вход — `utils/questAnswerEvaluation.ts:116`,
  нормализация `utils/questAdapters.ts:225-235` заточена под RU/BE (ё→е, і→и, «ад»→«от»),
  морфология `utils/questAnswerMorphology.ts:29-69` — только русские/белорусские окончания.
- **Клиент.** Локаль — только состояние клиента (`i18n/config.ts`, `urlPrefix: ''` у всех пяти),
  в URL её нет. Общий API-клиент язык не шлёт (`api/client.ts:119-121`). Ключи запросов квестов
  (`api/queryKeys.ts:87-108`) и офлайн-копии `quest-bundle:{questId}`, `quest-list:v1`
  (`api/questBundleCache.ts:10-21`) локали не содержат.
- **Адреса.** Алиас города выводится из длины русского `city_name` (`utils/questCityAlias.js`,
  #1931) — локализованное имя сломало бы URL.
- **Значки.** Счёт «квестов в городе» фильтрует по тексту `QuestCity.name`
  (`achievements/services.py:1143-1151`) — каноническое имя обязано остаться неизменным.
- **Объём.** 2,72 млн знаков источника × 4 локали ≈ 10,9 млн знаков перевода; типы ответов:
  `exact_any` 1 163, `exact` 72, `any`/`any_text`/`any_number` 843, `range` 108.

## Goals / Non-Goals

**Goals:**

- Один контракт локали контента для бэка, клиента и контент-конвейера.
- Старые сборки приложения (без `lang`) продолжают работать без изменений.
- Новая локаль — без миграций, без изменения формы API и без правки визарда.
- Ни один ответ, принимаемый сегодня, не перестаёт приниматься.

**Non-Goals:**

- Языковые URL, `hreflang`, локализованный SSG — отдельный change (SEO routing contract).
- Отдельный переключатель «язык квестов», независимый от языка интерфейса.
- Серверная проверка ответов.
- Перерисовка финальных видео с вшитой русской надписью.

## Decisions

### D1. Хранение: таблицы переводов с ключом «сущность + локаль»

`QuestTranslation(quest, locale, title, status, updated_at)`,
`QuestStepTranslation(step, locale, title, location, story, task, hint, answer_variants[], poi_opening_hours, poi_ticket_price, source_hash, origin)`,
`QuestFinaleTranslation(finale, locale, text, source_hash)`,
`QuestCityTranslation(city, locale, name)`; уникальность по паре, `locale` — строка, не enum в схеме.
Базовые строки (`Quest`, `QuestStep`, …) остаются русским источником и не меняются.

- **Почему:** локаль — данные, а не схема: шестой язык не требует миграции. Строка на шаг даёт
  правку одного шага в админке, каскад при удалении шага и хеш источника на шаг.
- **Отвергнуто — колонки `title_en`, `story_pl` (django-modeltranslation):** 12 полей × локаль =
  миграция на каждый язык; так уже сделан `Country.title_ru/title_en` и именно это не расширяется.
- **Отвергнуто — один JSON-документ перевода на квест:** атомарность достигается транзакцией
  записи, а JSON лишает админку и запросы построчного доступа.
- **Отвергнуто — JSON-поле `translations` на базовой строке:** правка русского текста и перевода
  конкурируют за одну строку, статус публикации негде хранить.

### D2. Единица публикации — «квест + локаль»

`QuestTranslation.status ∈ {draft, published}`. Публикация разрешена, только когда переведены
название, финал (если есть) и каждый шаг источника, включая вступление. Отдача — «всё или
ничего»: нет опубликованного полного перевода → квест целиком на русском.

- **Почему:** смесь языков в одном прохождении хуже, чем честный русский.
- **Устаревание:** `source_hash` шага = хеш русских `title|location|story|task|hint|answer_pattern`
  на момент перевода. Не совпал — шаг «stale»: остаётся в выдаче, попадает в отчёт статуса.
  Новый шаг без перевода — квест возвращается на русский (перевод перестал быть полным).
- **Отвергнуто — снимать перевод при любой правке источника:** опечатка в русском тексте
  выключала бы четыре языка до следующего прогона конвейера.

### D3. Язык запроса — параметр `?lang=`, не заголовок

Все read-эндпоинты квестов принимают `lang`. Разбор кода — существующим
`normalize_quest_result_locale`, вынесенным в общий модуль; набор локалей — одна настройка
`QUEST_CONTENT_LOCALES`, из неё же берётся набор карточки результата.

- **Почему:** кэш списков уже ключуется полным URL, а `near-location` кэшируется публично —
  параметр безопасен без правки `Vary` и CDN. Отсутствие параметра = прежний ответ, значит
  выпущенные сборки приложений не затронуты.
- **Отвергнуто — `Accept-Language`:** требует `Vary` на каждом кэшируемом ответе; браузерный
  заголовок не равен выбранному в приложении языку.

Форма ответа (добавляется, ничего не удаляется):

```jsonc
// деталь: GET /api/quests/by-quest-id/{quest_id}/?lang=pl
{
  "content_locale": "pl",              // на каком языке реально отдан контент
  "available_locales": ["ru", "pl"],   // ru — всегда
  "source_locale": "ru",
  "title": "…",                        // на content_locale
  "city": { "name": "Kraków", "name_canonical": "Краков", "country_code": "pl" },
  "steps": [{ "step_id": "…", "title": "…", "location": "…", "story": "…", "task": "…", "hint": "…",
              "answer_pattern": { "type": "exact_any", "value": "[…варианты pl…, …варианты ru…]" },
              "poi_info": { "opening_hours": "…" } }],
  "finale": { "text": "…" }
}
// каталог: в каждом элементе — content_locale, available_locales, city_name, city_name_canonical
```

`answer_pattern.value` для `exact`/`exact_any` сервер отдаёт уже объединённым (варианты локали +
варианты источника, без дублей) — форма поля не меняется, клиент не собирает объединение сам.

### D4. Запись переводов — один атомарный admin-запрос на «квест + локаль»

```
PUT    /api/quests/{id}/translations/{locale}/   — заменить перевод целиком
GET    /api/quests/{id}/translations/{locale}/   — прочитать (включая черновик)
DELETE /api/quests/{id}/translations/{locale}/   — снять (откат)
GET    /api/quests/translations/status/?locale=  — по каждому квесту: missing|draft|published,
                                                   stale_step_ids[], missing_step_ids[]
PUT    /api/quest-cities/{id}/translations/{locale}/ — { "name": "…" }
```

Тело `PUT`: `{ title, status, finale: {text}, steps: [{ step_id, title, location, story, task, hint, answer_variants[], poi_opening_hours?, poi_ticket_price?, origin: "machine"|"human" }] }`.
`source_hash` сервер считает сам в момент записи. Отказ `400` с перечнем — при неизвестном
`step_id`, пустом обязательном поле, публикации неполного перевода, локали вне набора.

- **Почему один запрос:** конвейер переводит квест целиком (сквозные имена, тон); частичная
  запись по шагам оставляла бы квест в промежуточном состоянии при обрыве сети.
- **Отвергнуто — писать переводы существующими `quest-steps/` PATCH:** это перегружает
  контракт источника и не даёт атомарности.

### D5. Клиент: локаль контента = локаль интерфейса, один резолвер

`getQuestContentLocale()` в data-слое квестов возвращает `getActiveLocale()`; все чтения квестов
добавляют `lang`, все ключи квестов в `api/queryKeys.ts` получают локаль, офлайн-копии —
`quest-bundle:{questId}:{locale}` и `quest-list:v2:{locale}`. Адаптер прокидывает в модель
`contentLocale` и `availableLocales`.

- **Офлайн:** читается копия на запрошенной локали; нет её — любая сохранённая копия квеста
  (лучше пройти на другом языке, чем потерять квест без сети). Старые ключи без локали читаются
  как `ru` и не мигрируются.
- **Пометка fallback:** на детали квеста — строка «квест пока доступен на …» через `@/i18n`,
  когда `contentLocale !== локаль интерфейса`. В каталоге — без бейджей на первом этапе:
  пока переводов мало, бейдж стоял бы на каждой карточке.
- **Web SSR/гидрация:** статический HTML остаётся русским; после гидрации запрос с `lang`
  подменяет контент — тот же механизм, которым сегодня подменяются строки интерфейса.
- **Алиас города:** `questCityAlias` и SSG-скрипты считают по `city_name_canonical`
  (fallback — `city_name` для ответа старого бэка).
- **Отвергнуто — отдельная настройка «язык квестов»:** второе языковое состояние в настройках и
  хранилище; вернуться можно позже, контракт API этого не запрещает.

### D6. Проверка ответа: реестр нормализаторов по локали контента

`normalize(input, locale)` выбирается из реестра: `ru`, `be` — текущие правила; `uk`, `pl`, `en` —
свои (диакритика, артикли); остальные — универсальный (NFKD без диакритики, регистр, пунктуация,
пробелы). Ответ принят, если совпал под нормализатором локали контента **или** под нормализатором
источника (`ru`). Морфология остаётся только для `ru`/`be`; для прочих локалей падежи и формы
покрываются вариантами из перевода.

- **Почему «или»:** объединённый перечень содержит русские варианты; русские правила (ё→е)
  под польским нормализатором не применились бы, и часть сегодняшних ответов перестала бы
  приниматься.
- **Засчитанный шаг не перепроверяется:** вердикт выносится один раз при вводе
  (`components/quests/questWizardStepCard.tsx:428`) и хранится в прохождении; смена языка его
  не трогает — закрепляется тестом.
- **Телеметрия:** `QuestAnswerAttempt.locale` заполняется локалью контента, а не интерфейса
  (сейчас `utils/questAnswerTelemetry.ts:224` шлёт `getActiveLocale()`): статистика отказов
  должна разделяться по языку, на котором игрок читал задание.

### D7. Конвейер перевода — скрипт в `scripts/`, источник правды — БД

`quest-translate`: (1) читает русский бандл и статус переводов из API и готовит задание; (2) агент
`quest-translator` переводит квест целиком по стайл-гайду и глоссарию (топонимы и надписи «как на табличке» не переводятся, тон сохраняется);
(3) для `exact`/`exact_any` строит варианты ответа на языке локали по правилу «что игрок прочтёт
на месте — остаётся как есть, что игрок называет сам — переводится»; (4) структурные проверки:
тот же набор `step_id`, непустые поля, нет кириллицы в `pl`/`en`, числа и URL источника сохранены,
отношение длины в допуске; (5) смысловая проверка «по переведённому заданию ответ достижим из
вариантов»; (6) пишет черновик `PUT …/translations/{locale}/`, публикация — отдельным флагом.
Повторный запуск переводит только `missing`/`stale` шаги и не трогает `origin: human`.

- **Почему БД, а не файлы в git:** ~16 МБ переводов в репозитории, а правки носителя языка в
  админке всё равно делали бы файл неактуальным. Сохранность — штатный бэкап базы.
- **Движок перевода — агентские сессии** (решение владельца 04.10.2026): скрипт сам текст не
  переводит, а готовит задание, проверяет результат и заливает; переводит агент `quest-translator`.
  Внешних платных API и ключей нет.
- **Темп — 10 квестов в день на четыре локали** ежедневной запланированной задачей
  `quest-translate-daily`; около 22 дней на 215 квестов. Готовый перевод заливается сразу, а не в
  конце пачки: лимит сессии обрывает всех субагентов разом, и пачка должна переживать обрыв.
- **Отвергнуто — волны по языкам** (сначала весь английский, потом польский): квест, попавший в
  пачку, сразу доступен на всех языках, а имена и термины согласуются между переводами одного квеста.

### D8. Смежные поверхности без собственной логики перевода

Печать, шаринг, напоминания и поиск по каталогу берут текст из уже локализованного бандла/списка.
Карточка результата на бэке снимает `quest_title`/`city_name` на локали карточки. Линтеры
контента (`scan-quest-mixed-script-text.js`, `scan-quest-answer-reachability.js`) остаются
проверкой русского источника; для переводов — проверки конвейера (D7).

## Risks / Trade-offs

- [Машинный перевод искажает загадку или ответ] → смысловая проверка в конвейере, пилот на 5
  квестах с вычиткой владельцем, публикация отдельным флагом, союз с русскими вариантами.
- [Устаревший перевод расходится с исправленным русским текстом] → отчёт статуса и повторный
  прогон конвейера как шаг skill `metravel-quest` и работы `quest-editor`.
- [Утечка языка через кэш] → локаль в каждом ключе запроса и офлайн-копии; тест на переключение.
- [Вспышка русского текста на web до гидрации] → принято на первом этапе; устраняется SEO-change
  с языковыми страницами.
- [Бэкенд задержится] → клиентская часть безопасна раньше бэка: старый бэк игнорирует `lang`,
  клиент читает отсутствие `content_locale` как `ru`.
- [Финальное видео с русской надписью в переведённом квесте] → вынесено отдельной задачей
  (надпись — из пикселей в интерфейс).

## Migration Plan

1. Бэк: таблицы и `?lang=` (без переводов поведение не меняется) → выкат.
2. Фронт: `lang`, ключи, офлайн, пометка, нормализаторы → выкат; при пустых переводах
   пользователь видит прежний русский контент плюс пометку на не-русском интерфейсе.
3. Конвейер, пилот 5 квестов × 4 локали в черновике → вычитка → публикация.
4. Массовый перевод: ежедневно 10 квестов сразу на четыре локали (#2202).

Откат: `DELETE` перевода или смена `status` на `draft` возвращает квест на русский без выката;
клиентский откат — обычный rollback фронта (старый клиент не шлёт `lang`).
