## 1. Транспорт запроса

- [ ] 1.1 На native явно отправлять запросы без cookie (`credentials: 'omit'`), сохранив текущее поведение web (`usesWebCookieAuth()` не меняется)
- [ ] 1.2 Проверить весь пишущий путь нативного клиента на отсутствие вызовов, фактически опиравшихся на cookie-сессию

## 2. Честное состояние сессии

- [ ] 2.1 Перед небезопасным методом проверять наличие токена и при его отсутствии не отправлять запрос анонимно
- [ ] 2.2 Инвалидировать сессию существующим действием стора авторизации и показывать требование войти заново
- [ ] 2.3 Трактовать ответ 401 на запрос с токеном так же: сессия завершена, показываем то же требование
- [ ] 2.4 Не применять требование входа к публичным чтениям (`skipAuth`)

## 3. Чтение защищённого хранилища

- [ ] 3.1 Различать в чтении секрета «значения нет» и «хранилище не ответило»
- [ ] 3.2 На сбое хранилища делать повторное чтение, а при повторном сбое — требовать вход, не отправляя анонимную запись

## 4. Локализация

- [ ] 4.1 Завести ключ текста «сессия истекла, войдите заново» во всех продуктовых локалях (RU/BE/UK/PL/EN)

## 5. Тесты

- [ ] 5.1 Тест: нативный запрос уходит без cookie, web-запрос — как раньше
- [ ] 5.2 Тест: запись без токена не уходит анонимно и приводит к инвалидации сессии
- [ ] 5.3 Тест: ответ 401 на запись с токеном приводит к тому же состоянию
- [ ] 5.4 Тест: сбой чтения хранилища отличается от отсутствия значения и не делает пользователя гостем молча
- [ ] 5.5 Тест: публичное чтение без токена работает как раньше
