## Context

Мотивация — `proposal.md`, поведение — `specs/quest-catalog-sidebar/spec.md`.

Текущее устройство, которое определяет подход:

- Сайдбар `screens/tabs/QuestsSidebar.tsx` смонтирован дважды из `screens/tabs/QuestsScreen.tsx`:
  постоянной колонкой на desktop и внутри drawer на мобильной ширине — на web и в Android/iOS.
- Все фильтры каталога живут в одном слоте `selectedCityId`: id города либо виртуальный id
  (`__all__`, `__kids__`, `__completed__` …) из `utils/questCatalogSelection.ts`. Слот сохраняется в
  `AsyncStorage` (`STORAGE_SELECTED_CITY`), при восстановлении проходит
  `resolveStoredQuestCatalogSelection`, а после загрузки каталога — эффект валидности в
  `QuestsScreen.tsx`, который сбрасывает неизвестный id на «Все квесты».
- Сетка берёт квесты по слоту в `QuestsScreen.tsx` (`cityQuests[id]` для города); текстовый поиск
  перекрывает слот. Видимый заголовок — `QuestsContentPanel` по `selectedCityName`
  (`locationTitle`: «Квесты: {{value1}}»), заголовок документа — `titleText`.
- Группы стран строит `citiesByCountry` в `QuestsScreen.tsx` из каталога городов по
  `city.countryCode`; число квестов страны сайдбар считает суммой `cityQuestCountById` её городов.
  Там же для web считается `countryLandingHref` через `buildQuestCountryLandingGroups` по всему
  каталогу — только ради ссылки на лендинг.
- Раскрытие — `collapsedCountryCodes` в состоянии экрана, по умолчанию развёрнуто
  (`prev[code] ?? false`), не сохраняется.
- `accessibilityState={{ expanded }}` в react-native-web атрибутом не становится: на проде у тумблера
  страны `aria-expanded` отсутствует (замер 21.09.2026).
- Ритм (замер прода, 1280 px): строка фильтра 50 px при шаге 54 px; свёрнутая страна — заголовок
  54 px + `marginTop` 12 + `marginBottom` 4 + `paddingVertical` секции 8 × 2 = шаг 86 px.

## Goals / Non-Goals

**Goals:**

- Один механизм выбора для города и страны — тот же слот, те же сохранение, валидность, сброс,
  заголовок и закрытие drawer.
- Число на пункте «Все квесты страны» и число квестов в сетке считаются из одного источника.
- Ноль платформенных веток в поведении строки страны.

**Non-Goals:**

- Переделка drawer, чипов и заголовка каталога сверх подстановки имени страны.
- Сохранение состояния раскрытия между визитами — раскрытие выводится из выбора.
- Изменение лендинга страны, его SSG и генератора статических страниц.

## Decisions

### D1. Страна — ещё одно значение общего слота выбора

Выбор страны кодируется в том же `selectedCityId` значением `__country__:<ISO alpha-2>` (например
`__country__:BY`). Префикс и два помощника — собрать id из кода и достать код из id — живут в
`utils/questCatalogSelection.ts` рядом с остальными виртуальными id, без зависимостей.

Альтернатива — отдельное состояние `selectedCountryCode` рядом со слотом — отвергнута: два слота
могут разойтись (город одной страны и выбранная другая), и каждому потребителю слота (сетка,
заголовки, чип сброса, сохранение, передача среза из профиля #1794) пришлось бы учить второе поле.
Формат `__…__` совпадает со стилем виртуальных id и не пересекается с id городов.

### D2. Квесты страны — объединение квестов её городов из каталога городов

Сетка при выбранной стране берёт `cityQuests[cityId]` всех городов группы страны из того же
`citiesByCountry`, по которому сайдбар считает счётчик, с дедупликацией по ключу квеста. Так число
на пункте и число карточек совпадают по построению.

Альтернатива — фильтр всего каталога по полю страны у квеста — отвергнута: группы сайдбара строятся
по стране ГОРОДА через слияние алиасов каталога городов, и квест, у которого город и собственное
поле страны разошлись, дал бы расхождение счётчика и сетки.

Группа `OTHER` (города без кода страны, пустое имя) пункта «Все квесты страны» не получает.

### D3. Имя страны в тех же заголовках

`selectedCityName` для странового id возвращает имя страны (`getQuestCountryName`), поэтому видимый
заголовок «Квесты: <страна>» и заголовок документа приходят существующими ключами без изменений.
Описание каталога для города сформулировано про город («…в городе {{value1}}»), поэтому для страны
добавляется свой ключ описания. Чип «Все квесты» уже показывается при любом выборе, кроме `__all__`
(`filtersActive`), — стране ничего добавлять не нужно.

### D4. Строка страны — одна кнопка-тумблер с ARIA-атрибутом

Заголовок страны — один `Pressable` с `accessibilityRole="button"` и явным `aria-expanded` (его
react-native-web выводит атрибутом; `accessibilityState.expanded` оставляется для native). Ветка со
ссылкой `Link` на `/quests/country/<alias>`, поле `countryLandingHref` и вычисление
`buildQuestCountryLandingGroups` в каталоге удаляются.

Пункт «Все квесты страны» рендерится первым в раскрытой группе при двух городах и больше, в той же
визуальной форме, что строка города (иконка `globe` вместо `map-pin`, счётчик справа), со
`accessibilityState.selected`/`aria-selected`. Подпись для скринридера — существующий ключ
`screens.tabs.QuestsSidebar.countryLandingA11y` («Все квесты страны {{value1}} — {{value2}}»): он уже
переведён на пять языков и по смыслу описывает именно этот пункт.

Альтернатива — «разделённая кнопка» (имя выбирает страну, шеврон сворачивает) — отвергнута: две зоны
на одной строке и есть исходная путаница; паттерн NN/g для аккордеон-навигации — родитель только
раскрывает, обзор родителя идёт первым дочерним пунктом.

### D5. Свёрнуто по умолчанию, раскрыта страна активного выбора

Неизвестная группа в `collapsedCountryCodes` получает `true` (свёрнута). Из слота выводится
`activeCountryCode`: код группы выбранного города либо код из странового id. Эффект по изменению
`activeCountryCode` раскрывает эту группу один раз — пользователь может свернуть её снова, и
повторного раскрытия не будет, пока выбор не сменится. Восстановленный из хранилища выбор проходит
тот же путь, поэтому его страна раскрыта при входе.

Альтернатива — сохранять набор раскрытых стран — отвергнута: лишнее состояние в хранилище, а
главный сценарий «вернуться туда, где был» покрывается раскрытием страны выбора.

### D6. Маркер активного выбора на свёрнутой стране

Если группа свёрнута и `activeCountryCode` совпадает с её кодом, имя страны окрашивается фирменным
цветом и перед счётчиком появляется точка 8 px (`colors.brand`). Подпись тумблера для скринридера
дополняется «выбрано». Токены — из `useThemedColors`, без хардкода.

### D7. Drawer закрывает только выбор

Пункт «Все квесты страны» вызывает тот же `onSelectCity(id)`, что и город; `handleSelectCity` уже
закрывает drawer на мобильной ширине. Тумблер страны `onSelectCity` не вызывает, поэтому drawer
остаётся открытым. Отдельный `onCloseDrawer`, висевший на ссылке страны, уходит вместе с ней.

### D8. Ритм строки страны — по строке фильтра

У секции страны снимается `paddingVertical`, у заголовка — `marginTop`. Вся строка страны теперь
одна зона нажатия, поэтому частям строки свои `minHeight` не нужны: заголовок держит
`touchTarget.minHeight` (44 px) и `marginBottom` 4 px — шаг свёрнутых стран 48 px против 54 px у
строк фильтров. Список стран отделяется от строк фильтров над ним отступом обёртки `countryList`
(`spacing.sm`): прежде это делали вертикальные отступы каждой страны. Мёртвые стили того же блока
(`countryToolsSection`, `collapseAllBtn`, `collapseAllBtnText`, `cityListLabel` — не используются
нигде) удаляются.

### D9. Валидность и восстановление странового выбора

`resolveStoredQuestCatalogSelection` пропускает страновой id как есть. Эффект валидности в
`QuestsScreen.tsx` считает страновой id валидным, если в `citiesByCountry` есть группа с этим кодом и
хотя бы одним квестом; иначе — сброс на «Все квесты», как для исчезнувшего города. Передача среза из
профиля (#1794) страновые id не создаёт и не затрагивается.

### D10. Страновая логика — отдельный хук, а не рост экрана

`QuestsScreen.tsx` уже 845 строк, и страж `guard:file-complexity:changed` не даёт растить файлы
больше 800 строк. Вывод `activeCountryCode`, квесты выбранной страны, её имя и проверка валидности
выносятся в `screens/tabs/useQuestCountrySelection.ts`; экран только подключает хук и передаёт
результат в существующие места. Хук получает `citiesByCountry`, `cityQuests` и слот выбора — новых
источников данных у него нет.

## Risks / Trade-offs

- [Старый бандл прочитает сохранённый `__country__:BY` после отката] → эффект валидности старого
  кода не найдёт такого города и сбросит выбор на «Все квесты» — безопасный откат без миграции.
- [Тесты #1989 закрепляют ссылку на лендинг] → `__tests__/screens/QuestsSidebar.countryLink.test.tsx`
  и `__tests__/screens/QuestsScreen.countryLink.test.tsx` переписываются под новый контракт
  (тумблер, отсутствие ссылки, пункт страны); удаление без замены запрещено.
- [Свёрнутый список прячет города от того, кто их просматривает] → кнопка «Развернуть все»
  остаётся, страна активного выбора раскрыта; после выката сверить с владельцем.
- [Карта при выбранной стране] → режим карты берёт те же `visibleQuests`, что и сетка; проверить
  масштаб по квестам страны в testing.
- [Новые ключи i18n не видны живому Metro] → после добавления ключей перезапуск Metro (известная
  ловушка проекта); `npm run test:i18n` до review.
- [Страна теряет второй город] → пункт «Все квесты страны» исчезает, но уже выбранная страна
  остаётся валидной, пока в ней есть квесты: выбор не ломается от изменения каталога.

## Migration Plan

Миграции данных нет: страновой id появляется только после выбора в новом интерфейсе. Выкат — обычный
web-деплой по пайплайну задачи; native получает изменение со следующей сборкой приложения. Откат —
revert коммита: сохранённый страновой id старый код сбрасывает на «Все квесты» (см. риски).
