## Purpose

Сохранять настоящую историю чтения разных публичных статей в одном документе, чтобы пользователь мог предсказуемо вернуться и продолжить чтение.

## ADDED Requirements

### Requirement: Каждая новая статья сохраняет предыдущую запись

Публичная web-навигация SHALL сохранять отдельную browser history entry для обычного перехода на другую статью, сохраняя текущий документ и не изменяя серверные данные.

#### Scenario: Две статьи
- **WHEN** читатель нажимает настоящую карточку B в статье A
- **THEN** история содержит A и B, один browser Back восстанавливает A, один Forward восстанавливает B, без второго traversal, нового документа и записей API
- **AND** title, canonical и main/OG/Twitter description соответствуют показанной статье

#### Scenario: Три статьи
- **WHEN** читатель последовательно открывает A→B→C настоящими карточками
- **THEN** два Back возвращают B и A, два Forward возвращают B и C, каждый раз за одно действие

#### Scenario: Возврат через интерфейс
- **WHEN** читатель открывает B из A и нажимает доступную кнопку возврата в приложении
- **THEN** показана A, а существующая Forward history сохраняется

### Requirement: Browser traversal сохраняет полные снимки навигатора

История web-навигации SHALL сохранять полное состояние каждой доступной записи при browser Back/Forward и несостоявшемся программном traversal. Восстановление сохранённой записи MUST сохранять возможность app Back; последующие переходы или замены текущей страницы MUST сохранять доступные предыдущие записи.

#### Scenario: App Back после полного browser Back/Forward цикла
- **WHEN** читатель открывает A→B, выполняет Back A и Forward B, открывает C, затем выполняет Back B, Back A, Forward B и Forward C
- **THEN** сохранены полные state snapshots и исходные browser entry IDs A/B/C, доступна app Back, а одно её нажатие возвращает B с одним browser traversal без fallback на главную
- **AND** последующий browser Forward восстанавливает C

#### Scenario: Новая статья после внешнего Back
- **WHEN** после A→B→C→D читатель возвращается browser Back к C и открывает E
- **THEN** история сохраняет A/B/C, удаляет только недоступную forward запись D и добавляет E

#### Scenario: Go не вызвал popstate
- **WHEN** программный go завершился по timeout, а браузер остался на исходной записи
- **THEN** последующий push сохраняет исходную текущую запись и не использует предполагаемую позицию несостоявшегося traversal

### Requirement: Соседние сценарии сохраняют обычную семантику ссылок

Система SHALL сохранять прямой вход без фиктивного предшественника, повтор текущего назначения без бесконечных дублей, каталог→деталь и переход через другой раздел. Клики с модификатором и средней кнопкой MUST открывать отдельную вкладку, сохраняя исходную историю.

#### Scenario: Прямой вход и повтор текущей цели
- **WHEN** читатель напрямую открывает статью и повторяет переход на ту же текущую цель
- **THEN** приложение не добавляет искусственную предыдущую статью или дубли текущей записи

#### Scenario: Каталог и другой раздел
- **WHEN** читатель открывает статью из каталога либо переходит из статьи в поиск
- **THEN** один Back и один Forward восстанавливают соответствующие предыдущий и следующий маршруты в том же документе

#### Scenario: Новая вкладка
- **WHEN** читатель нажимает карточку другой статьи с Ctrl/Cmd либо средней кнопкой мыши
- **THEN** другая статья открывается в отдельной вкладке, а адрес и история исходной вкладки сохраняются
