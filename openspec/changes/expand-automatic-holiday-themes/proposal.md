## Why

Владелец просит автоматическое оформление на праздничные периоды, более выразительный визуал и дополнительные праздники. Авто уже является дефолтом, но `hooks/useTheme.ts:193–200` обновляет дату только при `visibilitychange`: непрерывно открытая вкладка не переключается в полночь. Сейчас доступны только два фиксированных периода.

## What Changes

- Сохранить автоматический выбор по местной календарной дате, добавить переключение в полночь и пересчёт после возврата/восстановления вкладки.
- Сохранить Хэллоуин 15.10–01.11 и Рождество/Новый год 01.12–14.01, обе границы включительно.
- Предложенный набор: весна/8 Марта 01.03–10.03; Пасха — по западной и православной датам ежегодно, каждое окно от семи дней до праздника до двух дней после; золотая осень 15.09–14.10. Весна и осень обозначаются как сезонное оформление, а не государственные праздники.
- Сделать спокойное оформление богаче: многослойное свечение, небольшие тематические детали в шапке, сезонные акценты птицы/словесного знака. Центральная область чтения свободна, движения и мерцания нет.
- Показать в автоматическом режиме текущий сезон и период его действия; вне окна — ближайший период. Сохранить ручной выбор и полное отключение.
- Поддержать все варианты в меню гостя, аккаунта, мобильной шапке и настройках на пяти языках.

## Capabilities

### New Capabilities

- `holiday-calendar`: календарные периоды, авто/ручной/выключено, подвижные праздники, жизненный цикл вкладки и первый кадр.
- `holiday-appearance`: спокойный сезонный визуал и доступные локализованные контролы.

### Modified Capabilities

Нет существующей living spec сезонных тем; действующее поведение сохраняется в новых требованиях.

## Impact

**Task type и ожидаемый результат:** L; planning-only предложение расширения существующей системы. Apply начинается отдельным сообщением владельца.

**Task-owned paths сейчас:** только `openspec/changes/expand-automatic-holiday-themes/**`.

**Будущие affected paths:** `constants/seasonalThemes.ts`, `utils/seasonalThemeBootScript.ts`, `hooks/useTheme.ts`, `app/global.css`, существующие сезонные контролы/локали/тесты и `docs/features/seasonal-theme.md`; точный список в design.

**Platform impact:** desktop web | mobile web. Общие модули остаются безопасными для Android/iOS, визуал и таймер ограничены web; device/runtime/store scope отсутствует.

**Localization impact:** all current locales — RU/BE/UK/PL/EN, fallback RU.

**Risk/operation gates:** ошибка даты, DST, boot/runtime расхождение, пересечения окон, переполнение меню; независимое ревью и code gate до browser testing. Эта proposal не выполняет публикацию или внешние мутации.

**Validation:** календарные границы/високосные годы/DST/полночь, boot/runtime parity, off/manual, i18n/static/guard checks; после ревью desktop/mobile screenshots и console evidence.

**Dependencies:** API/backend отсутствуют; даты вычисляются локально. Дополнительный набор подтверждён владельцем: «Весна, Пасха и осенний сезон» (11.10.2026). Окна и дизайн ниже представлены на принятие перед apply.

**Fallback/mock policy:** неизвестная сохранённая настройка означает auto; недоступное хранилище сохраняет календарный авто-режим без записи. Никаких сетевых календарей, mock-only production fallback или определения религии по языку/IP.

**Existing behavior to preserve:** ключ `seasonal-theme`, значения auto/off/halloween/christmas, ручной приоритет над календарём, независимый светлый/тёмный режим, отсутствие гидратационной вспышки, размеры/URL/preload птицы, кликабельность логотипа и шапки.

**Impact summary:** user-visible — новые темы и понятный автоматический статус; data — дополнительные локальные theme IDs, без API; SEO — URL/canonical/индексация/контент не меняются; accessibility — контраст, focus, radio labels, 44px targets и отсутствие движения; performance — без новых запросов/растров/постоянного polling, один календарный таймер; security — закрытый реестр и валидация сохранённого значения, без HTML из внешних данных; analytics — существующие события сохраняются, новые не требуются.

**Non-goals:** backend, native seasonal palettes, настройки устройства/store release, принудительная замена ручной настройки, политические/национальные праздники, смена статьи/квеста/SEO-текстов, снег/мыши/конфетти поверх страницы, музыка, новые растровые ассеты и изменения чужих файлов.

**Open questions:** нет неразрешённых вопросов о наборе праздников. Это предложение периодов и реализации, а не уже опубликованная функция; переход к apply требует отдельного сообщения владельца.
