## Purpose

Автор путешествия получает актуальный список категорий после возвращения из админки в открытый редактор точки. Обновление не теряет правки, не предлагает повторно создать существующее полное имя и не порождает лишних сетевых запросов.

## ADDED Requirements

### Requirement: Fresh categories after returning to the editor

На desktop web и mobile web система SHALL обновлять категории после возвращения во вкладку или окно редактора на шаге 2 или 3, даже если шаг и открытая точка не изменились. Новая активная категория из успешного ответа SHALL появляться в поиске не позднее 5 секунд после получения ответа, без перезагрузки страницы.

#### Scenario: A category is added while the editor remains on the same step

- **GIVEN** редактор точки на шаге 2 уже загрузил список без категории «Планетарий»
- **WHEN** автор переходит в админку, создаёт активную категорию и возвращается в редактор, а новый ответ справочника содержит её id и имя
- **THEN** поиск `пла` показывает «Планетарий» в течение 5 секунд после ответа, сохраняя шаг 2 и открытую точку

#### Scenario: A quick return does not reuse the step throttle

- **GIVEN** с последнего обновления при переходе на шаг прошло менее 60 секунд
- **WHEN** автор возвращается после создания категории в админке
- **THEN** выполняется новая проверка справочника, а ожидание остатка 60-секундного окна не требуется

### Requirement: Requests are bounded and correspond to the return

Система SHALL выполнять не более одного нового запроса справочника на один возврат, независимо от количества сопровождающих браузерных событий. Запрос, начатый до возврата, MUST NOT заменять обновление после возврата. Обычные переходы между шагами SHALL сохранять 60-секундное ограничение, а фоновые периодические запросы MUST NOT добавляться.

#### Scenario: Several events describe one return

- **WHEN** одно возвращение вызывает несколько событий активации вкладки/окна
- **THEN** начинается ровно один новый запрос; последующие дублирующие события не добавляют запросов

#### Scenario: The earlier request is still pending

- **GIVEN** запрос со старым справочником начат до возврата и ещё не завершён
- **WHEN** автор возвращается после создания категории
- **THEN** после завершения прежнего запроса выполняется не более одного отложенного свежего запроса для этого возврата; новая категория из его ответа появляется в списке

#### Scenario: Ordinary step navigation preserves its budget

- **GIVEN** первый переход на шаг 2 успешно обновил категории
- **WHEN** автор проходит 2 → 3 → 2 внутри 60 секунд, не покидая окно редактора
- **THEN** дополнительных запросов справочника нет; новый вход после истечения окна допускает одно обновление

#### Scenario: Inactive or unrelated pages do not poll

- **WHEN** вкладка скрыта, редактор закрыт либо открыт шаг 1, 4, 5 или 6
- **THEN** события активации не запускают обновление категорий точек, а без пользовательских переходов нет периодических запросов

### Requirement: Refresh preserves edits and search

Обновление категорий SHALL сохранять выбранные id, текст поиска, фокус, адрес, фото, страны и состояние открытого редактора. Медленный ответ MUST NOT заменять уже показанные данные пустым списком или общим экраном загрузки.

#### Scenario: The author searches while a refresh is pending

- **GIVEN** выбрана категория «Парк», введён поиск `пла` и обновление ещё выполняется
- **WHEN** приходит ответ с «Планетарий» и прежними категориями
- **THEN** «Парк» остаётся выбранным, поиск и фокус сохраняются, новый пункт появляется, остальные поля не меняются

### Requirement: Search and creation remain distinct

Система SHALL искать новую категорию по подстроке и SHALL сохранять запрет предложения создать категорию с уже существующим полным именем без учёта регистра. Наличие предложения создать короткий префикс MUST NOT считаться доказательством отсутствия длинного имени.

#### Scenario: Prefix and full-name searches

- **GIVEN** свежий справочник содержит «Планетарий»
- **WHEN** автор ищет `пла`, а затем `Планетарий`
- **THEN** категория видна в обоих случаях; предложение создать «пла» допустимо, предложение создать повторный «Планетарий» отсутствует

### Requirement: Failure is not mistaken for freshness

При ошибке, недоступной сети или невалидном ответе система SHALL сохранять последний доступный справочник и правки. Возврат после восстановления сети SHALL позволять повторить обновление. Успешный пустой ответ SHALL оставаться пустым результатом сервера, не запускать цикл запросов и не подменяться выдуманными категориями.

#### Scenario: Offline return followed by recovery

- **GIVEN** ранее были загружены категории, а сеть недоступна
- **WHEN** автор возвращается в редактор, затем восстанавливает сеть и снова возвращается
- **THEN** первая ошибка не очищает категории и правки; второй возврат запрашивает свежий справочник и показывает новую запись из успешного ответа

#### Scenario: Empty response

- **WHEN** обновление возвращает валидный пустой справочник
- **THEN** новые варианты не выдумываются, сохранённые id точки не удаляются из её данных и сам пустой ответ не вызывает повторных запросов
