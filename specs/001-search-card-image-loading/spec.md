## Problem

Обложки карточек на `/search` появляются с задержкой и перезапрашиваются при
повторном показе, вместо того чтобы браться из кэша.

Задокументированные в репозитории факты (`docs/features/images.md`):

- часть классов изображений отдаётся с `no-store`, поэтому при каждом показе
  идёт полный перезапрос вместо чтения из кэша;
- частичный фронтовый обход от 2026-08-02 увёл класс `**/conversions/**` на
  `/media-resize/legacy/`, и замер `/search` desktop 1280 дал 6 обложек
  985 914 B `no-store` → 864 200 B `immutable`, а повторный заход — 0 B из сети
  (до обхода был полный перезапрос на каждый показ);
- обход **не покрывает** классы без legacy-роута: плоский корень
  `/gallery/<hash>.webp?w=320` — 110 084 B `no-store`, именованная конверсия
  `/address-image/<id>/conversions/…-thumb_400_wp.webp` — 25 528 B `no-store`
  (размер верный, кэша нет). Эти классы ждут бэкенд-задачу #1195
  (family-routes passthrough).

Дополнительно на `/search` наблюдалось мигание обложек, связанное с
перемонтированием списка, а не с сетью. В `app/(tabs)/search.tsx:28` список
на web гейтится условием `viewportWidth > 0`, то есть до появления измеренной
ширины результаты не рендерятся — это отдельный подозреваемый на «задержку»,
который нужно измерить, а не чинить вслепую.

Пользователь видит: пустые или «прыгающие» карточки при первом показе и
повторную загрузку тех же обложек при возврате на страницу.

## Goal

Обложки карточек на `/search` появляются без лишнего кадра ожидания, а при
повторном показе берутся из кэша, а не из сети — без изменения внешнего вида
карточек и без второго растра на слот.

## User scenarios

1. **Given** пользователь открывает `/search` с результатами, **When** страница
   загружается, **Then** каждая карточка сразу занимает финальную геометрию, а
   обложка появляется без промежуточного кадра нулевой ширины и без сдвига
   layout.
2. **Given** пользователь уже просмотрел выдачу, **When** он уходит на другую
   страницу и возвращается на `/search` с тем же запросом, **Then** ранее
   показанные обложки берутся из кэша и не создают новых сетевых запросов.
3. **Given** пользователь скроллит выдачу вниз и возвращается вверх, **When**
   ранее показанные карточки снова попадают во вьюпорт, **Then** их обложки не
   перезапрашиваются.
4. **Given** обложка недоступна или не загрузилась, **When** карточка
   отрисована, **Then** показан нейтральный placeholder той же геометрии — без
   иконки, текста, emoji и ярких акцентов — и layout не сдвигается.
5. **Given** пользователь открывает `/search` на mobile web и в Android-сборке,
   **When** он проходит те же шаги, **Then** поведение и геометрия совпадают.

## Functional requirements

- **FR-001**: Один визуальный слот обложки MUST использовать ровно один
  эффективный сетевой URL; на web — ровно один растр.
- **FR-002**: Повторный показ ранее загруженной обложки MUST обслуживаться из
  кэша без нового сетевого запроса.
- **FR-003**: Карточка MUST резервировать финальную геометрию до появления
  обложки, чтобы не возникало layout shift.
- **FR-004**: При отсутствии или ошибке загрузки обложки MUST отображаться
  нейтральный placeholder той же геометрии.
- **FR-005**: Letterbox-заливка MUST приходить из единственного пути
  `utils/mediaPlaceholderIndex.ts`; вторая локальная копия логики запрещена.
- **FR-006**: Изображение MUST сохранять исходное соотношение сторон (`contain`).
- **FR-007**: Система MUST NOT вводить принудительные таймеры раскрытия контента
  дольше `1000ms` для маскировки задержки загрузки.
- **FR-008**: Запрашиваемая ступень размера MUST соответствовать фактическому
  размеру слота, без загрузки мастер-файла под маленькую карточку.
- **FR-009**: Поведение MUST совпадать на desktop web, mobile web и Android.
- **FR-010**: Изменение MUST NOT затрагивать классы изображений, кэширование
  которых зависит от бэкенд-задачи #1195 — для них фиксируется блокер, а не
  фронтовый обход.

## Acceptance criteria

- **AC-001**: На `/search` desktop 1280 повторный заход даёт **0 B** сетевого
  трафика по обложкам карточек (метод замера — CDP `encodedDataLength` с
  группировкой по полному URL и initiator, согласно
  `docs/features/images.md`).
- **AC-002**: Число уникальных URL изображений равно числу видимых слотов
  обложек; на web число растров на слот равно 1.
- **AC-003**: CLS на `/search` не выше текущего baseline, измерено на
  production-экспорте (`yarn build:web:prod`) или на боевом URL — не на dev-сервере.
- **AC-004**: `yarn check:image-architecture` — зелёный.
- **AC-005**: `yarn lint` и `yarn test:run` — зелёные.
- **AC-006**: Скриншоты `/search` на desktop 1280 и mobile 390 до и после
  показывают идентичную вёрстку карточек.
- **AC-007**: Android-сборка на USB-устройстве воспроизводит сценарии 1–4.
- **AC-008**: В консоли браузера нет новых ошибок после изменения.

## Non-functional requirements

- Замеры производительности принимаются только с production-экспорта или боевого
  URL; счётчики Metro dev-сервера не являются истиной.
- Изменение не должно увеличивать вес web-бандла:
  `yarn guard:bundle-budget:fail` и `yarn guard:eager-web:fail` остаются
  зелёными.
- Поведение при медленной сети: карточка остаётся стабильной, placeholder не
  мигает и не сменяется вторым промежуточным состоянием.

## SEO impact

Публичные URL, canonical, sitemap, robots и метаданные не затрагиваются:
изменение касается загрузки медиа внутри уже существующей страницы `/search`.
Маршруты не переименовываются, редиректы не требуются. Индексируемость не
меняется. Если в ходе работы понадобится тронуть маршрут — спецификация
пересматривается, и добавляется план 301.

## Accessibility impact

- Смысловые обложки сохраняют описательный `alt`; декоративные — пустой `alt`.
- Placeholder не вводит текст, который читалка объявит как контент.
- Клавиатурная навигация по карточкам и видимый фокус не меняются.
- Порядок заголовков и семантика карточки не меняются.
- Контраст не снижается; размеры тач-таргетов не уменьшаются
  (`yarn guard:touch-targets`).

## Performance impact

Основной ожидаемый эффект — снижение повторного сетевого трафика на `/search`
до нуля для ранее показанных обложек и устранение лишнего кадра ожидания.
Контролируется: число запросов, `encodedDataLength`, CLS, LCP, вес бандла.
Правило «один слот — один URL, на web один растр» — обязательный инвариант, а не
цель оптимизации.

Гейт `yarn verify:slider` / `yarn verify:slider-perf` **не требуется**, если
изменение не затрагивает `components/travel/sliderParts/**`,
`components/travel/details/**`, `ImageCardMedia` и hero-геометрию. Если
`ImageCardMedia` попадает в scope — оба гейта становятся обязательными.

## Security considerations

Новый пользовательский ввод не обрабатывается. URL изображений нормализуются
существующим пайплайном; собственная сборка URL из непроверенных частей не
вводится. Токены, внутренние URL и конфигурация в код, логи и скриншоты не
попадают. Security headers и правила авторизации не затрагиваются.

## Analytics impact

Новые события не добавляются, существующие не удаляются. Если для диагностики
понадобится временная телеметрия загрузки изображений — она оформляется
отдельной задачей, а не этой спецификацией.

## Existing behavior to preserve

- Внешний вид, геометрия и радиусы карточек выдачи.
- Пагинация и подгрузка следующей страницы результатов.
- Сортировка и фильтры выдачи.
- Переход с карточки на страницу travel.
- Нейтральный placeholder без иконок и текста.
- `contain` + letterbox-заливка из `dominant_color`.
- Поведение остальных страниц, использующих те же карточки (каталог, главная):
  они не должны измениться незапланированно.

## Out of scope

- Бэкенд-задача #1195 (family-routes passthrough) и любые правки в
  `../metravel-backend`. Классы без legacy-роута остаются `no-store` до её
  закрытия; здесь фиксируется блокер.
- Изменение заголовков кэширования на сервере и в nginx.
- Редизайн карточки выдачи, сетки и вёрстки `/search`.
- Оптимизация изображений на других страницах (каталог, travel details, карта,
  квесты), если это не прямое следствие правки общего слоя.
- Перегенерация или перезаливка медиафайлов.
- Замена библиотеки работы с изображениями.
- Гейт `viewportWidth > 0` в `app/(tabs)/search.tsx:28` — если замер покажет, что
  задержка вызвана им, это отдельная спецификация: правка гейта затрагивает
  гидратацию и CLS шире, чем загрузку картинок.

## Assumptions

- `/search` рендерит выдачу через `components/listTravel/ListTravelRoute`
  (`app/(tabs)/search.tsx:14`); отдельного компонента карточки поиска нет —
  используются общие карточки каталога.
- Правка ожидается во фронтенде; бэкенд из этого workspace не редактируется.
- Правки затрагивают общий слой карточек, поэтому каталог и главная проверяются
  на отсутствие регрессии.
- iOS вне scope проекта.
