## Goal

Транзиентная ошибка production API во время сборки не должна приводить к
выкатке статики без целого контент-слоя: билд либо содержит полный набор
quest-страниц, city-лендингов и travel-промо квестов, либо падает до rsync.

## Context

Инцидент прод-деплоя 2026-07-28. В `scripts/generate-seo-pages.js` сбой одного
HTTP-запроса к `https://metravel.by/api/quests/?page=N` ронял весь quest-блок
генератора: `catch` → `console.error('❌ Failed to fetch quests: … Quest pages
and travel quest promos will not be generated')` → скрипт продолжал работу и
завершался кодом `0`. Транзиентный `HTTP 502` прилетел на 7-й (последней)
странице пагинации. Сборка уехала бы без 137 quest-страниц, 137 city aliases и
190 city-лендингов. `build-prod.sh` этого не ловил: его гварды проверяли только
travel-слой (`ssg-travel-article` и инвариант одного `<h1>`). Деплой прервали и
перезапустили вручную.

Корневая причина — три слоя:

1. build-time HTTP-клиент без ретраев на транзиентные ошибки;
2. fail-open вместо fail-fast: частичный/пустой каталог не валил сборку;
3. deploy guard покрывал только travel-страницы, не quest/city/промо.

Источник самих 502 — backend (`area=back`, см. #1054 про gunicorn worker
recycle) и в этот скоуп не входит: фронт обязан переживать транзиентные 5xx
независимо от их причины.

Изменения в `scripts/` и `build-prod.sh` выполнены по явному запросу
пользователя (тикет и есть разрешение), скоуп ограничен пунктами запроса.

## Task Contract

Scope:

1. `scripts/lib/fetchJson.js` (новый) — общий fetch-хелпер с ретраями и
   экспоненциальным backoff (3 попытки, 500ms → 1000ms). Ретраятся
   `408/425/429/500/502/503/504`, таймауты и сокет-ошибки; детерминированные
   ошибки падают сразу. `generate-seo-pages.js` переведён на него, его inline
   `fetchJson` удалён.
2. Fail-policy в `scripts/generate-seo-pages.js`: `throw` на недоступном
   quest-каталоге и на частичном travel-каталоге вместо тихого продолжения;
   `main().catch` → `process.exit(1)`. Отдельно: если не разрезолвился ни один
   quest detail bundle (`/api/quests/by-quest-id/` мёртв) — тоже `throw`, иначе
   все quest-страницы уехали бы деградированными.
3. `scripts/verify-static-quest-seo.js` (новый гвард, по аналогии с FE-IDX-1) —
   сверяет живой каталог квестов с собранным `dist/$ENV`: каждая quest-страница
   в обеих формах (`quests/<city>/<id>.html` и `quests/<city>/<id>/index.html`)
   для canonical и city-alias маршрутов; каждый city-лендинг + его crawlable
   секция `data-ssg-quest-city`; метаданные quest-страниц (title/description/
   og/canonical/JSON-LD `TouristTrip`/crawlable intro) — не голый SPA-шелл;
   ненулевое покрытие travel-промо (`data-ssg-travel-quest-promo`).
4. Гвард подключён в оба build-flow до rsync: `build-prod.sh` (после
   `verify-static-travel-seo.js`, до `copy-public-files`/`deploy_prod`) и
   `scripts/build-web-prod.js`.

Почему промо-гвард «> 0», а не «все travel-страницы»: промо подбирается
гео/город-скорингом, часть статей легитимно без промо (замер на проде — 6 из 8
выборочных страниц несут промо). Ноль промо на всём дереве при непустом
каталоге квестов = каталог схлопнулся, это ровно целевой режим деградации.

## Догруз 2026-07-29: QUEST-ALIAS-001 (найдено при разборе логов прод-сборки)

Расхождение «187 проверено гвардом против 190 сгенерированных лендингов»
оказалось не слепой зоной гварда (множества совпадают ровно, 187 = 187), а
**тремя молчаливыми перезаписями**: каталог отдаёт один город под несколькими
`city_id`, оба претендуют на один alias-сегмент.

| alias | city_id | квестов | было на проде |
| --- | --- | --- | --- |
| `gomel` | 19 + 92 | 3 + 3 | 3 из 6 |
| `grodno` | 11 + 91 | 2 + 3 | 3 из 5 |
| `mogilev` | 14 + 93 | 1 + 3 | 3 из 4 |

Усугубляющий фактор: numeric-лендинги обоих `city_id` канонизируются на
`/quests/<alias>` (проверено на проде: и `/quests/19`, и `/quests/92` дают
`canonical = https://metravel.by/quests/gomel`). То есть выпавшие квесты теряли
и внутреннюю ссылку с городской посадочной, и место в канонической группе.

Сделано:

- `mergeQuestCityLandingsByAlias()` в `scripts/generate-seo-pages.js` — alias-лендинг
  собирается из объединения квестов всех `city_id` с этим alias; numeric-лендинги
  остаются пер-городскими. Записей стало 95 numeric + 92 alias = 187 в 187
  различных путей, счётчик в логе больше не врёт.
- `scripts/verify-static-quest-seo.js` — новый шаг: alias-лендинг обязан
  ссылаться на каждый квест всех своих `city_id`, иначе сборка падает до rsync.
- Тесты: `mergeQuestCityLandingsByAlias` (5 кейсов) и
  `expectedAliasLandingQuests`/`missingLandingQuestLinks` (6 кейсов).

Проверено против живого каталога: 6/5/4 квеста вместо 3/3/3, 0 из 92
alias-лендингов нарушают инвариант, гвард роняет сборку на старом выводе.
Полный `__tests__/scripts/` — 136 suites / 849 тестов зелёные, governance 27/81,
eslint чисто, e2e-харнесс гварда 9/9.

**Требуется деплой,** чтобы исправление доехало до прода: на текущем проде
`/quests/gomel`, `/quests/grodno`, `/quests/mogilev` всё ещё неполные.

**Отдельная задача для `area=back`:** справочник городов отдаёт дубли
(Гомель 19/92, Гродно 11/91, Могилёв 14/93). Фронт теперь это переживает, но
первопричина на бэкенде. Завести, когда поднимется борд.
