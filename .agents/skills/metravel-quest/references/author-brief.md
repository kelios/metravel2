# Бриф автора нового квеста

Новый квест пишет субагент `general-purpose` с `model: "opus"` — только Opus,
даже если сессия на другой модели (правило владельца 13.07.2026: на младших
моделях выдуманных «наблюдаемых» деталей заметно больше). Один автор = ресёрч и
квест одного города. Оркестратор (сессия, получившая заказ) делает остальное:
ревью, перенос в `scripts/`, заливку и шаги из `upload-after.md`.

## Как запускать волну

- Не больше 4 авторов разом (лимит сессии Opus обрывает все субагенты сразу,
  а Nominatim/Overpass ловят 429 при параллели).
- Автор пишет файл ПО ХОДУ, поэтому оборванный лимитом автор возобновляется
  `SendMessage` по его agentId — контекст ресёрча сохраняется; новый автор с
  нуля — только если старого не поднять.
- Бриф — копия шаблона ниже с заполненными `<…>`. Сезонная волна (Пасха,
  Хэллоуин) копирует шаблон вместе с блоком «Тема волны» и порогами зимы.
- Ревью сдачи: `quest:gates` и geocheck перепрогоняет оркестратор сам, затем
  вычитка по `questions.md` (типовые находки ниже). Правка шага python-скриптом
  ломает файл, если `answer_pattern` многострочный, — после любой правки сразу
  `quest:gates`.

## Шаблон брифа

```markdown
# Бриф автора квеста — <волна/пакет>, <дата>

Ты пишешь ОДИН новый городской квест для metravel.by: сам делаешь ресёрч и сам
пишешь файл. Аудитория — русскоязычные путешественники, жители и семьи; язык —
русский. Город: <город>, quest_id: <quest_id>, id города: <id или «новый»>,
страна: <id>. Существующие квесты города: <quest_id…>. Слой/сюжет: <…>.
Крючки для старта: <…>.

## Прочитать до начала
1. `.claude/skills/metravel-quest/SKILL.md` — ядро: полномочия не твои
   (заливает оркестратор), таблица жёстких чисел, запреты.
2. `references/research-route.md`, `references/questions.md`,
   `references/data-format.md` (и `references/kids.md` для детского).
3. `scripts/golshany-quest-data.js` — образец формата и тона.
4. `assets/quests/osloHallvard/PROMPT.md` — образец промпта обложки.

## Где файл
`.codex-temp/quests-plan/<city>/<quest_id>-quest-data.js` — в `scripts/` НЕ
класть (недописанный data-файл роняет общий pre-commit у всех сессий, #2228).
Пиши по ходу: каркас (quest_id, title, city, meta, storage_key, intro, пустой
steps), затем каждую точку сразу после её ресёрча. Заметки —
`.codex-temp/quests-plan/<city>/research.md` (крючок → объект → 2 источника с
URL), тоже по ходу. Промпт обложки — сразу в
`assets/quests/<camelCaseId>/PROMPT.md`: ландшафт 3:2, `1536x1024`, выход
`cover.png`, узнаваемое место маршрута, без людей крупным планом, без текста,
место под заголовок.

## Что сдать
Data-файл `module.exports = [ { quest } ]`: 9–11 точек + intro + finale; PROMPT.md.

## Жёсткие требования
- Точки существующих квестов города выписаны в research.md, пересечение ≤2 и
  только с другим ответом.
- Числа из таблицы ядра: маршрут ≤<4 / 3,5 зимой> км суммой перегонов, перегон
  ≤<1,2 / 1> км, без возвратов; ≥6 обязательных шагов с проверяемым ответом,
  `any_text` среди обязательных ≤3; привал с именем в середине (`point_role:
  'optional'`, `poi_info` из 4 ключей).
- Каждый нетривиальный факт — 2 независимых источника; каждый проверяемый
  ответ — по ДВУМ фото объекта, одно не старше 2020; OSM `name` не источник.
  Нет 100% уверенности в ответе — свободный ответ, игроку легко и понятно.
- Статус объектов — на <сезон/дату>: закрыто, в лесах, на реставрации — нет.
- Запросы к Nominatim/Overpass строго последовательно, пауза ≥2,5 с, с
  User-Agent (параллельно работают другие авторы).
- Беларусь: никаких ссылок и упоминаний ресурсов из перечня экстремистских
  материалов РБ, ни в тексте, ни в ресёрче; политики в квесте нет.

## Тема волны (для сезонной — заполнить, иначе удалить)
<Сквозная нить — праздник ЭТОГО города, а не «вообще»; ≥5 точек из 9–11 несут
тему. Задания выполнимы КРУГЛЫЙ ГОД: временное (ёлка, ярмарка, иллюминация,
каток) — только в story. Название праздника не в title и не в quest_id; теги —
сезонный + вечный жанровый + место. В intro одной фразой — когда лучше идти и что
задания работают круглый год. Храмы — задание снаружи, обе конфессии нейтрально.>

## Проверки перед сдачей
    npm run quest:gates -- --source=.codex-temp/quests-plan/<city>/<файл>.js <--max-route-m=3500 --max-leg-m=1000 для зимы>
    node scripts/quest-geocheck.js --source-file=.codex-temp/quests-plan/<city>/<файл>.js --quest-id=<quest_id> --delay-ms=2500
Нужен выход 0 у quest:gates и разобранные WARN/FAIL geocheck. Красный скан
чини текстом квеста, не baseline-файлами. geocheck — один раз в конце и после
правок координат, не в цикле.

## Запреты
- Никакой заливки: миграция только `--dry-run`; никаких `--apply`, POST/PATCH на
  metravel.by. Чтение `GET https://metravel.by/api/...` разрешено.
- Никаких git-команд, меняющих состояние. Не трогать другие файлы репозитория,
  baseline-файлы, `docs/`, `scripts/`. Временные файлы — только в своей папке.
- Секреты не читать и не выводить.

## Финальный отчёт (до 350 слов)
quest_id и title; точек; route total и max leg; итог quest:gates; остаток
geocheck; таблица «шаг → ответ → чем подтверждён (2 фото/источника)»;
пересечения с квестами города; места с наименьшей уверенностью; факты, не
взятые из-за одного источника.
```

## Типовые находки ревью (вписывать в бриф при повторе)

- Устаревшее «сегодня там работает…» — сверь на дату.
- Задание смотрит не на ту сторону здания, куда приводит маркер.
- Подсказка почти называет ответ; задание само называет ответ («фигуры с
  крыльями — кто?»).
- `exact_any`: смешанные алфавиты, опечатка («мечь»), дословный повтор слова из
  story/title/hint своего шага.
- Цветовой корень в имени собственном задания («Вас**сер**кирхе») — перефразируй.
- `quest_id` или заголовок выдаёт ответ шага (`madrid-oso-madrono`).
- `poi_info.website` чужого музея; часы без перерывов.
- Автор скульптуры, возраст персонажа, год — по одному источнику: убрать.
- Авторы без порога сдают 2–4 проверяемых из 8–9 — порог ≥6 в брифе обязателен.
- Ответ на фонтане, с земли, мелкая надпись выше 3 м, живое дерево, вывеска
  арендатора — зимой не читается.
