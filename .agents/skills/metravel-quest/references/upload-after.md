# Заливка и шаги после неё

Полномочия — блок «Полномочия» ядра `SKILL.md`: заказанный квест идёт на прод
без отдельного «да». Токены операторских инструментов — `docs/DEVELOPMENT.md` →
«Operator token sessions»: скрипты берут токен общим resolver'ом QA104 сами
(`METRAVEL_TOKEN` / `~/.metravel_token`, при 401 — свежая сессия
`node scripts/get-quest-token.js`, он печатает только статус). Токен не
печатать, не читать руками и не вставлять в команды.

## 1. Перенос черновика и заливка

1. Черновик живёт в `.codex-temp/quests-plan/<city>/<quest_id>-quest-data.js`.
   `npm run quest:gates -- --source=<черновик>` и разобранный
   `quest-geocheck.js` по объектам — зелёные.
2. Оркестратор переносит файл в `scripts/<city>-quest-data.js` (детские —
   `<city>-kids-…`) и перепрогоняет `quest:gates` по новому пути.
3. `node scripts/migrate-quest-from-file.js --source-file=scripts/<…>.js
   --dry-run`, затем `--apply` (режим обязателен, дефолта нет). Миграция
   универсальная и идемпотентная: city-reuse по имени, `poi_info`,
   `point_role`. Отдельный `migrate-<city>-quest.js` — только для нестандартной
   логики.
4. **`status=1` — сразу опубликован**, не черновик: квест виден в каталоге в
   момент `--apply`. Непроверенные ответы не заливаются.
5. Новый город: сразу после заливки `curl -s https://metravel.by/sitemap.xml |
   grep -o 'quests/<alias>[^<]*'` совпадает с прогнозом `quest:gates`;
   расхождение — квест не остаётся опубликованным молча (сообщить владельцу,
   предложить снять до фикса).

## 2. Проверка заливки

`GET /api/quests/by-quest-id/<quest_id>/`: на месте intro, все steps, finale,
типы `answer_pattern`, координаты, `maps_url`, `poi_info` на музеях и
опциональных, теги (детские — возрастной тир; теги смотреть в списке
`/api/quests/`, bundle их не отдаёт).

## 3. Перевод (#2206)

По всем целевым локалям `i18n/config.ts` (be/uk/pl/en):
`npm run quest:translate -- prepare --quest <quest_id> --locale <код>` → агент
`quest-translator` → `check` → независимая смысловая проверка (второй
`quest-translator` по `*.review-task.json`) → `upload --publish` при зелёных
проверках. Команды, status до/после, ручные переводы и откат —
`docs/features/quests.md` → «Перевод квеста». Нулевой stale по шагам не
заменяет проверку финала. Ошибку одной локали не правят в русском
`answer_pattern`.

## 4. Обложка

Агент пишет только `assets/quests/<camelCaseId>/PROMPT.md` (образец —
`assets/quests/osloHallvard/PROMPT.md`); картинку генерирует Codex по этому
файлу. PIL-плейсхолдеры и любые самодельные обложки запрещены: заглушка
занимает `cover_url`, `upload-missing-quest-covers-prod.js` пропускает
непустой `cover_url`, и настоящая обложка потом не доезжает (17.07.2026).
Пока обложки нет — дефолтный SVG.

- Кадр — ЛАНДШАФТ 3:2, `1536x1024`, выход `cover.png`: слот карточки каталога
  1,4615 (`screens/tabs/QuestCard.tsx`) кадрируется `contain`; квадрат даёт
  31,6% пустого поля (#1987). Квадрат под плитку `QuestForCityCard` —
  производная `src_square`/`square_320` из манифеста. Гейт
  `scripts/lib/questCoverAspect.js` отбивает кадр вне 1,30…1,80 во всех трёх
  скриптах заливки.
- Заливка новой: `upload-missing-quest-covers-prod.js` (`--dry-run`, затем без
  него; модуль не require-ить для проверки — он сразу исполняет main).
  Перезалив существующей: `scripts/upload-quest-media-prod.js --quest-id=<id>`
  (поле `cover_image`).

## 5. Финал-видео

Скилл `metravel-quest-finale`. `finaleId` не обязан равняться id квеста —
находится сверкой текста финала.

## 6. Прохождение и страницы

- Пройти квест залогиненным на мобильном вьюпорте: задания понятны и
  выполнимы, проверка ответов работает, блок `poi_info` рендерится, печатная
  версия (`QuestPrintable`) цела. Счётчик на детали — только обязательные шаги:
  «0/5 при 8 шагах» не баг.
- SSG страниц квестов строится из прод-API (`generate-seo-pages.js`): после
  `--apply` выкат любого свежего `main` публикует страницы, даже если коммит
  data-файла ещё не прошёл.
- Проверочный таргет до ревью — локальный бэк `localhost:8000` (квест заливается
  туда `--api-url=http://localhost:8000`); прод-квест — против прод-API в
  `testing` после своей заливки. Prod Static не имеет SPA-fallback для
  `/quests/{cityId}/{quest_id}` — открывай переходом из списка; `city_id` бери
  фактический, не угадывай. Прохождение требует логина (e2e-аккаунт, пароль
  руками не вводить). Транзиентный «Квест не найден» до гидрации — норма.

## 7. Перелинковка

Авто-блок «Квест по городу» на travel-детали срабатывает по координатам
(`utils/questForLocation.ts`). Дополнительно — инлайн-ссылка из статьи-
путеводителя автора 1, если есть: `scripts/seo-edit.js --append-file` (бэкапы
в `scripts/.seo-backups/`), лид и SSG-мету статьи не трогать. Новые URL уходят в
IndexNow кроном; «Запросить индексирование» в GSC — `seo-daily` браузером,
только после пререндера статики на проде.
