# Конвейер: команды и ловушки

Все скрипты лежат в `scripts/` этого скилла. Исходный фильм, исходники и
проекты Filmora только читаются.

## Инструменты

- `ffmpeg`, `ffprobe` из Homebrew. В сборке нет фильтра `drawtext`: подписи на
  листах рисует Pillow, титры готовятся картинкой PNG.
- `uv` запускает Python-скрипты с зависимостями без установки в систему:
  `uv run --with pillow ...`, `uv run --with numpy --with soundfile ...`.
- Расшифровка: `uv tool install --python 3.12 mlx-whisper`, модель
  `mlx-community/whisper-large-v3-turbo`. На M1 идёт в 2–4 раза быстрее
  реального времени.

## 1. Просмотр

```bash
scripts/watch_film.sh "<фильм.mp4>" "<рабочая папка>" 5 ru "Имена и места через запятую"
```

Проход по 4K-фильму идёт примерно вдвое быстрее реального времени. Затем:

- прочитай каждый лист `sheets/sheet_NNNN.jpg` (30 кадров, шаг 5 секунд);
- прочитай расшифровку: `python3 scripts/compact_transcript.py tr/audio16k.json [от] [до]`;
- чёрные и застывшие кадры: `grep -E "black_start|black_end|freeze_start" freeze.txt`.

Ловушки расшифровки:

- С опорой на предыдущий текст модель зацикливается на музыке («И Камино» 49
  раз) и теряет речь после неё. В скрипте опора выключена.
- На музыке без речи появляются выдуманные строки вроде «Субтитры сделал…».
  Это не текст фильма.
- Бессвязная строка в месте, где человек явно говорит, означает плохую
  разборчивость: речь тонет в музыке или ветре. Это находка по звуку.
- Времена слов могут уходить на полсекунды. Границу вырезки проверяй по уровню
  звука с шагом 50 мс и ставь в паузу.

## 2. Состав фильма и раскладка

Фильм из нескольких дней обычно склеен из отдельных экспортов. Сумма их
длительностей (`ffprobe -show_entries format=duration`) равна длительности
фильма, границы совпадают с паузами из `silence.txt`.

```bash
python3 scripts/filmora_edl.py "<проект.wfp>" --offset <начало части в фильме, с> --json part.json
```

Раскладка показывает исходник каждого плана, музыку, уже сделанные вырезки
внутри длинных планов и вставки. Новая вырезка не должна оставлять между двумя
склейками обрывок короче секунды: сдвинь границу на существующую склейку.

Подбор перебивок по папке исходников дня:

```bash
uv run --with pillow --with pillow-heif scripts/library_sheets.py "<папка дня>" "<рабочая папка>/lib"
```

Жёлтая подпись — видео с длительностью, белая — фото. Узкий кадр с чёрными
полями по бокам — вертикальный, для перебивки на весь экран не годится. Номера
уже использованных исходников видны в раскладке.

## 3. Звук: измерения

- Громкость сцены: `ffmpeg -ss <от> -t <длина> -i audio_full.wav -af ebur128 -f null -`,
  строка `I:` в конце вывода (20 последних строк, не 12).
- Сравни речь по частям. Разница больше 1 LU исправляется усилением отрезка
  (`gain_db` в плане), выравнивание в мастеринге снимает остаток.
- Баланс речи и музыки внутри готового микса исправить нельзя: дорожки уже
  сведены. Такие места выносятся владельцу списком с таймкодами для правки в
  проекте Filmora.

## 4. План и сборка

Два сборщика — по происхождению материала:

- `scripts/render_plan.py` — монтаж из исходников по плану, из которого
  `make_wfp` строит проект Filmora: отрезки главной дорожки с перебивками,
  титрами, переходами (`xd_out`), музыкой и голосом за кадром (`music.cues`),
  покраской (`grade`). Куски кешируются по содержимому отрезка: картинка —
  «начало», «середина» и «конец» отдельными файлами; середины встают в фильм
  копированием потока, кодируются только растворения на стыках. Формат плана —
  в начале скрипта; таймкоды результата совпадают с таймкодами проекта.
  Громкость задаёт план (`loud_gain` отрезков к −14 LUFS речи, уровни
  `music.cues`), рендер только ограничивает пики около −3 dBFS. Итог сверяет
  `audit_tech.py`; промах правится в плане.
- `scripts/assemble_film.py` — правка готового экспорта владельца: вырезки и
  перебивки поверх уже сведённого фильма. Формат его плана описан в начале
  скрипта.

Правила плана правок готового экспорта:

- Вырезка — это два соседних отрезка с пропуском между ними. Непрерывный
  материал с разным усилением тоже делится на отрезки: стык станет плавным.
- Перебивка, закрывающая вырезку в статичном плане, задаётся двумя записями:
  в конце отрезка до вырезки и в начале отрезка после. Для фото это бесшовно.
- Один чёрный кадр убирается отрезками до него и после него.
- Исправленный экспорт части подключается вторым источником; его времена
  считаются от начала этого файла.

```bash
python3 scripts/assemble_film.py plan.json --dry-run   # таблица отрезков
python3 scripts/assemble_film.py plan.json             # сборка, запускать фоном
```

Сначала собери короткий пробный план из мест с перебивками и вырезками
(по 8–10 секунд каждое) и посмотри его лист кадров. Полный рендер 4K идёт
примерно в полтора раза быстрее реального времени; куски кешируются, повторный
запуск после правки плана пересчитывает только изменённые отрезки.

Мастеринг внутри `assemble_film.py` (`scripts/master_audio.py`) делает выравнивание,
компрессию выбросов и ограничение пиков на частоте 192 кГц. Ограничитель без
передискретизации оставляет истинные пики на 2–3 дБ выше цели.

### Сборщик серии: `film_serial.py`

План серии для `render_plan.py` пишет сборщик `plan_sN.py` в папке планов.
В нём только сцены; общая механика лежит в `scripts/film_serial.py` и
настраивается через `film.json`. Новый фильм: `film.py init`, затем
`film.py series sN --days <дни> --title "Название"` — сборщик из шаблона
`scripts/plan_template.py`, в который подставлены первые клипы дня.

```python
import film_serial as S
from film_serial import clip, story, file_seg, rv, ph, photo_seg, card, put
S.start("s2", intro=("0.",), auto_level=True)
S.serial_intro(2)                                   # интро сериала и «ранее» из film.json
sg = clip(2, "C3901", 4.0, 31.5, "1. выходим")       # день, часть имени файла, от, до, заметка
put(sg, card("место", "s2 место Дьеп", "Дьеп · порт"), 0.5, 4.0)
story(2, "0042", "сегодня идём", "до города", note="2. рассказ: план", over=[rv(2, "C3907"), ph(2, 1805, 5)])
```

| Что | Функции |
| --- | --- |
| главная дорожка | `clip` (клип дня по части имени), `story` и `at` (кусок от фразы до фразы по расшифровке), `file_seg` (любой файл), `photo_seg` (фото) |
| перебивки | `over=[rv(…), ph(…), ext(…)]` у `clip` и `story`; `cutaways("перебивки_sN.json", day)` ставит слой из таблицы «мысль → кадр» и снимает остальные |
| плашки | `card(вид, имя, строки…)` рисует `scripts/titry.py` (место, дата, цена, блок, серия, крупно, справка, номер), `put` и `put_across` ставят на отрезок; `prices` — цена в момент слов |
| правка речи | `cut_words`, `mute_words`, `bleeps` |
| проходы | `fit_broll_to_files`, `join_runs`, `whole_phrases`, `vertical_main`, `no_flashes`, `loudness`, `blur_substitute`, `transitions_and_edges`, `dedupe_broll` — в порядке шаблона |
| рамка-рассказ | `memory_look` (тёплые копии и окошко рассказчика), `exit_marks`, `whooshes` |
| звук | `voice` (голос за кадром), `part_beds` (музыка по `части_sN.json` через `music_fit.beds`), `bed`, `cue`, `duck_beds`, `sfx` |
| начало и конец | `serial_intro`, `serial_intro_sound`, `episode_card`, `end_card` |
| запись | `save(plan.json)`: проверяет плашки под окошком и привязку звука, печатает находки таблицы перебивок |

Заметка отрезка несёт смысл: «N. …» — номер сцены сценария, «рассказ:» —
кусок рамки-рассказа, «0.» — интро сериала и «ранее», «T.» — тизер и
концовка. По префиксам заметок ставятся плашки, музыка и голос.

Ключи `film.json` для этого слоя — в начале `film_serial.py`: папки (`prep`,
`maps`, `cards`, `music`, `intro_voice`), название серии (`series` → `sN` →
`title`), кадры интро (`intro.shots`) и блоков «ранее» (`recap`), звуки,
шрифты плашек и концовки (`fonts`; без них — шрифты из загрузок Filmora в
домашней папке, затем системные). Интро без кадров пропускается; блок «ранее» без кадров или без
записи голоса тоже, причина печатается в итоге `save`.

Копии, которые заказывает сборщик, делают `scripts/vertical_render.py`
(вертикальные куски, `vertical_jobs_sN.json`) и `scripts/memory_grade.py`
(«воспоминание», `memory_jobs_sN.json`). `film.py init` вписывает оба в
`after_plan`: `film.py plan sN` запускает их и собирает план второй раз, уже
на готовых копиях. Без заданий оба выходят сразу.

Проверочный прогон: `FILM_SERIAL_SHADOW=<папка> python3 -I plan_sN.py
<папка>/plan.json`. Задания копий, кеши громкости, новые плашки и фото-копии
пишутся в `<папка>`, готовое читается с места. Так план сверяется с прежним,
а папка фильма остаётся нетронутой.

Сборщик, написанный под `gr21_serial.py` (фильм GR21), переводится без правки
сцен: имена функций и переменных совпадают. В `film.json` добавляются
названия серий, `intro` и `recap`; в сборщике меняются путь к скриптам и две
строки импорта. Перед заменой план сверяется проверочным прогоном.

### Следующие круги: правки по таймкодам результата

Рецензент называет таймкоды готового файла. `scripts/recut_plan.py round.json`
переводит их в таймкоды источников и пишет новый план: границы вырезок
привязывает к паузам, делит перебивки по обе стороны стыка и печатает обрывки
планов короче секунды рядом с перебивками, уже вшитыми в экспорт владельца.
Обрывок убирается сдвигом границы на край перебивки или расширением вырезки.
Таймкоды вырезок выбирай по расшифровке прошлого результата; в тихую точку
границу сдвигает сам скрипт по уровню звука, расшифровку он не читает. Звук
прошлого результата для него — WAV 16 бит. Новый план пишется отдельным файлом:
базовый план нужен, пока жив собранный по нему результат.

### Титры

Титры дней собираются картинкой 3840×2160 из знаков уже существующих титров
владельца (те же шрифт, кегль и положение строк), недостающие знаки
дорисовываются шрифтом проекта из папки шрифтов Filmora. Картинка кладётся
ключом `cards` поверх старого титра. Перед сборкой все титры фильма
сравниваются на одном листе.

## 5. Цвет

Исходники серий GR21 — обычный SDR bt709, log-профилей нет: Osmo Pocket 3
(HEVC 10 бит 4:2:0), Sony ZV-E1 (H.264 10 бит 4:2:2), iPhone 16 Pro (SDR, не
HLG), дрон DJI (H.264 8 бит). Значит, покраска — это не «проявка» log, а
выравнивание камер между собой и общий лук. Перед покраской нового материала
проверь метки: `ffprobe -show_entries stream=pix_fmt,color_transfer,color_primaries`.
HLG (`arib-std-b67`) или PQ (`smpte2084`) требуют тонмаппинга в bt709 до
`grade.py`, иначе картинка выйдет блёклой.

**По умолчанию покраски нет (владелец 23.11, s3 v20):** «покраска не должна быть
явной, нравятся натуральные цвета». Замер: без `grade` рендер совпадает с
исходником, всё отличие давала `eq=gamma` 1,10–1,18 из `--minimal` (+10–15
уровней). `render_plan.py` пропускает ключи `grade`, кроме `"grade_owner": true`
(осветление по её просьбе на конкретный план). Полная покраска — только по
просьбе владельца:

```bash
uv run --with numpy python scripts/grade.py plan.json plan_цвет.json --look-on \
    --look "<папка>/цвет/metravel_look.cube" --cache "<папка>/цвет/замеры.json"
python3 scripts/render_plan.py plan_цвет.json черновик.mp4 --grade    # --grade — применить покраску
```

- Замер — 3 кадра на каждый используемый кусок (главная дорожка и перебивки),
  кешируется. Цель фильма — медиана яркости и насыщенности всех камерных
  планов.
- Поправки мягкие и ограниченные: уровни растягиваются только у сжатого
  диапазона и не больше чем ×1,25; баланс белого — полпути к нейтрали, не
  больше ±7% по каналу (закат остаётся тёплым); экспозиция — треть пути к цели,
  гамма 0,85–1,18; насыщенность 0,88–1,2. Ночь, туман и низкий ключ не
  вытягиваются к «среднему».
- Лук `metravel_look.cube` (33³): мягкая S-кривая, откат светов, тёплые света
  и чуть холодные тени, +10% насыщенности с защитой тона кожи. В Filmora он
  подключается как пользовательский LUT, и проект совпадает с рендером.
- Уже обработанные файлы не красятся: «память» (свой лук воспоминаний),
  титры, карты (`--skip-dirs`). Чёрно-белый финал лежит в титрах.
- Изменение лука меняет ключ кеша кусков `render_plan.py`: перекрашенный план
  пересчитывается целиком, остальной кеш живёт.

Проверка — `scripts/audit_color.py` по черновику из `plan_цвет.json` и по
финалу. Начинай с `_лента.jpg`: по кадру на план подряд, разнобой камер виден
сразу. Затем `_скопы.jpg` для планов с находками: осциллограф показывает
выбитые света и проваленные тени, вектороскоп — куда ушёл оттенок. Находка
чинится в плане (другой кусок, точка входа или ручной ключ `grade` у плана
вместе с `"grade_manual": true` — перезапуск `grade.py` его не затрёт), а не
в луке.

## 6. Замена музыки без отдельных дорожек

Отдельных дорожек в экспорте нет, но исходные музыкальные файлы известны из
раскладки (`ES_*.mp3` в «Загрузках» владельца). `scripts/remusic.py`
выравнивает исходный трек с миксом, вычитает его и подмешивает новый.

- Сначала аудит: признаки треков (темп, доля ударных, яркость) считает
  `librosa`, жанр и настроение берутся со страниц Epidemic Sound. Вердикт по
  каждому куску — оставить или заменить, с кандидатом из скачанных треков.
- Глубина подавления старой музыки проверяется там, где она звучит одна (титр
  дня, заставка). Трек из MP3 после кодирования фильма в AAC вычитается
  примерно на 16 дБ, трек из WAV — на 25 дБ. Остаток закрывает новая музыка.
- Музыка в миксах Filmora обычно тише, чем кажется по замерам «без речи»: в
  паузах слышны шаги и ветер самого плана. Неразборчивая речь на ходу чаще
  вызвана шумом записи, а не музыкой.
- В плане сборки куски старого трека задаются таймкодами источника из
  раскладки. Сборщик пересчитывает их через вырезки, поэтому новый трек не
  рвётся на склейках. Живую музыку в кадре закрывает окно `mute`.
- Новая музыка звучит только на кусках старой. Если трек стоит в раскладке
  дважды с другим материалом между кусками, это два задания: у каждого свой
  новый трек или своя точка входа `new_start`. Короткую паузу старого трека
  (пара секунд между двумя его кусками) новая музыка проходит без остановки,
  если заданию дать `bridge` длиннее этой паузы.
- Кусок трека короче секунды между двумя склейками не вычитается, сборка
  печатает предупреждение. Расширь вырезку или сдвинь её границу.
- Тот же приём убирает скачок музыки на вырезке: задание, где новый трек
  равен старому, кладёт музыку заново и непрерывно. Применять там, где музыка
  звучит на переднем плане; тихую подложку под речью достаточно свести
  кроссфейдом.
- В экспорт пишутся две звуковые дорожки: первая с новой музыкой, вторая с
  исходной. Владелец переключает их в плеере и выбирает на слух.

## 7. Проверка экспорта

```bash
python3 scripts/audit_tech.py "<экспорт.mp4>" --out "<рабочая папка>/audit_tech.md"   # вердикт ГОДЕН / НЕ ГОДЕН
scripts/verify_export.sh "<экспорт.mp4>" "<рабочая папка>/verify"                    # листы кадров
```

`audit_tech.py` проходит файл один раз и сводит технические пункты в таблицу:
faststart, равные длины видео и звука, кодек и постоянная частота кадров,
метки цвета bt709 (без них YouTube угадывает пространство и цвет «плывёт»),
битрейт по рекомендациям YouTube (4K30 SDR ≥ 35 Мбит/с), AAC 48 кГц ≥ 256 кбит/с,
−14 ±1 LUFS, истинный пик ≤ −1 dBTP, клиппинг, постоянная составляющая,
противофаза каналов, тишина дольше 2 с, ошибки декодирования, чёрные кадры
дольше 0,5 с и застывшая картинка дольше 6 с. Концовку (`--end-card`, 6 с)
он не считает тишиной и чёрным. `--quick` пропускает декодирование картинки —
для черновиков. Пункт ❌ — блокер выдачи, ⚠ — посмотреть глазами.

`verify_export.sh` снимает листы кадров результата с шагом 5 секунд. После
обоих скриптов:

- сверь листы результата в местах правок с листами исходного фильма;
