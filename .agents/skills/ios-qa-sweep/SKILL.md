# iOS QA Sweep — план → тест → борд → фикс → верификация

Зеркало `/android-qa-sweep` для iPhone. Универсальные правила оценки (целостность
вёрстки, закрываемость оверлеев, все состояния компонента, z-order) не дублируются
— читай их в `.claude/skills/android-qa-sweep/SKILL.md`, пункты 9–12 чеклиста, и
применяй один в один.

## Предусловия

1. Окружение: `npm run ios:environment:check` — Xcode/SDK, пригодный iPhone-симулятор,
   состояние Pods. Красное чинится до обхода, а не обходится.
2. Панель симулятора: `mcp__Claude_Code_iOS_Simulator__control` → `attach` **до** сборки,
   чтобы владелец видел прогон. Скриншоты и ввод работают и без панели.
3. Сборка: dev/debug сборка на симулятор. Подписанные `preview`/`production` профили для
   QA не собираются — они за отдельным разрешением владельца (`/ios-release`).
4. API-гейт: таргет по умолчанию — локальный бэк (`http://localhost:8000`), и он обязан быть
   обновлён до `origin/master` перед прогоном (`docs/WORKFLOW_OPERATIONS.md` → «3.0 Локальный
   стек»): `git -C ../metravel-backend fetch origin master && git -C ../metravel-backend reset
   --hard origin/master`, затем `bash /Users/juliasavran/Sites/metravel/run-backend.sh`.
   Симулятор ходит на `localhost` как и мак; физическое устройство — на LAN-IP мака с
   `EXPO_PUBLIC_IS_LOCAL_API=true`. Бэк не поднят или отстал — приложение покажет **пустоту
   везде** или ложные дефекты по старому API, и это легко принять за UI-баг. Прод-API
   подключается временной правкой `.env` только по явному запросу владельца, с обязательным
   возвратом файла; проверь, что `build-prod.sh` не оставил там прод-URL. `EXPO_PUBLIC_*`
   инлайнятся при сборке, поэтому нужен рестарт Metro `--clear`.
5. Логин e2e-аккаунтом разрешён постоянно (переспрашивать — ошибка), креды в `.env.e2e`.
   Пароль в поля не набирается: токен кладётся программно. На симуляторе это делается через
   dev-сборку; в TestFlight-сборке инжекции нет — там нужен один ручной вход владельца, и
   это не повод блокировать обход, а строка в отчёте.

## Что симулятор НЕ доказывает

Не помечай пройденным на симуляторе и выноси в раздел «нужен физический iPhone»:
камера, фото-библиотека и HEIC, реальная геолокация, sharing во внешние приложения,
Keychain и сессия после холодного рестарта, биометрия, реальные safe area и
клавиатура на устройстве, Universal Links из внешних приложений, APNs, поведение
подписанной сборки и производительность. Приёмка релиз-кандидата — только exact
processed TestFlight build. Физическим iPhone и TestFlight-слоем владеет `ios-tester`,
драйвить их этим скиллом нельзя; регламент живого устройства —
`.claude/skills/ios-device-qa/SKILL.md`.

## Инструменты

`mcp__Claude_Code_iOS_Simulator__control`:

- `attach` — панель для владельца; `launch` — установка и запуск собранного `.app`;
- `screenshot` — снимок экрана (координаты в points, origin слева сверху);
- `tap` / `swipe` / `touch_path` / `text` / `button` — ввод. Свайп, начинающийся ближе
  4 pt к краю, выполняет системный жест (back / шторка / домой), а не скролл — начинай
  дальше от бортика;
- `open_url` — deep link (`metravel://<route>`, `https://metravel.by/<path>` для проверки
  роутинга Universal Link внутри симулятора).

Логи и краши читай из симулятора (`xcrun simctl spawn booted log stream` по нужному
предикату) — краш без стектрейса в отчёт не идёт.

## Пайплайн

1. **План:** список фаз — статические экраны → интеракции → локали → тёмная/светлая тема →
   тикеты → фиксы.
2. **Обход:** каждый роут → `screenshot` → критическая оценка (вёрстка, обрезки, пустые
   блоки, контраст, высота шапки ≤20% вьюпорта, safe area под Dynamic Island и home
   indicator, тап-таргеты ≥44 pt) → интеракции: каждая кнопка, скроллы медленные и
   быстрые, скролл до конца списка, тогглы в обе стороны, реальный ввод и сохранение форм
   с тест-аккаунтом. После каждого действия — проверка логов на ошибку.
3. **Локали:** RU/BE/UK/PL/EN — переключение и холодный перезапуск; ищи обрезанный и
   непереведённый текст, съехавшую вёрстку на длинных строках.
4. **Отчёт:** `artifacts/ios-qa/QA_REPORT_<ЭКРАН>.md` — таблица обхода + находки
   `### F-NN (critical/major/minor/info)` со скринами и, где известно, `файл:строка`.
   Отдельным блоком — что осталось непроверенным и на каком слое это проверять.
5. **Борд:** через `ticket-board` — тикеты `[IOS-NN] суть`, `area=front`, с моделью
   симулятора/устройства, версией iOS, `Platform impact` и `Localization impact`,
   привязка к активному спринту. Подтверждённый серверный дефект — `area=back`.
6. **Фиксы** по severity: код и платформенные файлы — `ios-expert`, карта — `map-expert`,
   визуал и HIG — `ios-designer`. Web — прод, его не ломать ради native: несовместимость
   лечится платформенным файлом, после правки общего файла обязательна web-проверка.
   Каждый фикс верифицируется повторным скрином и во **всех** состояниях тронутого
   компонента, а не только на том пути, который менялся.
7. **Регресс:** `npm run test:run` + `npm run typecheck` + `npm run lint` до зелёного;
   при правке конфигурации дополнительно `npm run ios:release:guard`.

## Что можно и нельзя

**Можно и нужно** с тест-аккаунтом: создавать и удалять своё, лайкать, менять статусы,
проходить квесты, слать сообщения второму тест-аккаунту, реально заполнять и сохранять
формы; после прогона прибрать за собой.

**Нельзя:** деструктив над чужими и продовыми данными, платежи, массовые рассылки,
любые store-операции (build/upload/submit/release — только `ios-deployer` по явной
команде владельца) и подмена физического/TestFlight evidence скрином симулятора.
