# Фото: архивы, EXIF, отбор, подписи, заливка

Читается на шагах «разведка папки», «отбор», «подписи», «заливка».

## Где лежат кадры

- `/Volumes/4 TB/Наши Фотки/` — 2010–2022 по годам («Стамбул (ноябрь 2019)»),
  `ОТДЫХ/` — Индия, Турция, Доминикана; там же ответ на спорные месяцы поездок;
- `/Volumes/4tbJuli/НАШИ ФОТКИ/` — 2022–2026;
- `/Volumes/T7/` — большие поездки (Люксембург, рождественские ярмарки, видео).

Диски только читаются. Вывод «кадров нет» допустим лишь после
`find /Volumes/* -maxdepth 3 -type d -iname '*<место>*'` по всем дискам.
`find` на T7 показывает `._`-двойники (метаданные macOS) — их отбрасывать;
PNG в архиве — скриншоты (Garmin, карты, брони): в отбор не идут, но дают цифры
и названия жилья.

## EXIF-разведка — обязательна, если есть папка

```bash
python3 .claude/skills/metravel-travel-article/scripts/photo_survey.py \
  "<папка поездки>" --out .codex-temp/survey --geocode [--no-sheets]
```

Подкоманд нет — папка позиционным аргументом. Скрипт вытаскивает GPS и даты,
собирает кластеры мест, обратно геокодирует через OSM и режет контактные листы
6×6. Так восстанавливается фактическая канва поездки (какие места, в каком
порядке, в какие дни); без неё география в тексте выдумана. `_exif()` движка
для этого не годится — он лишь привязывает загружаемое фото к готовой точке.

Название места — два независимых признака: reverse-геокод (Nominatim,
`User-Agent` обязателен, пауза ≥1,1 с) и текст щита/вывески в самом кадре; при
сомнении — веб-поиск. Дни поездки сопоставлять с папками по содержимому кадров,
а не по порядку папок.

## Отбор — глазами, не по именам файлов

1. Read'ом открыть КАЖДЫЙ лист из `--out/sheets`, выписать номера кандидатов.
2. Собрать проверочный лист из кандидатов (4×3, ~470 px) и посмотреть ещё раз —
   на превью 264 px похожие объекты путаются, потом кадр подписан неверно.
3. Ориентир: 5–8 кадров на раздел/день, 35–50 на большую статью. Приоритет —
   то, о чём текст есть, а фото нет.

### Большой архив (1500+ кадров)

- `photo_survey.py` нумерует по `sorted()` имён; у «Медиатека - N из M» это не
  хронология. Свои листы: сортировка по N из имени, подпись плитки = N + время,
  N — id кадра на весь архив.
- Отбор — ≤4 субагента параллельно (лимит сессии Opus убивает все разом), по
  12–16 листов каждому, общий бриф файлом, результат в `sel_<буква>.json`;
  оркестратор смотрит только проверочные листы отобранного (5×4, 320 px).
- Безымянные кадры — один общий Overpass `nwr(around:R,lat,lon)[name]` на все
  точки плюс Nominatim search с viewbox (расстояние кадр↔объект).
- Заливку пускать фоном, файл результатов — на каждую коллекцию свой (общий
  JSON затирается). Текст писать ПОСЛЕ окончания заливки фото точек: upsert
  шлёт `image` точек из свежего GET.

### Только видео

1. Превью-проход: 1–2 кадра на клип —
   `ffmpeg -ss <t> -i clip.MP4 -frames:v 1 -vf "scale=260:195:force_original_aspect_ratio=decrease,pad=264:198:(ow-iw)/2:(oh-ih)/2" -q:v 3 out.jpg`;
   момент — доля от длительности (`ffprobe -show_entries format=duration`),
   `-ss` ДО `-i`. Вести `index.tsv`: кадр → файл → таймкод → день → камера.
2. Листы 6×6 из превью, просмотр глазами.
3. Выбранные переизвлечь в полном разрешении по таймкоду (без `-vf`, `-q:v 2`),
   потом ресайз и заливка.

## Подпись = место, сверенное с координатами

- **С точки зрения места, а не людей** (решение владельца 20.09.2026): объект и
  где он — «Карьер в Забежуве: известняковая стена над водой», «Парковка у
  трассы S7 в Pcim», «Тропа к смотровой на Тронке». У портрета на фоне места
  подписывается фон. Шаблон запрета — SKILL.md, проверка — `article-acceptance-check`.
- Подписывать только то, что видно на 100 % (кадр открыть Read'ом).
- Перед «в заповеднике», «у замка», «в городе X» взять GPS ЭТОГО файла из
  `survey.json` и посчитать расстояние до объекта; координаты объекта — из
  `travelAddress[].coord` самой статьи. До ~400 м у крупного объекта — «на
  месте», дальше — нет. В одной папке почти всегда несколько мест.
- Кадр, не попавший уверенно ни к одному объекту, подписывается нейтрально
  («дорожка в пойме реки между парковкой и заповедником»).

```python
import math
def dist(a, b):                     # метры между (lat, lon)
    R = 6371000
    p1, p2 = math.radians(a[0]), math.radians(b[0])
    dp, dl = p2 - p1, math.radians(b[1] - a[1])
    x = math.sin(dp/2)**2 + math.cos(p1)*math.cos(p2)*math.sin(dl/2)**2
    return 2 * R * math.asin(math.sqrt(x))
```

Подписи — обе группы при любой правке: `alt` каждого `<img>` тела и
`gallery[].caption` каждого кадра (`PATCH /api/gallery/{imageId}/`
`{"caption": "…"}`, ≤500 — они видны на hero-слайдере). Лишний кадр галереи
(еда, ТЦ, случайное) — `DELETE /api/gallery/{imageId}/`.

## Дубли кадров

Визард и ручные заливки дают один снимок под разными `<hash>`; перекодированная
копия имеет другой md5 (#1980). Поэтому сравнивать md5 И перцептивный хэш
(dhash 17×16, расстояние ≤12) — по телу, по галерее и тело↔галерея. Это делает
`node scripts/article-acceptance-check.js --id <id>` (нужен локальный ffmpeg).
Какой из пары убирать, решают `alt` и абзац вокруг, а не порядок; повтор сюжета
(семь кадров одного места) — не дефект, дефект — чужая подпись на дубле.
Удалять весь `<p>` с картинкой, иначе остаётся пустой абзац; писать через
`seo-edit.js --desc-file` и после записи прогнать проверку снова.

## Заливка в тело

```bash
# бэкенд всё равно ужимает до 1024 px по длинной стороне — больше 1600 не слать
ffmpeg -y -i in.JPG -vf "scale=1600:1600:force_original_aspect_ratio=decrease" -q:v 4 out.jpg
```

**Темп — строго последовательно, duty ≤50 %.** Один `POST /api/upload` — ~10 с
CPU единственного ядра прода (варианты картинки генерируются синхронно). Без
пауз хост держится на 70–90 %, живые пользователи ждут API по 5 с, а
`monitor.sh` шлёт владельцу письма «SYSTEM ALERT» (#2306). После каждого ответа
пауза не меньше длительности самого запроса и не меньше 10 с; без параллельных
коллекций и воркеров. 300 кадров ≈ 1,5–2 ч — это нормально. Движок держит паузу
сам; ручной цикл:

```bash
t0=$(date +%s); <заливка одного кадра>; dt=$(( $(date +%s) - t0 ))
sleep $(( dt > 10 ? dt : 10 ))
```

`POST /api/upload` (multipart): `file`, `collection=description`, `id=<travelId>`,
токен owner1 через `createToolSession`. Ответ `{"url": "...", "id": N}`; URL
приходит по `http://` и без сегмента `/<id>/description/` — привести к
`https://` и класть как есть. Разметка — `body-html.md`.
