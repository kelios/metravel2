# metravel-travel-article

Ядро регламента статей автора 1: режимы, жёсткие правила, скелет шагов,
приёмка. Подробности — в `references/`, читать только нужный файл на своём шаге.

## Режимы и маршрутизация

| Запрос | Режим | Читать |
|---|---|---|
| папка фото / «сделай статьи из папки» | новая статья, движок `metravel_publish.py` | `references/new-article-engine.md`, `references/photo-pipeline.md` |
| статья (id/URL/slug) + «отредактируй», «добавь впечатления», «распиши», «добавь фото» | обогащение живой статьи | `references/audit-table.md`, `references/live-edit-recipes.md`, `references/body-html.md`, `references/photo-pipeline.md` |
| статья + дневник/сторис/заметки без папки | дневник, EXIF не нужен | `references/live-edit-recipes.md` → «Дневник» |
| `article-edits.md` от instagram-researcher | приём фактических правок | `references/live-edit-recipes.md` → «Правки от instagram-researcher» |
| комментарий редакции | часть любой правки | `references/editorial-comment.md` |

Не здесь:

- `title`, `meta_description`, лид-сниппет, внутренние ссылки, FAQ, SEO-аудит
  корпуса — `metravel-seo-audit` / агент `metravel-seo-expert`. Любая новая проза
  в теле (справка о месте, практика, эпизоды) приходит от них сюда;
- пост, карусель, Reels — скилл `instagram`;
- подача URL в индекс — агент `seo-daily` после выката;
- выкат: правка в API видна в SPA сразу, краулеру — после выката статики.
  Новая статья или смена `name` отдаёт 404 + noindex до выката. Выкатывает
  агент сам: `DEPLOY_QUIET=1 scripts/deploy-prod.sh <sha origin/main>`
  (`frontend-deployer`, ≤5 мин), затем `curl -o /dev/null -w "%{http_code}"
  https://metravel.by/travels/<slug>` = 200 по каждому новому/изменённому slug;
- делегирование целиком — агент `travel-writer` (те же правила, ядро + reference).

## Полномочия

- Именованная статья (id/URL/slug) плюс просьба вписать дневник, впечатления,
  высоты, еду, жильё, советы или фото — это подтверждение правки текста и записи
  в прод. Не переспрашивать. Аудит без такой просьбы правок не разрешает.
- Карточка борда на правку статьи (сезонная сверка, устаревшие факты, жанр 2d)
  и принятый `article-edits.md` — тоже подтверждение: всё по правилу 4 делается
  без отдельного «да» владельца (решение 19.10.2026).
- Автор — только Юля, user 1. `GET /api/travels/{id}/` → `userIds` без 1 —
  гостевая статья: текст неприкосновенен, ссылаться на неё можно.
- Публикация и снятие с публикации — решение владельца; `publish`/`moderation`
  до и после правки совпадают. Slug и `name` не менять (ломает индексацию).

## Жёсткие правила

1. **Токены.** Только через `createToolSession` / общий resolver
   (`docs/DEVELOPMENT.md` → «Operator token sessions»): owner1 — новая статья и
   правка тела (по умолчанию `bodyMaintenanceSession`); editor120 — комментарий
   редакции; qa104 — только правка тела с явным `METRAVEL_ACTOR_ID=104` (автор
   статьи не меняется). Движок берёт owner1 сам. Токены не печатать, не класть
   в argv, логи, коммиты и карточки.
2. **Фото — только свои с metravel.by.** Внешние, стоковые, Wikimedia и чужие
   статьи запрещены; каждый src отдаёт 200. Нет своего кадра — раздел без фото.
3. **Жанр 2d — журнальный рассказ на личной истории, не путеводитель** (решение
   владельца 03.09.2026, эталон — статья 582). Цель — польза тому, кто поедет,
   и память о поездке.
   - Читатель идёт за автором по дню: старт, подъём, обед, поляна, закат.
     Справка о месте (год, история, легенда, топонимика) — одно-два предложения
     внутри абзаца рядом с фото этого места; объекты `travelAddress[]` — карта
     тем, к которым крепится справка.
   - Город — тоже рассказ по местам, где автор был. Топов «по рейтингам»,
     TripAdvisor и мест, где автора не было, в теле нет; максимум — одна строка
     «что ещё рядом» в «Если соберётесь».
   - Начало — абзац-крючок без заголовка, конец — абзац-вывод без заголовка.
     Заголовки — названия мест и эпизодов дня. Запрещены «Вступление», «Что
     увидели», «Как прошло», «Итог», «Точки», «Описание», «Наши впечатления»,
     «Сложность маршрута», «Что взять с собой», «Что посмотреть по дороге»,
     координаты под заголовками, вложенные нумерованные списки, `<ol>` с пустыми
     `<span>`, заголовок статьи в теле.
   - Вся практика — один короткий `<ul>` «Если соберётесь» перед абзацем-выводом:
     старт и парковка, км и набор одной фразой, когда идти, что проверить; часы и
     цены с офсайта с пометкой «актуально на <год>, уточняйте на офсайте».
   - При дописывании — ПО КОНТЕКСТУ: новый абзац рядом с его днём и кадром, не
     валом в конец и не вторым `<h2>` об объекте, у которого раздел уже есть.
   - Сезонная сверка (зима, ярмарки, канатка, «как добраться из …») — тоже 2d:
     цены, часы, транспорт и сезон 20XX/YY — пунктами в «Если соберётесь» с
     «актуально на <дата проверки>»; что меняется зимой у конкретного места —
     одно-два предложения в абзаце этого места. Разделы «<Место> зимой», «Как
     добраться», «Канатка в сезоне …», «Практическая информация», «… : статус,
     правила, сезон» не заводятся; встреченные старые — разбираются в
     «Если соберётесь» и абзацы мест. «Блок из Кракова» в карточке = пункт
     «Из Кракова: …» в «Если соберётесь». Гейт — проверка `genre-2d` в
     `scripts/article-acceptance-check.js`.
   - Тон — первое лицо и детали, видные на фото. AI-обороты («не просто …, а …»,
     «именно», «настоящий», «одна из самых», «отлично подходит тем, кто», жирный
     на каждом названии) — дефект.
4. **Факты и голос** (решение владельца 19.10.2026). Статью можно редактировать
   целиком; неприкосновенно только рассказанное о нас — события, что делали,
   ели, чувствовали, куда заходили, оценки и порядок дня: их смысл и голос не
   меняются, курсив-цитаты — дословно. Всё, что изменилось с поездки (цены,
   часы, транспорт, парковка, правила, закрытия), актуализируется и уточняется
   и внутри авторского абзаца: опыт остаётся с годом («в 2020-м мы оставили
   машину у Подъельцев»), рядом — как сейчас («с 2026 года парковка у начала
   тропы»). Ошибочный факт исправляется, неподтверждённое общее утверждение
   (не опыт) убирается. Стиль и разметка не «о нас» и правятся по жанру 2d:
   `<h1>` и эмодзи в заголовках, служебные шапки, разделы путеводителя,
   AI-обороты. Новый личный опыт — только из заметок владельца. Название
   места — по EXIF/GPS + надписи в кадре + веб-проверке, не на глаз.
   Неуверенное — `[уточнить]` в черновике; в опубликованном тексте маркера нет
   (гейт приёмки), вместо факта — «не подтверждено» в отчёте.
5. **Источник данных не упоминается**: «по GPS», «из фото», «по EXIF», «по точкам
   съёмки» — нельзя; цифры маршрута подаются как факт («около 5 км»).
6. **Подписи — с точки зрения места, не людей** (решение владельца 20.09.2026):
   `alt` каждого `<img>` и `gallery[].caption` каждого кадра — объект и где он
   («Карьер в Забежуве: известняковая стена над водой»). Обе группы при ЛЮБОЙ
   правке. Шаблон запрета (Python; в JS `\b` кириллицу не видит):
   `(?<![А-Яа-яЁё])(Юля|Юли|муж|мы|нас|селфи|человек|идём|едем|велосипедист)(?![А-Яа-яЁё])`
   с `re.I` — 0 совпадений; тот же шаблон в `article-acceptance-check`.
7. **Пустое поле — `null`.** `plus`, `minus`, `recommendation`, `youtube_link` без
   текста пишутся `null` — движком или `buildUpsertPayload` из
   `scripts/seo-edit.js`; `__draft_placeholder__` не пишется нигде, встреченный
   заменяется.
8. **Беларусь.** Ни упоминаний, ни ссылок на ресурсы из перечня экстремистских
   материалов РБ («Наша Ніва», «Зеркало»/TUT.BY, «Свабода», «Белсат»…). Перед
   записью: `node scripts/scan-content-sources.js <файл>` = 0. Легенду только из
   такого пересказа — «по поздним пересказам краеведов», без ссылки.
9. **Польские замки и монастыри** (Краков, Мальборк, Недзица, Ойцув, Тынец,
   Чорштын, Ланьцут…): опорный источник легенд — Zenon Gierała, «Zamki i klasztory
   w legendach i baśniach polskich»; ссылка «как рассказывает Зенон Герала».
   Книга бумажная у владельца — нужные главы попросить прислать.
10. **Архивы.** `/Volumes/4 TB/Наши Фотки`, `/Volumes/4tbJuli`, `/Volumes/T7`;
    «кадров нет» — только после `find /Volumes/* -maxdepth 3 -type d -iname '*<место>*'`.
11. **Instagram в теле** — только `<p><a href="https://www.instagram.com/reel/<id>/">…</a></p>`;
    iframe бэкенд режет.
12. **Дубли кадров** — по md5 И перцептивному хэшу; лишний удаляется целым `<p>`.
13. **Приватные данные**: скриншоты броней убрать; `sid=`, `checkin=`/`checkout=`
    срезать; `aid=`/`label=` (партнёрка) оставить.
14. **Заливка** `POST /api/upload` — строго последовательно, пауза ≥ max(длительность
    запроса, 10 с) (#2306); движок держит её сам.
15. **Дата статьи = дата поездки**: каталог сортирует по `created_at`, он пишется
    upsert'ом с 23.09.2026 (#1995) — `references/live-edit-recipes.md` → «Дата»;
    в движке — из `date:` черновика.
16. **Комментарий редакции** — ровно один, от user 120, под каждой тронутой статьёй.

## Скелет шагов

**Новая статья**: дедуп против сайта → разведка архива и EXIF → отбор глазами →
черновик с `date:` → `upsert --dry-run` → `upsert` → `photos` → обложка глазами
→ `descimg` → подписи → «Что рядом», квесты, FAQ → комментарий редакции →
приёмка. Черновик `publish=false`.

**Живая статья**:
0. Аудит: GET, тело целиком, `references/audit-table.md` + приёмка ниже — до
   любой записи. `docs/ARTICLE_ATTENTION_LOG.md` — брали ли статью за последние
   7 дней и что уже дописано.
1. Фото (если есть папка или нужны кадры): `references/photo-pipeline.md`.
2. Текст по жанру 2d и разметка: `references/body-html.md`.
3. Имена точек, дата, поля вне тела: `references/live-edit-recipes.md`.
4. Запись: `node scripts/seo-edit.js --id <ID> --desc-file full.html --dry-run`,
   затем без `--dry-run`; бэкап — `scripts/.seo-backups/`, откат `--restore <ID>`.
   `metravel_publish.py` на живой статье не используется.
5. Подписи тела и галереи (правило 6).
6. Комментарий редакции: `references/editorial-comment.md`.
7. Приёмка, строка в журнал, выкат и индекс — если появился новый slug или
   правка должна дойти до краулера.

## Приёмка одной командой

```bash
node scripts/article-acceptance-check.js --id <id>      # exit 0 = всё ✓; --json для машины
```

Читает прод-API без записи и проверяет: картинки тела и галереи отдают 200;
в теле только `travel-description-image`; непустой осмысленный alt; дубли по
md5 + dhash; люди в подписях; пустые подписи галереи; «Что рядом» и «Квесты по
городам рядом» ровно по одному, ссылки квестов из `/api/quests/`; комментарий
редакции от 120; `created_at` в месяце поездки; имена точек; запрещённые
источники; `sid=`/`checkin=`; `[уточнить]`, сентинел, U+FFFD, Instagram-iframe.
Руками сверху: FAQ на генераторе (`references/body-html.md`), `publish`/
`moderation` не изменились, свежий слаг отдаёт 200 после выката. Корпусный
404-прогон всех тел — `npm run test:media:body`.

## Отчёт

Структура §6 `docs/AGENT_ANALYSIS_PROTOCOL.md`, плюс:

- таблица сущностей: id | slug | URL | `userIds` (из GET) | что сделано;
- источник каждого добавленного факта — URL; для геопривязки подписи —
  координаты кадра и расстояние до объекта в метрах;
- фото: сколько залито, откуда, удалённые из галереи и почему;
- неподтверждённое: факты без источника, кадры без уверенной привязки и что
  написано вместо них;
- дата поездки (день или месяц) и её источник (EXIF / текст / `year`+`month`);
- вывод `article-acceptance-check` до и после;
- выкат (sha) и URL для `seo-daily`, если нужны; бэкап и команда `--restore`;
- id комментария редакции.

## Что нельзя

- менять slug/`name`, трогать гостевые статьи, публиковать или снимать с публикации;
- ставить в тело внешние фото, `address-image`, Instagram-iframe;
- слать точку с `id: null` при переименовании (пересоздание без фото);
  оставлять точкам имена-адреса («Krakowska 149», «S7») и дубли;
- сдавать правку без подписей обеих групп, без «Что рядом» с найденными своими
  статьями, без комментария редакции или с красной приёмкой;
- писать в тело справочные разделы, топы и места, где автора не было.
