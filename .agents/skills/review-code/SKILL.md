# review-code

Ревью на **корректность** (баги), не на стиль. Scope по умолчанию — текущий
незакоммиченный diff (`git diff HEAD`) + незапушенные коммиты; аргументом можно
передать каталог/фичу.

## Шаги

1. **Собери scope**: `git status --short --untracked-files=all`, `git diff HEAD` и
   `git diff origin/main...HEAD`. Прочитай новые файлы задачи отдельно. При пустом
   scope сообщи, что изменений для ревью нет; указанную пользователем ревизию проверь явно.
2. **Найди кандидатов** — делегируй агенту `review-auditor` (или нескольким параллельно
   при большом scope) с углами:
   - line-by-line: инвертированные условия, off-by-one, null/undefined, пропущенный
     `await`, falsy-zero, copy-paste не той переменной, проглоченные ошибки;
   - removed-behavior: для каждой удалённой строки — какой инвариант она держала и где
     он теперь;
   - cross-file: вызовы изменённых функций по всему репо (новые предусловия, изменённая
     форма результата, web/native расхождения).
3. **Верифицируй** каждый кандидат чтением кода: REFUTED отбрасывай, остальное чини.
4. **Чини и проверяй**: фикс + Jest на затронутый scope + `npm run typecheck` + ESLint
   по затронутым файлам. Поведенческие изменения контракта — фиксируй обновлением теста.
5. **Отчёт**: находка → severity → что сделано (или почему скип).

## Правила

- Не репортить стиль и невозможные сценарии.
- Этот скилл ревьюит frontend. Для `area=back` используй независимое ревью канонического backend workflow.
- Не отмечать «готово» без зелёных проверок.
